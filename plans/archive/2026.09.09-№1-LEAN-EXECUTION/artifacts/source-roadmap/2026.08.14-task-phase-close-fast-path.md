# Roadmap: Task phase-close fast path

**Статус:** ⬜ к внедрению — группа измеренных 2026-08-14 проблем.

## Цель группы

Вернуть штатный быстрый путь `terminal evidence → justified close`: не терять уже
проведённый GREEN audit, разрешать доказанно лёгким фазам direct close и не превращать
каждое расхождение между audit и close в повторную дорогую работу.

Это execution pack, а не четвёртый источник policy. Он группирует ровно три
существующие спеки:

1. [`2026.08.14-phase-assurance-contract.md`](2026.08.14-phase-assurance-contract.md) —
   semantic impact/seams, которые агент обязан зафиксировать до close;
2. [`2026.08.14-phase-close-impact-broker.md`](2026.08.14-phase-close-impact-broker.md) —
   классификация изменения после уже GREEN audit;
3. [`2026.08.14-repeat-audit-evidence-reuse-budget.md`](2026.08.14-repeat-audit-evidence-reuse-budget.md) —
   reuse terminal evidence и бюджет повторных full audit.

## Порядок без лишних действий

### Slice A — immediate close recovery

Владелец: `packages/task`. Цель — исправить текущий P1 и создать безопасный
минимальный policy foundation.

- Канонизировать `phase-audit-subject/v1`: новые writer'ы пишут `Pn`, все consumers
  принимают исторический `Pn — режим фазы` через один normalizer.
- Добавить `Phase Assurance | v1` в Phase Context: `Impact`, named seams,
  `Live or Irreversible`, `Audit Intent`, rationale.
- `phase_audit_policy()` основывает first-audit decision на assurance + current candidate
  evidence. `Review` и число items больше не являются самостоятельными phase blockers.
- Direct close разрешён только для `direct-close-eligible` isolated phase с зелёными
  receipts/closure gates; public, security/external, live/irreversible и unknown assurance
  остаются audit-required.
- Добавить регрессии на legacy subject, multi-item direct-close, mandatory-risk refusal и
  невозможность скрыть red/material evidence declaration'ом.
- После green package validation штатно закрыть
  `2026.08.02-PROVIDER-CONTRACT-LOCALE P1`, переиспользовав existing GREEN audit.

**Не входит:** новый typed receipt format, diff graph, второй full audit или изменение
product scope P1. Это удерживает slice в пределах одного Task package и одного
доказанного recovery.

### Slice B — audited-candidate impact broker

Запускается сразу после Slice A только если он всё ещё нужен для уже измеренного P10
инцидента. Он вводит `audit-impact/v1` и разделяет `gate-rebind`, `delta`,
`wide-material`, `unclassifiable`. Не повторяет subject/assurance работу Slice A.

### Slice C — reusable validation evidence

Вводит `validation-receipt/v2` и full/delta budget только после того, как Slice B
назвал точный invalidation graph. Не блокирует ни direct close лёгкой фазы, ни P1 recovery.

## Решение о продолжении

| После Slice A | Следующее действие |
|:--|:--|
| P1 закрывается, а P10 broker остаётся единственным подтверждённым mismatch | Выполнить Slice B; Slice C оставить отдельным до его inputs. |
| Новые field cases показывают, что terminal receipts нельзя безопасно переиспользовать | Выполнить Slice B + Slice C как один contract-first план. |
| Нет нового broker/reuse trigger | Не расширять Slice A: записи B/C остаются в roadmap. |

## Общая приёмка Slice A

1. Один audit с legacy/current subject имеет один phase identity для writer, lint,
   delivery, Task Contract и close gate.
2. Показательно лёгкая multi-item phase закрывается без audit только при валидном
   `Phase Assurance | v1` и полном green candidate evidence.
3. Исторический `Review: full` не вынуждает audit сам по себе.
4. Невалидная/отсутствующая assurance и any material/live/public/security risk закрытие не
   разрешают; diagnostics называют точную причину.
5. Existing P1 GREEN audit закрывает P1 без второго audit и без запуска P1 item validation.
6. `bash packages/task/scripts/validate.sh`, generated-projection checks и обе provider
   command golden suites зелёные.

## Критерий запуска

Запускать Slice A следующим изменением lifecycle `plan-audit`/`plan-close`; критерий уже
сработал. Slice B и C запускаются только по правилам таблицы выше, а не по инерции
«раз уж тронули policy».
