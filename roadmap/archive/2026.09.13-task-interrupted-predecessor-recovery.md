# Roadmap: Task восстанавливает прерванный predecessor без цикла ручных запусков

**Статус:** 🔥 trigger сработал; owner-prioritized.

## Field incident

В `edufy`, plan `2026.08.06-EDUFY-BUILD`, после терминального P1.6 handoff
корректно назвал `P2.1` следующим item. В рабочем дереве при этом уже лежит
частичный P2.1 scope: `Modules/SchoolOrg` migrations, модели, фабрики, read
contracts и `SchoolOrgSchemaTest`. Его plan state и journal остаются
`Not started`: стартовая lifecycle-запись не была закреплена до product write.

Повторный ручной запуск P2.2 не может восстановить эту работу. Пять-carrier
snapshot останавливается на отсутствующем `bundles/P2.2.json`; это ожидаемо:
P2.2 зависит от terminal результата P2.1, поэтому его bundle должен быть
materialized только после P2.1 terminal journal event. Нынешний ответ, однако,
выглядит для владельца как бессодержательное «запусти P2.1 ещё раз» и теряет
информацию о незавершённом predecessor.

Оператор сообщил о пяти повторениях этого сценария за 2026-09-13. Один случай
воспроизведён детерминированно.

## Воспроизводимый сигнал

Из корня `edufy`:

```bash

from pathlib import Path
```

Текущий результат: `NEXT_ITEM_NOT_READY`. Отдельно
`task.plan_context.capture(..., 'P2.2')` возвращает `PLAN_CONTEXT_TRUNCATED` на
том же отсутствующем bundle. Оба guard правильны, но ни один не сообщает
оператору recovery state P2.1.

## Граница исправления

Это не повод заранее создавать future bundles и не повод разрешать обход
predecessor dependency. Bundle P2.2 обязан оставаться производным terminal
P2.1, иначе manifest не привязан к актуальному producer state.

Нужен один ограниченный Task change:

1. До `plan_context.capture()` проверять requested item против durable active
   position/semantic Next. Запрос successor при незавершённом predecessor должен
   возвращать typed `OUT_OF_ORDER_REQUEST`, с `active_item`, причиной и точным
   режимом `resume`/`start`, а не только low-level missing carrier.
2. Admission должен атомарно durable-mark `in-progress` до первого product
   write. После прерывания новый invocation может определить, что незакоммиченный
   scope принадлежит активному item, и продолжить его, не предлагая новый запуск
   вслепую.
3. Terminal projection predecessor materializes ровно следующий ready bundle
   после terminal journal event и до delivery validation. Future
   predecessor-dependent bundles раньше времени не создаются.
4. Добавить regression cases: interrupted P2.1-style worktree → resume verdict;
   successor before predecessor → typed diagnosis; terminal predecessor →
   successor bundle materialized and delivery succeeds.

## Acceptance

- Повторный запуск не теряет identity незавершённого item и не создаёт второй
  start event.
- Пользователь получает один объясняющий recovery verdict, а не циклический
  launch block.
- Нельзя открыть P2.2 до P2.1 terminal event.
- Existing delayed producer-bundle semantics и fail-closed snapshot сохраняются.

## Owner and next step

Вынести carrier в одно bounded task-задание `task` после приоритизации владельцем;
не менять runtime из consumer project `edufy`.
