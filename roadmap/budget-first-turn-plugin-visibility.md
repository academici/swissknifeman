# Roadmap: единый измеритель always-on первого хода (проект + marketplace-плагины)

**Статус:** deferred (стаб заведён `2026.07.25-ECO-OPT` P7.3, D142).

## Идея

`skiller budget --first-turn` и `claude plugin details <plugin>` сегодня — два раздельных
инструмента, каждый видящий свою поверхность (проектный `.claude/**`/`.mcp.json`/skiller-реестр
против user-scope marketplace-плагина). Владелец сравнивает их вручную по формуле
(`T_before` + `D_plugin` против порога `FIRST_TURN_WARN`). Цель — один агрегатор, который
берёт `--json` первого и текстовый вывод второго и отдаёт единую цифру + вердикт, без ручного
сложения оценок разной природы.

## Почему не сейчас

Отвергнуто расширять `budget.py` чтением `~/.claude/plugins/**`/`enabledPlugins` напрямую —
это заставило бы stdlib-only пакет отслеживать раскладку чужого продукта
(`docs/rejected-optimizations.md`, строка D142). Агрегатор ДВУХ существующих выводов — другая
конструкция (не парсинг чужой раскладки, а склейка двух готовых чисел), но её ценность не
измерена: на 2026-07-29 известен ровно один прецедент установки плагина (`codex@openai-codex`,
~449 ток) — недостаточно, чтобы решить, стоит ли агрегатор своей сложности (парсинг текстового
вывода `claude plugin details`, у которого нет `--json` и формат может измениться).

## Критерий вытягивания

Появляется ВТОРОЙ независимый случай установки marketplace-плагина в экосистеме (другой проект
или другой плагин), где владельцу снова приходится вручную сравнивать `T_before`/`D_plugin` с
порогом — то есть формула `research/28-P7.3-redesign-2026-07-29.md` §2.3 применяется не в
единственный раз, а повторно. Один прецедент — недостаточно для агрегатора; два независимых —
достаточно, чтобы ручное сравнение стало трением, которое стоит автоматизировать.

## Набросок реализации (при возврате к идее)

1. Обёртка (bash/python, вне `packages/skiller/lib/` — не трогает stdlib-only ядро измерителя)
   гоняет `skiller budget --target <T> --first-turn --json` и `claude plugin details <plugin>`
   по списку установленных плагинов, парсит `Always-on: ~N tok` из текста (регэксп, с явным
   `[UNVERIFIED]` при несовпадении формата).
2. Суммирует, сравнивает с `FIRST_TURN_WARN`, печатает то же трёхветочное правило
   (`research/28-…` §2.3), что сейчас применяется вручную.
3. Регресс-тест на зафиксированном текстовом выводе `claude plugin details` (фикстура, не живой
   вызов) — формат апстримный, тест обязан упасть на изменении формата, а не молча дать 0.
