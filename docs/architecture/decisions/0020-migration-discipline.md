# ADR 0020: Migration discipline: golden fixtures, shims with a window, shadow comparison, rollback

## Status

Accepted

## Context

Behaviour must survive a hard refactoring, and architecture claims must be checkable.

## Decision

Before code moves, golden fixtures capture the behaviour of the CLIs and generators, and architecture checks cover
import boundaries, manifests and schema identifiers. Every stage then: (1) adds its own architecture checks;
(2) gives any shim, alias or old-format reader a compatibility window, a removal stage and a test; (3) compares old
and new output where it is comparable (byte-for-byte generation, old and new config reads, `upgrade --dry-run`)
without doubled side effects; (4) defines rollback: revert the stage commits on the branch, and a separate rollback
plan for the cutover. A claim that "X must not own Y" without a check is treated as unfinished.

## Alternatives considered

- Rely on the existing test suites only: rejected, they do not pin CLI output or generated bytes.

## Consequences

- Golden fixtures are scaffolding, not a CI step (ADR 0027).
- Every shim has a removal date in the stage plan.

## Supersedes

None.
