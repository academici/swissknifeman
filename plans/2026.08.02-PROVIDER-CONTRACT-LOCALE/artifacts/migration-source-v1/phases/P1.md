# P1 — Freeze provider-neutral control-plane contract

## Phase Context

P1 freezes the contract that turns existing provider selection, capability, artifact and
adapter evidence into one deterministic control-plane view without creating a second source
of truth. The frozen predecessor contracts remain authoritative: provider config owns desired
selection, the capability manifest owns support, artifact locks own managed provenance, and
each adapter owns only its projection and observed status. P0 is detailed but not executed,
so this authoring pass consumes no claimed P0 output; P1 execution remains closed until P0.1–P0.4
are terminal and the P0 recovery gate supplies committed evidence. The three items are sequential:
P1.2 consumes the schema from P1.1, and P1.3 consumes both that schema and the ownership matrix.

**Scope Included:** provider-neutral desired/last-applied/observed/drift schema; per-provider status and aggregate rules; capability negotiation; exact canonical/adapter/target/status ownership; recognized legacy upgrade, backup, rollback and no-write gates; normative goldens, checker and Owner freeze.

**Scope Excluded:** package implementation; provider target writes; fleet or Brain migration; locale fields/rendering (P2); rewriting archived contracts; inferring trust, approval or sandbox from another security axis; credential material.

> **Контракт фазы (contract-first).** Потребляет: `brief/00-brief.md`, `research/01-target-architecture.md`, `findings/05-p1-contract-verification-2026-08-02.md`, current `core/provider` implementations and frozen `2026.07.19-DUAL-PROVIDER` contracts; execution additionally requires terminal P0 committed outputs and frozen recovery gates, which do not yet exist · Производит: `root/contracts/provider-control-plane-v1.md` v1.0.0, normative schema/goldens/checker, provider ownership-capability matrix and explicit upgrade/rollback contract · Границы: no package/provider-file/fleet mutation, no locale design, no archived-contract rewrite and no implicit adoption.
