### 1.2. Разрыв «7,9% UI» vs «5178 ток SKM»

Процент в Cursor **не равен** только Swiss Knife Man:

1. **SKM first-turn receipt** (~5,2K ток) — управляемый слой: скиллы профиля, agents pack, root MD, SessionStart, объявленные MCP.
2. **+ Marketplace plugins always-on** (+2,8K) — если провайдер реально поднимает plugin instructions на каждый ход (`--with-plugins`).
3. **+ Платформа Cursor** (вне SKM): system/developer instructions, схемы встроенных tools (Shell, Grep, …), **user rules** (git/PR/стиль), каталог subagent types (bugbot, explore, …), **агрегированный skill index** из нескольких корней (см. §4).
4. **Дубли MCP в UI:** `maind` + `plugin-core-maind`, `perplexity` + `plugin-core-perplexity` — один сервер, два namespace (проектный `.mcp.json` + встроенные plugin MCP Cursor).

Оценка: при окне **~65–100K** effective tokens 7,9% ≈ **5–8K** — согласуется с SKM first-turn **без** полного учёта платформенного слоя. При окне **200K** тот же абсолютный объём даст меньший %.

**Вывод:** 7,9% на «привет» — не обязательно «сломанный SKM»; это сигнал сравнить **SKM receipt** с **provider-visible** каталогом и убрать дубли каналов.

## 2. Почему «каждый провайдер смотрит не только в своё место»

Это не баг одной настройки, а **наложение контрактов discovery**:

| Провайдер | Нативный корень скиллов | Как SKM подключается | Типичный второй канал |
|:--|:--|:--|:--|
| **Claude Code** | `.claude/skills`, marketplace plugins | `connect` → `settings.local.json` + hub stub | Старый vendor в `.claude/skills`, plugin cache |
| **Codex** | `.agents/skills` (auto-discovery) | symlinks / publication projection | Marketplace + **физические копии** в `.agents/skills` |
| **Cursor** | `.cursor/skills`, **глобально** `~/.cursor/skills-cursor`, agent skills list | `.agents/skills` symlinks (D8 ownership) | Claude plugin cache `~/.claude/plugins/cache/swissknifeman/**` (сотни `SKILL.md`) |

`skiller` считает **один** active set из `.swissknife.json` (у chatom: 45 скиллов, ⊕~1,5–1,8K ток). **IDE** дополнительно индексирует всё, что находит по своим правилам, **без** dedup по `skills-lock.json`.

Отсюда шок владельца: профиль узкий, а в system prompt — длинный `agent_skills` из **нескольких деревьев**.

**Почему SKM «допускает»:** исторически channels (`connect`, `vendor`, `publication`) решали **доставку**, а не **единый resident index** на провайдера. Doctor проверяет vendor drift и hub sha, но **не** полный provider-visible inventory с collision report (gap уже описан в [2026.09.21 §B](2026.09.21-consumer-context-rollout-regression.md)).

## 3. Разбор по слоям (ответ на пункты 2A–2E)

### 3A. Платформа (не Swiss Knife Man)

| Слой | Выпиливать? | Комментарий |
|:--|:--|:--|
| System / developer instructions | **Нет** (вне контроля SKM) | Задаёт поведение агента; «автоматизировать» может только вендор (Cursor). SKM может лишь **не раздувать** свой слой. |
| User rules (git, `gh` PR, стиль) | **Нет** по умолчанию | Осознанный выбор владельца; даёт стабильный налог. Сокращать только осознанно в настройках Cursor. |
| Описания built-in tools | **Нет** | Нужны для корректного tool use; отключение ухудшит агента. |
| Subagent types (bugbot, explore, chatom-*, …) | **Частично** | Cursor/репо задают каталог. **Harness agent pack:** optional роли не должны ставиться автоматически (см. [2026.09.21 §D](2026.09.21-consumer-context-rollout-regression.md)). В chatom first-turn: **8 агентов / 711 ток** — кандидат на prune до 4 «рабочих» ролей. |
| Bugbot / security-review subagents | **Не грузят тела до вызова** | Метаданные в каталоге; убрать из `.claude/agents` или пометить optional, если не используются. |

**Автоматизация (граница SKM):** единый **`skiller budget --first-turn --strict`** в CI/template onboarding; **`maind doctor --context`** (см. [2026.09.21 §E](2026.09.21-consumer-context-rollout-regression.md)) как post-sync receipt — не замена вендорского %, но ловит **наш** регресс.

### 3C. Скиллы — корень неэффективности

| Факт | Значение |
|:--|:--|
| Профиль skiller | 45 скиллов, ⊕~1458–1776 ток (зависит от метода подсчёта) |
| Symlinks `.agents/skills` | **99** (шире профиля — projection/historical) |
| Глобальный scan (оценка) | 540 `SKILL.md`, ~47K ток **если** все meta в индекс |
| Дубли по `name` | ~204 имени в нескольких корнях |

**Почему возникло:**

1. `skiller connect` **merge-only** — старые plugins не снимаются ([2026.09.21 §1](2026.09.21-consumer-context-rollout-regression.md)).
2. Codex/Cursor **нативно** читают `.agents/skills` — symlink forest остаётся видимым даже при marketplace connect.
3. Claude **plugin cache** хранит версии скиллов — второй каталог с теми же `name`.
4. `_measure_skills()` в first-turn **не** включает весь provider-visible set ([2026.09.21 §5](2026.09.21-consumer-context-rollout-regression.md)).

**Требование владельца:** при старте сессии — **минимум**; task/plan скиллы — **только по явной команде** (пакет `task`).

| Тип инструкций | Сейчас | Целевое |
|:--|:--|:--|
| Core/php/quality ⊕ always | name+description каждый ход | Оставить узкий профиль `.swissknife.json`; tier-0 только действительно universal |
| Bucket `task` (`task-plan-*`, `task-dev`, …) | Входит в 45 скиллов профиля chatom | **Не** resident: `admission: command-only` / slash-command injection; ⊕ always = 0 для task bucket вне plan session |
| Тела скиллов | On read | Уже ленивые; сохранить |
| Plan markdown (`plans/ACTIVE.md`) | Не в first-turn SKM | Не инжектить через hooks; только Task/plan-run |

### 3D. mAInd (память, SessionStart digest)

| Параметр | Значение |
|:--|:--|
| Режим | `native off` + digest inject |
| Стоимость | **1270 ток / 24,5%** SKM first-turn (chatom) |
| Сырой digest | 5308 байт; длинные усечённые факты (build-status, schema, ui-sdk…) |
| MCP maind | В `.mcp.json`; дубль namespace в Cursor |

**Смысл памяти:** cross-session continuity, graph, `maind_memory_recall` по запросу. **Проблема:** digest на **каждый** SessionStart тащит **исторические** факты → шум, «тормоза» (latency хука + размер контекста), риск устаревших решений.

**Режимы (предложение для `maind`):**

| Режим | SessionStart | Когда |
|:--|:--|:--|
| `off` | нет | Чистые исследовательские чаты |
| `minimal` | 1–3 строки: scope + `maind health` one-liner | Default для обычной разработки |
| `digest` | текущее поведение | Явный flag в проекте / plan session |
| `recall-only` | нет inject; агент вызывает MCP recall | Максимально лениво |

**Отключать ли память целиком:** нет для ecosystem projects; **отключать или сжимать digest по умолчанию**, оставить MCP + daemon для явного recall/store.

## 4. Что должен делать Swiss Knife Man (новые/усиленные контракты)

Сводка владельцев — расширение [2026.09.21 § «Предлагаемый контракт ремонта»](2026.09.21-consumer-context-rollout-regression.md):

### SK-CTX-1 — `skiller connect --reconcile` (A)

Без изменений carrier 2026.09.21: desired state из `.swissknife.json`, снятие лишних `*@swissknifeman` plugins.

### SK-CTX-2 — Provider-visible skill inventory + duplicate diagnostics (B)

Новая обязательная проверка `skiller doctor --context` / `budget --first-turn`:

- объединить: marketplace active set, `.agents/skills`, `.claude/skills`, `.cursor/skills`, **plugin cache paths** (read-only detect);
- typed codes: `SKILL_DUPLICATE_NAME`, `SKILL_MULTI_CHANNEL`, `SKILL_ORPHAN_SYMLINK`;
- JSON для fleet scripts.

**Acceptance (chatom):** после reconcile один канал на провайдер; doctor **WARN** если `name` встречается >1 в provider-visible set.

### SK-CTX-3 — Task bucket не resident (skiller + task)

- В `provider-distribution.json` / skill metadata: bucket `task` → **exclude from ⊕ always** unless `TASK_SESSION=1` или journal marker plan-run.
- Task CLI при `plan-run` / `plan-design` injectает command body (уже частично есть); **не** полагаться на SessionStart.

### SK-CTX-4 — mAInd digest policy (maind)

- Project config: `memory.session_start: minimal|digest|off`.
- `maind health` показывает **токены digest** и рекомендацию.
- Миграция: убрать `priority-block` из CLAUDE при `memory-hook` active.

### SK-CTX-5 — MCP profiles (maind + harness)

- `baseline`: maind only.
- `research`: + perplexity.
- `ide`: + codegraph.
- `harness mcp plan|apply --profile <name>`; Task research commands request profile switch.

### SK-CTX-6 — First-turn provider parity (skiller)

Закрыть gap [2026.09.21 §8](2026.09.21-consumer-context-rollout-regression.md): `--provider cursor|codex` должен мерить **AGENTS.md**, Codex/Cursor hooks, не только `CLAUDE.md`.

### SK-CTX-7 — Fleet rollout

Template в `repository-bootstrap`:

1. `skiller budget --first-turn --strict --json > .skm-first-turn.json` (опционально tracked).
2. `maind doctor --context` после `maind sync`.
3. Порог CI: total ≤16K без plugins, ≤23K с plugins (текущие кодовые пороги).

## 7. Ответы на прямые вопросы владельца

1. **«Каждый смотрит только в своё место»** — неверная модель; верная — **SKM задаёт desired set**, провайдер **сканирует все свои корни**. Нужен reconcile + collision doctor.
2. **GitHub user rules** — оставить; не SKM.
3. **Built-in tools** — оставить; не SKM.
4. **CLAUDE + AGENTS для multi-provider** — один SSOT, разные generated targets; не копировать maind prose в оба.
5. **Task/plan инструкции с начала сессии** — согласен владелец; цель SK-CTX-3/5.
6. **Память mAInd** — не выкидывать; **сменить default** с полного digest на minimal/recall-only.
7. **Perplexity** — условный profile, не baseline SessionStart.

1. На chatom (и 2 других template-проектах) `skiller budget --first-turn --strict` GREEN **и** doctor без `SKILL_DUPLICATE_NAME` / `MCP_DUPLICATE_NAMESPACE`.

3. Perplexity отсутствует в baseline MCP; включается Task research/plan-design path.
4. Task bucket не увеличивает ⊕ always вне plan session (измеримо `skiller budget`).
5. Документированный fleet rollout в `repository-bootstrap` / `ecosystem-setup`.

Carrier остаётся **🟡 partial**: Codex W1/provider часть W7 исправлена в source, а W2–W5,

## 12. Первый ход: что в контексте, что нет

| Компонент | На «привет» в контексте? | Кто управляет |
|:--|:--|:--|
| ⊕ skill descriptions (45) | **Да** (meta) | skiller profile |
| ↻ skill bodies (~50K) | **Нет** (пока не `Read` SKILL.md) | агент |
| Task/plan skill bodies | **Нет** (цель: и meta не resident вне plan) | SK-CTX-3 |
| `plans/ACTIVE.md`, plan markdown | **Нет** | не инжектить hooks |
| SessionStart digest | **Да** (~1270 ток) | `maind` hook |
| `CLAUDE.md` / rules | **Да** (~837 ток) | harness/skiller/maind writers |
| Agent `.md` metadata | **Да** (~711 ток) | harness pack |
| MCP full tool schemas | **Частично deferred** (~584 нижняя граница в SKM) | `.mcp.json` + Cursor plugins |
| Perplexity вызовы | **Нет** | только после tool use |
| Код репозитория | **Нет** | — |
| User rules, system prompt, built-in tools | **Да** (Cursor) | вне SKM |
| Aggregated skill index (100+ paths) | **Часто да** (Cursor) | вне `skiller budget` |

## 14. Анти-паттерны и non-goals

**Не делать при ремонте:**

- Считать «7,9% UI» единственным KPI без `skiller budget --first-turn --json`.
- Удалять user rules или встроенные tool schemas «для экономии».
- Выключать mAInd daemon целиком на linked projects без замены на явный recall workflow.
- Дублировать полный hub-index в `CLAUDE.md` (stub уже правильный паттерн).
- Автоудалять **уникальные** project skills при collision cleanup — только provenance SKM ([2026.09.21 §B](2026.09.21-consumer-context-rollout-regression.md)).

**Non-goals этого carrier:** изменение SemVer API пакетов chatom; рефакторинг Task control plane целиком (см. отдельные roadmap task-productivity / plan-exec overhead).
