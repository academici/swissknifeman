## 4. Процедура включения/выключения — фактически прогнана

### 4.1 Включить (уже было выполнено установкой, здесь — точные команды/ключи)

```bash
claude plugin marketplace add openai/codex-plugin-cc
claude plugin install codex@openai-codex
node "$CLAUDE_PLUGIN_ROOT/scripts/codex-companion.mjs" setup --json --disable-review-gate
```

Проверка: `jq '.enabledPlugins["codex@openai-codex"]' ~/.claude/settings.json` → `true`.
Пин `model`/`effort` для маршрутизированной работы — см. §4.3: без него плагин шлёт `null` →
действуют дефолты машины (`findings/P7-codex-delegation-facts.md` §1.4).

### 4.2 Выключить — фактический прогон (снять → подтвердить → вернуть → подтвердить)

```
$ claude plugin disable codex@openai-codex
✔ Successfully disabled plugin: codex (scope: user)

$ jq '.enabledPlugins' ~/.claude/settings.json
{
  "skm@swissknifeman": true,
  "brain@brain": true,
  "maind@swissknifeman": true,
  "blender@swissknifeman": false,
  "codex@openai-codex": false
}
```

Отсутствие подтверждено ключом `enabledPlugins["codex@openai-codex"] == false` (`claude plugin
details codex@openai-codex` в этой версии продолжает печатать статичный каталог компонентов
даже для выключенного плагина — он не отказывает и не годится как сигнал отсутствия; рабочий
сигнал — именно ключ `enabledPlugins`, как и предусматривала альтернатива ТЗ «либо его отказом»,
здесь сработала альтернатива через `enabledPlugins`).

Возврат:

```
$ claude plugin enable codex@openai-codex
✔ Successfully enabled plugin: codex (scope: user)

$ jq '.enabledPlugins' ~/.claude/settings.json
{
  "skm@swissknifeman": true,
  "brain@brain": true,
  "maind@swissknifeman": true,
  "blender@swissknifeman": false,
  "codex@openai-codex": true
}
```

Возврат подтверждён тем же ключом (`true`). **Возврат `skiller budget --first-turn` к
до-установочному значению проверкой выключения НЕ является и здесь не использовался** (число
не двигалось ни разу — §1 таблица, `research/28-…` §2.3 явно предупреждает об этом).

### 4.3 Пин `model`/`effort` (обязателен, плагин шлёт `null`)

Маршрутизированный вызов обязан явно передавать `--model`/`--effort` в `codex-companion.mjs
task ...` (форма, которую строит `/codex:rescue`) — без явного значения действуют дефолты
машины `gpt-5.6-sol`/`xhigh` (`findings/P7-codex-delegation-facts.md` §1.4). Факт пина и его
исполнение — §5 ниже.

## 5. Проба маршрутизированного вызова — отдельный worktree

Worktree создан вызывающей стороной вне основного дерева:

```bash

```

Вызов (эквивалент `/codex:rescue`: команда плагина — тонкий форвардер к тому же скрипту,
`commands/rescue.md` §«Operating rules» — «one Bash call to invoke node …/codex-companion.mjs
task …»), с явным пином:

```
$ node .../codex-companion.mjs task --model gpt-5.6-terra --effort low \
    "reply with exactly: RESCUE-PROBE-OK, and do not modify any files"
[codex] Starting Codex task thread.
[codex] Thread ready (019fac9b-85ea-7aa3-901d-65e943f08958).

[codex] Assistant message captured: RESCUE-PROBE-OK

```

**Фактические `model`/`effort`, подтверждённые НЕ выводом обёртки, а сырой сессией Codex**
(`~/.codex/sessions/2026/07/29/rollout-2026-07-29T09-41-41-019fac9b-….jsonl`,

удалён (`git worktree remove --force`) после пробы; `git status --short` основного дерева не
несёт изменений от делегата (проверено до и после).

## 6. Правило активации — дословно, с границей

> Плагин `codex-plugin-cc` может быть установлен и включён постоянно, но **задействуется
> только при ЯВНОМ указании в плане, что данную работу ведут субагенты Codex**; по умолчанию не
> используется.

**Машинного гейта у этого правила нет** (D84): ничто в `plan-exec`/`plan-run`/`plan_lint.py` не
проверяет, упомянут ли Codex в ТЗ item'а, прежде чем разрешить вызов `/codex:rescue` или
`Agent(subagent_type="codex:codex-rescue")`. Enforcement — предмет будущего roadmap-кандидата
«провайдер/исполнитель как измерение routing» (D84 Consequences), не этой фазы. Правило
соблюдается дисциплиной автора ТЗ, а не инструментом.

## 7. Правило отката — сработавшая ветвь

Формула `research/28-P7.3-redesign-2026-07-29.md` §2.3, три взаимоисключающие ветви:

```
T_before = 13915  (> 10 000 — проект уже WARN ДО установки плагина)
D_plugin = ~449
```

`T_before > 10 000` ⇒ **ветвь 2**: автоматического отката нет; оба числа называются врозь
(`T_before` = 13915 с разбивкой §1 `findings/P7.3-budget-tool-boundary.md` §2, `D_plugin` = ~449
из §2 этого файла); WARN проекта **унаследован** и не вызван установкой плагина (доказано §2
`findings/P7.3-budget-tool-boundary.md` — инструментальная дельта от установки = 0 по всем пяти
источникам). Ветвь 1 (перевод через порог) не применима: проект уже был выше порога до плагина.
Владельцу предъявляется факт, не требование отката — решение «плагин остаётся» уже принято
2026-07-29 (D142) до записи самого правила.
