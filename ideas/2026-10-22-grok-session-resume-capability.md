# Использовать поддерживаемое продолжение сессии Grok

Статус: расхождение возможностей CLI и каталога подтверждено; исправление и
проверка headless resume ещё не выполнены.

Установленный `grok --help` на 22 октября описывает `--resume [SESSION_ID_OR_TITLE]`,
продолжение разговора без восстановления кода по умолчанию, совместимость с
`--fork-session` и отдельный `--restore-code`. В
`packages/orch/configs/launch-catalog.json` executor Grok имеет только обычный argv;
`resume_argv` отсутствует. У Codex этот маршрут уже есть.

В conductor `shared_session` считает сессию возобновляемой только для Claude Code
или маршрута с `resume_argv`. Поэтому режим handoff сам по себе сейчас не включает
продолжение Grok: следующие коррекции получают свежую сессию и полный prompt.
Разные session IDs в наблюдаемом запуске соответствуют конфигурации; это не
доказательство поломки транспорта или самого CLI.

Минимальное улучшение: проверить точный headless контракт установленного Grok,
добавить provider-specific resume template в каталог и использовать существующие
нейтральные session/task-digest/delta механизмы conductor. Сессия должна совпадать
с item и смысловым task digest; потеря/ошибка сессии требует штатного fallback на
полный prompt. Не использовать `--restore-code`, не восстанавливать старые файлы
и не менять работающие процессы или глобальные настройки.

Дешёвая приёмка: построение argv и доставка session ID, сохранение полного prompt
при изменении задания, delta только при совпадении значимых входов, корректное
поведение при недоступной сессии. Следующее разрешённое штатное исправление может
подтвердить реальный CLI контракт; отдельная сравнительная кампания не нужна.
