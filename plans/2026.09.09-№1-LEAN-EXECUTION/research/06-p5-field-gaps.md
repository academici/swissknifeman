## Vertical decomposition

1. **P5.1 makes existing description policy executable.** The trigger ratchet already owns legal
   debt and the bucket audit already owns budget/usage facts. Joining them additively produces a
   deterministic author queue while retaining honest evidence classes. A positive direct call can
   raise priority; resident-only or zero-call data cannot prove a routing miss. This closes the
   tooling gap without rewriting 61 skills on an incomplete two-project signal.
2. **P5.2 makes field workflow evidence comparable.** Analyst receives one new on-demand command
   whose read boundary is the registered local/vault plan roots. It hashes before extraction,
   collapses mirrors, parses JavaScript as untrusted text and compares field feature signatures with
   signatures from the same four Task templates. The committed report is both the owner-visible
   result and the evidence for any existing-template refinement.
3. **P5.3 closes the promoted Laravel safety carrier at its actual owner.** The serial bootstrap
   guard stays in `createApplication()`, while exact worker-DB proof moves to Laravel's
   before-migrating callback and process filesystem isolation moves to `setUpProcess()`. Missing
   lifecycle evidence fails closed; no suffix widening or Task-level framework rule is introduced.
4. **Promotion stays bounded.** Three distinct plan identities after digest deduplication are the
   minimum evidence for an uncovered slot/guard. Existing-template refinements may land in P5.2;
   a fifth family or a changed mandatory-stage matrix remains a report-only proposal for a later
   decision. A `covered` or `hold` report is a valid result, not pressure to invent a patch.

## Ownership and alternatives

- Copying the ratchet or trigger regex into a second scanner is rejected. P5.1 reads ratchet
  membership and reuses the budget/usage owners.
- Bulk description repair is rejected because the current direct-call evidence is empty and partial.
  The one-way ratchet continues to prevent regression while later edits consume the queue.
- Extending Analyst's lesson `scan` mode with workflow-specific branches is rejected. A separate
  `workflow-scan` module keeps lesson lifecycle and static artifact analysis independently testable.
- Recursive vault crawling is rejected. Explicit project local/vault plan roots are sufficient and
  bound both privacy and runtime.
- Executing JavaScript to obtain `meta` is rejected. Field files are untrusted content; conservative
  static extraction with explicit unknowns is the safe evidence contract.
- Counting raw path occurrences is rejected because the registry exposes local/vault mirrors.
- Automatic template creation is rejected. The Analyst human-gate and Task's four-template canon
  require an explicit later decision for a new family or stage matrix.
- Folding Laravel isolation into P5.1 is rejected: description ranking and pre-write DB/filesystem
  safety have different acceptance boundaries. P5.3 remains a dedicated vertical item but reuses
  the same Skiller registry and docs-build context.
- A suffix/regex allowlist for parallel DBs is rejected. The framework-selected database observed
  in `setUpTestDatabaseBeforeMigrating()` is the exact comparison input; unavailable lifecycle
  evidence yields `FRAMEWORK_LIFECYCLE_CONFLICT`.

## Data contracts

`description-trigger-priority/v1` is additive to bucket-audit JSON. It exposes ratchet membership,
existing listing cost/share, direct usage, evidence class, normalized priority score, stable order,
debt totals and signal coverage. Its filtered CLI view is a read-only projection.

`workflow-fleet-report/v1` records registry scope, missing roots, normalized source identities,
content digests and aliases, extractor status, type/stage/test-strategy features, canonical-template
coverage, anti-patterns, distinct-plan counts and a closed `covered|refine-existing|hold|propose-new`
outcome. Absolute home paths, raw prompts and script bodies are excluded from the committed report.

## Coupling and order

P5.1–P5.3 share package validation, docs impact, generated registry and changelog context but not
product state; they remain adjacent in one P5 batch. P5.2/P5.3 read the preceding state only as an
ordered batch boundary and do not consume unrelated product output. The phase audit checks the
cross-package boundary once: all outputs must be evidence-bearing, deterministic and non-mutating
outside their declared repository files.

## Stop conditions

- Stop P5.1 if a proposed score treats zero calls as a negative verdict, duplicates trigger/token
  formulas, or mutates skills/ratchet from the audit command.
- Stop P5.2 if discovery escapes explicit plan roots, report output contains absolute home paths or
  raw prompt bodies, any field JavaScript executes, mirrors inflate Rule-of-Three evidence, or the
  command writes a foreign tree.
- Stop P5.3 if exact worker DB/token evidence is unavailable before migration, any writable disk
  remains remote/uncontained, cleanup can cross the owned process root, or a proposal weakens the
  serial guard; record `FRAMEWORK_LIFECYCLE_CONFLICT` instead of broadening an allowlist.
- Record `hold` rather than changing Task when fewer than three distinct plans support an uncovered
  feature or the extractor returns unknown/malformed evidence.
- Escalate to a later D-record before adding a fifth template family or changing the design/dev
  mandatory-stage matrix.
