# Roadmap: Task не должен терять Unicode cross-plan input при генерации bundle

**Статус:** код и локальная native delivery проверены в Task 0.17.0; отдельный CoreX consumer-domain gate остаётся у P3.1.
**Критерий закрытия:** опубликованный Task runtime содержит repair и regression test
проходит в consumer-проекции; затем carrier переносится в archive.

## Инцидент

CoreX `2026.09.12-№2-COREX-APPROVED-SPECS P3.1` объявляет два cross-plan decision
inputs в каталоге `2026.09.12-№1-COREX-SUCCESSOR`. При запуске `task:plan-exec`
пятиносительный snapshot отказал `PLAN_CONTEXT_TRUNCATED`: `bundles/P3.1.json`
отсутствует.

Причина воспроизводима без product code:

```bash
PYTHONPATH=packages/task/lib python3 -c 'from task import plan_weight; print(plan_weight.path_candidates("`plans/2026.09.12-№1-COREX-SUCCESSOR/decisions/D16-owner-domain-control-plane.md`"))'
```

До repair команда печатала `[]`. `PATH_TOKEN_RE` разрешал только ASCII, тогда как
Task уже принимает Unicode plan IDs и сам использует `№` в fixtures. После исправления
этого parser `plan_bundle` обнаружил второй дефект: `D16` внутри уже объявленного
пути был повторно разобран как ссылка на `D16-*` текущего плана. В результате bundle
отказывался `unresolvable_entry`; executor затем корректно отказывался читать
отсутствующий carrier.

После генерации bundle тот же P3.1 выявил третий, fail-open дефект: Task Contract
компилировал item с явным `[NEEDS CLARIFICATION: CONSUMER-DOMAIN …]` как `routine`
и возвращал `pre_mutation=allow`. Это могло выдать ложное разрешение на consumer write
с placeholder-путями. Такой marker теперь даёт typed `AUTHORITY_CONTRACT_GAP`; продолжение
возможно только после finite owner gate и concrete binding.

## Исправление и защита

- Путь теперь принимается как один non-whitespace/non-backtick Unicode token и по-прежнему
  разрешается только через `pathlib` к существующему файлу; строка не исполняется.
- Сканер decision IDs работает только по прозе вне backticked paths; явный
  cross-plan путь является одним источником и не создаёт ложную локальную зависимость.
- Contract compiler fail-closed отклоняет любой item с неразрешённым
  `[NEEDS CLARIFICATION: …]`, вместо неявного routine-authority.
- `test_backticked_unicode_plan_identifier_is_a_declared_path` закрепляет точный
  `№`-регресс. Путь остаётся declared input: отсутствующий файл даёт fail-closed
  `missing_file`, а не молчаливую эвристику.
- CoreX должен повторно сгенерировать P3.1 bundle после того, как его отдельный
  consumer-domain authority gate будет квалифицирован. Исправление parser не выдаёт
  consumer, schema или DNS/TLS authority.

## Границы

Это defect Task runtime, не ошибка Cloud Code и не удалённый CoreX artifact. Он объясняет
отсутствие bundle, но не отменяет независимый P3.1 `CONSUMER-DOMAIN` gate: concrete consumer,
operator, entrypoints, source hashes and state/cache protocol всё ещё должны быть bound before
product execution.

## Результат аудита 2026-09-14

Реализация и проверенные границы: `tasks/2026.09.14-skills-and-task-audit/implementation.md`.
