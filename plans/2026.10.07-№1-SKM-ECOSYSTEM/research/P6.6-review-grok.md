## 1. Medium — a forked child keeps `journal.lock`, so later appends drop events

`packages/aicore/lib/aicore/ext/journal.py:99`

`append` holds an exclusive `flock` on `ext/journal.lock` across `os.write` and `os.fsync`, and releases it by closing that descriptor (`journal.py:113-117`). `fork` copies the descriptor. The parent’s close does not release the lock while the child still has it. The next `append` waits out `LOCK_TIMEOUT_S` and raises `JOURNAL_LOCKED`. Non-strict `emit` then returns `None`, so every event until the child exits is dropped (I1, I11).

`subprocess.Popen` closes inherited descriptors before `exec`, so that path does not stick the lock. `os.fork` does. The pause below is inside the real `os.fsync` `append` already calls while the lock is held.

```text
after subprocess.Popen sleep, append OK
after os.fork JOURNAL_LOCKED
the journal lock .../state/ext/journal.lock is held by another process for more than 0.3 s
```

## 1. `packages/aicore/lib/aicore/util/schemacompat.py:283` — conflicting `$ref` siblings hide a tighter target

When a keyword sits on both the `$ref` target and the reference, and it is not one of the merged keywords, the sibling value replaces the target (`merged[keyword] = value`) and the keyword is recorded as a conflict. `ref-sibling-conflict` is emitted only for keywords in `set(new_conflicts) - set(old_conflicts)` (`schemacompat.py:100`). If both versions already conflict on that keyword, a tightening of the target is dropped. The validator applies the target and the siblings together, so a document that was valid becomes invalid while `compare()` reports no breaking change. The same hole covers `pattern`, `items`, and `oneOf`.

```text
document: {"a": "h"}
old valid: True
new valid: False /a: string is shorter than 5
breaking: NONE
```

Old schema: `$ref` to `properties.a` = `{type: string, minLength: 1}`, with sibling `properties.a` = `{type: string}`. New schema: the same sibling, and the target `minLength` raised to 5. `pattern` `^a` → `^ab` with a shared sibling pattern `a|b` likewise reports no breaking change for the document `"a"`.

## 2. `packages/aicore/lib/aicore/util/schemacompat.py:280` — empty `type` intersection is replaced by the sibling type

`_merge_types(...) or value` treats an empty intersection as missing and keeps the sibling type. The validator still requires both types, so the new schema accepts nothing of the old type.

```text
document: 1
old valid: True
new valid: False /: expected string, got integer
breaking: NONE
```

Old: target `type: ["string", "integer"]` and sibling `type: "integer"` (integers pass). New: target `type: "string"` and the same sibling (no value is both).

Direct `$ref` cycles raise `RefError` immediately. A recursive object with a sibling on the back-edge terminates. A 400-case fuzzer of schemas without `$ref` found no false negative in the `patternProperties` rules.

## 4. `packages/aicore/lib/aicore/ext/journal.py:116` — a fork before the fd is tracked keeps the lock

`_held.add` runs after `os.open`, and `_held.discard` runs before `os.close`. A fork in either gap inherits the open file description. `flock` stays held until every copy of that description is closed, and `after_in_child` only closes fds already in `_held`. Another thread can fork between those bytecodes; the reproduction forks inside `os.open`, before `append` adds the fd.

```text

second append FAILED after 0.40s: JOURNAL_LOCKED: JOURNAL_LOCKED: the journal lock .../journal.lock is held by another process for more than 0.4 s
lines [b'{"a":1}']
```

## 5. `packages/aicore/lib/aicore/ext/journal.py:50` — the child closes a descriptor that was reused

`after_in_child` closes every held fd, then `append`'s `finally` closes the same numbers again. If the forking thread continues in the child (the signal-handler case named in the comment), the second `os.close` hits `EBADF`, and a number opened in between is the keep-file fd.

Fork during `os.fsync`, child opens a new file and returns into `finally`:

`newfd` 4 is the reused lock descriptor. The later write fails with `EBADF`.
