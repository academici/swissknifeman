# Changelog

## [Unreleased]

### Fixed

- planner-orch/orch/planner: review из плана доходит до orch. Brief несёт `review_route` (`review.reviewer` без note) и `review_rounds_max` (аддитивные поля exec/v1 execution-input); conductor ревьюит по маршруту плана, если у запуска нет явного reviewer (конфиг, `orchestration.options.reviewer`, `--options` сильнее плана; поставляемый default больше не считается явным — источник `default`), частичный маршрут дополняет reviewer по умолчанию; `rounds_max` понижает `limits.review_rounds` и не даёт раундов сверх него. `requested` при policy без review даёт info `REVIEW_REQUESTED_POLICY_OFF`; групповой review берёт общий маршрут пунктов, при расхождении — самый сильный класс и `GROUP_REVIEW_ROUTE_CONFLICT`. planner `check`: неизвестный id в `review.covers` — `ref_unknown` при любом `design`; `covers` больше не основание для `none`/`self` (conductor его не исполняет), описание в схеме и plan-protocol синхронно.
- orch: учёт usage вычитает cached input из входных токенов Codex, сохраняя форму Claude/Grok; попытки сохраняют `usage_complete`, неполный JSONL отмечает пункт `usage_incomplete` и одним info `BUDGET_UNMETERED`. Повторное чтение usage одного агента не удваивает токены пункта и run.
- orch: проверки checks-stage запускаются со `stdin=/dev/null`, а не с унаследованным stdin conductor: команда, читающая stdin (`docker buildx bake --file -`, `cat`), больше не виснет на открытом пайпе (зависание `tools/bin/gate main` в P2.1).
- planner: `plan.py next` не предлагает батч из пунктов разных шаблонов маршрута как один запуск: готовые пункты `recommended`-батча делятся по шаблону route (первая группа — команда, остальные — `later` и строка батча); цепочки зависимостей остаются в одном запуске, `required` не делится, старт группы не даёт предупреждения о разбиении.
- planner-orch: brief отклоняет только указание запустить `plan.py start|finish`, `unit return`, `planner:plan-run` (глагол запуска, shell-приглашение, кодовый блок); описание гейта («перед `plan.py finish` проверки зелёные», «не вызывай `plan.py finish`») проходит. `report_api` по-прежнему отклоняется при любом упоминании.
- orch: при `checks.executor_runs_checks: false` промпт исполнителя называет acceptance-проверки по id и ожиданию, без команд; исполнителю запрещены docker и контейнерные проверки, а недоказуемое в песочнице он оформляет `pending`, а не `blocked`.
- orch: `run --dry-run` показывает `claim_actor` (actor для `source claim --actor`) и предупреждает, если он не совпадает с маршрутом исполнителя, который dry-run показывает зелёным.
- orch: claim называет исполнителя из `--options` запуска (provider, model, effort), а не только исполнителя по умолчанию; маршрут пункта с другим провайдером проходит claim без дублирующего `orchestration` в плане (`ROUTE_MISMATCH` / `ROUTE_UNDERSHOOT` при зелёном dry-run).
- orch: повтор blocked ad-hoc регистрации допускает done в том же attempt; recovery отвергает квитанцию, предшествующую новому started-шагу, и сохраняет source SHA при дозавершении workspace-коммита для handoff и group review.
- orch: восстановление close/register/commit после сбоя проверяет квитанции work source, attempt и успешный outcome; незавершённая workspace-часть commit повторяется без второго source-коммита. Durable-запросы связывают старые ответы с attempt по digest, close сохраняет `{by, ...}`, а work-source/v1 commit получает аддитивное необязательное поле `attempt`. Раздел «Recovery after a crash» документирует сверку квитанций; документация отделяет локальную durability conductor от non-goals Engine Port.

### Added

- orch: README и docs/index orch ссылаются на матрицу ролей, ownership/recovery, токены и лимиты, stubs-варианты и gui-orch.
- gui-orch: routes (записанный used отдельно от available now), manifest промпта без текстов, budget и gates; gates-clear — argv-команда с обязательным подтверждением и enum провайдера. `conduct status --json` аддитивно показывает lease, эффективные limits, токены/неполноту usage/whitelist routes пунктов и info beacons; `runs --json` — owner. GUI отмечает orphaned как warn с resume, диагностические строки редактируются до обрезки. `route explain --run RUN --item ITEM` читает историю указанного run, а prompt explain отвергает traversal step и symlink escape (`PROMPT_PATH_INVALID`).
- orch: stub-варианты `role@provider.md` и `role@provider--family.md` дополняют общие инструкции один раз, выбираются по фактическому маршруту и пересобираются вместе с manifest при fallback. Снимок run хранит варианты и `variant_resolution` для resume; digest без вариантов сохранён. `orch stubs list` показывает варианты, `show --provider P --model M` — эффективный текст и происхождение частей.
- orch: жёсткие лимиты свежих токенов `tokens_hard_max` пункта и `run_tokens_hard_max` запуска (по умолчанию 0) останавливают новые модельные шаги с `TOKEN_BUDGET`, сохраняя done-шаги. `conduct resume --raise-limit KEY=N` продолжает работу с provenance `limit_raises` и info `LIMIT_RAISED`; run cap фиксируется в `run.json.limits_run` только из доверенных слоёв, `tokens_max` остаётся маяком.
- orch: необязательная проверка окружения Docker — зонд окружения `orch.docker`, `orch.docker-credentials`, `orch.docker-compose` (`skm doctor`, скрипт `packages/orch/scripts/docker-env-check.py`; отдельно от оркестрации: запуски и `orch doctor` его не вызывают): доступен ли демон, rootless ли он, к чему даёт доступ группа `docker`, не сломан ли credential helper; без docker всё `skip`. Краткая инструкция по rootless docker — `packages/orch/docs/docker-environment.md`.
- orch: каталог запуска переопределяется конфигурацией: `[orch.launch] catalog` (файл вместо поставляемого, только machine) и `[orch.launch.entries.<роль>_<провайдер>]` (меняются только отличающиеся поля: `model_class`, `effort`, `timeout_s` — и на машине, и в проекте; `argv`, `transport`, `model_set` — только machine). Источник значения виден в `route explain` и `orch launch show`; `configs/launch-catalog.json` при обычных запусках не меняется.
- orch: статус отчёта исполнителя `done_pending_checks` (работа готова, проверки не запускались в его среде; нужна `pending`-запись): checks-stage запускает проверки как после `done`, пункт регистрируется `done` с evidence проверок; если ни одна проверка не запускалась — `CHECKS_NOT_RUN`. Не регистрируемый статус: планировщик и work source его не видят.
- orch: durable started/stopped step records and crash reconciliation on resume; interrupted executors continue partial work with a correction note, checks detect changed paths, and result readers accept only done steps. Settled items discard unfinished steps, and blocked-item retries clear them before reconciliation, so unknown step keys do not prevent recovery after an owner action.
- orch: local run leases and one conductor per checkout; busy run/resume/settle/release commands preserve state, prune removes old runs under ownership, question updates serialize answers, and orphaned runs expose their status and stop unfinished role groups safely on resume.
- orch: Grok scout (text), triager, researcher и advisor завершают матрицу role × provider; каталог хранит три явных `refusals` с кодом `LAUNCH_REFUSED`, который сохраняется в routing, dry-run, explain и planner-orch. Семь проверок матрицы фиксируют полноту, read-only ограничения, transport и декодирование потока; таблицы доступны в документации.

### Changed

- orch (**изменение умолчания безопасности, решение владельца**): роли, которые пишут (executor, bounded-implementer, registrar), в Codex по умолчанию запускаются без песочницы провайдера — `--sandbox danger-full-access` вместо `workspace-write`; настройка `[orch.launch] access = "open" | "confined"` (умолчание `open`; проект может только ужесточить; `aicore config set --machine orch.launch.access confined`), плейсхолдер `{write_sandbox}` в каталоге; read-only роли остаются read-only. Промпт исполнителя не запрещает docker, если провайдерская песочница его не отрезает. Claude Code и Grok не менялись. `confined` возвращает прежнее поведение.
- orch: `configs/launch-catalog.json` хранит только специфичное: `defaults`, общие поля роли, именованные части argv (`parts`, `@имя`) и у провайдера — лишь отличия (13,7 КБ → 7 КБ). Разрешённый каталог не изменился: он закреплён снимком `tests/golden/launch-catalog-resolved.json`; файл в прежнем (развёрнутом) виде по-прежнему принимается. `catalog_version` не менялся.
- orch: Grok executor и bounded-implementer запускаются conductor через jsonl (`streaming-messages-json`) под Landlock `ro-run.py`; `ro-run.py --protect` делает read-only Grok-роли fail-closed. Preflight проверяет команду за wrapper; capability seed и matrix подтверждены probe флагов и фикстурой реального потока.

## [0.31.1] - 2026-10-19
