### P5.4 — Принудить frozen queue contract и fail-closed outcome semantics

**Intent:** Закрыть RED-аудит захода 2 по D146 без смены frozen semantics: один semantic-outcome reducer определяет permission/pending для response и auto-answer во всех state/pending/owner/join consumers; 2–5 substantive options считаются отдельно от mandatory `escalate`/`reject`; request/resolve после transient projection failure принимают exact retry и сходятся к согласованным queue/journal/views, не публикуя continuation до freshness checks. RAG:— (repo-grounded: последний Audit P5 findings 1–3; `research/23-p5-audit-reopen-round2-2026-08-09.md`).
**Why:** После D144 runtime валидирует shape и пишет правильный blocked item state, но `pending_groups()`/`unresolved_for_phase()` всё ещё считают любой auto-answer разрешением; option bounds включают mandatory ids; append предшествует projection, а duplicate/reuse guards блокируют repair того же decision. Это три дефекта одного consumer boundary, а не недостаток P5.1/P5.2. RAG:— (repo-grounded: `packages/task/lib/task/plan_requests.py:156,451-566`; `phases/P5/P5.md` Audit P5, заход 2).
**Scope Included:** Один semantic-outcome reducer для request/response/auto-answer; согласованный verdict в journal/item state, `pending_groups()`, `unresolved_for_phase()`, `render_gates()` и terminal phase join; `reclassified_to=authorization` остаётся pending/blocked и видим owner gate; substantive option filtering/count 2–5 отдельно от mandatory choices, unique ids по всему массиву; exact-payload idempotent retry request и resolve; continuation только после item-state/status/owner-gate regeneration + `--check`; test-only RED commit до runtime fix; отдельные lower/upper/mandatory-only и request-/resolve-failure regression tests; новый terminal evidence с канонической `write-site: pre_mutation: allow · pre_final: allow`.

**Implementation Rules:**
- Frozen schema — единственный словарь формы: validator читает `request`/`response`/`auto_answer_event`, `kinds`, `reason_codes`, `options`, `timeout_policy`, `constants` и `canonical_action.material_fields` из JSON; второй ручной required/enum список запрещён. Domain-specific cross-field rules допускаются только там, где schema ссылается на authority frame или tool computation. RAG:— (repo-grounded: D29, frozen schema).
- D145: `action` — только construction input детерминированного writer, не durable request field. Writer обязан свернуть его в `canonical_action.action`, пересчитать доверенные поля и удалить до closed-shape validation/append; stored request не может нести extra `action`. RAG:— (repo-grounded: D145; frozen `request.additional_properties: false`).
- Schema dialect fail-closed: interpreter явно перечисляет поддержанные keywords/refs и отвергает неизвестный или непроверенный keyword вместо молчаливого пропуска; тест сверяет покрытие фактического frozen schema. RAG:— (repo-grounded: `research/22-…` pre-mortem).
- Request до append обязан пройти closed-shape и cross-field проверку. Substantive rows считаются после исключения РОВНО frozen mandatory ids; допустимы 2 и 5 inclusive, а `escalate`/`reject` проверяются отдельно. Mandatory-only отвергается, 2+2 и 5+2 принимаются, unique ids охватывают весь массив. RAG:— (repo-grounded: audit-2 finding 2; frozen schema `options`).
- Response до append/application проходит closed response schema, identity/version/digest, ISO time, resolver/reason/provenance и selected option. Для clarification обязателен `reclassified_to`; повторное применение exact decision/action запрещено. RAG:— (repo-grounded: audit finding 2; frozen response section).
- Один semantic-outcome reducer возвращает `pending|pending-authorization|apply|park|reject|escalate`; только `apply` означает permission. Item transition, `pending_groups()`, `unresolved_for_phase()`, `render_gates()` и phase join обязаны использовать этот verdict. `reclassified_to=authorization` → `pending-authorization`, blocked state, owner row и unresolved join. RAG:— (repo-grounded: audit-2 finding 1; `research/23-…` §3).
- Request/resolve retry идентифицируется по exact canonical durable payload + decision/action/resolver identity. Exact existing request/response повторяет repair boundary без duplicate queue event; любое расхождение остаётся fail-closed duplicate/reuse error. RAG:— (repo-grounded: D146; audit-2 finding 3).
- Durable response event не публикует continuation. Для `apply` continuation добавляется только в успешный return после journal semantic result, target `.state.md`, `status.md` и `decisions/_gates.md` regeneration + `--check`; исключение не возвращает и не сохраняет разрешение root. RAG:— (repo-grounded: D146; frozen continuation identity уже живёт в request).
- Repair boundary идемпотентен: если latest journal result соответствует semantic verdict и три views свежи, повтор — no-op; иначе он append'ит необходимый result, регенерирует и проверяет views. Ошибка может оставить append-only provenance, но exact retry обязан сойтись; generated views руками не правятся. RAG:— (repo-grounded: `research/23-…` §5; root.generated-artifacts).
- Frozen P5/P4 contracts, D143 hash, carrier registry, P6 и `packages/artifex` read-only. Если исправление требует их изменения — STOP и escalation к plan-design; молча расширять scope запрещено.
