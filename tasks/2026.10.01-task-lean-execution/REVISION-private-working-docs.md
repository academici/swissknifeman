# Ревизия: рабочие документы (планы, roadmap, задания) в публичном дереве

**Дата:** 2026-10-01. **Триггер:** `packages/task/configs/calibration-probe-log-v2.json` хранил
`source_path` в `plans/2026.08.03-ARTIFEX-SUPERVISOR/…`; владелец: информации о планах в репозитории быть
не должно, всё такое — в игнорируемой корневой папке. Плюс требование «в репозитории нет абсолютных путей».

## Что сделано (локально, без коммита)

| Что | Результат |
|:--|:--|
| Абсолютные пути рабочего окружения в продуктовых файлах | 6849 → 0 (`packages`, `core`, `configs`, `docs`, `scripts`); тестовые фикстуры — `/home/user/…`, документация — `<REPO_ROOT>`/`~`. Исключение: `packages/maind/tests/test_provider_deploy.py` (точный preimage D108/D115, его sha256 закреплён в `provider_deploy.py`). |
| Калибровка `packages/task/configs/*calibration*.json` | `source_path` плановых источников → нейтральный `corpus/<имя>`, продуктовых — относительный путь; `plan_weight` ищет по sha256, путь — fallback от корня репозитория. `calibrate-token-estimate.py` пишет те же метки. |
| Запрет возврата | `scripts/public-hygiene.py`: проверка содержимого (путь домашнего каталога + типовая раскладка `projects/`, `.claude/` …; синтетические `/home/user`, `/home/example` разрешены), тесты. |
| Рабочие документы | **Байты не менял.** Моя массовая замена в `plans/`, `roadmap/`, `tasks/` ломала sha256-печати (запечатанные артефакты, journal) — возвращено к HEAD; они временно исключены из проверки содержимого. |

## Измерения для решения

- Tracked рабочие документы: `plans/` 4372 файла, `roadmap/` 59, `tasks/` 32 (≈4.5 МБ), `.cursor/plans/` 3.
  В них остаются 49+254+19+13 файлов с `/home/<owner>/…` (запечатанные evidence).
- Упоминания конкретных планов (`2026.MM.DD-…`) в продуктовой части: ≈700 — task/tests 143, task/lib 120
  (в основном комментарии-цитаты), skiller/skills 86 (74 файла), docs/ 150+, skiller/lib 38, task/configs 33 …
- **Функциональные зависимости** (симуляция чистого клона без `plans/ roadmap/ tasks/ .cursor/plans/`):
  task — 9 тестов (lifted-schema byte-identical, `resolve_plan_dir(...)` примеры контрактов, route/task_contract
  фикстуры), skiller — 1, harness — ≥30 (instruction-* тесты читают плановые носители), artifex — тесты читают
  артефакты ARTIFEX-плана (7 уже красные на HEAD). То есть вывод планов из git без развязки ломает продукт.

## Варианты

| | Что | Цена | Риск |
|:--|:--|:--|:--|
| A | Развязать продукт от планов (фикстуры/эталоны → `tests/fixtures_data`, цитаты в коде/доках → ссылки по `Short ID`, не пути), затем `git rm --cached` + `/plans/ /roadmap/ /tasks/ /.cursor/plans/` в `.gitignore`; файлы остаются локально | крупная работа: ≈55 тестов, ≈700 цитат | средний; история в git сохраняется |
| B | Не выводить, а прекратить утечку: правило «продукт не ссылается на плановые пути» (gate) + чистка конфигов/кода от путей; планы остаются в git | малая | низкий; планы остаются публичными |
| C | A, но планы хранить в отдельном приватном репозитории/подмодуле | A + инфраструктура | выше |

Рекомендация: **A поэтапно** — (1) gate «продукт без путей к планам» (вместе с уже сделанным gate абсолютных путей),
(2) развязка 55 функциональных зависимостей по пакетам (task → harness → skiller → artifex), (3) вывод
рабочих папок из индекса одним коммитом. Шаги 1–2 обратимы; шаг 3 меняет, что публикует репозиторий — только по
явному решению владельца. Проекты флота хранят свои `plans/` в git сознательно (протокол Task: «repository files
are source of truth») — это решение касается только публичного swissknifeman.
