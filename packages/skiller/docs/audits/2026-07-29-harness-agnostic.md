## Мета-находка прогона (важно для петли)

Аудит собирался по публичным README монорепо, а не по дереву, и получил на вход
`framework-overview.md`, объявлявший каркас `v0.1.0-wip (2026-06-23)` с семью `🔜` при
готовой реализации (`backend-laravel@0.12.2`, lock, universal roles). Отсюда систематический
сдвиг: аудит предлагает построить уже стоящее (§3, §5, §10.3) и почти не видит
недоделанного. **Причина — невыполненный шаг 5 предыдущего цикла** («обнови
`framework-overview.md` — он вход следующего аудита»), не выполнявшийся 36 дней. Ремонт
петли — предмет этого же прогона: см. «Куда легло».

## Куда легло

Прогон принят статусом `partially-absorbed`: absorb-now пункты исполняются фазами
мастер-плана — **P1** (паритет корневых инструкций),
**P2** (паритет capability второго провайдера), **P3** (живой канон каркаса и гигиена
реестра), **P4** (декларативная политика спавна/делегирования, поглощённый супервизор-трек
); изоляция работ — **P0.1**, возврат в основное дерево — **P5**.
Решения зафиксированы в [decisions-ledger](../agent-framework/decisions-ledger),
ledger-строка прогона — в `packages/skiller/references/framework-audits.md`.

Побочный результат прогона — механический: разрыв петли аудита закрыт не только
содержанием, но и гейтом. `framework-overview.md` объявляет таблицу «пак → версия», а
`scripts/validate.sh` сверяет её с `pack.json` каждого пака — вход следующего аудита не
может тихо отстать от дерева.
