# Roadmap исполнения — 2026.07.29-HARNESS-AGNOSTIC

**Обновлён:** 2026-07-29 · **Соответствует plan.md:** v0.8.2 (штамп сверяется с `plan.md`

> **Карта ПЕРЕСОБРАНА заходом `finish` (design pass 3/3)** и провизорной больше не является.
> Две правки против прошлой редакции: (1) девять items переведены с `plan-exec` на `plan-run`
> — их §3 Routing приведена в исполнимый вид (`Exec = manual`, **D47** во исполнение D39);
> (2) батчи **B2** и **B3** расформированы — обе пары проваливают критерий склейки
> `plan-protocol` §9 «Inputs одного не ждут Deliverables другого внутри батча» (**D53**).
> Roadmap моделей не назначает: колонка «Model class/Effort» здесь — копия §3 Routing.
>
> **Ни один из трёх заходов `finish` по находкам design-аудита карту НЕ перестраивал:** ни
> маршруты, ни батчи, ни гейты владельца ими не менялись — правки были текстовыми внутри ТЗ items.
> · Заход 1 (**D56–D62**): единственная синхронная строка — расширенный предмет **P0.5** (регистр
> очереди флота, D61). · Заход 2 (**D63–D67**): суженные машинные предикаты P0.5, `P4.3` в гейте
> переадресации P1.1, порядок коммитов P1.5, Scope P3.2 — карта не задета ни одной строкой.
> · Заход 3 (**D68–D70**, этот): design-коммит истории ветки, форма гейта переадресации P1.1,
> ретроспективная запись журнала, штамп версии выше — маршруты, батчи и гейты владельца
> не менялись. Арифметика карты (8 `plan-exec` + 2 в B1 + 19 solo = 29) в силе.

**Почему батч ровно один.** Каждая фаза объявила строгий порядок исполнения, а `Inputs`
большинства items ссылаются на `Deliverables` предыдущего внутри той же фазы (см. вердикты
«оркестрация НЕ объявляется» в `phases/P4.md` и `phases/P5.md`). После замера сцепленности
критерий склейки выполняется ровно у одной пары — **B1**; остальное идёт solo, и у каждого solo
названа причина. **Workflow-групп нет ни одной**: ни одна фаза не прошла критерий «N≥3 items с
независимым scope» (`plan-protocol` §7), каталог `plans/2026.07.29-HARNESS-AGNOSTIC/workflows/`
не заводится.

**Чем `plan-run` отличается от `plan-exec` в этой карте.** `plan-exec` запинен
`implementation/medium` и даёт ЖЁСТКИЙ гейт маршрута; `plan-run` наследует модель/effort сессии
и гейт ИНВЕРТИРУЕТ — сверяет фактический маршрут с §3 и печатает `Session: <model>/<effort>` в
отчёте. Для items с `effort = high` второй путь единственный (граница честности
`plan-protocol` §9); владелец выставляет модель/effort сессии ПЕРЕД запуском по колонке
«Model class/Effort».

### Серия solo-items под `plan-run` — форма запуска

Девятнадцать solo-items с `Exec = manual` идут по ОДНОЙ форме — по одному item'у за сессию,
модель и effort выставляются владельцем ПЕРЕД запуском по колонке карты. Разбивка: **одиннадцать
`implementation/high`** — P1.2, P1.3, P1.4, P2.2, P2.3, P2.4, P3.3, P3.4, P3.6 (девять,
переведённых D47) плюс P4.4 и P5.1, которые несли `manual` изначально; **восемь
`frontier/high`** — P0.4, P1.1, P1.5, P2.1, P4.1, P4.2, P5.2, P5.3. Батчем они не идут: каждый
несёт либо зависимость по `Inputs` от предыдущего, либо класс `Review = full`. Сверка счёта:
19 solo + 2 в батче B1 = 21 `manual`, плюс 8 `plan-exec` = 29 items плана.

| Параметр | Значение |
|:--|:--|
| Model class | из колонки «Model class/Effort» строки item'а (implementation либо frontier) |
| Effort | high |
| Capabilities | — |
| Context | cold-start — plan-step |
| Суть | Один item мастер-плана под маршрутом §3 Routing; команда наследует модель/effort сессии и печатает `Session: <model>/<effort>` в отчёте |

```
run-items: task:plan-run 2026.07.29-HARNESS-AGNOSTIC <Pn.m>
```
