**Implementation Rules:** `core/locale` accepts already-read descriptors and has no environment/provider I/O; its only filesystem semantic input is the exact P2-pinned registry file read through one stdlib loader whose File-Date/SHA-256/upstream identity is checked before use. Each surface runs frozen P2 syntax → canonicalization → catalog stages independently. RFC canonical tag and SKM catalog result are separate values: `ru-RU` stays canonical `ru-RU` and resolves to catalog `ru`; valid registered unsupported tags may fall back to `en`; any tag containing private-use is syntax-valid but catalog-refused as `unsupported-private-use`, with opaque private subtags preserved and never labeled `malformed`. RAG:✅ 2026-08-03 official IANA/RFC 5646 verification in `findings/12-design-audit-remediation-2026-08-03.md`; RAG:— (internal catalog policy: D17 and P2 contract/research) `scripts/update-iana-language-subtag-registry.py` is the sole update producer: it accepts an explicit downloaded source file, verifies registry structure/File-Date, writes snapshot plus adjacent provenance atomically, and requires an explicit reviewed hash change; runtime never fetches host-time data. Provenance contains only declared rank/kind/requested/canonical/resolved/fallback/diagnostic fields. Catalog values may change human prose only: keys, placeholders, commands, paths, codes and literals are byte-preserved or the render refuses. Packages own catalogs and targets; both providers consume the same resolved semantic context, and neither stores locale as adapter intent.
