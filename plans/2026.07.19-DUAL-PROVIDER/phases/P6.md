# P6 — mAInd deployment, memory и provider-neutral analytics

## Phase Context

P6 переводит mAInd project deployment/onboard/sync с Claude-specific target writes на
явный provider loop и вводит общий normalized analytics contract для `analyst`/`maind`.
mAInd владеет выборкой проектов, memory scope, semantic MCP inventory и sequencing, но
provider paths/trust/hooks/serialization получает только из frozen P5 adapters. Analyst
владеет neutral event/run schema и named raw readers; provider raw logs остаются local-only.
Root/package instruction sync также потребляет только frozen P5 instruction catalog/render
plans: mAInd выбирает project/provider/scope, но не переписывает common rules и не строит
`AGENTS.md` из `CLAUDE.md`.
Legacy Claude surfaces сохраняются через compatibility adapters и dual-read/single-write
migration, без удаления source data. P6 завершается durable pre-restart checkpoint и
отдельным cold-session proof; self-host apply/release остаются P7, FOREMAN/fleet не меняются.

**Scope Included:** effective-provider loop; provider-tagged deploy/sync/onboard results;
semantic mAInd/MCP/code-graph/Perplexity inventory; P5 target/trust/context projections;
root/package instruction plan/check/apply/repair; managed section/source-hash diagnostics;
provider-aware health/doctor; neutral analytics contract/store;
Claude/Codex readers; legacy read/migration; analyst/maind consumers; bootstrap checkpoint;
memory/code-graph/Serena/Perplexity cold-restart proof.

**Scope Excluded:** изменение P1 precedence или P2 artifact kernel; повторный дизайн P5
profiles/hooks/MCP projections; provider SDK/runtime dependency; raw log aggregation;
secret values; auto-promotion analyst lessons; live self-host apply/release P7; запуск
FOREMAN; mass fleet writes; удаление legacy `.claude` data; unattended multi-provider runner.

> **Контракт фазы (contract-first).** Потребляет: terminal P5.7, frozen v1.0.0 capability/config/artifact/migration/skill-publication/command-routing/harness/instruction contracts, P1 resolver, P2 artifact engine и P5 harness+instruction conformance · Производит: provider-aware mAInd deploy/onboard/sync включая root/package instruction plan/check/apply/repair, frozen provider-analytics contract, neutral readers/store/migration, provider-tagged conformance и post-restart bootstrap checkpoint для P7 · Границы: не меняет P1/P2/P5 semantics, не копирует raw provider logs, не выводит один provider instruction file из другого, не применяет self-host/fleet config, не исполняет FOREMAN и не удаляет legacy data.

**Entry gate:** P6.1 не начинается, пока P0.3/P0.4, P1.1–P1.4, P2.1–P2.4,
P3.1–P3.5, P4.1–P4.5 и P5.1–P5.7 не терминальны; восемь predecessor contracts не
frozen v1.0.0; P5 conformance не отдаёт provider projection/trust/diagnostic API.
Draft placeholders, текущий Codex bootstrap и mAInd memory checkpoint не являются
implementation/release evidence. RAG:— (repo-grounded: D11/D12/D28–D32,
`research/10-p6-maind-analytics-bootstrap-design.md`)
