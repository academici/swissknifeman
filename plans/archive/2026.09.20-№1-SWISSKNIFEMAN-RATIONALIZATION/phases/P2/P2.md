# P2 — Field audit corex, agentools и edufy

## Phase Context

P2 отдельно и только read-only изучает corex, agentools и edufy как три разные
field case. Каждый case сначала снимает свой commit/configuration/coverage baseline и
прогоняется по одной rubric; cross-case synthesis начинается только после трёх
законченных findings. Consumer source читается как commit-bound `git show`, а свежие task/run-report
артефакты — только из managed provenance-preserving stores через read-only инструменты.
Tracked-only граница применяется только к consumer repository bytes; эти managed stores —
явное read-only исключение. Грязные
worktrees не читаются и не меняются. Результат — три независимых findings и один
ограниченный синтез фактической ценности/трения swissknifeman в этих case, без каузальных
или population-wide заявлений.

**Scope Included:** corex field finding; agentools field finding; edufy field finding; cross-project synthesis по единой P1 rubric.
**Scope Excluded:** запись в consumer repositories; secrets и untracked/vendor/generated consumer repository bytes; обобщение одного проекта на все. Managed provenance-preserving run-report stores допустимы только как read-only исключение.

> **Контракт фазы (contract-first).** Потребляет: sealed P1 baseline и rubric · Производит: три field findings и cross-project synthesis для P3/P4 · Границы: consumer trees остаются read-only.

> **Phase Assurance | v1.**
> Impact: internal-integration
> Integration Seams: `corex-field` · `agentools-field` · `edufy-field` · `cross-case-synthesis`
> Live or Irreversible: no
