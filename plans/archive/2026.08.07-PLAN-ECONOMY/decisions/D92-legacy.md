## Решение

**Якорь калибровки переносится с `POST /v1/messages/count_tokens` на ДИФФЕРЕНЦИАЛЬНЫЙ замер по `usage` транскриптов Claude Code.** Истина файла: `true(f) = sum3(B) − (sum3(A) + sum3(A'))/2`, где `sum3 = input_tokens + cache_creation_input_tokens + cache_read_input_tokens`, `A`/`A'` — прогоны обёртки с пустой полезной нагрузкой, `B` — с содержимым; расхождение контроля выше объявленного δ отбраковывает замер файла. Артефакт калибровки получает поля провенанса (`source`, `probe_protocol_version`, разброс контроля, число отбраковок). `count_tokens` НЕ удаляется — становится альтернативным источником, различаемым машинно полем `source`; смешение источников в одном артефакте запрещено. **Consequences:** `supersedes D11` в части КАНАЛА доступа к настоящему токенизатору и отменяет формулировку «точный режим `--exact` = вызов `count_tokens`» — `--exact` означает дифференциальный харнесс; существо D11 (оценка сверху, оффлайн, stdlib-only, детерминированная, калиброванная один раз) и целиком D14/D15 в силе; платой становится более шумная истина, и эта цена платится МНОЖИТЕЛЕМ БЕЗОПАСНОСТИ, а не ослаблением гейта — `violations: 0` и p95 ≤ 1.6 остаются дословно, недостижимость обоих есть эскалация к владельцу.

## Почему

Владелец заявил 2026-08-07: «ключа у меня не будет, вход по подписке». Проверено внешне: `count_tokens` бесплатен и имеет собственные RPM-лимиты, НО требует учётных данных Console (`sk-ant-api…` в `x-api-key` либо bearer через Workload Identity Federation), а подписка Pro/Max доступа к Console/API не даёт вовсе — её OAuth-токен документирован как способный делать ТОЛЬКО запросы модели, тогда как `count_tokens` есть отдельный служебный эндпоинт. RAG:✅ 2026-08-07 (`findings/14-…` R21, R22; `platform.claude.com/docs/en/build-with-claude/token-counting`, `…/manage-claude/authentication`, `docs.anthropic.com/en/docs/claude-code/iam`). Значит прежний канал закрыт навсегда, а не временно, и «эскалация при недоступности» была бы остановкой плана на первом item'е. Замена существует и проверена в среде: Claude Code пишет фактический `usage` каждого ответа API в транскрипт сессии, а полный размер промпта равен СУММЕ трёх входных полей (наблюдено `input_tokens: 2` при `cache_creation 31878` + `cache_read 20598`) — это счёт настоящего токенизатора названной моделью, по подписке, без ключа и без сети со стороны инструмента. RAG:— (env-grounded: `~/.claude/projects/<slug>/<session>.jsonl`, 54 записи с `usage`, 2026-08-07; правило суммы — справочник `claude-api`, `shared/prompt-caching.md`). Оптимизационные токены, которые счёт может включать (R21), смещают истину ВВЕРХ — для оценки сверху это безопасная сторона. Запрет на `probe.tool_reported_tokens` как калибровочную точку (D15) переносом не ослабляется: это счётчик среды чтения, а не токенизатор модели. Синтез — `research/09-…` §3
