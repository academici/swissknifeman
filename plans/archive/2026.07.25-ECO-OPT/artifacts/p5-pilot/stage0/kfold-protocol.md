# Протокол k-fold-перезамера `P_impact` (объявлен ДО первого прогона)

**Зачем.** Единственная честная слабость замера P5.1 против собственного вердикта: на каждый
коммит брался **ОДИН** seed-файл, то есть медиана считалась по трём точкам, каждая из которых —
одна случайная реализация. Владелец 2026-07-27 выбрал «skip, но сначала усилить замер; порог
неприкосновенен» (D112). Этот файл фиксирует метод **до** запуска графа — как `impact-cases.json`
фиксировал co-change ground truth до первого прогона P5.1 (коммит `a8639c82`).

**Что НЕ меняется:** порог `P_impact ≥ 0.40` (правило ступени 0 п.2, D35), набор коммитов,
co-change ground truth (`impact-cases.json`), версия CRG (2.3.7), режим эмбеддингов (выключены),
флаг `--max-results 200`, метод «граф строится на РОДИТЕЛЕ коммита».

## Метод

Для каждого из трёх коммитов `C ∈ {80182e8 (small), c9c4089 (medium), 87af600 (large)}`:

1. `git checkout --detach <parent(C)>` в `git worktree`-копии `flexcrm`; `code-review-graph build --repo . -q`.
2. **Множество допустимых seed'ов** `S(C)` = файлы из `ground_truth_files(C)`, которые
   **существуют на родителе** (`git cat-file -e <parent>:<path>`). Новые/переименованные файлы
   seed'ом быть не могут — у графа-предшественника для них нет узла (та же причина, что в P5.1).
3. **Каждый** `s ∈ S(C)` идёт в замер — ни один не выбрасывается ни по какой причине
   (анти-подгонка; «неудобный» fold остаётся в выборке):
   - `predicted(s)` = `impacted_files` из `code-review-graph impact --repo . --files <s> --max-results 200`;
   - `held_out(s)` = `ground_truth_files(C) \ {s}`;
   - `precision(s)` = `|predicted(s) ∩ held_out(s)| / |predicted(s)|`, **0.0 при пустом
     `predicted(s)`** (объявлено ДО прогона);
   - `recall(s)` = `|predicted(s) ∩ held_out(s)| / |held_out(s)|` — контекст, не порог;
   - `precision@10(s)`, `precision@20(s)` — самое благосклонное к инструменту усечение выдачи.
4. `precision(C)` = **среднее** по всем fold'ам коммита (стандартная k-fold-агрегация);
   для прозрачности печатается и медиана по fold'ам.
5. **`P_impact` (k-fold)** = **медиана** трёх `precision(C)` — внешняя агрегация та же, что в P5.1.

## Границы метода (названы заранее, не постфактум)

- Сверка множеств — по путям; файл, **переименованный** в коммите, предсказан быть не может.
  Это занижает числа графа на `87af600` (перенос в `modules/`), и это ограничение co-change-метода
  как таковой, а не выбор в чью-либо пользу.
- Весь changed-set коммита разом seed'ом **НЕ подаётся**: предсказывать файлы, которые сам же и
  скормил, — круговая метрика по построению, ровно та, за которую D34 дисквалифицировал
  заявленный автором F1 0.714.
- CRG индексирует только tracked-файлы (`git ls-files`) — seed вне индекса даёт пустую выдачу и
  считается `precision = 0` по п. 3.

## Правило вердикта (не меняется)

`P_impact (k-fold) < 0.40` ⇒ **skip** подтверждён усиленным замером.
`P_impact (k-fold) ≥ 0.40` ⇒ вердикт владельца **НЕ предрешён**: пакет решения P5.2
пересобирается на новых числах и вопрос уходит владельцу заново (D112).
