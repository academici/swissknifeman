# Roadmap: авто-эмит `.mcp.json.example` + ведение `.gitignore` в maind deploy/sync

**Статус:** отложено (дисциплина агента покрывает кейс сейчас). **Критерий внедрения:** повторно
поймано на практике, что онбордженный проект утёк абсолютными путями/секретами в репо ИЛИ внешний
разработчик не смог поднять MCP без `.example` (нет карты структуры). Источник наблюдения —
полевой кейс agelto (настройка playwright-MCP + ревизия `.mcp.json` с абсолютными путями maind/Serena).

## Проблема

`maind deploy`/`sync` (`lib/maind/mcpconfig.py`, `lib/maind/deploy.py`) пишет реальные
`.mcp.json` / `.cursor/mcp.json` / `.vscode/mcp.json`. Путь к бинарю `maind` уже **индиректирован**
(`${MAIND_BIN:-maind}`, см. `deploy.py::_maind_entry`) — остаётся **machine-specific абсолютный путь
Serena** `--project <abs>`. Сейчас тулинг:

- НЕ создаёт парный `<файл>.example` с плейсхолдерами;
- НЕ дописывает реальный файл в `.gitignore`.

Гигиена («индирекция через `.env` либо gitignore + синхронный `.example`») держится **дисциплиной
агента** — описана в скилле [`project-tooling-runbook`] §«Гигиена machine-specific конфигов» и
кросс-ссылкой в [`ecosystem-integration`] (шаг deploy). Это работает, но не гарантировано: агент
может забыть, а проектов много.

## Дизайн (когда дойдём)

- При записи MCP-конфига в `mcpconfig.py` — рядом эмитить `<файл>.example`, где machine-specific
  значения заменены плейсхолдерами (`<ABS_PATH_TO_SWISSKNIFEMAN>`, `<REPO_ROOT>`,
  `<ABS_PATH_TO_PROJECT>`); `.example` **коммитится**, реальный файл — нет.
- Идемпотентность и **синк**: на каждом `sync` `.example` пере-генерируется из того же источника, что
  и реальный файл (один генератор → два выхода) — расхождение невозможно by design (сильнее, чем
  ручная дисциплина).
- Дописать реальный файл в `.gitignore` проекта (идемпотентно; если уже трекался — предупредить,
  `git rm --cached` оставить агенту/пользователю, не делать молча).
- **Что плейсхолдерить** — данные, не хардкод: список «machine-specific» полей (абсолютные пути,
  env-секреты) вынести в конфиг генератора, чтобы покрыть новых провайдеров без правки логики.
- Тесты в `packages/maind` (офлайн): генерится `.example` без абс.путей/секретов; `.gitignore`
  содержит запись; повторный `sync` не плодит дублей.

## Риски / почему осторожно

- Управление чужим `.gitignore` — деликатно (не перетереть, не сломать существующие правила;
  только append-if-absent).
- Часть значений лучше уводить **индирекцией** (`${VAR}`/враппер из `.env`), а не плейсхолдером —
  тогда `.example` для них не нужен вовсе. Генератор должен различать «индиректируемое» и
  «обязано-в-файле», иначе размножит лишние `.example`.
- Не дублировать примитив записи atomic-JSON — переиспользовать `core.io` (см. `CLAUDE.md`).

## Связано

- Скилл [`project-tooling-runbook`] §«Гигиена machine-specific конфигов» (текущая дисциплина).
- [`field-feedback-loop`] — маршрут наблюдения (этот файл — путь 2: новое/проектируемое).
- `package-architecture` — `.mcp.json` генерируется (чинить генератор, не артефакт).
