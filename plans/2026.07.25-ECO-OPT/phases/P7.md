# P7 — Codex как второй водитель (переключение + инструкционный слой + плагин)

## Phase Context

Фаза отвечает на вопрос владельца о постоянной роли Codex — но **вопрос переопределён владельцем
на `finish` (D84)**, и вместе с ним переопределена фаза. Прежняя постановка («делегировать ли
Codex'у лёгкие задачи, и выгодно ли это») закрыта не выбором из трёх вариантов, а **четвёртым**:
**Codex — ВТОРОЙ ВОДИТЕЛЬ.** Та же экосистема, те же скиллы, те же команды, тот же план; при
проблемах с подпиской Claude владелец пересаживается и продолжает работу. Плагин
`codex-plugin-cc` (субагенты Codex ИЗНУТРИ Claude Code) — отдельная, второстепенная возможность:
может быть установлен и включён постоянно, но **задействуется только при ЯВНОМ указании в плане**,
что данную работу ведут субагенты Codex.

Поэтому фаза мерит не экономику, а **доезжаемость**: проходит ли Codex наш собственный протокол от
холодного старта до закрытого item'а, и если нет — где именно и по какому адресу.

**Три items и что каждый закрывает:**

1. **P7.1 — тест переключения (dogfood).** 1–2 ЖИВЫХ item'а этого плана ведёт Codex целиком: cold
   start по launch-блоку → чтение плана/handoff → исполнение → Validation → закрытие item'а →
   handoff. Вердикт **человеческий и списочный**: «дошёл сам» / «дошёл с N вмешательствами» /
   «сломался на X» + перечень поломок **с адресом** (какое правило не увидел, где отошёл от
   протокола, чего не хватило в инструкциях).
2. **P7.2 — тонкий инструкционный слой ПО ИТОГАМ P7.1** (+ трек 1 OQ-4: router A2 и
   untrusted-import F1) и запись вердикта роли.
3. **P7.3 — плагин как явно маршрутизируемая возможность:** установка, гейт бюджета до/после,
   процедура включения/выключения, запись правила активации.

**Отправная точка — не «первый контакт с Codex».** Codex CLI 0.145.0 стоит на машине, репозиторий
уже дуал-провайдерный (корневой `AGENTS.md`, `.agents/skills/` 30 записей, `packages/*/adapters/codex/`,
`configs/codex/`, замороженный инструкционный каталог `lib/harness/instructions.py`), и владелец
водит этот репозиторий Codex'ом напрямую. Наблюдение владельца, зафиксированное как есть: Codex
«вроде работал, но эффективность не понравилась» — поэтому проверка идёт **реальными задачами**
(dogfood), а не отдельным замером.

**Что разведка этого захода изменила в постановке** (слой 1 — `findings/P7-codex-delegation-facts.md`;
слой 2 — `research/15-P7-fact-classes.md` карта классов ДО поиска и `research/16-P7-target-design.md`
целевой дизайн; **§2 того файла теперь описывает СНЯТЫЙ пилот** — он вынесен в `roadmap.md`, D84):

1. **«Интеграция в harness plugin-management» невозможна — поверхности нет.** Плагинами Claude
   Code управляют `maind` (`commands/plugins.md`) и `skiller connect.py`, а не `harness` (D61).
2. **Слоёный `AGENTS.md` для Codex ≠ файлы по пакетам.** Codex склеивает `AGENTS.md`
   **от корня проекта вниз до cwd** и «does not walk past the project root»; при нашем
   каноническом `codex -C <корень>` вложенные `packages/<pkg>/AGENTS.md` (объявленные в
   TARGETS замороженного каталога) **не грузятся вовсе**. Лимит склейки — 32 KiB с молчаливым
   усечением (D62). **Прямое следствие для P7.1/P7.2:** всё, что второй водитель обязан увидеть на
   cold start, живёт в КОРНЕВОМ файле, и его бюджет — дефицитный ресурс.
3. **Плагин шлёт `model`/`effort` = `null`** ⇒ действуют дефолты машины (`gpt-5.6-sol` + `xhigh`).
   Для P7.3 это не «разрушенная экономика делегирования» (постановка снята), а факт, который
   обязан попасть в процедуру включения: маршрутизированная работа получает явный пин.
4. **Установка плагина — новый always-on инжект** (1 субагент + 3 скилла + хуки ⇒ три из пяти
   источников `budget --first-turn`), ожидаемая дельта строго положительна (в отличие от P6.1/D54).
5. **Числа аддитивности кросс-модельного ревью** (56,8% подтверждённых дефектов находит ровно одна
   модель; покрытие 47%→72% от второго ревьюера) остаются в силе как ФАКТ, но правило вердикта
   дорожки B (D64) теперь **условно**: применяется, только если P7.1 фактически прогонит
   ревью-дорожку на живом диффе; иначе уходит в `roadmap.md` вместе со снятым пилотом.

**Чего фаза больше НЕ делает** (снято D84, живёт в `roadmap.md`): полный пилот делегирования — 12
стратифицированных задач, 6 диффов с эталоном, `slate`/`delegation-log`/`review-answer-key`,
детерминированный `compute_verdict.py` и числовое правило дорожки A (`A ≥ 0.50 ∧ R ≤ 0.70`, D63).

### P7.1 — Тест переключения: Codex ведёт живой item плана (dogfood)

**Status:** 🟠 Done with deviations
**Intent:** Проверить на реальной работе, доезжает ли **второй водитель** по нашим же инструкциям:
выбрать 1–2 ЖИВЫХ item'а этого плана из exec-класса с детерминированной Validation и провести
каждый Codex'ом ЦЕЛИКОМ — cold start по launch-блоку (корневой `AGENTS.md` → план → handoff) →
исполнение по ТЗ → прогон Validation → закрытие item'а по протоколу §8 (item-коммит + bookkeeping +
handoff) → плановые правки. Результат — **не число**: вердикт одной из трёх формулировок («дошёл
сам» / «дошёл с N вмешательствами» / «сломался на X») плюс перечень поломок, у каждой из которых
назван **адрес**: какое правило Codex не увидел, где отошёл от протокола, чего не хватило в
инструкционном слое. Каждая поломка становится кандидатом правки (вход P7.2 или строка
`roadmap.md`), а не поводом для рассуждения.
**Why:** Роль назначена владельцем (RAG:— owner-grounded: D84 — «Codex второй водитель; при
проблемах с подпиской Claude пересаживаюсь и продолжаю»), поэтому проверять надо ровно то, от чего
зависит эта роль: **переносимость нашего протокола на другого провайдера**, а не стоимость
делегирования. Владелец прямо отказался тратить время на замер и назвал способ проверки — дать
реальные задачи (dogfood). Предмет проверки не гипотетический: инцидент «Codex тупил неделю» по
разведке объясняется не «SKM вреден», а duplicate-identity коллизиями и отсутствием enforcement —
отсюда гейт на терминальные P1/P2 `AGENT-RELIABILITY` (RAG:✅ 2026-07-25 perplexity →
`findings/rag-2026-07-25.md` §4.1; D9), то есть тест ставится ПОСЛЕ устранения известных
усилителей, иначе он измерит их, а не протокол. Наиболее вероятная точка отказа известна заранее и
проверяема: Codex склеивает `AGENTS.md` от корня до cwd, потолок 32 KiB, **усечение молчаливое**
(RAG:✅ 2026-07-25 first-party `learn.chatgpt.com/docs/agent-configuration/agents-md` + прямое
чтение `codex-rs/core/src/agents_md.rs` → `findings/P7-codex-delegation-facts.md` §2) — значит
любое обязательное правило, не попавшее в корневой файл, для второго водителя не существует, и это
надо увидеть на живом прогоне, а не вывести. Числовой вердикт здесь сознательно НЕ применяется:
прецедент «пилот обязан быть числовым» (D33/D35/D63) относился к вопросу «выгодно ли», а вопрос
теперь «доезжает ли», и это человеческое суждение — отступление названо вслух (D84
