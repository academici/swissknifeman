## Что изменено

- AST-факты и parent-map кешируются внутри `SourceFile`; новые экземпляры видят новые файлы,
  публичные списки/словари остаются независимыми. Глобального кеша по имени файла нет.
- Архитектурные правила разделены при сохранении всех 75 определений и 40 публичных экспортов.
- MCP entry projection общая для четырёх клиентов; SecretRef остаётся непрозрачной строкой,
  правила имён каждого target сохранены. Добавлены 32 parity/negative теста.
- PostgreSQL artifacts разделён с совместимым фасадом. Сохранены 20 функций, 6 классов и 38 SQL-констант;
  SQL находится рядом с использующим его классом. DI и владельцы транзакций не менялись.
- Defaults ограничены `TEST_WORKERS=4`, `ARCH_WORKERS=2`, `PG_WORKERS=8`, `E2E_WORKERS=4`.
  Архитектура использует `loadfile`, сохраняя module-scoped кеши. Параметры переопределяются через make.
- Чистым тестам больше не создаётся `tmp_path` только из-за autouse-фикстуры; SKM scrub,
  session HOME и сетевые guards сохраняются. Отдельная регрессия проверяет все эти условия вместе.
- Добавлены [карта](../architecture/CODEBASE-MAP.md) с машинной сверкой 14 manifests и `make check-touched`.
  Обновлены устаревшие инструкции, примеры support/fakes и docstrings settings public/ports и PG support.
  Исправлено сужение типа nullable PG session и одна существовавшая ошибка форматирования стабильного теста.

## Проверки и границы результата

Ruff по `src tests tools` и format-check 1933 файлов прошли. Pyright `src/skm`, отдельного tools project
и всех изменённых тестовых файлов: 0 errors. Markdown links и `git diff --check` прошли.
Реальный `check_touched.py --base new` прошёл, включая 379 архитектурных тестов.
Он является preflight и не заменяет behavioral/PG/e2e проверки.

Дополнительно: 635 затронутых non-PG тестов; 393 после окончательного artifacts split;
274 архитектурных fixtures/tool tests; 26 тестов pytest isolation; 59 полных contract-import checks.
Примеры из support README исполнены. Проверена AST-эквивалентность механических переносов и форматирования.

Полный `make test` **не зелёный**:

1. Ожидание списка execution queries в `tests/contracts/execution/test_group_contracts.py` не содержит
   уже зарегистрированную `execution.get_fix_brief`. Ошибка есть в baseline. Это граница P08.10,
   которую пользователь запретил менять.
2. Два recovery-варианта `test_missing_cached_or_changed_admission_never_moves_target`
   получили `REPOSITORY_UNSAFE` на root-owned `/tmp`. Оба проходят отдельно и на baseline (15,76 с),
   и на текущем коде (16,87 с). Git runner и вспомогательные файлы побайтно одинаковы.
   Такой stack требует успешного `lstat('/tmp/.git')`; при повторе entry отсутствовал.
   Источник временного состояния не установлен, регрессия и baseline-only причина не доказаны.
   Проверка доверия не ослаблялась.

В baseline также воспроизведена нестабильность concurrent atomic writes: повторный `st_nlink=0`
может исчерпать восемь проверок и дать `hard_link`. Отдельные stress-пробы дали 6/600 и 8/400 отказов.
Последующий A/B прототип scheduler yield дал 0/0 в обеих версиях; улучшение не доказано,
поэтому production guard оставлен без изменений. В итоговом полном `test` этот тест прошёл.

## Следующие измеримые шаги

1. Проверить `worksteal` для non-arch наборов: `make test PYTEST='uv run --frozen pytest --dist worksteal'`.
   Он перераспределяет уже назначенные, ещё не начатые тесты; `load` этого не делает.
   Он не ускоряет одиночный долгий тест или последние два assigned items. `loadfile` оставить архитектуре.
   Не задавать scheduler через общий `PYTEST_ADDOPTS`: вложенные plugin-disabled runner tests наследуют env.
2. Объединить immutable source snapshot двух real-tree архитектурных fixtures внутри одной сессии:
   сейчас layer-import scan остаётся примерно 14,7 + 12,9 с. Проверять свежесть и отдельные synthetic trees.
   Следом профилировать neutral/provider literal scans: ещё примерно 11 с каждый.
3. Отделить быстрый PG contract loop от обязательных e2e при локальной разработке, сохранив полный gate.
   Уже существующая template DB не решает стоимость M3 (237,51 с), M1/restarts (150,61 с), worker-kill
   (92,99 с) и init-recovery (75,21 с) в baseline. Профилировать startup/повторную сборку App и registry
   в этих subprocess сценариях; mutable backend/UoW и проверки настоящих restart не объединять.
4. После текущей кампании устранить дублирование списка реализованных операций в group-contract tests
   и регистрационном инвентаре; отдельно воспроизвести временный ancestor `.git` и atomic-write race.

Сырые локальные логи и AST-equivalence evidence сохранены в `.pytest_cache/polish/` этого worktree.
Они не входят в коммиты; baseline snapshot находится там же. Репозиторный отчёт сохраняет существенные
числа, ограничения и команды воспроизведения без привязки к временным логам.
