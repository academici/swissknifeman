# 15 — Что headless-вызов Claude Code отдаёт наблюдаемого (проба под layer-2)

**Слой 1** (внешний факт, добыт в этом заходе дизайна фазы P3, 2026-07-26).
**Зачем:** ремонт находки F1 (`findings/P3.5-terminal-audit.md` § 3) требует харнеса
«живой вызов → типизированный event-транскрипт». Прежде чем писать ТЗ, нужно знать, что
именно CLI отдаёт машинно — иначе items встали бы на предположение.

**Метод:** две реальные пробы самым дешёвым классом модели (`--model haiku`,
промпт «reply with exactly: ok»), cwd `/tmp`, вне репозитория. Обе — read-only по отношению
к плану; стоимость обеих ≈ $0.02. Выдача ниже приведена дословно по значимым полям.

## Проба 1 — `--output-format json` (единый результат)

```
claude -p 'reply with exactly: ok' --model haiku --output-format json
```

Ключевые поля выхода (RAG:✅ 2026-07-26, локальный прогон, CLI `2.1.220`):

| Поле | Наблюдение | Для чего годится |
|:--|:--|:--|
| `session_id` | `8bd2be20-…` | стабильный `turn_id`/`session` трассы (`unified-agent-trace-v1.md`) |
| `num_turns` | `1` | счётчик оборотов диспатча |
| `usage.input_tokens` | `10` | **слагаемое** контекстного входа |
| `usage.cache_creation_input_tokens` | `7601` | **слагаемое** контекстного входа |
| `usage.cache_read_input_tokens` | `17536` | **слагаемое**, доминирующее по величине |
| `usage.output_tokens` | `33` | выход |
| `total_cost_usd` | `0.0177116` | бюджетный учёт прогона |
| `permission_denials` | `[]` | наблюдаемые отказы разрешений |
| `is_error` / `subtype` / `stop_reason` | `false` / `success` / `end_turn` | статус диспатча |
| `modelUsage.<model>` | пер-модельная разбивка + `contextWindow` | сверка фактической модели с routed |

**Следствие для F9 (`context_input_per_success_ratio`).** Знаменатель существует и машинно
доступен, но «контекстный вход» **не равен** `input_tokens`: в этой пробе `input_tokens = 10`
при `cache_read = 17 536`. Любая формула обязана быть объявлена дословно, иначе число
неопровержимо. Проба показывает, что формула, игнорирующая кэш-слагаемые, отчитается о
величине на три порядка меньше реально поданного контекста.

## Проба 2 — `--output-format stream-json` (пособытийный поток)

```
claude -p 'reply with exactly: ok' --model haiku --output-format stream-json --verbose
```

Первое событие потока — `{"type":"system","subtype":"init", …}` с полями `cwd`, `session_id`,
`tools` (полный список доступных инструментов), `mcp_servers`, `model`, `permissionMode`,
`slash_commands`. Далее поток несёт пообъектные сообщения (в т.ч. `tool_use`/`tool_result`)
и финальный `result`-объект той же формы, что проба 1.

**Жёсткая граница, проверенная явно:** без `--verbose` тот же вызов **отказывает**:

```
Error: When using --print, --output-format=stream-json requires --verbose
```

То есть комбинация флагов не опциональна — харнес обязан слать `--verbose`, а preflight
обязан падать fail-closed, если комбинация перестанет работать.

## Что проба НЕ доказала (честная граница)

- Форма и полнота `tool_use`/`tool_result` в потоке **на реальной рабочей задаче** не
  измерялась: промпт был тривиальным и инструментов не звал. Наблюдаемость событий словаря
  банка (`mutation`, `block`, `contract_compiled`, …) остаётся **гипотезой до измерения
  item'ом P3.9** — именно поэтому измерение вынесено в отдельный item.
- Codex-сторона не пробовалась в этом заходе: acting provider — Claude (D33/D50), а
  Codex-форма остаётся recovery-проекцией. Паритет провайдеров — предмет
  `provider_capability_matrix` P3.3, не этой пробы.
- Стоимость реального диспатча в репозитории (большой `CLAUDE.md`, MCP, хуки) на порядки
  выше пробы в `/tmp`; бюджет layer-2 нельзя экстраполировать с этих $0.02.
