## Дефекты механизма
5. `reads` пункта с `required` файлами, которые пункт сам удаляет (`test.yml`, `validate.yml`): повторный claim падает `READ_MISSING`. Исправлено в плане; для механизма — предложение: проверять `reads` по рабочему дереву только при первом claim, либо позволить `required: until-delete`.
6. `run --adopt` не принимает артефакты пункта (`artifacts/<item>/evidence`, `review-verdict.json`) от прерванного захода как «вне write set» — пришлось вынести в папку временных файлов. Предложение: артефактная папка пункта всегда разрешена при adopt.
7. Остановленный прогон (`WORKTREE_DIRTY` при adopt) оставляет пункт «в работе» у умершей сессии → следующий claim `ITEM_OWNED`; снимается вручную `finish --status blocked --owner-session` + `reopen` (дважды). Не исправлено: нужна правка жизненного цикла (снятие claim при Stop до начала работы) — на тяжёлую модель.

1. Прогон не стартует при неотслеживаемом файле владельца (`WORKTREE_DIRTY`, `ideas/`). Не дефект, но правило: перед прогоном дерево чистое. Предложение: опция игнорирования путей `ideas/`.
2. `RESULT_HEALED` + `RESULT_REPAIRED` на первом отчёте исполнителя (`stage-report` не JSON, запятая, строка 13). Один случай; следить за повтором — если растёт, править контракт промпта.
3. Наблюдатель не поставил монитор завершения прогона и не сообщил о конце пункта вовремя (ошибка наблюдателя; исправлено: один монитор на прогон).

4. (исправлено после P12.3) Блок Repository rules содержит HTML-комментарии разметки инструкций (`<!-- swissknifeman:instructions… -->`, `<!-- semantic:… -->`). Мусор в промпте роли; чинить при сборке блока (срезать комментарии). Не обязательный блокер — в очередь на правку механизма между пунктами.
