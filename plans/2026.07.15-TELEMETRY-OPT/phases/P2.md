# P2 — Churn-гейт файл-операций

## Phase Context

Baseline (`findings/telemetry-baseline.md`) в кластере tool-фейлов (328/4 дня) выделил
**устранимый churn файл-операций**: 46 EDIT/WRITE «not-read-first» + 16 edit
string-not-found/not-unique + reread(extra) **392**. Ключевой факт для дизайна: hook
run-report УЖЕ фиксирует эти сигналы сырьём — `tool_failures[]` (is_error результаты,
`_lib.py:445-447`) ловит фейлы Edit/Write, `reads.top_rereads` (`_lib.py:499-501`) — перечит;
но НЕ категоризирует их (числа «46/16» из baseline посчитаны разовым scratchpad-проходом,
`findings/agg.py` их не воспроизводит — категоризация утеряна). Второй факт: Edit/Write
Claude Code **уже нативно гейтят** read-before-edit (контракт тула: «You must Read the file …
or the call will fail»; Write: «Overwriting a file you haven't Read will fail») — значит 46
«not-read-first» это НЕ тихие перезаписи, а **срабатывания уже существующего гейта** (агент
пытается править ДО чтения, ловит фейл, перечитывает, повторяет) → добавочный блокирующий
хук-гейт был бы избыточен (D6). Рычаг фазы — **дисциплина, не новый гейт**: (P2.1) восстановить
и квантифицировать категории churn по реальным run-reports, установить доминирующий драйвер,
подтвердить нативный гейт, решить форму вмешательства; (P2.2) закодировать file-op-гигиену в
CORE-скилле `anti-drift` (read-before-edit + якорь-гигиена правок + анти-reread), RU→EN-регенерация.
**Завершение фазы:** findings квантифицируют churn и фиксируют вердикт «дисциплина vs хук-сигнал»;
`anti-drift` несёт конкретное правило file-op-гигиены (RU-источник + регенерённый EN, `skiller
registry` прогнан). Правки скилла — через двуязычную модель (`SKILL.ru.md` → `SKILL.md`), не руками EN.

### P2.2 — File-op-гигиена в CORE-скилле anti-drift (read-before-edit + якорь + анти-reread)

**Status:** ⬜ Not started
**Intent:** Расширить CORE-скилл `anti-drift` подсекцией file-op-гигиены: (a) **read-before-edit** — не пытаться Edit/Write до чтения актуального содержимого (нативный гейт всё равно отклонит — churn на попытке); (b) **якорь-гигиена** — против string-not-found/not-unique: брать `old_string` из свежепрочитанного точного текста, крупным уникальным контекстом, `replace_all` для повторов; (c) **анти-reread** — не перечитывать файл, уже находящийся в контексте сессии.
