# Owner refinement — P5.5 Codex R2 cap contract — 2026-08-05

Владелец репозитория прямо разрешил: «разрешаю D112 с этой заменой cap-contract».

D112 заменяет D111 только в части механически исполнимой семантики cap-enforcement для
Codex R2. Всё остальное в D111 остаётся активным: ровно две R2-попытки, по одной на provider;
`codex-cli 0.146.0` и Claude Code `2.1.222`; неизменные rooted security controls и R2 roots;
JSON-Schema/projection/complete-argv preflight с `process_count=0` до обеих попыток; все 14
D105 usage rows равны нулю; P5.2–P5.4 не запускаются; retry/fallback/R3 отсутствуют.

Новый исполнимый Codex cap-contract точен:

- одна fresh invocation поверхности `exec`;
- Artifex process wrapper жёстко обеспечивает `timeout_ms=120000`, aggregate output
  `<=8192` bytes и parsed events `<=16`;
- фиксированный experimental `rollout_budget` token limit `2000` применяется только если
  требуется и заранее доказан strict-config path;
- план не утверждает отсутствующие Codex CLI caps для `max_turns` или money;
- вместо таких ложных CLI-claims действуют отсутствие automatic retry и минимизированное
  measured post-run usage evidence.

Claude Code R2 controls/caps D111 не меняются. Это уточнение не расширяет package/schema/files,
business authority, D105 expiry/budget, provider count, roots или число попыток и не разрешает
package/schema/provider mutation в plan-design сессии.
