# P1 — Plan-система per-project

## Phase Context

Строим per-project plan-систему: планы Claude Code живут в проекте, а не в `~/.claude/plans/`.
Опорный факт: **`plansDirectory` — реальный top-level ключ settings.json Claude Code**
(слои глобальный/проектный/локальный; относительный путь резолвится от корня проекта).
Hook-события ExitPlanMode НЕТ и официального registry активного плана НЕТ (доки 2026-06) —
поэтому мост plan mode → протокол ручной (`from-draft`), а активный план трекается файлом.
Дизайн-решения фазы:

- **A. plansDirectory тремя слоями:** `harness hooks --plans-dir plans|off` (новый
  `block_plans_dir` через `set_setting_key` → **`.claude/settings.json`**, шаримый; ключ уже
  занят ДРУГИМ значением → НЕ перезаписывать, уважать локальный выбор) → провижионер maind
  `plans-dir` (opt-out `project.plans_dir="off"`) → блок `_block_plans_dir` в skiller
  integrate (новые онбординги). НЕ глобально (мусорные `plans/` в чужих каталогах машины).
- **B. Active-указатель** — `plans/ACTIVE.md` (~4 строки, строка `**Active:** <PLAN-ID>`;
  нет активного — `**Active:** —`); пишут plan-design (new/from-draft) и plan-close;
  plan-lint валидирует (несуществующий план → ERROR; ≥2 планов 🟡 без ACTIVE.md → WARNING).
- **C. CLAUDE.md-конвенция** — maind hashed-блок `maind:plan-conventions` (шаблон
  `templates/plans/conventions-block.md`, ≤10 строк), провижионер `plans-doc`, та же
  opt-out-ручка. НЕ hub-блок (тот целиком регенерится из каталога скиллов).
- **D. CORE_SKILLS += plan-protocol** — core-policy.json + синхронно фолбэк в config.py.
- **E. Мост plan mode → протокол** — 4-й режим `plan-design from-draft <файл>`: плоский
  черновик `plans/<slug>.md` → `plans/<ID>/` по шаблонам скилла, provenance в Decision Log,
  черновик удалить (история в git). Конвенция: «плоский .md в plans/ (кроме ACTIVE.md/
  README.md) = черновик»; plan-lint — WARNING о залежавшихся черновиках. Авто-хук отвергнут
  (события нет).
- **F. Цикл «фаза → handoff → /clear»** — фиксированная строка
  `Context: handoff свежий — рекомендован /clear перед следующим item` в Expected output
  plan-exec (после Next Suggested Step) и plan-close (после PHASE-CLOSED) + §6 скилла +
  строка в CLAUDE.md-блоке.

Канонический формат `plans/ACTIVE.md` (SSOT для P1.5/P1.6/P1.7/P1.8): 4 строки —
`# ACTIVE`, пустая строка, `**Active:** <PLAN-ID>` (или `—`), `**Updated:** <YYYY-MM-DD>`.
Фаза завершена, когда пилот P1.10 проходит end-to-end на azguard.
