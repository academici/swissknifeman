# P5 — changelog-discipline: enforcement заполнения CHANGELOG

## Phase Context

Фаза превращает CHANGELOG из «дисциплины на памяти сессии» в enforced-правило (спека
`roadmap/changelog-discipline.md`). Наблюдение владельца 2026-07-10: корневой `CHANGELOG.md`
заполняется нерегулярно; скилл `oss-dev/release-engineering` существует, но активируется только
на релизных задачах, а в повседневных коммитах запись в `[Unreleased]` пропускается (инцидент
подтверждён живьём — P2.4 закрыт 🟠 именно из-за пропущенной строки CHANGELOG).
Три поверхности, каждая — существующий дом (D8 «новых пакетов не заводим»): **(P5.1)** скилл
`release-engineering` получает секцию ПОВСЕДНЕВНОЙ дисциплины (два контура) поверх релизной;
**(P5.2)** commit-гейт в harness — новый opt-in Python-хук `changelog-gate` на `PreToolUse Bash`
(`git commit`), warning в контекст модели, НЕ блок (прецедент git-гейта SKM-AUDIT-004 P7.4 +
формы review-gate/pack-guard); **(P5.3, опц. механизация)** `skiller release` — сборка версии из
`[Unreleased]` + conventional commits.
Два контура дисциплины (D32/D33 задают ИНВАРИАНТЫ, не поверхность): пакеты монорепо
SemVer-строгие — классификация из conventional commits (`fix:`→patch, `feat:`→minor), **major —
ВСЕГДА ручное решение владельца** (breaking автоматикой НЕ выводится); проекты без SemVer —
компактные записи со ссылкой на коммит, систематизация в релиз. Enforcement — предупреждение, а
не запрет: осознанные исключения (docs/chore) снимаются либо типом conventional-commit, либо
явным skip-маркером (D33). Реализация механическая (bilingual-скилл + защищённый stdlib-хук +
CLI-команда), но хук обязан быть безопасным: любая внутренняя ошибка → exit 0, НИКОГДА не роняет
сессию (дисциплина pack-guard). Фаза закрыта, когда гейт ловит пропуск записи в `[Unreleased]`
на содержательном коммите, а `release-engineering` описывает повседневную дисциплину, не только
релиз; `skiller release` (P5.3) — опциональная механизация, может быть закрыт как ⛔ по решению
владельца, ядро дисциплины держат P5.1+P5.2.

**Scope Included (фаза):** секция «повседневная дисциплина» (два контура: пакеты SemVer-строгие ·
проекты без SemVer) в `release-engineering` (`SKILL.ru.md`→regen `SKILL.md`) · opt-in Python-хук
`changelog-gate` (`PreToolUse Bash`, `git commit`) в harness: содержательный дифф без правки
CHANGELOG → warning в контекст, режимы off/warn/strict, warn-дефолт · проводка хука
(`block_changelog_gate` в `hooks.py`, флаг `--changelog-gate`, глобальная установка файла в
`apply-permissions.sh`) + тесты · CLI `skiller release` (сборка версии из `[Unreleased]` +
conventional commits, umbrella-тег `vX.Y.Z`) + root-фасад `swissknifeman release` + тесты ·
строка статуса `changelog-discipline.md` → «внедрено» в `roadmap/README.md`.

**Scope Excluded (фаза):** авто-вывод major/breaking (D32/D33 — major всегда ручное решение
владельца, гейт его не классифицирует) · авто-тег/авто-push (`skiller release` только ПРЕДЛАГАЕТ
версию и команду тега; тег и push — только по явному действию владельца, как всюду в экосистеме) ·
per-package version-bump в `plugin.json`/`package.json` (репо релизится единым umbrella-тегом
`vX.Y.Z` — `findings` P5-release.md SKM-AUDIT-004; per-package версии правит владелец) ·
always-on/глобальная регистрация хука в `settings.global.json` (резидентный расход на КАЖДЫЙ
коммит любого репо — `context-economy`; хук opt-in per-project как pack-guard) · блокирующий
дефолт (спека прямо: warning, не блок) · правка `plan_lint.py` (git-состояние линтер по `.md` не
проверяет — не его слой, прецедент P7.4) · классификация содержательности по путям файлов (D33 —
по типу conventional-commit, path-эвристика отвергнута как хрупкая).
