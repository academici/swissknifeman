## R7. Managed-регионы: конвенции маркеров, идемпотентность, детекция дрейфа

**Вердикт: единого кросс-экосистемного стандарта НЕТ, но конвенция зрелая — и её главный совет
противоположен смешению.** Дословно по смыслу: сильнейший дефолт — **сначала отдельные генерируемые
файлы**; стабильные парные именованные маркеры — только когда смешанный файл неизбежен; финальный
гейт — регенерация плюс байтовое сравнение с чистым деревом.

### Что рекомендуется, если смешение НЕИЗБЕЖНО

Контракт managed-блока у источника:

- **парные сентинелы с ОДИНАКОВЫМ стабильным непрозрачным id** в обоих маркерах и с namespace'ом
  (`acme:routes id=public-api`, не просто `BEGIN GENERATED`);
- синтаксис маркера — валидный комментарий host-формата (`<!-- -->` для Markdown);
- в маркере — **имя и версия генератора, sha256 канонизированного входа**, опционально версия схемы;
- генератор находит пару по точному id, заменяет **только байты строго между маркерами**, сохраняет
  всё окружающее человеческое содержимое и даёт идентичный вывод на идентичных нормализованных входах.

**Хеш — это провенанс и быстрая диагностика устаревания, а НЕ граница целостности:** разработчик
может поменять и тело, и хеш. Поэтому «совпал хеш» не доказывает корректность — **в CI обязана идти
фактическая регенерация и байтовое сравнение**.

### Fail-closed политика обновляющего

Перечень источника, дословно по смыслу:

- нет `BEGIN` или `END` — не вставлять автоматически (кроме явного bootstrap-режима с якорем);
- больше одной пары на id — **отказ**, никогда не «взять первое совпадение»;
- вложенные managed-блоки — отказ, если парсер их явно не поддерживает;
- человеческая правка ВНУТРИ пролёта — перезаписывается штатной генерацией; режим `--check` сообщает
  дрейф до перезаписи;
- человеческая правка МАРКЕРА — сообщить файл, строку и ожидаемый синтаксис;
- недетерминизм генератора — это дефект генератора (убрать таймстемпы и случайный порядок), а не
  повод ослабить CI.

### Именованные прецеденты

| Прецедент | Что показывает |
|:--|:--|
| Ansible `ansible.builtin.blockinfile` | Прямейший аналог: шаблон маркера `# {mark} ANSIBLE MANAGED BLOCK`, `{mark}` → `BEGIN`/`END`. Документация прямо предупреждает: маркер без `{mark}` или многострочный маркер приводит к ПОВТОРНОЙ вставке на следующих прогонах — ровно тот отказ идемпотентности, который снимают парные уникальные сентинелы |
| Go `// Code generated … DO NOT EDIT.` | Канон владения на уровне ЦЕЛОГО файла (строка по строгому regex); предотвращает ручное сопровождение и даёт инструментам опознать генерируемое, но безопасного смешанного редактирования НЕ решает |
| Kubernetes code-generator | Целофайловая регенерация скриптами репозитория вместо ручного сопровождения — демонстрирует более сильную границу владения: где практично, генерировать ОТДЕЛЬНЫЕ файлы/каталоги, а не подрегионы |
| OpenAPI Generator | Источник истины — спецификация и конфиг генератора; кастомное кладётся в предусмотренные точки расширения, а не правкой перегенерируемого вывода |
| GraphQL Code Generator | Типовая CI-форма: перегенерировать и упасть на git-диффе — ловит и забытую генерацию, и правку генерируемого |
| sqlc `sqlc diff` | Сравнивает ожидаемый вывод `sqlc generate` с файлами на диске; по собственному руководству ловит обе стороны — забывших сгенерировать и правивших генерируемое руками |

### Хеш и устаревание — если он всё-таки нужен

- канонизировать ВСЕ входы: стабильный порядок файлов, нормализованные переводы строк,
  нормализованные структурные данные, явный конфиг генератора;
- хешировать **версионированный манифест**, а не сырую конкатенацию: имя и версия генератора, версия
  шаблона, id цели, пути/дайджесты входов, версия форматтера;
- исходы: равно — блок правдоподобно свежий; не равно — помечать устаревшим и регенерировать;
  битый/отсутствующий — **падать в строгом режиме**, а не пытаться частично обновить.

**Формулировка источника одной строкой:** сильнейший дефолт — сначала отдельные генерируемые файлы;
стабильные парные namespace'нутые managed-блоки только когда смешанный файл неизбежен; регенерация
плюс чистое дерево — финальный гейт.

Источники: `docs.ansible.com` (`ansible.builtin.blockinfile` — шаблон маркера и предупреждение о
неидемпотентности); конвенция генерируемого кода Go (`// Code generated … DO NOT EDIT.`);
Kubernetes code-generator (`hack/update-codegen.sh`); OpenAPI Generator (`@Generated`, точки
расширения); GraphQL Code Generator (перегенерация + падение на git-диффе); sqlc (`sqlc diff`).

## Что из этого следует для плана (перенос в слой 2 — `research/03-…`)

1. Слепок состояния пункта — **отдельный генерируемый файл**, а не блок внутри `Pn.m.md`
   (сильнейший дефолт источника; снимает необходимость писать парсер маркеров и fail-closed
   обновляющий).
2. Проверка свежести производного — **регенерация и байтовое сравнение**, а не доверие записанному
   хешу. Хеш входов остаётся как быстрая локальная диагностика и как провенанс.
3. Там, где смешение всё же неизбежно (генерируемая доска внутри рукописного `plan.md`), контракт
   маркеров обязан быть полным: namespace + стабильный id в ОБОИХ сентинелах, версия генератора,
   sha256 канонизированного входа, отказ при отсутствии пары и при двух парах на id.
4. Недетерминизм генератора — дефект генератора. Это сходится с правилом R4 (редьюсер проекции
   детерминирован и не имеет права звать модель) и с `## 2. Execution Rules` плана.
