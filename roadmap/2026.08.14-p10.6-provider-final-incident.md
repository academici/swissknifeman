# Roadmap: P10.6 false provider-final incident

**Статус:** ⬜ к внедрению — Task-side receipt уже реализован; отсутствует транспортный запрет
на отправку provider `final` для active `plan-run`.
**Владельцы:** Codex transport/runtime adapter, harness delivery seam; входной контракт —
`packages/task` terminal receipt.

## Факт инцидента

В Agelto при `$ task:plan-run 2026.08.09-RELEASE-READINESS P10.6` provider многократно
завершал turn пустым/ложным `final`, хотя item оставался `🟡 In progress` и PHPStan содержал
незакрытый in-scope inventory. Владелец явно и повторно запрещал terminal delivery до полного
результата. На момент фиксации было 38 сообщений владельца о том же нарушении.

## Версии и фактическая конфигурация

- Активный adapter: `task@0.13.2`, путь
  `.codex/plugins/cache/swissknifeman/task/0.13.2/adapters/codex/skills/task-plan-run/`.
- Упомянутый владельцем `task@0.13.1` не был effective runtime этой сессии.
- `task@0.13.2` требует `terminal-block` только после distinct `JUSTIFIED` evidence;
  `AVOIDABLE` обязан продолжать local repair. Его `plan-run` не создавал `blocked`.
- Текущий Task contract уже содержит `FINAL_BEFORE_TERMINAL_FORBIDDEN` и terminal delivery
  receipt, но они проверяют Task delivery write-site, а не фактическую отправку transport `final`.

## Причина

Ошибка была не в PHPStan, plan state или reducer Task. Исполнитель завершал рабочий turn после
промежуточного commentary; transport публиковал terminal `final` при завершении turn. Отсутствует
runtime predicate: «active plan-run с nonterminal state => provider final запрещён/turn продолжается».
Таким образом, текстовая дисциплина агента и Task receipt не стали фактическим stop-hook.

## Почему существующая защита не удержала инцидент

1. Task может отклонить terminal delivery, но не управляет lifecycle channel provider-а.
2. `final` transport-level, а не journal action; в journal не возникало легитимного terminal event.
3. Commentary heartbeat не удерживает turn и не заменяет transport guard.
4. Повторная инструкция владельца не является исполнимым runtime condition.

## Требуемое решение

1. Перед каждым provider `final` adapter вызывает terminal-receipt verifier с active `run_id`.
2. Если item nonterminal или receipt отсутствует/устарел, transport обязан отказать с
   `FINAL_BEFORE_TERMINAL_FORBIDDEN`, сохранить dispatch active и продолжить execution loop.
3. Для tool-yield/turn-boundary вводится heartbeat/resume lease; завершение только после green
   terminal receipt, а не после отсутствия следующего tool call.
4. Regression must simulate repeated provider turn boundaries for an active `plan-run` and prove
   zero `final` emissions; add a resumed-run case without renewed owner authorization.
5. Expose a machine-readable transcript event asserting `final_allowed=false|true`, bound to
   run_id and receipt digest, so a false final is detectable independently of prose.

## Приёмка

- P10.6-like active item with failed PHPStan cannot emit provider final;
- 40 consecutive artificial turn boundaries produce commentary/heartbeat or continued tool work,
  never final;
- terminal final succeeds only with current receipt and exact terminal journal pointer;
- tests cover Codex and Claude transport projections equally.
