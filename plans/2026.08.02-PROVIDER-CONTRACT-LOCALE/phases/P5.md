# P5 — Classify and migrate all consumer projects safely

## Phase Context

P5 выполняет controlled rollout по уже запечатанной P0 классификации и не открывает
новый источник provider-семантики. Сначала фаза компилирует exact-set no-write manifest
и получает Owner D#; затем отдельными rollback-domain сохраняет overrides, чинит только
approved managed/equivalent paths и последним шагом карантинирует доказанно obsolete assets.
Каждый consumer получает независимые Claude/Codex observe/readback rows. До первого live write
runner durable-appends and `fsync`'s a `before` event into one shared hash-chained
`artifacts/P5/fleet-transaction-log.jsonl`; item result JSON is only a derived view. Unresolved
state остаётся явным и не мешает честно завершить обработку остальных проектов, но не становится
GREEN и не позволяет restart cursor перепрыгнуть первый non-terminal transaction.

**Scope Included:** все stable project/artifact IDs из terminal P0 evidence; locator-only rebinding
к live roots; immutable owner-approved action manifest; preservation/explicit registration of
local overrides; approved relink/managed refresh; recoverable quarantine of proven obsolete
SKM-owned projections; per-project write-ahead transaction state, deterministic crash
resume/reconcile, rollback, readback, idempotence and redacted outcome evidence.

**Scope Excluded:** reclassification from live bytes; automatic action on `ambiguous`; adoption
of project-owned content as canon; implicit provider enablement; secrets/absolute roots/raw local
override bytes in plan artifacts; Brain profile/health repair (P6); release claims (P7); provider
or migration semantics duplicated outside frozen P1–P4 owners.

> **Контракт фазы (contract-first).** Потребляет: terminal P0 sealed inventory/classification/recovery gates, terminal P3 adapter/status APIs and terminal P4 migration tooling/repository acceptance bundle · Производит: immutable approved fleet action manifest, one durable append-only per-project transaction log, reconciled or explicit unresolved state, rollback evidence and second-run convergence report for P6/P7 · Границы: no action inferred from class names, no cross-provider write, no silent overwrite/adoption, no irreversible deletion and no fleet-health claim.
