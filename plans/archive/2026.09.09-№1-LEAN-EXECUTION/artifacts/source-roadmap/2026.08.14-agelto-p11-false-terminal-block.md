# Roadmap: test-runner collision must continue as a bounded repair

**Status:** ⬜ to implement. **Incident date:** 2026-08-14.
**Source:** Agelto plan `2026.08.09-RELEASE-READINESS`, item `P11.4`, owner feedback after a false terminal block.
**Owners:** `packages/task` (canonical command, classifier, journal and reducer), `packages/skiller` (provider projections and parity).

## Incident

The declared carrier `bash docker/tests/test-runtime-contract.sh` ran
`make test:tia-refresh`. Pest discovered a PHPUnit-class probe at
`tests/Unit/Support/PaoParatestContractTest.php` and stopped because TIA mode
requires Pest tests. The probe exists solely because the dedicated native
Paratest carrier `docker/tests/pao-paratest.xml` points at that exact file.
Converting the probe to Pest made its direct run green but made native Paratest
reject it and instruct the caller to run Pest instead.

The executor recorded `local-repair`, then classified the conflict as a
terminal `Blocked` case and handed off `task:plan-design ... P11.2`. The stated
reason was that the supporting Paratest config and its source path did not
belong to the current item's declared `Files`/ownership. This was wrong.

The incident is a small, reversible test-topology repair: normal Pest discovery
and the native-Paratest probe must be separated, then the original carrier must
be rerun. It does not change application behaviour, public/frozen API,
authority, schema, migration, dependency, deployment topology, secret or
acceptance criterion. A path outside `Files` is provenance requiring evidence,
not a terminal authority boundary by itself.

## Root cause

The continue-first policy is present in prose and the reducer has a
`local-repair` branch, but the closed evidence carrier is still incomplete for
a qualified repair outside `Files`. Consequently the executor reduced
`path not in Files` to `frozen/owner boundary` rather than evaluating the
actual material surface. The independent reviewer received that already
misclassified scope premise in its capsule, so `JUSTIFIED` only confirmed an
incorrect input classification; it was not independent proof of a true block.

This is the runner-topology counterpart of
`2026.08.11-local-repair-vs-escalation-classifier.md` and
`2026.08.14-validation-repair-without-redesign.md`. It demonstrates that the
remaining enforcement gap is observable in a real plan-run, not only in a
static-analysis scenario.

## Required policy and implementation

Implement `validation-repair/v1` as a closed record before any terminal block:

1. Capture the original declared carrier and the minimal reproduced signal.
2. Record affected paths, current item, attributed owner item (if any), and
   bounded diff.
3. Evaluate all material surfaces explicitly, including a test-topology class:
   a dedicated test-runner configuration or probe may be repaired outside
   `Files` only when it neither changes product semantics nor weakens the
   declared validation.
4. Require a pre/post proof that both consuming runners retain their intended
   execution: normal Pest/TIA discovery and the dedicated native-Paratest
   carrier.
5. When every predicate is green, reducer action is exactly
   `repair-in-current-attempt`. Terminal projections and launch/handoff blocks
   must be unable to recommend `plan-design` for that record.

For this incident, the expected bounded repair is to place the native PHPUnit
Paratest probe outside the normal `phpunit.xml` Pest discovery roots and update
only its dedicated config. The repair is accepted only if the original runtime
contract, the isolation/Paratest carrier, and their PAO output assertions all
pass afterwards. This is a design target, not permission to silently modify an
arbitrary neighbouring test.

## Acceptance

- A fixture contains a PHPUnit-only native-Paratest probe under a normal Pest
  discovery directory and reproduces the TIA rejection.
- The classifier records a qualified `local-repair` outside `Files`, preserves
  owner attribution, and returns `repair-in-current-attempt`, not `Blocked` or
  `plan-design`.
- After the bounded relocation/configuration repair, TIA/Pest and native
  Paratest both pass; PAO still reports each required result.
- A fixture that alters an application/public/frozen/security/schema/dependency
  surface still fails closed to the existing escalation path.
- Canonical Task command, Codex and Claude projections, journal reducer and
  launch/handoff output have parity; a terminal continuation for a qualified
  repair is rejected by regression tests.

## Measurement

For the first ten `validation-repair/v1` records, retain the signal, paths,
pre/post carriers and material-surface verdict. Count false terminal blocks
reopened to repair and time from the first red carrier to its successful rerun.
