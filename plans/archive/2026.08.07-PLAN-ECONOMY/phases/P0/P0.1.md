**Implementation Rules:** - Разделить provider-neutral `ProbeRecord`/validation/adapter Protocol (`task.token_probe`) и raw Codex command/parser (`task.token_probe_codex`). Calibration core принимает adapter через интерфейс; импорт/ветвление по Codex JSON keys вне Codex-модуля запрещены. Будущий Claude adapter добавляется отдельным модулем и не меняет neutral record. RAG:— (repo-grounded: root.provider-parity; D118).
- Нормализованная запись v1 несёт: `schema_version`, `provider.id`, `provider.adapter`, `model.requested_id`, nullable `model.effective_id`, `protocol_version`, неотрицательный integer `input_tokens_total`, diagnostic `usage_breakdown`, `wrapper_sha256`, `environment.cli/version/command_sha256`. Core валидирует запись fail-closed и запрещает смешение qualified targets.
- Codex adapter строит команду только как argv: `codex -C <пустой temp cwd> -m <requested> -c model_reasoning_effort="low" -a never -s read-only exec --ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check --json -`; prompt подаётся stdin. Cwd создаётся на probe и не содержит repo rules/files. Adapter принимает exit 0 и ровно один `turn.completed`; missing/duplicate terminal event, malformed JSONL или bad usage = reject. RAG:✅ `findings/18-…`.
- Для Codex `turn.completed.usage.input_tokens` маппится в `input_tokens_total`. `cached_input_tokens` и `cache_write_input_tokens` пишутся только в breakdown и никогда не прибавляются к total; neutral core не реконструирует provider total из частей. Terminal event не сообщает effective model id в проверенной среде, поэтому `requested_id` пинуется argv, `effective_id: null` допустим и явно записывается.
- Differential protocol v2 использует bracket-controls, а не `3 × N`: пустой control, не более трёх payload probes, следующий control; для каждого payload `true(f) = B.input_tokens_total − mean(left_control, right_control)`. `|left−right| > δ` отбраковывает весь bracket. Wrapper/command/provider/model/protocol/CLI совпадают; меняется только payload, thread id не входит в identity. Для 8 accepted samples зелёный schedule ограничен 12 provider calls (D120–D121).
- Формула D14, NNLS, fixed margin, `bound.violations == 0` и `tightness.p95 <= 1.6` сохраняются. `dense_ascii` первым забирает символы максимальных прогонов `>=32` из `[0-9A-Za-z+/=]`; остальные идут прежним classifier; `sum(counts.values()) == len(text)`. `DENSE_ASCII_MIN_RUN`, alphabet и `dense_ascii_share()` имеют один SSOT в `task.token_estimate`, а `plan_weight` лишь делегирует.
- Active artifact `version: "2.0.0"` требует blocks `calibration_target` (provider/adapter/requested_model_id/probe_protocol_version/usage_semantics), `classifier`, five `classes`, corpus/bound/tightness и fingerprints. Flat v1 `source/tokenizer` сохраняются лишь в historical snapshot. Loader fail-closed отвергает v1, missing target, несовпадающий classifier, отрицательные ставки и violations; runtime warning сравнивает явно переданные session provider/model с qualified target, не читает env.
- Bounded corpus: ровно 8 accepted samples из 8 РАЗНЫХ реальных файлов; каждый payload ≤16 KiB, сумма `sample_bytes <= 131072`, минимум два малых source идут целиком, `accepted_dense_samples >= 3` из трёх файлов `research/14-…` §4, все пять классов имеют ненулевое покрытие. Record пинует full-source sha256, byte range и sample sha256; полные sources проходят offline estimate/classifier canary без provider calls. Синтетика/копии/скрытый oversize запрещены (D121).
- До генерации байты active v1 сохраняются один раз в plan-owned snapshot; существующий отличающийся snapshot = STOP. Исходный `calibration-probe-log.json` (Claude v1) не меняется; Codex пишет только `calibration-probe-log-v2.json`. Generated JSON вручную не редактируется.
