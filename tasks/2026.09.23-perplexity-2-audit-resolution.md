# Принятые изменения по аудиту 2026-09-23-perplexity-2

Источник — `audits/2026-09-23-perplexity-2.md` (локальный, игнорируемый Git файл).
Проверена реализация на `ab1ef891` и пересечение с аудитом
`audits/2026-09-23-perplexity-1.md`. Здесь только изменения, встроенные в существующие
механизмы; это не Task-план.

## Короткий вход без обязательного workflow

Раньше основной вход из README вёл в длинный раннбук Claude Code, а вступление
описывал продукт только через Claude, хотя manifest уже охватывает Claude Code,
Codex и Cursor. Task уже работает по явному вызову: новый набор режимов для обычной
правки не нужен.

Встроено: [короткий маршрут](../docs/getting-started.md) от установки к первой
read-only задаче, прямой правке, проверке и выбору Task; README, главная сайта,
sidebar и [раннбук](../docs/develop.md) ведут к нему. README теперь прямо называет
трёх клиентов, различие их возможностей и необязательность Task. Пример
`codex -a never -s read-only` опирается на проверенный локальный CLI; текстовая
просьба агенту не выдаётся за машинное ограничение прав. `skiller connect --dry-run`
показан как отдельное действие для подключения скиллов.

## Провайдерский контракт: устранён дрейф его проверок

Машиночитаемый контракт уже расположен в `configs/provider-capabilities.json`:
37 возможностей, для каждого из трёх клиентов — `native`, `adapted` или
`unsupported`, привязка и evidence. `scripts/provider-docs.py` генерирует README и
[матрицу](../docs/provider-support.md). Дополнительная схема профилей дублировала бы
этот контракт и обещала бы одинаковые sandbox/permissions у разных клиентов.

Выявлен дефект: утверждённые SHA и ожидаемые счётчики в тестах остались от состояния
с 36 возможностями, хотя позднейшие коммиты добавили `lifecycle.tool-telemetry` и
изменили Cursor bindings. История manifest сверена с коммитом `b51b1a2d`; в
[тесте manifest](../core/tests/provider/test_manifest.py) перепривязаны
canonical/carrier SHA к текущим committed bytes и счётчики к 37/111, в
[тесте генератора](../scripts/test-provider-docs.py) и
[справочнике](../docs/reference/provider-distribution.md) устранено то же устаревшее
число. Проверки опять охраняют действующий, вручную редактируемый manifest.

При сборке сайта обнаружен другой дефект: evidence с `<session>` и `<conversation>`
попадал в Markdown как HTML. [Генератор](../scripts/provider-docs.py) теперь
экранирует эти текстовые поля, generated матрица обновлена, есть регрессионный тест.

## Lock: проверена фактическая семантика

`core/provider/lock.py` использует локальный `fcntl.flock` для сериализации writer'ов.
У него нет lease, heartbeat или срока истечения: блокировка снимается ядром при
закрытии дескриптора погибшего процесса. В
[тесте](../core/tests/provider/test_lock.py) второй процесс удерживает lock, writer
ожидает, после `SIGKILL` holder-процесса запись заканчивается, lock records корректны,
повторное планирование даёт `NOOP`. Проверка охватывает опасный сценарий аудита без
SQLite, fencing или часов в локальном протоколе.

## Видимые пределы доказательств

[Статус](../docs/status.md) связывает пять важных отказов с механизмом, автоматической
проверкой и пределом доказательства: ownership проекций, смерть lock holder, ложный
GREEN Task, дрейф релизной поставки, секреты. Это встроено в существующую страницу,
которую проверяет `scripts/status-check.py`. Отдельно названы непроверенная семантика
сетевых ФС и то, что `scripts/public-hygiene.py` проверяет имена отслеживаемых
файлов, а не их содержимое. Нынешние проверки не выдаются за несуществующую
изоляцию клиента или сканирование секретов.

## Разделены версия исходников и публикация GitHub Release

Проверка origin подтвердила тег `v0.24.4`, а список GitHub Releases заканчивался
`v0.17.5`. В [правилах поставки](../CONTRIBUTING.md) пояснено, что Git-тег,
attestation и локальный `release-fleet` не создают GitHub Release. Это устраняет
неоднозначность для выбора версии без изменения релизного протокола и без внешней
публикации.

Изменения отмечены в [CHANGELOG](../CHANGELOG.md) `[Unreleased]`.
