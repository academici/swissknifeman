# Разрешение конфликтов слияния

1. **Оцените текущее состояние** merge/rebase. Проверьте историю git и конфликтующие файлы.

2. **Найдите первичные источники** для каждого конфликта. Глубоко разберитесь, почему было сделано каждое изменение и в чём состояло исходное намерение. Прочитайте сообщения коммитов, проверьте PR'ы, проверьте исходные issue/тикеты.

3. **Разрешите каждый hunk.** Сохраняйте оба намерения, где это возможно. Где они несовместимы — выберите то, что соответствует заявленной цели слияния, и зафиксируйте компромисс. **Не** изобретайте новое поведение. Всегда разрешайте; никогда не делайте `--abort`.

4. Выясните, какие в проекте есть **автоматические проверки**, и запустите их — обычно это typecheck, затем тесты, затем форматирование. Исправьте всё, что сломало слияние. (Наш стек: `php artisan test` / `phpstan`; `dart analyze` + `flutter test`; `vitest` / `vue-tsc`.)

5. **Завершите merge/rebase.** Заиндексируйте всё (stage) и сделайте коммит. Если идёт rebase, продолжайте процесс перебазирования, пока не будут перебазированы все коммиты.
