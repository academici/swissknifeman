### P3.2 — Implement adapter observe-diff-apply-readback boundary

**Intent:** Implement a provider-neutral reconciliation protocol and provider-scoped package adapters that perform `observe → diff → preflighted apply → readback` against the P3.1 desired snapshot, with every write controlled by existing artifact-lock/adoption rules. RAG:— (repo-grounded: `core/provider/{registry,artifact,lock}.py`, package provider projection modules, D20).
**Why:** Current render/deploy paths already protect individual artifacts, but they do not share a typed control-plane readback contract; adapters must expose equal semantics without gaining authority over canonical intent or another provider's target. RAG:— (repo-grounded: `packages/{harness,maind,skiller,task}/lib/**`, `research/03-p3-control-plane-implementation-design.md`).
**Scope Included:** New shared no-write reconciliation protocol/types in `core/provider/reconcile.py`; adapter registration/selection integration only as required; package adapter façades around Harness provider render/hooks, Maind deploy, Skiller publication/connect/update, and Task command rendering; Harness public hook CLI target normalization before the absolute-root artifact-lock boundary; exact provider ownership/target declarations; no-write observe/diff/report, explicit apply from a previously validated plan, mandatory post-apply readback, and deterministic fixture tests for both providers.
**Scope Excluded:** Cross-provider target access; silent adoption/repair; rewriting generated artifacts by hand; project/fleet bulk rollout; changing canonical source text, command semantics, skill selection, trust policy, locale resources or provider capability levels; external provider API calls or credentials.

**Implementation Rules:** An adapter receives the immutable desired snapshot and may observe only declared provider-owned targets; it emits a value-free observation/diff and cannot write until all capability, ownership, provenance, boundary and recovery gates are green. RAG:— (repo-grounded: archived artifact/capability contracts, `core/provider/lock.py`) Apply consumes one immutable no-write plan and then repeats observe/readback; a failed or partial readback remains non-green and never updates canonical intent. Existing `plan_artifact_lock` and package renderers remain the only owners of their artifact semantics; the new boundary orchestrates, never reimplements them. RAG:— (repo-grounded: `core/provider/artifact.py`, `core/provider/lock.py`, package projection modules).
**Code Guidance:** Анти-подгонка: use declared desired/expected fixtures and temp roots for both providers; do not let the adapter under test construct expected output from its own observation. Repair F10 at the Harness public CLI boundary by resolving `--target` to an explicit absolute root before `plan_artifact_lock`; keep the shared core invariant that lock roots are explicit/absolute and do not special-case `.` inside `core/provider/lock.py`. Анти-самообман: a green unit import, Claude projection, byte-equal generated output, or a successful apply without a fresh readback does not prove the worktree-local public CLI, Codex parity, ownership isolation or drift safety. Retain existing `check`/`dry-run` as strictly no-write; `apply` accepts only the explicit, already-classified artifact plan and must preserve user-owned bytes/overrides. If an adapter needs an undeclared target, missing support level, raw credential, generated-file hand edit, or another package's write function, stop and escalate to P1/P3 design.
