# P4 — Permissions-слой: perplexity-web и safe-dirs

## Phase Context

Полевая проблема: в проектах экосистемы perplexity-web регулярно промптит,
хотя в user-scope `~/.claude/settings.json` allow есть (`mcp__perplexity-web`
+ все три search-тула — проверено 2026-07-07). Верифицированная семантика
Claude Code (официальные доки, снято через perplexity-web 2026-07-07):
(1) правила всех scope МЕРДЖАТСЯ и оцениваются deny → ask → allow — `ask`
проектного/local scope бьёт user-`allow`, «most permissive wins» НЕ
существует; (2) project-scoped серверы из `.mcp.json` требуют одобрения
сервера ОТДЕЛЬНО от permission-правил (allow не работает, пока сервер
«Pending approval»; сброс — `claude mcp reset-project-choices`); (3) с
v2.1.196 `enableAllProjectMcpServers`/`enabledMcpjsonServers` из project
settings игнорируются в untrusted-папках; (4) MCP-тулы с
`_meta["anthropic/requiresUserInteraction"]` промптят всегда. Вторая тема
фазы — safe-dirs (harness: `lib/harness/safedirs.py`, конфиг
`<монорепо>/safe-dirs.json`, лестница `$SKM_SAFE_DIRS_CONFIG` → корень →
legacy `~/.swissknifeman/safe-dirs.json`; известный капкан — статические
ask-правила rm в settings глушат hook-allow, лечится `prune-ask`).
Завершение: первопричина промптов найдена и устранена системно (пресеты
harness + раскатка), safe-dirs работает на всём флоте.

### P4.2 — Аудит safe-dirs по флоту

**Status:** 🟢 Done
**Intent:** Сквозная проверка подсистемы safe-dirs: конфиг, миграция, hook, и главное — не глушат ли статические ask-правила rm в settings проектов hook-allow.
**Why:** Пользователь ожидает: в доверенных папках удаление не промптит; известный капкан (`prune-ask` в safedirs.py) мог остаться неприменённым на части флота — тогда safe-dirs «подключён, но не работает».
**Scope Included:** состояние конфига safe-dirs (канон `<монорепо>/safe-dirs.json`, legacy-миграция — у пользователя лежат safe-dirs.json.bak/.migrated); auto-approve hook (configs/claude-code/hooks/auto-approve) — как решает по rm; по флоту: остались ли статические ask-правила rm в settings; какие директории покрыты.
**Scope Excluded:** фиксы и раскатка (P4.3); расширение функциональности safe-dirs.
**Inputs:** packages/harness/lib/harness/safedirs.py (лестница конфига, STATIC ask-правила, cmd_*); ~/.swissknifeman/safe-dirs.json.migrated (артефакт миграции).
**Files:** plans/2026.07.07-SKM-AUDIT-004/findings/P4-safedirs.md (создать)
**Required Reads:** 1) packages/harness/lib/harness/safedirs.py (целиком) 2) packages/harness/configs/claude-code/hooks/auto-approve/config.json + lib/safedirs.py хука 3) <монорепо>/safe-dirs.json (текущее содержимое) и safe-dirs.example.json 4) packages/harness/CLAUDE.md (раздел про auto-approve/safe-dirs)

**Code Guidance:** Ключевые вопросы аудита: (a) миграция legacy → корень монорепо завершена и `_state_file` резолвится в репо (проверить фактический резолв, не только код); (b) список STATIC_ASK-правил в safedirs.py совпадает с тем, что реально лежит в settings проектов (если пресеты harness эволюционировали — prune-ask может не находить новые формулировки → правило остаётся и промптит); (c) семантика Claude Code: hook-allow НЕ пробивает статическое ask-правило (уже верифицировано в Phase Context: ask форсит подтверждение до allow/hook) — значит наличие ЛЮБОГО ask-правила на rm в проекте с safe-dirs = дефект конфигурации этого проекта; (d) дополнительные рабочие директории (`permissions.additionalDirectories` в user settings) vs safe-dirs — не путаются ли роли (additionalDirectories даёт доступ, safe-dirs — авто-одобрение удаления).
