# P2.4 — почему `emit_example` не производит эффекта: живой разбор provider-managed пути

**Дата:** 2026-07-31 · **Класс:** живой прогон + чтение кода (repo-grounded) · **Дерево:**
рабочая копия на `b6e47b73` (последний коммит на момент замера) · **Клиент:** `maind` из
`packages/maind/bin/maind`, реестр `config.json` корня монорепо (26 записей).

Файл — вход design-захода `plan-design 2026.07.31-SKM-LEAN P2.4` после эскалации P2.4. Он
проверяет утверждения ESCALATION-блока НЕ по его прозе, а по коду и по живым прогонам, и
добавляет три факта, которых в блоке не было: масштаб отказов провайдерского плана, реальная
гигиена флота и позиция замороженных контрактов.

## 1. Ветка `emit_example` мертва во ВСЕХ прод-вызовах — подтверждено

`deploy.py:346–348` вызывает `write_example`/`reconcile_gitignore` только внутри цикла по
`legacy_targets`, а он определён как

```python
legacy_targets = () if provider_plan is not None else _resolve_targets(project_path, targets)
```

(`packages/maind/lib/maind/provision/deploy.py:326`). Значит эмиссия происходит, только когда
`provider_plan is None`. Все три прод-вызова `deploy_project` передают проекции:

| Вызов | Строка | Что передаёт |
|:--|:--|:--|
| `cmd_deploy` | `deploy.py:429–434` | `provider_projections=_provider_projections(env, config, proj)` |
| `sync/_mcp_run` | `sync.py:178–181` | `provider_projections=context.provider_context.projections` |
| `onboard` | `onboard.py:198–203` | `provider_projections=project_context.provider_context.projections` |

Резолвер проекций **не умеет возвращать пусто**: `provider_projection_context`
(`deploy.py:102–124`) при отсутствии включённых провайдеров **бросает** `MAIND_PROVIDER_DISABLED`,
а при валидной резолюции возвращает непустой кортеж (дефолт — минимум `claude-code`). То есть
`provider_plan is None` в проде недостижим, `legacy_targets` всегда пуст. Единственные живые
потребители legacy-ветки — тесты (`test_deploy.py`, `test_status.py`), которые зовут
`deploy_project` без `provider_projections`.

**Вывод:** утверждение эскалации верно. Дефолт `EMIT_EXAMPLE_DEFAULT = True` (item-коммит
`d16e2ce7`) корректен как плюмбинг и НЕ производит ни одного файла на флоте.

Диагностика отказа (одинаковая у всех `✗`, снята `--json`):

```console
$ packages/maind/bin/maind sync --project swissknifeman --only mcp --dry-run --json
  "providers": [{"provider_id": "claude-code", "status": "failed",
                 "required": true, "diagnostic": "unmanaged-target"}],
  "provider_aggregate": "non-green"
```

`unmanaged-target` — штатный отказ гейта владения (`provider-artifact-contract` v1.3.0,
observation `ownership-conflict` → action `refuse`, no write): существующий `.mcp.json` не
принадлежит нашему lock'у. Это НЕ дефект этого item'а и НЕ следствие смены дефолта —
состояние флота такое же до и после `d16e2ce7` (сверено `git stash` в заходе эскалации).

**Следствие для P2.4:** любой вариант «эмитировать под провайдером» действует ТОЛЬКО на
зелёные строки. Сегодня это 5 проектов из 22.

## 3. Реальная гигиена флота (что вообще надо чинить)

Прогон `mcpconfig.check_hygiene` по всем 26 записям реестра:

| Класс | Число | Проекты |
|:--|--:|:--|
| `clean` (есть `.mcp.json` и `.example`, файл не в индексе) | 14 | agelto, diabox, flexcrm, axiomaerpsdk, azguard, vaulter, swissknifeman, axiomastudio, sibintek-insiders, chatom, perplexity-web-mcp, loqum, brain, agentools |
| **`missing-example`** | **3** | **botkit**, corex, cms |
| `tracked-in-git` (`.example` есть, реальный файл в индексе) | 2 | memster, edufy |
| нет `.mcp.json` вовсе | 3 | vintera, dterema, dterema-app |
| путь недоступен (stale-записи) | 4 | local-repo ×4 |

Пересечение с §2 — это и есть измеренный эффект варианта (а) НА СЕГОДНЯ:

- **`botkit`** — `missing-example` И провайдер зелёный → получит `.example` + строку `.gitignore`;
- **`vintera` / `dterema` / `dterema-app`** — `.mcp.json` будет СОЗДАН этим же sync'ом, значит
  `.example` появится вместе с ним;
- `agentools` — уже `clean`, эмиссия идемпотентна (эффекта ноль, и это правильный ноль);
- **`corex` / `cms`** — `missing-example`, но провайдер отказывает → эмиссии НЕ будет.
  Честная граница варианта (а), названная вслух;
- `memster` / `edufy` — `tracked-in-git` не автоматизируется по канону (`mcpconfig.py:145`
  «`git rm --cached` сделай сам»), к предмету item'а отношения не имеет.

## 4. `maind health` действительно несёт подсказку, которая сегодня не срабатывает

`health.py:150–152` при `missing-example` печатает «нет `<файл>.example` → `maind sync --only
mcp --project <id>` (эмитит портируемый шаблон + `.gitignore`)», а `cmd_health --fix`
(`health.py:373–383`) на этом же условии зовёт `run_sync(..., only="mcp")`. Тот же текст —
в докстринге `mcpconfig.check_hygiene` (`mcpconfig.py:155–157`) и в `probe.py:130`
(`"fix": "maind sync --only mcp --project <id>"`). Пока ветка мертва, все четыре носителя
обещают починку, которой не происходит. После варианта (а) обещание становится истинным для
зелёных строк и остаётся ложным для отказавших — граница обязана быть названа в тексте
подсказки, иначе это «гейт зеленеет на пустоте» в подсказочной форме.

## 5. Позиция замороженных контрактов: эмиссия `.example` их НЕ трогает

Проверено ровно потому, что на этом же месте застряла P2.2 (замороженный
`provider-instruction-contract`).

- **`mcp.catalog`** (`configs/provider-capabilities.json`) — intent «Render semantic MCP
  descriptors with secret references only», уровень `adapted` у обоих провайдеров. Речь о
  рендере ОПИСАТЕЛЕЙ в нативную цель; портируемый `.example` и гигиена `.gitignore` —
  не описатели MCP и не нативная цель провайдера.
- **`provider-artifact-contract` v1.3.0** (`plans/archive/2026.07.19-DUAL-PROVIDER/root/contracts/`)
  нормирует путь Canonical Source → Adapter → Rendered Artifact → **Managed Artifact** и прямо
  говорит: «Контракт не назначает package/module layout, конкретный lock path или provider
  output paths». Запрет касается managed-выходов и их lock-записей. `.mcp.json.example` и
  `.gitignore` managed-артефактами не становятся — у них нет `artifact_id`, provenance и записи
  в `.swissknifeman/provider-artifacts.lock.json`.
- Единственная клауза контракта, которую эмиссия ОБЯЗАНА соблюсти: «`check` и `dry-run`
  являются strictly no-write: target, lock, sidecar, backup и project config не меняются»
  (§Observation/action). Значит в `dry` эмиссия только печатает.

**Почему `.example` НЕ делается managed-артефактом (измеренная цена варианта):** добавление
второй `ArtifactRenderRequest` на `<target>.example` внесло бы новую цель в тот же
`plan_artifact_lock`; у 14 проектов `.example` уже существует и нашему lock'у не принадлежит →
классификатор дал бы `ownership-conflict/refuse` (§2 выше — тот же `unmanaged-target`), и
**проекты, зелёные сегодня (`agentools`), стали бы красными**. Регрессия измерена по тому же
прогону §2, а не предположена. `.gitignore` вдобавок физически не укладывается в
`whole-file`-границу (файл пользовательский) и требовал бы managed-blocks кодека.

## 6. Точка врезки, которую даёт код (без нового пакета)

Эскалация предполагала «другой пакет/Files». Это не так: шов находится в той же функции.

- `project_provider_preflight` (`provider_deploy.py:374–387`) уже помечает отказавшую строку
  `status="failed"` — значит предикат «применилось» выражается без нового состояния:
  строка с `status == "planned"` при не-refused операции.
- `ProviderDeployResult.rendered` (`provider_deploy.py:110–118`) несёт ТОЧНЫЕ байты, которые
  ложатся в цель, — значит `.example` строится из того же источника, что и реальный файл, и
  расхождение real↔`.example` остаётся невозможным by design (инвариант докстринга
  `write_example`).
- Цель claude-канала — `.mcp.json` (`packages/harness/configs/claude-code/mcp/bindings.json`,
  `target_path`), рендер — JSON (`harness/mcp.py:191–192`). Цель codex-канала рендерится в
  TOML, поэтому JSON-эмиссия к ней неприменима; `check_hygiene` по той же причине смотрит
  только claude-канал (`mcpconfig.py:150–158`). Граница «эмитируем только claude-строку»
  совпадает с уже принятой границей диагностики.

## 7. Что из этого следует (входы решений)

1. Вариант (а) реализуем внутри `packages/maind`, без расфриза контрактов — **D91**.
2. `.example` не становится managed-артефактом; цена альтернативы измерена — **D92**.
3. Отказ `unmanaged-target` у 17 проектов — самостоятельная находка масштаба флота, её адрес
   **P2.6** (там и происходит раскатка) — **D93**.
