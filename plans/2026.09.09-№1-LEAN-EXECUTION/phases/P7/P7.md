# P7 — Lean Task control loop consolidation

## Phase Context

P7 is the owner-prioritized branch after P2 and before P3. It converts the measured P2 audit
overhead into one deletion-led Task lifecycle: compact admission, implementation, changed-scope
validation, one terminal projection pass, one semantic Next and one scoped commit by default.
Existing runtime owners remain authoritative; command Markdown becomes invocation guidance instead
of a second copy of their algorithms. The phase removes the unstarted P3.3 validation-receipt
programme and P6 context-evaluation phase rather than adding a parallel `lean` protocol. Completion
requires at least 40% canonical prompt/canon byte reduction plus deterministic low-risk and hard-
boundary fixtures. RAG:— (repo-grounded: findings 15–16, research 08, D14 and current Task sources).

**Scope Included:** normal-path lifecycle selection; compact command/canon contract; changed-impact
validation; read-only audit disposition; selective terminal projection; one-commit default; one
semantic Next and native rendering; route evidence reuse; provider projections; focused regressions,
Task/Skiller/docs qualification and release note.
**Scope Excluded:** a second `lean` mode or provider command family; new persisted schema/carrier/
status/review kind; weakening security/authentication, destructive migration, irreversible external
action, payment/accounting, concurrency/shared-state or public API/schema gates; changing historical
journal evidence; consumer rollout, release, tag, push or deployment.

> **Phase Assurance | v1.**

> Integration Seams: `task-lifecycle-selection` · `plan-command-canon` · `changed-scope-validation` · `projection-delivery`
> Live or Irreversible: none; repository edits are reversible
> Audit Intent: light
> Rationale: one vertical Task-core simplification with focused negative-boundary fixtures; a single-item light phase closes directly when all declared validation is green.
