### P3.2 — Гейт: error>450, warn>300 + burn-down-рэтчет

**Status:** 🟢 Done
**Intent:** Ужесточить validate.sh: `DESC_WARN_MAX` 450→300 (warn), новый `DESC_ERROR_MAX=450` (hard error); burn-down файл `scripts/desc-burndown.txt` — скиллы >300 из списка легальны (warn), НЕ из списка — error; удаление из списка one-way.
**Why:** Без гейта рост описаний тихий (134 скилла проскочили таргет 150 незамеченными); рэтчет запрещает новым скиллам толстые описания, не блокируя релиз на хвосте старых.
**Scope Included:** packages/skiller/scripts/validate.sh (секция description-гейтов, строки ~82–199); scripts/desc-burndown.txt (новый); тест гейта.
**Scope Excluded:** eval.py DESC_MAX=150 (остаётся генераторным таргетом, не трогать); сами описания (P3.1).
**Inputs:** P3.1 закрыт (0 скиллов >450 — иначе CI красный сразу). Остаток >300 после P3.1 — из Completion Notes P3.1.
**Files:** packages/skiller/scripts/validate.sh · packages/skiller/scripts/desc-burndown.txt · packages/skiller/tests/ (тест гейта, если тестовая обвязка validate есть — иначе прогон validate)
**Required Reads:** 1) packages/skiller/scripts/validate.sh:82-199 (существующие DESC-гейты; формат errors/warnings) 2) packages/skiller/scripts/validate.sh:1024-1031 (паттерн hard-гейта check-core) 3) Completion Notes P3.1
**Implementation Rules:** bash + heredoc-python в стиле существующего validate.sh; burn-down формат — по строке `bucket/skill` + `#`-комменты; сообщение error должно печатать команду-подсказку (сократи description или добавь в burn-down с обоснованием).
**Code Guidance:** ЗАПРЕЩЕНО помечать item 🟢 при красном validate.sh на текущем реестре — гейт обязан быть зелёным на HEAD сразу после введения (иначе он вводится преждевременно); подтверждение — полный прогон validate.sh в Validation. Burn-down: скиллы добавляются в файл ТОЛЬКО в этом item (bootstrap-список = остаток P3.1); процедура удаления — вместе с сокращением description. One-way: тест/гейт не должен позволять новые записи проходить молча (validate предупреждает, если в burn-down есть скилл, которого больше нет или который уже ≤300 — «протухшая запись, убери»).
**Validation:** `bash packages/skiller/scripts/validate.sh` зелёный; негативная проверка: временно раздуть description тестового скилла >450 → validate красный (вернуть обратно); скилл >300 вне burn-down → error, в burn-down → warn.
**Deliverables:** обновлённый validate.sh + desc-burndown.txt + подтверждённые негативные прогоны (лог в Completion Notes).
**Completion Notes:** `DESC_WARN_MAX` 450→300, новый `DESC_ERROR_MAX=450` (hard, burn-down не
спасает). Между WARN и ERROR: скилл в `scripts/desc-burndown.txt` (`bucket/name` per строка,
bootstrap = все 64 скилла из остатка P3.1, реальный скан HEAD, не переиспользован устаревший
список Completion Notes P3.1 дословно — 2 имени успели поменяться, например
`architect/engineering`→`architect/dev-engineering-super-skill`) → warn («унаследованный долг»);
вне списка → error («новый долг запрещён»). Добавлен one-way-гейт протухших записей: строка
burn-down, чей скилл удалён/переименован ИЛИ чей description уже ≤300 — warn «протухшая запись,
убери» (секция 1b validate.sh). Ключ `bucket/name` строится из ПУТИ (`skills/<bucket>/<name>/`),
не из frontmatter `bucket` — upstream-скиллы часто без этого поля, ключ по frontmatter ложно
уводил их в error/протухшую-запись одновременно (поймано первым прогоном на
`frontend-nuxt/nuxt-modules` и `frontend-vue/vue-best-practices`, исправлено до коммита).
