# Q5

Запрос (perplexity-web-mcp stdio, default pool; search; 2026-10-07):

```text
October 2026. BMAD Method "bmad-loop" (separate official package orchestrating fresh dev/review sessions with different coding CLIs per stage) and Task Master AI "loop" command: verify they exist and describe precisely, with primary GitHub/doc URLs: 1) how the loop/orchestrator gets work from the planning artifacts (reads files directly vs calls a planner API like next_task/set_task_status), 2) how engines/CLIs are plugged in (adapters, config, capability checks), 3) whether the planning tool works fully without the loop installed, 4) known problems reported by users. Answer in Russian, max 500 words.
```

Ответ (как вернул сервис):

Да, оба существуют: официальный отдельный и встроенная команда Task Master loop, выпущенная в 0.41.0 11 января 2026 года. Это разные архитектуры: BMAD управляет стадиями и проверяет артефакты кодом; Task Master запускает свежие Claude Code-сессии с инструкциями.

## 1. Откуда берётся работа

Точные Task Master инструкции и реализация опубликованы в официальном , включая presets/default.ts и loop.service.ts. Другие presets — coverage/linting/duplication/entropy — ищут работу в коде, необязательно в backlog.

## 2. Подключение движков

- BMAD: generic tmux adapter и CLI profiles для claude, codex, gemini, copilot, antigravity; разрешено смешивать их по стадиям. Profile выбирает adapter kind; реестр принимает внешние adapter/profile packages. .bmad-loop/policy.toml хранит настройки; adapters, validate, probe-adapter дают перечисление, preflight и сбор hook/transcript/token-данных. Проверяются binary, hooks, окружение и поддержка skill-контрактов; это не гарантия качества модели. Dev и дополнительный review получают отдельные свежие контексты; review запускается по policy/рекомендации, не обязательно всегда.
- Task Master: loop ориентирован на Claude Code, не на взаимозаменяемые per-stage adapters. По умолчанию — claude -p с --dangerously-skip-permissions; Docker включается --sandbox. Multi-provider настройки планировщика, включая Codex, не означают Codex executor для loop.

## 3. Независимость планирования

BMAD полностью работает без loop: это opt-in module, не выбранный по умолчанию. Task Master также сохраняет PRD parsing, decomposition, dependencies, CLI/MCP без запуска loop; отдельно устанавливать loop не требуется — команда входит в пакет.
