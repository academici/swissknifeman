# P6.8 — item-scoped journal/state freshness repair

## Источники

- `findings/P6.8-design-journal-freshness-cascade-2026-08-09.md` — локальный repro: один
  `plan-design` event P6.8 сделал stale state views остальных items и оставил baseline K=9.
- `decisions/D148-separate-design-provenance-from-execution-state.md` — design events входят в
  history/freshness выбранного item, но не меняют execution position.
- `packages/task/lib/task/plan_item_state.py` — `source_scope` объявлен item-scoped, тогда как
  `through.journal_line` и `inputs_sha256` до repair зависели от всего `journal.jsonl`.
- `packages/task/tests/test_plan_item_state.py` — public seam `build_states(..., check=True)`.

Все выводы repo-grounded; внешних факт-классов нет.

## Целевая семантика

Freshness одного `P<n>.<m>.state.md` зависит только от immutable item spec и exact journal rows с
тем же `item_id`, в append-only порядке. `through` указывает физическую строку и timestamp
последнего matching event; append другого item не меняет ни metadata, ни bytes этого state.
Execution `position` по D148 продолжает учитывать только execution-команды, поэтому design event
обновляет freshness/history выбранного item, но не создаёт ложный execution attempt.

Регрессия доказывается двумя item specs: после генерации обоих state append для первого обязан
сделать stale только первый; `--check` второго остаётся зелёным и его bytes не меняются. Repair не
меняет journal schema, state schema, acceptance protocol или raw/report history. Existing state
views пересобираются owning generator один раз; отсутствующие baseline bundles не создаются.

Чтобы baseline K сравнивал одинаковую диагностическую поверхность, ref-tree проверяется в detached
git worktree, а не в архиве одного plan-dir: bundle inputs и git-backed downstream evidence тогда
остаются разрешимыми. В baseline identity нормализуются только observed read-budget числа; item,
threshold, path, limits и calibration остаются частью ключа, поэтому новая категория ошибки не
маскируется.

## Closure boundary

P6.8 можно передать в `task:plan-close` только после targeted test, полного task validation,
freshness checks generated views и `plan-lint --baseline HEAD --gate new` с K=0. Абсолютные
исторические ошибки плана остаются baseline debt и не объявляются исправленными этим repair.
