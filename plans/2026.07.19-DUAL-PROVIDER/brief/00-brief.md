# Бриф владельца — dual-provider migration

**Зафиксирован:** 2026-07-19  
**Владелец:** Dmitry Vostrikov

## Исходная цель

Swissknifeman изначально проектировался вокруг Claude Code. Его нужно превратить в
provider-neutral umbrella, который одновременно и без потери возможностей обслуживает
Claude Code и ChatGPT/Codex. Миграция должна предшествовать дальнейшему исполнению
`plans/2026.07.18-FOREMAN`: сначала Codex получает тот же рабочий фундамент, затем
дорабатывается Artifex/FOREMAN, после этого решения раскатываются по остальным проектам.

## Что должно стать общим

- Один максимально единый источник истины для skills, task-команд, планового протокола,
  памяти, аналитики, MCP-пресетов и общих правил работы.
- Канонические skills остаются в `packages/skiller/skills/`, канонические task-команды —
  в `packages/task/commands/`; provider-каталоги являются адаптерами, а не форками.
- Публикация, marketplace, connect/vendor/install/update/doctor должны работать по циклу
  для включённых провайдеров и не требовать ручного копирования.
- В каждом проекте нужен явный provider-config, вероятно секция `providers` в
  `.swissknife.json`; fleet-конфиг в корневом `config.json` должен уметь задавать defaults
  и project overrides.
- Skills публикуются для обоих провайдеров; конкретный проект выбирает, какие из них
  включать. Изменение канона размножается детерминированным инструментом с контролем
  версии/хеша/дрейфа. Symlink допустим лишь как запасной локальный режим, не как основной
  контракт доставки.
- Одинаковые по смыслу команды должны быть доступны в обоих провайдерах: task design,
  research, review, fix, plan design/exec/run/audit/close, работа по фазам и item'ам,
  формирование workflow и связанные management-команды.
- Исполнение должно уметь разбивать работу на малые задачи и направлять её моделям
  подходящего класса, не привязывая общий контракт к названиям моделей одного провайдера.

## Что должно остаться provider-specific

- Claude Code сохраняет `CLAUDE.md`, `.claude/`, существующие команды, marketplace,
  permissions, hooks, agent packs и другие нативные возможности.
- Codex получает `AGENTS.md`, `.agents/skills`, `.codex/`, Codex plugins/marketplace,
  MCP, hooks, agents/subagents, config/trust/approval/sandbox и другие нативные возможности.
- Общий слой не должен сводиться к наименьшему общему знаменателю: capability manifest
  описывает различия, а каждый адаптер использует полезные возможности своего provider'а,
  включая lifecycle hooks, контекст/кэширование, нативную оркестрацию и безопасность.
- Корневой README должен содержать поддерживаемую из capability manifest таблицу:
  что умеет каждый provider, где его особенности и какова степень паритета.

## Базовый рабочий контур до реализации

- Сначала подключить Codex к локальным skills, mAInd memory/code graph, Serena и
  Perplexity Web MCP; после каждого значимого bootstrap-шага допустим перезапуск сессии.
- Сохранять checkpoint в репозитории/памяти так, чтобы перезапуск не терял решения.
- Для Codex владелец хочет максимально автономный режим без постоянных подтверждений.
  Текущий запуск использует `approval_policy=never` и полный доступ; итоговая миграция
  должна документировать безопасные provider-native профили, включая различие между
  `workspace-write` fail-closed и явно выбранным full-access.
- Текущей сильной Codex-модели достаточно для исполнения по умолчанию; владелец готов
  переключать модель/effort, когда routing плана этого потребует.

## Последовательность программы

1. Завершить bootstrap Codex/MCP/skills/memory и подтвердить его работоспособность.
2. Спроектировать и утвердить dual-provider migration.
3. Реализовать миграцию и self-hosting-пилот в самом swissknifeman.
4. Снять паузу с FOREMAN и адаптировать его runner к provider-neutral контракту.
5. Только после этого отдельной управляемой волной раскатать изменения на остальные
   проекты из корневого fleet-конфига.

## Ограничения

- Claude Code compatibility нельзя ломать или заменять Codex-файлами.
- Python-пакеты остаются stdlib-only.
- Не продолжать FOREMAN за текущий checkpoint до утверждения и реализации bootstrap/migration.
- Сохранять посторонние и пользовательские изменения в рабочем дереве.
- Нельзя считать временные `.agents/skills` новым каноном: это только bootstrap-адаптеры.
