## Operator contract projection

- Provider support is always provider-qualified: stored support values remain `native`,
  `adapted`, or `unsupported`; derived presentation never lets one ready provider hide a missing,
  failed, unsupported, stale or untrusted peer. Adapters write only their own declared targets and
  never use another provider's output as source.
- Locale intent has three independent surfaces (`response`, `plan`, `diagnostics`) and precedence
  `command-session > environment > project > user > built-in en`. Missing values inherit per
  surface; provider state is forbidden as locale preference. RFC 5646 syntax, pinned-registry
  canonicalization and the `en|ru` render catalog are distinct stages. Provenance excludes raw
  environment values, host paths, credentials and provider payloads.
- English is the sole semantic source. Russian is a sparse key-addressed overlay with exact source
  digests and immutable tokens. Development docs stay compact English; generated provider docs are
  regenerated through their owner and never patched.
- Operational migration is preserve-first. `plan`, `check`, and `dry-run` are no-write. `apply`
  needs an accepted action digest, exact ownership/preimages/backups, full provider snapshot,
  readback and an empty second reconcile. Any mismatch keeps the aggregate non-green and rollback
  restores only declared owned preimages.
- Project/fleet health is exact-set and non-masking. Producing a complete `non-green` report is a
  successful evaluator result, not evidence of release readiness. Stable diagnostic codes and
  source identities remain English machine fields; only human messages may localize.
