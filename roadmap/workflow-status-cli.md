# Roadmap: wf-status — консольный статус-репортер workflow-прогонов

**Статус:** ⬜ к внедрению — критерий сработал (field-case 2026-07-10, повторяющееся трение).
**Дом:** CLI swissknifeman (прецедент `harness`-команд); реализация — дешёвая модель
(механика парсинга, дизайна не требует).

## Проблема (измеренная)

Два повторяющихся трения при фоновых workflow (Owner 2026-07-10):

1. **Агенты советуют владельцу «/workflows — живой прогресс»**, но в его окружении такой
   команды нет (VSCode-поверхность) — совет бесполезен и повторяется в каждой сессии.
2. На запрос «дай детальный статус» агент **каждый раз заново** парсит journal/процессы/git
   импровизированным кодом и собирает красивый ответ (проценты, фазы, агенты). Результат
   хороший, но: (а) жжёт токены на одноразовый парсинг, (б) формат каждый раз разный,
   (в) качество зависит от того, как сессия догадается парсить.

Формат прогонов при этом **стандартный и стабильный**: transcript-директория
`~/.claude/projects/<proj>/<session>/subagents/workflows/wf_*/` содержит `journal.jsonl`
(события started/result), `agent-*.meta.json`, а скрипт прогона несёт `export const meta`
с декларацией фаз. Парсится детерминированно — LLM для этого не нужен.

## Решение: консольная команда (НЕ копирование скрипта по пакетам)

Развилку «копия bash-артефакта в каждый пакет vs консольная команда» решаем в пользу
**команды** — копии дрейфуют (сам owner отметил проблему обновления версий), а CLI
swissknifeman уже раскатан и доступен из любого проекта. Прецедент: `harness`/`maind doctor`.

`swissknifeman wf status [--run wf_<id>] [--project <path>] [--json] [--watch]`

1. **Discovery:** без аргументов — найти свежие прогоны по mtime в
   `~/.claude/projects/*/​*/subagents/workflows/wf_*`; `--run` — конкретный.
2. **Парсинг:** journal.jsonl (агенты started/завершены, последние result-выжимки),
   meta скрипта (фазы + детали), сопоставление агентов фазам по label/meta.
3. **Выход — фиксированный шаблон** (один и тот же всегда):
   run id · имя · статус · фазы таблицей (✅/⏳/⬜, счётчик агентов) · агенты в полёте ·
   последние N результатов (по 1 строке) · грубый % (завершённые агенты / оценка по фазам).
   `--json` — те же данные машинно (для хуков/статуслайна).
4. **Потребление агентом:** сессия на «дай статус» вызывает команду и ретранслирует —
   стабильный формат, копеечные токены. Прошить подсказку в скиллы task:* /
   конструктор workflow: «статус — через `swissknifeman wf status`, НЕ советовать
   /workflows» (закрывает трение №1).

## Ограничения (зафиксировать в реализации)

- Формат transcript-директорий — внутренний для Claude Code и может меняться между
  версиями: парсер защищённый (unknown-поля игнорировать, при несовпадении формата —
  честное «формат не распознан, версия CC?», не трейсбек).
- Прогоны других машин/сессий не видны — только локальная FS, это ок.
- Не заменяет журнал плана: команда про «что происходит сейчас», не про историю.

## Критерий внедрения

Сработал: трение повторяется многократно (каждый фоновый прогон), парсинг-импровизации
жгут токены уже сейчас. Реализация — Sonnet-задача по этой спеке (парсер + шаблон + тесты
на фикстурной transcript-директории).
