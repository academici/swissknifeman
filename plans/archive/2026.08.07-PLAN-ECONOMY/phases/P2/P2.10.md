**Implementation Rules:** - Layout определяется только объявленным Meta `Layout`; угадывание по дереву запрещено.
- Layout v1 сохраняет роли/порядок `plan`, `handoff`, `phase`, `required_read` и существующую resolution semantics.
- Layout v2 измеряет ровно обязательные carrier roles `plan-core`, `phase-context`, `item-spec`, `item-input-bundle`, `item-state`; `handoff.md` и legacy prose traversal в эту ветвь не входят.
- Bundle до чтения проверяется owning generator `--check`; state — owning state projector `--check`. Missing carrier даёт fail-closed gap, stale/hash mismatch — unresolved gap; generated carriers руками не чинятся.
- Bundle entries обходятся в объявленном порядке, selected bytes вычисляются по selector и сверяются с `sha256`/`selected_sha256`; одинаковая пара path+selector считается один раз на item.
- Five-slot carrier floor считается отдельно от bundle selections; существующие output keys и stage-aware admission сохраняются для совместимости.
- Никаких пороговых либо item-specific исключений. Любой новый design вопрос возвращается в plan-design, а не решается скрытым кодом.
**Code Guidance:** Вынести layout dispatch на узкую границу, оставив v1 branch максимально неизменной. Для v2 переиспользовать `plan_layout` для адресации, `plan_bundle` для freshness/selector semantics и `plan_item_state` для byte freshness. Ошибку generated-carrier validation переводить в закрытую существующую taxonomy gaps, не расширяя frozen enum без отдельного решения.
