**Intent:** Заменить в пяти командах печать уточняющего вопроса в чат производством `DecisionRequest` по замороженной форме P5.1 с решением через резолвер P5.3; создать ВЕРСИОНИРОВАННЫЙ АССЕТ рубрики среза-суждения по `return-judgement` v1, собрать калибровочный банк на историческом корпусе, назвать его границу честно и принудить правило перекалибровки редьюсером. **Why:** Оба интерфейса — точки, где недетерминированное суждение модели входит в детерминированную петлю, и у них один инвариант: модель ПРЕДЛАГАЕТ, детерминированная петля РЕШАЕТ (D56 для вердикта, D62 для действия). Пока команды печатают вопрос в чат, безлюдный прогон невозможен, а весь механизм P5 остаётся инструментом без обязанности — риск, названный в pre-mortem P5 дословно: «механизм построен, но никто им не пользуется» — RAG:— (repo-grounded: `research/07-…` §10 строка 10; `phases/P5.md` P5.4/P5.5 Scope Excluded). Носитель рубрики уточняется против формулировки P4.5 («как текст команды»): внешняя практика прямо предписывает держать каноническую рубрику ОТДЕЛЬНЫМ версионированным ассетом, а не многостраничным изменяемым промптом внутри вызывающей команды, и требует, чтобы запись вердикта несла разрешённую версию и `content_sha256`, а не семантический псевдоним — RAG:✅ 2026-08-07 (`findings/11-…` R18.3). Это не противоречит P4.5, а исполняет его же требование провенанса «хеш рубрики»: хешируемым объектом абзац внутри команды быть не может, потому что меняется вместе с любой её правкой — RAG:— (repo-grounded: `phases/P4.md` P4.5 Implementation Rules). Форма самой рубрики берётся из практики: якорные наблюдаемые определения метк, ЯВНЫЙ порядок решения, в котором достаточность улик проверяется ПЕРЕД содержательным вердиктом, единица улики на каждое условие, запрет предлагать действия, заданный tie-breaking — RAG:✅ 2026-08-07 (`findings/11-…` R18.1). Правило перекалибровки тоже внешнее и переносится дословно: смена модели есть МИГРАЦИЯ ОЦЕНЩИКА, и до перекалибровки судья имеет право производить только воздержание или неблокирующую телеметрию — RAG:✅ 2026-08-07 (`findings/11-…` R18.4).

**Implementation Rules:** - **Model judgement is an isolated child/tool call, not a handoff:** the root executor builds the P4.5 capsule, selects reviewer model/effort independently, invokes exactly one fresh reviewer, validates the returned schema and resumes the same root session. Raw provider flags live only in the provider adapter; canonical commands express `isolated-child-return` (RAG:✅ 2026-08-08, `findings/19-…` R23; D125).
- **No review on the first eligible local failure:** the interface refuses a reviewer request without either a risk trigger or a repeated durable fingerprint. It also refuses self-review, full parent transcript, unrelated history and a second sample for the same return event. Capability absence produces explicit `cold-start-root: capability-missing`, never silent self-review.
- **Рубрика — ОТДЕЛЬНЫЙ версионированный ассет**, команда ссылается на него идентификатором и версией, а не цитирует; запись вердикта пинит `content_sha256` (уже обязательное поле провенанса P4.5) — RAG:✅ 2026-08-07 (`findings/11-…` R18.3). Поле существующего `model_id` хранит каноническую форму `<provider>:<model>`; отдельная provider-specific schema не заводится.
- **Замороженная схема записи суждения НЕ расширяется:** `rubric_id` и `version` живут ВНУТРИ текста ассета, поэтому хеш их покрывает, а разрешение «хеш → ассет» делается поиском по закоммиченным версиям. Добавление поля в схему — эскалация, а не удобство. В этом item банк и `verified` row создаются только для Codex; Claude получает `pending-provider` + replay, а его отсутствие трактуется редьюсером как штатное воздержание, не как green.
- **Порядок решения в рубрике: достаточность улик ПЕРЕД содержательным вердиктом**, `AVOIDABLE` требует названного прямо подтверждённого признака, «по усмотрению» финальным правилом запрещено — RAG:✅ 2026-08-07 (`findings/11-…` R18.1).
- **Судья не предлагает действий** (D56, подтверждено R18.1): в рубрике явный запрет на ремедиацию, ранжирование и «следующий шаг»; единственная разрешённая инициатива — КАНДИДАТ объявления шва, принимаемый только schema-valid и штатным носителем.
- **Swap-прогон даёт воздержание, а не среднее:** зависимость вердикта от порядка предъявления улик → `INSUFFICIENT_EVIDENCE`. Это УЖЕСТОЧЕНИЕ, то есть монотонность D56 не нарушена — RAG:✅ 2026-08-07 (`findings/11-…` R18.2).
- **Перекалибровка принуждается редьюсером:** пара «id модели × хеш рубрики», отсутствующая в реестре откалиброванных, даёт трактовку ВОЗДЕРЖАНИЕ; реализуется без правки схемы, потому что оба поля уже обязательны — RAG:✅ 2026-08-07 (`findings/11-…` R18.4).
- **Банк объявляется в режиме ОБНАРУЖЕНИЯ рубрики, а не продакшн-гейта**, и отчёт калибровки первой строкой называет эту границу (образец — D58): практика даёт 30–50 для обнаружения и 100–300 как ИНЖЕНЕРНУЮ эвристику для продакшн-гейта, объявленных швов в истории нет по построению — RAG:✅ 2026-08-07 (`findings/11-…` R18.4) + RAG:— (repo-grounded: D58).
- **Уточнение никогда не становится апрувом:** после каждого ответа намерение переклассифицируется (D59); автоответ — только из закрытого allowlist'а и только с провенансом системы-записи, никогда из памяти модели и не из чата.
- **Свободная проза как канал решения запрещена** (D10): команда не имеет права «спросить в чате вместо запроса», и это пишется как запрет.
**Code Guidance:** Item несёт два места, где красивая формулировка отменяет весь механизм. Первое — «если срез признал возврат обоснованным, продолжаем»: это право модели снять собственный ограничитель, запрещённое D56 закрытым перечнем; рубрика обязана быть написана так, чтобы вердикт физически не мог означать разрешение. Второе — «спрошу владельца в чате, а запрос оформлю потом»: свободная проза в самой чувствительной к безопасности точке, ровно то, против чего заведён `DecisionRequest`. Третий риск — рубрика как эссе: прилагательные вместо наблюдаемых признаков («возврат выглядит обоснованным»), после чего вердикты несравнимы между прогонами и калибровка бессмысленна. Четвёртый — «подкрутить банк»: разметить спорные кейсы так, чтобы согласие вышло красивым. Согласие — измеряемая величина, а не цель; низкое согласие есть находка о РУБРИКЕ, и её место в отчёте и D-записи, а не в переразметке. ЗАПРЕЩЕНО помечать item 🟢 при незакрытых предусловиях: (а) ассет рубрики закоммичен, несёт id и версию внутри текста, и его хеш совпадает с пиннуемым в записи; (б) монотонность проверена перебором enum на тестовых записях — ни одно значение не даёт исхода мягче, чем без вердикта; (в) запись от пары вне реестра откалиброванных трактуется воздержанием (кейс); (г) swap-прогон на не менее чем трёх кейсах даёт `INSUFFICIENT_EVIDENCE` при зависимости от порядка; (д) отчёт калибровки первой строкой называет границу банка и печатает κ и сырое согласие; (е) ни одна команда больше не печатает уточняющий вопрос в чат (грепом по прозе); (ж) проекции свежи, паритет-тесты зелёные. Обходить гейты («банк соберём в приёмке», «реестр откалиброванных заведём позже») запрещено — не пройден → статус остаётся 🟡 + Pending Work с точной причиной. Если окажется, что замороженная схема записи не позволяет выразить нужное, — НЕ расширять её: остановиться и эскалировать. Пятый риск — продублировать rubric/reducer «под Claude»: provider различает только qualified calibration row и command projection, алгоритм общий.
