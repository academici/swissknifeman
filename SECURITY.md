# Security policy

## Report a vulnerability

Write privately to **dv.vostrikov@gmail.com** (or use GitHub private vulnerability reporting when it is enabled on
the repository). Do not open a public issue before a fix is agreed. Describe the affected module and file, the steps
to reproduce and the impact; the answer comes within a few days, the fix and the disclosure follow by agreement.
Module-specific notes: [`packages/skiller/SECURITY.md`](packages/skiller/SECURITY.md) (imported skills, snippets),
[`packages/maind/SECURITY.md`](packages/maind/SECURITY.md) (memory hub).

## Supported versions and platforms

| What | Supported |
|---|---|
| Version | the latest umbrella tag reachable from `main` (`releases/vX.Y.Z.json` attests it) |
| OS | Linux (CI: Ubuntu). macOS and WSL are expected to work as POSIX hosts but are not tested in CI; native Windows is not supported |
| Python | 3.11 – 3.14 (`aicore.MIN_PYTHON`; CI tests 3.11, 3.13 and 3.14) |
| Tools | `git`, `bash`; provider CLIs (`claude`, `codex`, `grok`) only for the roles that use them |

`maind` and `analyst` are tools: their CI jobs never block the core (`configs/ecosystem-units.json`
`standalone.tools`), and they are outside this support line.

## Trust boundaries

- **Provider prompts.** A run sends prompts to external model providers. The filesystem research source never reads
  secret-named files, files git ignores, symlinks, fifos or devices, and redacts tokens in every returned line
  (`packages/orch/lib/orch/research/local_files.py`). Role stubs that look like a secret are refused before a prompt.
- **Run options.** Plan, phase, item and invocation layers can only tighten the sandbox, the scope fence and review;
  `extra_paths` come from the conductor config only (`OPTIONS_UNTRUSTED`, `OPTIONS_UNSAFE_PATH`).
- **Run state** lives in `0700` folders, JSON is written durably (temp file, `fsync`, rename).
- **Workflows.** Every action is pinned to a commit SHA, every workflow narrows its token with top-level
  `permissions`, no step hides a failure with `|| true` (`scripts/workflow-policy.py`, run by the hub CI job). No
  workflow pushes to `main`: generated files are regenerated by the author and CI proves they are current.
- **Releases.** A release tag must be on `main`, have the top `CHANGELOG.md` heading and a current
  `releases/vX.Y.Z.json` attestation (`scripts/verify-tag.py`, the `release-tag` job of `hygiene.yml`).

## Settings kept on GitHub (checked by the owner, not by code)

Branch protection of `main` with the required checks of `modules.yml` and `hygiene.yml`, no force push and no
deletion of `v*` tags, CODEOWNERS review, secret scanning with push protection.
