## Phase Context

> **Контракт фазы (contract-first).** Потребляет: схему policy-файла (P0.3), факт-лист
> permission-режимов (findings §3), драйвер P2 (точки передачи `--permission-mode` /
> `--allowedTools` в worker.py). Производит: settings-фрагменты unattended-профиля
> (allowlist-паттерны + маппинг permission-mode per тип-запуска, задаётся ФЛАГОМ, не хуком —
> D28), PreToolUse-хук детерминированного auto-approve по policy проекта (РАСШИРЯЕТ harness
> auto-approve, не заменяет — D29), скилл `supervisor-protocol` (директивы воркеру: спорное →
> ATTENTION в handoff + friction в журнале P1.1, не спрашивать; философия владельца из
> policy). Границы: TG/MAX-хуки и таймаут-деградация по severity — P4; раскатка фрагментов в
> проекты — P6; bypassPermissions не используется как дефолт ни в одном профиле; Layer 3
> defer/remote-approve — P4.3.

Фаза даёт unattended-профиль, которым драйвер P2 гоняет воркеров без ручных подтверждений:
статичный allowlist (settings-фрагмент) + permission-mode флагом при запуске + PreToolUse-хук
policy-driven для остального + поведенческий скилл воркера. **Security-sensitive поверхность**
(unattended-агент исполняет команды сам) → fail-safe жёстко: неизвестное/вне-правил → deny/ask
(эскалация), НИКОГДА silent allow; bypassPermissions — не дефолт; allowlist — только
pattern-scoped, никогда голый `Bash`. Несущий факт основания: permission-mode нельзя надёжно
переключать хуком (upstream-баги CC #49525/#39973) — только флагом при запуске (D28).

**Pre-mortem-заметка (security):** провал через 6–12 мес — «unattended-агент выполнил опасную
команду». Митигации в дизайне: (1) allowlist без голого `Bash` (pitfall §3); (2) компаунд-команды
разбираются AST'ом harness (опасный сегмент внутри «безопасной» составной ловится); (3) вне
policy → deny/ask, не allow; (4) bypassPermissions не дефолт. Все четыре — в Code Guidance items.

**Дом исполнения:** репо swissknifeman (`~/projects/packages/swissknifeman`) — при exec SSOT
плана = репо (§12), план там же зеркалом (`brain sync`). P3.1–P3.2 → `packages/artifex/configs/`
+ reconcile `packages/artifex/lib/artifex/worker.py` (P2.2); P3.3 → `packages/skiller/skills/`.

**Рекомендованный порядок:** P3.1 (профиль-фрагменты + маппинг mode) → P3.2 (PreToolUse-хук
поверх allowlist) → P3.3 (скилл воркера, ссылается на policy/журнал/plan-protocol). P3.1–P3.2 —
`plan-exec` (sonnet/medium, конфиг по готовой схеме P0); P3.3 — manual (opus/high, несущие
директивы).
