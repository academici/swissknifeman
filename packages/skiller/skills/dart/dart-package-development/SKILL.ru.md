# Разработка Dart-пакета

Этот скилл ведёт разработку библиотек и SDK на Dart: публичный контракт, раскладка
пакета, совместимость и проверяемость. Он не заменяет `mobile/figma-to-flutter` для
Flutter-интерфейсов и не навязывает Flutter, state-management или FFI пакету без таких
зависимостей.

## Когда активировать

- создаёшь или меняешь Dart-пакет, библиотеку или SDK;
- меняешь публичные типы, экспорт, async-контракт, сериализацию или версию пакета;
- готовишь релиз или проверяешь обратную совместимость Dart API.

Не активируй для верстки Flutter-экрана по Figma: это `mobile/figma-to-flutter`.

## Входные данные

- `pubspec.yaml` и поддерживаемый SDK constraint;
- существующие публичные entrypoint-файлы из `lib/`, тесты и команды CI;
- цель изменения и ожидаемый контракт потребителя.

## Алгоритм

1. Сначала прочитай `pubspec.yaml`: имя, SDK constraint, runtime/dev dependencies и
   доступные скрипты. Не меняй constraint или версии зависимостей без задачи на это.
2. Отдели публичную поверхность от реализации: потребитель получает стабильные entrypoint-
   экспорты из `lib/`; внутренние детали не становятся случайным контрактом. Перед изменением
   перечисли затронутые публичные типы, методы, enum-значения, ошибки и payload.
3. Сохраняй типовой и async-контракт: не превращай sync API в async и наоборот без явной
   миграции; не маскируй nullable/non-nullable изменение; новые ошибки и поля должны быть
   совместимы с ожидаемым поведением потребителя.
4. Для моделей на границе сети/файла проверяй оба направления: корректный payload кодируется
   ожидаемо, допустимый вход декодируется, а ошибочный вход даёт контролируемую диагностику.
   Межъязыковой контракт фиксируй общими fixtures, а не ручными дубликатами тестов.
5. Добавь или обнови тесты на изменённое наблюдаемое поведение. Используй реальные команды
   проекта; типовой минимум — `dart analyze`, `dart format --output=none --set-exit-if-changed .`
   и `dart test`. Не заявляй зелёный результат, если команда не запускалась или недоступна.
6. Перед релизом отдели совместимое изменение от breaking change, обнови версию только в
   рамках релизной задачи и проверь, что changelog/миграционные заметки покрывают изменение
   публичного контракта.

## Чеклист качества

- [ ] Публичные exports и затронутый API перечислены до реализации.
- [ ] Null safety, sync/async и ошибки не изменены неявно.
- [ ] Изменённое наблюдаемое поведение покрыто тестом.
- [ ] Для данных на границе есть проверка encode/decode или conformance-fixture.
- [ ] `dart analyze`, format-check и тесты запущены либо честно отмечены как недоступные.
- [ ] Версия и migration/changelog менялись только при релизном или breaking scope.
