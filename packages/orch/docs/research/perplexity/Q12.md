## Query

October 2026: machine-readable headless interfaces of coding CLIs for building a local orchestrator. 1) Claude Code `claude -p --output-format stream-json` (and --input-format stream-json): event types, final result event, session_id, does it work with Pro/Max subscription OAuth login (not API key), effect of --bare. 2) OpenAI Codex CLI `codex exec --json` and Codex SDK: event schema (thread.started, turn.completed, usage), stability guarantees, ChatGPT-plan login support, resume. 3) xAI Grok Build CLI headless `-p --output-format streaming-json` and `grok agent stdio` (ACP): event shape, completion signal, SuperGrok subscription auth. ## Answer (unchanged)

Для локального оркестратора все три CLI дают пригодный поток событий, но не стоит считать их JSONL-схемы стабильным межверсионным API: фиксируйте версии, терпимо разбирайте неизвестные поля и отделяйте «поток завершился» от «задача успешна».

## Claude Code

- claude -p --output-format stream-json выдаёт JSONL; --verbose --include-partial-messages нужны для подробных событий и текстовых дельт. Встречаются system (в частности, subtype: "init"), assistant, user, stream_event, события инструментов и разрешений. system/init содержит session_id; последний объект — type: "result" с итоговым текстом и метаданными. --input-format stream-json используется для потоковой подачи входных сообщений, но не меняет формат выходных событий.
- Pro/Max OAuth работает при обычном входе Claude Code; API key не обязателен. Но официальный CLI прямо указывает, что --bare не читает OAuth-учётные данные и системный keychain: нужен ANTHROPIC_API_KEY либо другой поддерживаемый провайдер. --bare также пропускает автозагрузку hooks, skills, команд, subagents, плагинов, MCP, auto-memory и CLAUDE.md; нужное передавайте явно.
- История изменений показывает изменения в stream-json, в том числе исправления пропуска сообщений subagent и нюансы обёрток stream_event; в документации описаны и версионные различия. Закладывайте result как обязательный терминальный маркер, а EOF без него — как ошибку/неполный запуск.

## OpenAI Codex CLI

- codex exec --json печатает JSONL в stdout: thread.started с thread_id, turn.started, item.* для сообщений, shell-команд, изменений файлов и других действий, затем turn.completed с usage (input_tokens, cached_input_tokens, output_tokens, reasoning_output_tokens). Возможны turn.failed и error; успех определяйте не только по EOF, но и по финальному событию и коду возврата.
- CLI использует сохранённую авторизацию; документация описывает вход через ChatGPT и отдельный advanced-путь ChatGPT-managed auth для доверенных CI-runner’ов. То есть API key не единственный вариант, но надо заранее выполнить codex login и безопасно хранить ~/.codex/auth.json.
- Возобновление: codex exec resume --last ... либо codex exec resume <SESSION_ID> .... TypeScript SDK позволяет startThread(), повторно вызывать run() и resumeThread(threadId); Python SDK управляет локальным app-server через JSON-RPC. Документация называет Python SDK stable, но это не равнозначно обещанию неизменной схемы каждого CLI-события.

## xAI Grok Build

- grok -p ... --output-format streaming-json выдаёт инкрементальные JSONL-события, но официальная headless-документация не фиксирует исчерпывающий список типов или имя терминального события. Парсеру следует сохранять неизвестные записи; критерием завершения использовать закрытие процесса плюс exit code, а не предполагать конкретный end-тип.
- Для оркестрации предпочтительнее grok agent stdio (ACP, JSON-RPC): session/update несёт чанки текста agent_message_chunk, а ответ на session/prompt возвращает completion metadata. Официальный пример выбирает cached_token после grok login либо xai.api_key при XAI_API_KEY.
- Grok Build объявлен доступным подписчикам SuperGrok и X Premium Plus; документация подтверждает вход через учётную запись и локальный cached token. Но явной гарантии, что именно SuperGrok OAuth поддерживается как стабильный headless-контракт, найденные первичные документы не дают.
- Статус раннего beta важен: есть сторонние сообщения о зависаниях streaming-json и GitHub issue о зависании resume большой headless-сессии. Это сигналы риска, не SLA и не универсально воспроизводимые дефекты.

## Практический вывод

Наиболее определённо документированы терминальные события у Claude (result) и Codex (turn.completed/turn.failed). У Grok лучше использовать ACP, но предусмотреть таймауты, отмену процесса, сохранение сырых сообщений и resume/retry с идемпотентностью. Для всех вариантов тестируйте поведение на закреплённой версии, включая сбой авторизации, ранний EOF и длительный запуск.
