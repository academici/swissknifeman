# P1 — Пилот и стабилизация

## Phase Context

Пилот выбирается только из P0.2 eligible rows и выполняется на одном проекте. Он
проверяет не наличие отдельных файлов, а parity semantic selection: skills,
plugins/commands и MCP для Claude Code и Codex согласно effective provider config.
При воспроизводимом сбое второй item обязан исправить owning package и повторить
тот же pilot; на следующий проект переходить запрещено.

> **Контракт фазы (contract-first).** Потребляет: P0 carrier, eligibility и acceptance matrix · Производит: один repeatable green pilot или documented blocker · Границы: остальные fleet проекты.

### P1.2 — Исправить и повторить тот же pilot

**Status:** ⬜ Not started
**Intent:** Если P1.1 выявит воспроизводимый automation defect, исправить owning source и повторить именно этот consumer до terminal verdict.
**Why:** Запрос владельца требует fix-forward, а не перехода к следующему проекту с известным failure. RAG:— (repo-grounded: brief/00-brief.md).
**Scope Included:** reproducer/test в owning package, minimal repair, повтор P1.1 acceptance.
**Scope Excluded:** новый pilot, обход fail-closed checks, broad configuration refactor.
**Inputs:** P1.1 finding и concrete diagnostic.
**Files:** owning package files из diagnostic · tests · findings/P1.2-remediation.md.
**Required Reads:** 1) P1.1 finding 2) owning source and tests 3) phases/P1.md.
**Implementation Rules:** Один defect — один test/reproducer — один repair; если repair меняет frozen provider contract, эскалировать план-design. RAG:— (repo-grounded: packages/skiller/lib/skiller/publication.py:571).
**Code Guidance:** Не лечить symptom в consumer; не изменять user-owned bytes. После repair повторить полный P1.1 matrix, не только ранее упавшую строку.
**Validation:** affected package `scripts/validate.sh` · P1.1 validation commands повторно.
**Deliverables:** remediation finding и повторённый pilot verdict; при green — handoff P2.
