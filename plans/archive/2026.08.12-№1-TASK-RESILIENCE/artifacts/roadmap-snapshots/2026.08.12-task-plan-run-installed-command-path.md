# `task:plan-run`: installed command-path projection

## Наблюдение

При двух fresh native-запусках Agelto `2026.08.09-RELEASE-READINESS P6.3` Codex получил
актуальный installed Task plugin, но до product work пытался прочитать
`~/.codex/plugins/cache/swissknifeman/task/0.12.0/packages/task/commands/plan-exec.md`.
Такого файла в installed package нет: `packages/task/commands/plan-exec.md` — monorepo-relative
путь, а в публикации носитель — `<task-package-root>/commands/plan-exec.md`. Запуск завершался
до journal/product mutation.

## Почему это дефект

Нативная команда должна работать в published projection без знания layout исходного monorepo.
Иначе корректный `$ task:plan-run` зависит от случайного cache path и не исполняет план, хотя
проверки canonical marketplace root проходят.

## Требуемое изменение

В Codex adapter/runtime резолвить parent command относительно обнаруженного package root либо
передавать canonical marketplace root как явный параметр. Не склеивать cache root с
`packages/task/...`.

## Приёмка

Добавить fixture установленного Task package без monorepo `packages/`; native `$ task:plan-run`
должен прочитать inheritable `plan-exec` и начать journal. Проверить равенство поведения source,
Codex publication и Claude publication.
