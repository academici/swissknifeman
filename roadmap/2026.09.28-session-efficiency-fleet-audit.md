# Roadmap: эффективность сессий и context economy во fleet

**Статус:** P0/P1 rollout завершён; дальнейшая оптимизация — только по новым receipts.  
**Дата замера:** 2026-09-28, Europe/Volgograd.  
**Граница:** сессии Codeburn за 2026-09-26—2026-09-28 включительно; provider-aware
first-turn inventory снят в тот же день. Это не доказательство экономии после
изменений и не разрешение на массовое удаление MCP/скиллов.

## Вердикт

Resident-слой Codex у проверенных проектов в целом умеренный: CoreX — 4 004
токена, ERP SDK — 3 320, Chatom — 5 569, Edufy — 3 082, Loqum — 5 306 и
Swiss Knife Man — 3 433 после rollout. Главная подтверждённая причина тяжёлых окон — не этот
слой, а накопленные `exec` results: в двух проверенных сессиях они занимали
100 200/144 358 (69%) и 109 893/149 598 (73%) effective tokens.

### P0 receipt — 2026-09-28

Проверены все 23 зарегистрированных проекта через provider-observed
`skiller budget --first-turn --provider codex`. В каждом `integrity=clean`:
нет duplicate skill names, локальная policy совпадает с effective native
inventory. SKM снижен с 4 693 до 3 433 токенов, Vaulter — с 7 581 до 4 006.

Сделано безопасно и обратимо:

1. `general` выключен как глобальный donor при активном `core`; SKM также
   исключает эту конфликтную пару при любом новом `connect` (для полного
   `general` нужен явный `--no-core`).
2. Шесть зарегистрированных roots получили Codex `trust_level = "trusted"`,
   поэтому их project `.codex/config.toml` действительно участвует в native
   discovery.
3. Legacy `.agents/skills` carriers архивированы только в
   `.swissknifeman/backups/` после проверки native replacement. Новый
   `--cleanup-codex-equivalent-links` удаляет лишь симлинки с идентичным
   runtime-содержимым и сохраняет исходные `.ai/skills` и provenance.

Бывшие budget-outliers устранены без удаления исходных правил:

| Проект | First-turn | Причина | Следующее действие |
|:--|--:|:--|:--|
| CMS | 4 819 (OK) | `AGENTS.md`: 14 033 → 252 токена; 0 duplicates | Короткий entrypoint + on-demand `.ai/`/`docs/`; мониторить только новые receipts. |
| Sova | 5 328 (OK) | `AGENTS.md`: 20 412 → 293 токена; 0 duplicates | Короткий Ticket-flow entrypoint + on-demand workflow/docs; мониторить только новые receipts. |

Laravel Boost в обоих проектах больше не инжектирует весь `guidelines` bundle
на каждый turn (`guidelines=false`). Детальные правила остаются в `.ai/` и
`docs/`; entrypoint содержит только gates и routing. Повреждённый старый Boost
marker не редактировался вручную: generated files пересобраны после отключения
blanket-injection.

|:--|--:|:--|:--|
| Vaulter | 7 581 | 131 entries / 121 unique; 10 duplicate skill names | исправлено: 4 006, 0 duplicates |

`skiller` также выводит общий target/warn first-turn `≤16K`/`>23K`, тогда как
экосистемное правило для **always-on injection** — target 3–7K и warn 10K.
Это разные величины, но их названия сейчас недостаточно различены: итог `OK`
не должен скрывать resident-дубли. Сначала нужен единый контракт метрик, а не
произвольное ужесточение существующего гейта.

## Сырым данным — правильный вес

Codeburn `0.9.25` за границу аудита увидел 202 sessions, 14 743 calls,
43 615 996 input tokens, 7 704 977 output tokens и ~$968.24. `cacheReadTokens`
(1.76B) не является уникальным prompt-контекстом и не складывается с resident
budget. Крупнейшие потоки по input: ERP SDK — 11.29M, Chatom — 9.31M, Edufy —
8.70M, CoreX — 7.00M, Vaulter — 4.72M.

Проверка `codeburn context --full` даёт причину, недоступную только по cost:

| Сессия | Контекст | Compactions | Tool results | Вывод |
|:--|--:|--:|--:|:--|
| ERP SDK `01a0d656-…` | 149 598 | 0 | 109 893 (73%) | широкие результаты `exec` надо ограничивать/сворачивать |
| Vaulter `01a0e8f5-…` | 144 358 | 0 | 100 200 (69%) | делегирование не заменяет контроль output payload |
| CoreX `01a0e386-…` | 32 288 | 3 | 11 989 (37%) | compaction снизила рабочее окно; resident system 5 355 |

Codeburn оценивает health как `D/48` и называет 84 sessions «possibly
low-worth», но это только сигнал для ревью: plan/design/research-сессии нередко
создают проверяемый carrier без edit turn или `git` delivery command. Две
Cursor-agent transcript'а он не распарсил. Его finding `unused-mcp` тоже не
достаточен для удаления: инструмент считает MCP не вызванными в своём
телеметрическом формате, но CoreX обязан использовать mAInd вручную, а active
plan требует внешнее исследование для зависимых от него решений. `skiller`
измеряет весь набор CoreX MCP всего в 584 токена, а не Codeburn heuristic
«~2000 на сервер».

## Очередь улучшений

### P0 — измеримый discovery и вывод инструментов

1. **Готово:** `skiller budget --first-turn --provider codex --strict` теперь
   завершится ошибкой при duplicate names, policy drift или incomplete native
   inventory; JSON receipt несёт `integrity.status/issues`.
2. **Готово:** устранены коллизии SKM, Vaulter и consumer-проектов через
   project policy, trusted roots и обратимое архивирование только подтверждённых
   legacy carriers; canonical skills остаются доступными через native plugins.
3. Закрепить Codex output discipline как короткую процедурную инструкцию,
   не always-on prose: сначала symbols/`rg`, затем узкий диапазон; JSON и логи
   проецировать через `jq`; один tool result держать в пределах уже включённого
   machine-local cap 15K, исключения — только с причиной в carrier.
4. Ввести добровольный checkpoint для длинной задачи: при ~50% окна или когда
   results инструмента преобладают над задачей — записать source-linked
   `active-handoff` и продолжить свежую сессию с goal, релевантными файлами и
   последним failing output. Это не автоперезапуск и не повод дробить один
   связный implementation batch.

### P1 — профили, агенты и достоверная эффективность

1. Сравнить на matched tasks Codex base-profile с research/graph-profile:
   `maind`, Serena/codegraph и Perplexity остаются доступны, но не должны быть
   globally removed по эвристике Codeburn. Принять профиль только если его
   provider-observed first-turn и задача не теряют нужный инструмент.
2. Не добавлять subagents по умолчанию. Делегировать лишь независимую ветку
   или обязательный независимый review; измерять parent + child как один work
   unit. Codeburn сейчас не даёт такого разреза для Codex, поэтому сначала
   добавить correlation в run-report/Task, затем делать claims об экономии.
3. Пометить в Task/receipts тип доказуемого результата (`code`, `plan`,
   `research`, `review`), чтобы «low-worth» от Codeburn был очередью ручной
   проверки, а не proxy для отсутствия ценности.
4. Исправить parser coverage для двух текущих Cursor transcript formats и
   добавить в weekly report явный `parsed/skipped` denominator.

## Безопасный fleet rollout

1. **Завершено — SKM + Vaulter.** Before/after receipts дали 0 duplicates и
   clean integrity; изменение закреплено в CLI и тестах.
2. **Завершено — consumer fleet.** Применены только project-local selection,
   explicit trust для зарегистрированных roots и backup-first cleanup. Не было
   blanket MCP removal или удаления исходных skill trees.
3. **Завершено — CMS + Sova.** Переведены на краткие entrypoints и on-demand
   references; strict Codex receipts: CMS 4 819, Sova 5 328, integrity clean.

## Проверка результата

Для каждого пилота сохранить команды, точный provider/model, диапазон сессий и
raw receipts. Успех требует одновременно: no duplicate names, first-turn в
объявленном типе бюджета, сохранённые нужные capability, delivery carrier и
отсутствие роста matched-task context/tool-result доли. Токеновая экономия
заявляется только по provider telemetry до/после; иначе вывод формулируется
как структурное улучшение без числового savings claim.
