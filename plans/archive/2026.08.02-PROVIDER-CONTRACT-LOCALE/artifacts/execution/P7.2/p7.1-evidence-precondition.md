# P7.2 prerequisite — P7.1 evidence exact-set failure

## Observation

The required P7.1 evidence verification was run before any P7.2 regression mutation:

```text
python3 plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/artifacts/P7.1/evidence/verify.py \
  --bundle-root plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/artifacts/P7.1/evidence \
  --manifest plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/artifacts/P7.1/evidence/manifest.json
```

It exited non-zero with:

```text
P7.1 evidence verifier: bundle members are not exact
```

`manifest.json` declares exactly six evidence members. The directory additionally contains
`route-p71-owner-decision.json`, while the verifier excludes only `manifest.json` and
`verify.py`. Therefore the P7.1 bundle is not byte-valid as required by P7.2 Validation.

## Classification

`local-repair` for the owning producer, P7.1. This is a deterministic package-artifact
topology defect, not a provider/fleet result and not an authority boundary.

## Required continuation

Repair P7.1 forward: keep the frozen six-member evidence bundle exact and retain route-decision
provenance outside that exact-set directory (or regenerate the producer through its owning
contract if that contract legitimately changes). Re-run the P7.1 verifier and only then resume
P7.2. P7.2 must not relax the verifier, alter the frozen P7.1 manifest, or treat the failed
carrier as green.
