# Вендоренные скиллы: доверие, аудит, триаж

Страница про **процедуру доверия** к внешним скиллам, а не про механику синка.
Механика — [Upstream-sync](./upstream-sync.md); раздача физических копий в проект —
[Скиллы из пакетов](./vendor-skills.md).

## Несущее правило

::: danger no findings ≠ safe
Триаж-ступень `update-upstreams.sh --check` — **паттерновый скан, а не граница доверия**.
Пустой результат не означает, что бандл безопасен.

- Первопартийного сканера скиллов Anthropic **не поставляет**; её предписание —
  «thoroughly audit it before use», то есть **человеческое чтение всех файлов бандла**
  ([Anthropic Engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)).
- CSA по данным Trail of Bits (2026-06) обошли ClawHub, Cisco и skills.sh простыми приёмами —
  whitespace inflation, precompiled bytecode hiding, archive indirection, prompt-style social
  engineering для LLM-ступени; вывод дословно **«Don't outsource trust to a scanner»**
  ([CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-agent-skill-scanner-bypass-20260610-csa/)).

Отсюда конструкция: **человеческий аудит — граница, триаж — ускоритель повторного прохода.**
Фраза «скан зелёный, значит безопасно» в отчётах и коммитах запрещена.
:::

## Что делает `--check`

Две независимые вещи, у каждой свой код выхода:

| Что | Событие | Код выхода |
|:--|:--|--:|
| Сверка целостности | апстрим/локальная копия разошлись | `10` |
| **Триаж содержимого** | в файлах бандла найден подозрительный паттерн | **`11`** |
| Сбой сети | не скачался хотя бы один файл | `2` |
| Всё чисто | — | `0` |

Коды **намеренно не слиты**: «апстрим изменился» и «в бандле подозрительный паттерн» — разные
события, и оператор обязан их различать. Код один скаляр, поэтому старший гасит младший
(`2 > 10 > 11 > 0`); полная картина **всегда** есть в `--json` (ключи `triage`,
`stale_verdicts`, `triage_disclaimer`).

```bash
# человеку
bash packages/skiller/scripts/update-upstreams.sh --check

# машине (JSON в stdout, человеческий отчёт в stderr)
bash packages/skiller/scripts/update-upstreams.sh --check --json | python3 -m json.tool
```

## Четыре класса угрозы

Правила стдлиб-регулярные, по одному-двум на класс; каждое несёт в коде комментарий «какой
класс ловит». Правило без названного класса в набор не добавляется.

| Класс | Правила | Что ищем |
|:--|:--|:--|
| **prompt injection** | `INJ_IGNORE`, `INJ_DISREGARD`, `INJ_HIDE_FROM_USER`, `INJ_ROLE_OVERRIDE`, `INJ_INVISIBLE_CHAR` | инструкция-перехват в прозе/комментарии/фенсе, подмена роли, невидимые символы |
| **data exfiltration** | `EXF_SUSPECT_HOST`, `EXF_CRED_TO_NET`, `EXF_ENV_DUMP` | эфемерные приёмники (`webhook.site`, ngrok, pastebin), чтение секрета вместе с сетевым вызовом, дамп env |
| **malicious code execution** | `EXE_PIPE_TO_SHELL`, `EXE_B64_EXEC`, `EXE_OBFUSC_BLOB` | `curl … \| bash`, исполнение base64, длинные base64-блобы |
| **over-permissive tool use** | `PRM_TOOL_WILDCARD`, `PRM_PERMISSION_BYPASS`, `PRM_REMOTE_INSTRUCTIONS` | wildcard в `allowed-tools`, обход разрешений, **инструкции, подтягиваемые из сети** |

Плюс `BIN_UNREADABLE`: файл, не прочитанный как UTF-8, попадает в находки — «не смогли
прочитать» и «чисто» это не одно и то же.

**Чего в ступени нет и не будет.** YARA — внешняя зависимость (запрещена
`root.engineering-invariants`). LLM-as-judge — прямо названа CSA обходимой через social
engineering. IOC-листы — публичного списка именно по Agent Skills не существует, заявлять
«IOC-скан» без списка было бы самообманом.

## Носитель вердикта: блок `audit` в `upstream.json`

Вердикт человека — не строка в отчёте, а **машинно читаемая запись рядом с бандлом**:
плановый файл смертен, скилл раздаётся дальше. Блок аддитивный, лежит в `upstream.json`:

```json
"audit": {
  "verdict": "clean",
  "at": "2026-08-01",
  "by": "2026.07.31-SKM-LEAN P5.1",
  "upstream_sha": "bb30f388386f647ddfd3e8e7cf8c69826ac59bbefe6b11403e5a498c09f1d2d7",
  "note": "обязателен при attention/risk — что именно, одной строкой"
}
```

| Поле | Что значит | Гейт `validate.sh` |
|:--|:--|:--|
| `verdict` | `clean` · `attention` · `risk` | вне enum → ERROR |
| `at` | дата ЧТЕНИЯ бандла (не дата правки файла) | не `YYYY-MM-DD` → ERROR |
| `by` | адрес читавшего: `<PLAN-ID> <item>` либо дата ручного чтения | пусто → ERROR |
| `upstream_sha` | якорь: байты, ПРОТИВ которых вынесен вердикт | не sha256 → ERROR |
| `note` | суть находки одной строкой | нет при `attention`/`risk` → ERROR |

**Блок ставит тот, кто ПРОЧИТАЛ бандл**, а не тот, кто его привёз: запись без адреса
(`by`) ничего не значит, а `clean`, проставленный «по списку каталогов», превращает аудит
в фикцию. Молчаливый `attention` неотличим от опечатки — поэтому `note` обязателен машинно.

**Якорь `upstream_sha`** описывает те самые байты, что читал человек: `sha256` **названного
тела** (`body_path`), когда бандл его называет, иначе — свёртку всей провенансной базы (пары
`path:sha256` из `files[]`/`origins[]`, та же конструкция, что `audited_at`). Хранится он
ОТДЕЛЬНО от `files[].sha256` и не обновляется ни `--apply`, ни `--resolve` — в этом вся его
ценность (см. ниже).

## Гейт: `AUDIT_MISSING` и `AUDIT_STALE`

`--check` различает **три разных события** — и не сливает их, как не слиты коды `10` и `11`:

| Находка | Что означает | Что делать |
|:--|:--|:--|
| дрейф (`10`) | апстрим сдвинулся относительно записанного `sha256` | перенести/принять изменения апстрима |
| `AUDIT_MISSING` | блока `audit` нет — бандл не читал никто | прочитать бандл целиком и записать вердикт |
| `AUDIT_STALE` | `audit.upstream_sha` разошёлся с якорем | перечитать бандл и обновить блок `audit` |

Обе находки идут в общий канал триажа: код выхода **`11`**, ключ `triage` в `--json`.
«Не проверяли» и «чисто» перестают быть неразличимыми — это и есть исполнимая форма правила
**«вендоренья без аудита не бывает»**.

::: tip Почему якорь собственный, а не производный
Раньше протухание вердикта было ПРОИЗВОДНЫМ: «байты разошлись с `audited_at`» выводилось из
дрейфа относительно `files[].sha256`. После `--apply` свежий sha записывался, дрейф исчезал —
и отметка вместе с ним, хотя человеческий вердикт остался протухшим. Собственный якорь
`audit.upstream_sha` `--apply` не трогает, поэтому `AUDIT_STALE` **переживает** применение
апстрима (тест `test_apply_refreshes_files_sha_but_audit_stale_survives`).
:::

Производная отметка `stale_verdicts` осталась ровно для бандлов **без** блока `audit` (то
есть для тех, кого ловит `AUDIT_MISSING`), и печатается различимо — два источника одной
отметки не путаются:

```
[stale]    <бандл>   (verdict)   байты разошлись с audited_at — человеческий вердикт бандла
                                 ПРОТУХ … (производная отметка: блока audit у бандла нет)
```

Скрипт по-прежнему **не читает файлов плана**: вердикт живёт рядом со скиллом, связи
«скрипт `skiller` читает `plans/**`» нет.

## Граница ремедиации: что чинится, а что принимается

Триаж находит больше, чем подлежит починке, и это названная граница, а не «руки не дошли»:

> **Ремедиируется то, что попадает к агенту как ПРАВИЛА ПОВЕДЕНИЯ. Не ремедиируется то, что
> попадает как справка или как артефакт пользователя.**

- **правила поведения** (скилл предписывает сходить в сеть и применить полученное как
  инструкции и формат вывода) → ремедиация: вендоринг payload под `sha256` + `strategy: fork`,
  сетевой канал снимается (см. ниже, «Пиновка и пере-пиновка»);
- **справочная документация** (WebFetch README чужого SDK с ветки `main`) — тот же класс
  непиновки, но payload агент читает как **справку**; форк официального бандла ради пиновки
  doc-URL непропорционален. Принятый класс, находка остаётся видимой;
- **сторонний код в артефакте ПОЛЬЗОВАТЕЛЯ** (CDN в шаблоне генерируемого отчёта) исполняется
  в его браузере — вне контура доверия агента и вне контура `skiller`. Принятый класс;
- **корпус атакующих строк по назначению** (скилл-справочник по безопасности) — постоянная
  краснота триажа есть **свойство** гейта, а не дефект: ослаблять правило под этот бандл
  запрещено.

Принятый класс записывается вердиктом `attention` + `note` в блоке `audit` бандла — то есть
остаётся видимым, а не исчезает из поля зрения.

## `kind: "reference-only"` — бандл, который ничего не вендорит

Признак машинный: **все** `files[].path` пусты, то есть записи — провенанс-ССЫЛКИ на внешние
спеки, а тело скилла написано у нас. Такой бандл обязан объявить `kind: "reference-only"`
(`validate.sh` требует этого в обе стороны), и у него `audit.upstream_sha` **опущен** —
якорить нечего, зеркал нет. Гейт наличия якоря от него не требует: иначе правило начало бы
врать на классе, ради честности которого заведено. `--check` печатает такие бандлы отдельно
(`reference_only` в `--json`), потому что знаменатель «N вендоренных бандлов» иначе неоднороден.

## Процедура вендоренья нового скилла

1. **Прочитать бандл целиком** — все файлы: `SKILL.md`/`body_path`, `references/**`,
   `snippets/**`, скрипты, ресурсы. Особое внимание: скрипты, зависимости, любые обращения к
   внешним сетевым источникам, а также «unusual patterns» — вызовы и операции, не отвечающие
   заявленному назначению скилла.
2. **Вынести поимённый вердикт**: `clean` / `attention: <что именно>` / `risk: <что именно>`.
3. **Записать провенанс** — `upstream.json` рядом со `SKILL.md` (`root.reference-provenance`),
   источник паттернов, если что-то взято как паттерн, — в `docs/reference.md`. **Там же —
   блок `audit`** с вердиктом шага 2, адресом читавшего и якорем `upstream_sha`; без него
   `--check` даёт `AUDIT_MISSING` и бандл не считается проверенным.
4. **Прогнать `--check`** и разобрать каждое срабатывание триажа: либо это находка, либо
   объяснённое исключение. Ослаблять правило, «чтобы стало зелено», запрещено.
5. **Находку класса `risk` не чинить самовольно** — назвать поимённо и эскалировать владельцу.

**Обновление вердикта** (после `AUDIT_STALE` или планового перечтения): перечитать бандл →
обновить `verdict`/`note` → поставить сегодняшнюю `at` и свой адрес в `by` → пересчитать
`upstream_sha` по текущей провенансной базе (или `sha256` `body_path`). Порядок обязателен:
`--check` **до** `--apply`, иначе перечитывать придётся уже другие байты.

## Известные срабатывания и границы

- **Скилл-справочник по безопасности будет гореть всегда.** Корпус атакующих строк — его
  содержание; правило под него не ослаблялось. Следствие: «зелёный триаж по всему реестру»
  недостижим по конструкции.
- **Механизма подавления/allowlist нет.** Он и есть решение о политике доверия (что считать
  принятым исключением) — предмет решения владельца, а не скрипта.
- **Правила англоязычные.** RU-ветка есть только у `PRM_REMOTE_INSTRUCTIONS`, потому что рядом
  locale-копии не являются registry canon. Остальные правила на переводах не
  покрыты — известная граница.
- **Скан не покрывает то, что тянется в рантайме.** Если скилл предписывает сходить в сеть за
  правилами, sha256 бандла эту поверхность не описывает. `PRM_REMOTE_INSTRUCTIONS` такой скилл
  находит, но проверить содержимое по ссылке может только человек.

## Провенанс-запись без зеркала

`files[]`-запись с пустым `path` — **ссылка на внешнюю спеку**, а не локальное зеркало: чужой
код не вендорился, сверять по sha нечего. `--check` печатает такую запись отдельным тегом и
идёт дальше:

```
[ref]      <бандл>   (no mirror)   reference-only provenance, sha не сверяется: <url>
```

Считать такой бандл «вендоренным» нельзя: целостность его содержимого не покрыта ничем.

## Пиновка и пере-пиновка внешнего payload

Когда бандл несёт правила поведения из ВТОРОГО апстрима (не самого скилла, а контента,
который скилл раньше тянул сетью и применял как инструкции — класс `PRM_REMOTE_INSTRUCTIONS`),
непиновка URL на ветку недостаточна: подмену содержимого ветка не ловит, а удаление/приватизация
чужого репозитория ломает скилл молча, и в обоих случаях целостность остаётся ВНЕШНЕЙ гарантией.
Закрытие — `strategy: fork` + payload вендорится pristine-копией в `references/` под sha256,
скачанной строго по **SHA-URL** (`.../<40-символьный commit SHA>/...`), никогда по `/main/`.
Пример — `frontend/web-design-guidelines`, где `references/web-interface-guidelines.md`
(`body_path`) зеркалит `vercel-labs/web-interface-guidelines` на пинованном коммите.

**Апстримное тело, которое САМО несёт инструкционный паттерн, зеркалом не вендорится (D111).**
Если бы обёртка апстрима (например, чужой `SKILL.md`) была скопирована в `references/`
pristine-копией, эта копия уехала бы вместе со скиллом в каждый проект флота и продолжала бы
нести ту же снимаемую инструкцию — ремедиация была бы формальной, а не действительной. Поэтому
провенанс такой обёртки остаётся ТОЛЬКО машинно читаемой записью `files[]` с пустым `path`
(см. выше, «reference-only provenance») — без локальной копии её содержимого; `sha не сверяется`
для неё сознательно, а не по недосмотру. Правило триажа (`PRM_REMOTE_INSTRUCTIONS` и весь скан)
не получает исключений для `body_path`/`references/**`/fork-зеркал ни под одну ремедиацию —
файл бандла раздаётся по флоту и читается агентом по ссылке, поэтому «это всего лишь зеркало»
риск не снижает (D112).

Процедура пере-пиновки — РУЧНАЯ, `--apply` реестра payload не трогает:

1. скачать новый SHA-URL нового коммита;
2. сверить sha256 полученных байт с ожидаемым значением ДО записи — расхождение либо
   означает не тот SHA, либо подмену, и в обоих случаях константа не переписывается «чтобы
   сошлось» (анти-подгонка);
3. обновить соответствующую запись `files[]` (`sha256`, `fetched_at`) и `notes` тем же
   коммитом, что и сам факт пере-пиновки.

Свежесть здесь сознательно обменяна на целостность: вендоренный payload не следует за
апстримом автоматически, окно устаревания закрывается только явной пере-пиновкой.
