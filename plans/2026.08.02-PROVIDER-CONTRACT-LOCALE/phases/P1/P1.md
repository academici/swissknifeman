# P1 — Freeze provider-neutral control-plane, Skill Core, and adapter contracts

## Phase Context

P1 freezes the contract that turns existing provider selection, capability, artifact and
adapter evidence into one deterministic control-plane view without creating a second source
of truth. The frozen predecessor contracts remain authoritative: provider config owns desired
selection, the capability manifest owns support, artifact locks own managed provenance, and
each adapter owns only its projection and observed status. P1 execution consumed the committed
terminal P0 outputs and frozen recovery gates; no uncommitted P0 claim was accepted. The three
items were executed sequentially: P1.2 consumed the schema from P1.1, and P1.3 consumed both that
schema and the ownership matrix.

P1.2 also freezes the minimum provider-neutral Skill Core and the additive provider adapter seam.
Canonical skill meaning contains no Claude/Codex control field. Discovery, invocation, target
layout, measurement and replay are provider-owned mappings. The contract includes a third-provider
fixture so extensibility is proven by addition rather than a future cross-cutting rewrite.

**Scope Included:** provider-neutral desired/last-applied/observed/drift schema; minimum Skill Core;
per-provider status and aggregate rules; capability negotiation; provider descriptor/renderer/
invocation/meter/replay seams; exact canonical/adapter/target/status ownership; third-provider
registration fixture; recognized legacy upgrade, backup, rollback and no-write gates; normative
goldens, checker and Owner freeze.

**Scope Excluded:** package implementation; provider target writes; fleet or Brain migration; locale fields/rendering (P2); rewriting archived contracts; inferring trust, approval or sandbox from another security axis; credential material.
