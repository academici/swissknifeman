# P5 — Run measured pilots and prove product readiness

## Phase Context

P5 turns the terminal P4-assured G2 `packages/artifex` product into measured evidence without letting it choose tasks,
baselines or verdict rules after seeing results. It freezes archive mappings and all live trials,
obtains an exact owner grant over the hashed business request, materializes every per-trial
manifest/replay/admission before provider dispatch, then runs a reversible three-slice repository
pilot, a controlled recovery/provider-failure pilot and exactly five paired battle waves.

**Scope Included:** candidate-independent trial catalog and shadow replay; controlled disposable
repository pilots; exact owner-approved business grants and per-trial admissions; real fresh provider workers under frozen authority; crash/resume/duplicate/failure
evidence; matched manual/delegated/`harness run` baselines; normalized economy/intervention metrics;
independent release-readiness adjudication whose RED result keeps the item open for forward repair.

**Scope Excluded:** P0–P4 execution shortcuts; owner dirty-tree/business/fleet/Brain/package/root-CLI/
generated/docs/release mutation; archive edits or imports; raw prompts/transcripts/thinking/tool payloads/
environment values; credential/quota manipulation; post-hoc task/baseline/threshold replacement;
productization or release.

> **Контракт фазы (contract-first).** Потребляет: terminal exact-green admission-aware P4 G2 assurance over the P3.8 package lineage and exact current package file/hash set, frozen P0 baseline/rubric, terminal P1 six-contract set and P3 smoke carriers only as negative lineage · Производит: frozen trial/shadow evidence, owner-hash-bound business grants, deterministic per-trial manifest/replay/admission index, reversible three-slice/recovery pilots, five paired battle waves and independent G3 `GO` (release-ready) evidence over unchanged G2 bytes for mandatory P6 · Границы: controlled disposable repositories and minimized evidence only; P3 smoke authority is never business authority; P5 cannot mutate G2/archive/product-source/package/fleet/Brain/release state; `NO-GO` keeps P5.4 and the plan non-terminal.

Items execute strictly P5.1→P5.4 through individual plan carriers: every item consumes the previous
artifact, while the autonomous chain inside the pilot is the candidate under measurement, not a
second plan scheduler. RAG:— (repo-grounded: `research/11-p5-pilot-economics-design.md`).

Generation rule (D89): before every candidate call, recompute the current `packages/artifex`
file/hash set and standalone CLI identity from terminal P4.5 G2 assurance. Any drift, extra package
row or fallback to historical G1 refuses before intent. P5 owns evidence only and never refreshes
G1/G2 or writes package bytes; P5.4 G3 pins the exact G2 digest it measured. RAG:—
(repo-grounded: `research/28-early-package-cross-phase-finish.md`).

Last-pass cadence (D105–D106): historical leaf validators run only on their owning Git snapshots;
current successor/provenance/G2 gates run on the current tree. P5.1→P5.4 execute sequentially with
no intermediate design/audit checkpoint, and P5.4 performs the single consolidated phase fan-in
before P5 close/audit. A real safety/authority/frozen-contract/acceptance refusal remains
fail-closed. RAG:— (owner-grounded: `brief/22-p5-last-pass-fast-track.md`; repo-grounded:
`research/33-p5-last-pass-generation-gate.md`).
