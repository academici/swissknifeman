# P6 — Decide product home, integrate, and operationalize

## Phase Context

P6 starts only after terminal P5 and treats its independently recomputed GO/NO-GO as data, not
as authorization to mutate package topology. It first freezes one product-home decision and exact
file inventory. A NO-GO returns the concept to roadmap with no live runtime; a GO may reuse `task`
or `harness` only when closed ownership predicates hold, otherwise a new `artifex` package needs an
exact Owner D# and root routing remains a separate approval axis.

**Scope Included:** terminal P5 verdict verification; package/CLI ownership decision; exact
integration inventory; approved code migration or roadmap return; opt-in compatibility,
operations, rollback and docs; cold independent release-candidate or NO-GO audit.

**Scope Excluded:** changing P5 evidence/thresholds; embedding an independent scheduler into an
unrelated package to avoid approval; automatic fleet/Brain/project rollout; always-on context;
raw run-data publication; tag, push, publish or release; root router, package count or public
default changes without the exact Owner D# named by P6.1.

> **Контракт фазы (contract-first).** Потребляет: terminal P5 GO/NO-GO, P0–P5 manifests and the P4-assured candidate · Производит: one validated home decision, approved integration or roadmap return, opt-in compatibility/operations/rollback evidence and a cold audit · Границы: no live mutation before terminal P6.1; no package/root-router/fleet/default/release expansion without exact authority.

Items execute strictly P6.1→P6.4. No workflow is declared: each item consumes the previous
terminal artifact, P6.1 may stop at an Owner gate, and P6.4 must run in a distinct cold session.
RAG:— (repo-grounded: `research/12-p6-productization-design.md`).
