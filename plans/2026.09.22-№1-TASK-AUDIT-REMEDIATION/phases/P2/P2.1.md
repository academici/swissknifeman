**Implementation Rules:** Preserve CLI compatibility defined by P1; if subcommands are introduced, legacy `check` remains the full final gate and any `block:*` required for that mode returns non-zero. Compile-time Validation evidence is declaration-only; only a runtime receipt bound to contract/spec/tree/environment and successful exit may promote proof class. Derive completed prefix from current plan terminal evidence for both mandatory and recommended branches; receipt fields may bind evidence but never override it. Validate every transported chunk against immutable snapshot member path, member digest, exact contiguous bytes and terminal state, then hash reconstructed bytes. **Code Guidance:** Start each finding with its failing production-entry regression, then implement the smallest shared invariant. CLI test must execute the real module/script and assert process return code plus JSON. Batch tests tamper prefix, plan/spec/routing/handoff identity and exercise both branch policies. Validation tests distinguish declared, executed-success, executed-nonzero and stale-HEAD receipts. CI test parses workflow structure and asserts the authoritative Task job/commands without relying on line text alone.
