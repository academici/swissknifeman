# P5 — Пилот code-review-graph vs Serena

## Phase Context

Фаза отвечает на OQ-1 (Обсуждение §2, D8): подключать ли внешний MCP-граф кода
`tirth8205/code-review-graph` (CRG) как retrieval-слой под ревью, при том что канон графа
кода сегодня — **Serena** (LSP через `uvx`, пиннована `v1.5.3`, включена у 15 из 25 проектов
реестра). Ответ обязан быть **числом на наших репозиториях**, а не пересказом README:
фаза меряет (P5.1) и выносит вердикт с owner-гейтом (P5.2).

**Что разведка этого захода изменила в постановке** (слой 1 — `findings/P5-codegraph-vs-serena-facts.md`;
слой 2 — `research/07-P5-fact-classes.md` карта классов ДО поиска и `research/08-P5-pilot-protocol.md`
протокол):

1. **Премиса «+1 резидентный MCP = +30 схем инструментов» опровергнута first-party.** Tool
   search в Claude Code включён **по умолчанию**: «Only tool names and server instructions load
   at session start»; описания и server instructions режутся на 2KB. Замер «а» контракта
   остаётся, но как ВЕРХНЯЯ граница (findings §6, D33).
2. **Настоящий always-on риск — не тулы, а установщик.** `code-review-graph install` пишет
   хуки, ставит 7 скиллов и «injects graph-aware instructions into your platform rules»
   (findings §2). Это ровно тот класс, который по рамке репо требует гейта
   `skiller budget --first-turn`, — поэтому в пилоте он **запрещён** (D36).
3. **Заявка «медиана ~82×» не является ожиданием.** Baseline — «прочитать весь репозиторий»,
   автором же названный «upper bound no real agent pays»; реалистичный `agent_baseline`
   (grep top-3) в репо есть кодом, но **числами не опубликован**; формальный `token_efficiency`
   даёт **<1.0×** на мелких коммитах (findings §3, D33).
4. **Вариант «adopt вместо Serena» снят фактами до пилота.** Автор CRG: «LSP is more precise
   per symbol», «if you want symbol-precise *editing* tools, Serena's LSP approach is a better
   fit»; F1 0.714 при **круговом** recall, co-change-числа не опубликованы (findings §4).
   Остаются **combine** и **skip** (D34).
5. **Механика замера уже существует в репо**: `claude -p --output-format json` + `usage`
   (`packages/skiller/lib/skiller/quality/eval.py:311-333`), плюс `--mcp-config` /
   `--strict-mcp-config` для чистых рук (сверено `claude --help`).

**Что добавила сверка состояния флота 2026-07-25 (D65).** Прежде чем мерить цену ВТОРОГО графа,
выяснилось, что не закрыта гигиена ПЕРВОГО: политика `code_graph.args` в корневом `config.json`
несёт **непиннованный** источник Serena (`git+https://github.com/oraios/serena` без `@v1.5.3`),
хотя `packages/maind/lib/maind/constants.py:60` объявляет пин. Политика перебивает дефолт, поэтому
раскатанные `.mcp.json` **всего флота** ссылаются на плавающий HEAD (проверено на `swissknifeman`,
`flexcrm`, `corex`, `agelto`). Отсюда третий item **P5.3** — гигиена действующего движка, не
относящаяся к вердикту OQ-1 и исполняемая независимо от него.

**Что изменило решение владельца 2026-07-25 (D67/D72).** Разбор показал, что механизм ревью
распадается на четыре слоя, и CRG бьёт только в **L1** (какой контекст видит ревьюер), тогда
как главная боль — **L2** (процедура: какие измерения обязательны) и **L4** (гейт: что
происходит при находке). Они адресуются новой фазой **P9** своими средствами, а не покупкой
внешнего движка. Поэтому P5.1 пересобран: вместо 78 прогонов на двух проектах — **ступень 0
(kill-gate, ~1 час, без агентных прогонов)**: пиннованная установка в `git worktree`-копии
`flexcrm`, `Ops` против порогов D35, `P_impact` против co-change ground truth и ручная сверка
нашего `[UNVERIFIED]` про evidence-gated Laravel. Полный протокол
`research/08-P5-pilot-protocol.md` §3 **не удалён** — он стал описанием **ветки эскалации**
(ступень 1: корзина S + 1 ревью-дифф, 24 прогона), которая запускается только при вердикте
«в пределах» И решении владельца в P5.2. Правило D35, запрет `install` (D36), пиннование
версии, запрет облачных эмбеддингов и read-only дисциплина сохранены дословно.

**Гейты и границы.** Гейтом плана `2026.07.24-AGENT-RELIABILITY` фаза НЕ накрыта — идёт в
параллельном окне D11. Serena не отключается ни на одном проекте до вердикта; CRG не входит
в CORE-раскатку — только opt-in. P5.2 правит **тело** скилла `general/mcp-advisor`, но не его
`description` — тот в ведении P3.1 (burn-down, D38). P5.3 не чинит провайдерский контур
(`unmanaged-target`) — только фиксирует его адресом и выносит владельцу (D65).

### P5.1 — Ступень 0 (kill-gate): установка + Ops + precision impact

**Status:** ⬜ Not started
**Intent:** Ответить на вопрос «стоит ли вообще мерить CRG дальше» **за ~1 час и без единого
агентного прогона**. Ступень 0 — kill-gate: пиннованная изолированная установка CRG
(`pipx`/`uvx`, БЕЗ `code-review-graph install` — D36) в `git worktree`-копии `flexcrm`, замер
**Ops** (полный build и инкремент после правки одного файла) против порогов D35, замер
**`P_impact`** (precision blast-radius на 3 реальных коммитах против co-change ground truth —
честного режима, который автор сам называет ожидаемо более низким) и ручная сверка
**`L_evidence`** — нашего собственного `[UNVERIFIED]` про «evidence-gated» Laravel-семантику
(фасады · `resolve()` · макросы · Eloquent-связь · Blade-инклюд). Вердикт — по числовому
правилу ниже: сорванный порог ⇒ **`skip` уходит в P5.2 без дальнейших замеров**; всё в
пределах ⇒ **ступень 1** (24 прогона) как ВЕТКА ЭСКАЛАЦИИ, а не дефолт.
**Why:** Владелец 2026-07-25 переопределил цену вопроса: главная боль ревью — **не L1**
(какой контекст видит ревьюер, куда бил CRG), а **L2/L4** — процедура и гейт, и они
адресуются фазой **P9** своими средствами, а не покупкой внешнего движка (RAG:— owner-grounded:
решение 2026-07-25, D67; синтез — `research/18-P9-target-design.md` §1). Поэтому 78 прогонов
на двух живых проектах перестали быть пропорциональны вопросу: это цена полноценного
сравнения там, где сначала надо проверить, проходит ли кандидат вообще. Все публичные числа
CRG остаются дисквалифицированными их же автором: «The whole-corpus baseline above is an upper
bound no real agent pays», реалистичный `agent_baseline` «not quoted before being measured»,
формальный `token_efficiency` даёт ratio **<1.0×** на мелких коммитах (RAG:✅ 2026-07-25 raw
README + `docs/REPRODUCING.md` → `findings/P5-codegraph-vs-serena-facts.md` §3). Точность
против LSP тоже не в пользу «просто подключить»: F1 0.714 при recall 1.0, который автор
называет **круговым по построению** («derived from the same graph the predictor traverses»),
честные co-change-числа в коде есть, но не опубликованы, и ожидание автора — «expect those
numbers to be substantially lower»; MRR поиска 0.35, flow detection 33% (RAG:✅ там же §4).
Именно поэтому ступень 0 меряет co-change-precision, а не заявленный F1: круговую метрику
D34 уже дисквалифицировал. Отдельно проверяется наш собственный вывод, честно помеченный
`[UNVERIFIED]`: слово «evidence-gated» у автора означает включение Laravel-семантики только
при доказуемых признаках фреймворка, и динамическая магия (фасады, `resolve()`, макросы) под
это описание не подпадает — «это вывод из формулировки, не утверждение автора» (RAG:✅
2026-07-25 README § Features → `findings` §5). Проверить его дешевле ручной сверкой, чем
агентными прогонами, и именно он определяет, есть ли у графа предмет на нашем самом массовом
классе флота.
