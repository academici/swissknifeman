## Defect class

The P2 validator has two roles coupled into one current-tree comparison: it proves the terminal P2
snapshot at P2 closure, but later P3 acceptance treats it as if P2-owned source bytes must never be
extended by a declared successor. Regenerating the P2 manifest would destroy the earlier snapshot;
forbidding the P3 edit would contradict D39/D74 and P3.4 Files. Treating the predictable failure as
green would falsify validation. RAG:— (repo-grounded: P2.6/P3.4 specifications and D39/D74).

## Required design boundary

Keep the P2 manifest and validator byte-stable as historical evidence. P3.4 must produce an additive
adapter manifest that pins the P2 manifest hash and terminal commit, verifies the P2 file hashes
against that Git snapshot, and separately hashes the current P3 implementation/evidence bytes. The
P3 validator, not a regenerated P2 carrier, owns the cross-generation proof.
