## §1. Измерение: что именно горит на бандле сейчас

Команда (read-only, файлов не пишет):


Вывод (собственный прогон 2026-08-01, дословно по существу):

Три факта из одного прогона:

3. **Апстрим antfu на `main` НЕ дрейфовал** — запись `references/source.md` (`sha256`
   `f4647ca8…`) тоже `up-to-date`.

## §2. Почему зеркало горит: это тот же текст, что снимался

`references/source.md` — байт-в-байт копия ПРЕЖНЕГО `SKILL.md` бандла (апстрим antfu). Её
содержимое несёт дословно:

- `Fetch the latest guidelines from the source URL below`;
- `Fetch fresh guidelines before each review:` + голый URL на ветку `main` того же репозитория;
- `Use WebFetch to retrieve the latest rules. The fetched content contains all the rules and
  output format instructions.`

Правило `PRM_REMOTE_INSTRUCTIONS` (`packages/skiller/scripts/update-upstreams.sh:305–322`)
ловит ровно эти две формы («fetch … latest/fresh … guidelines/rules» и «fetched content
contains all the rules»). То есть зеркало — не «похожий текст», а **буквально тот носитель
инструкции, ради снятия которого заведён item**.

## §3. Скан бандла исключений не имеет — и это конструкция, а не упущение

`triage_bundle()` (`update-upstreams.sh:324–340`) идёт по `skill_dir.rglob("*")` и пропускает
РОВНО один файл — сам `upstream.json` (`:331`). Ни `references/**`, ни `body_path`, ни
`upstream/*.incoming.md` (куда `--apply` кладёт свежий апстрим форка) исключений не имеют.
Правило дисклеймера в выводе (`triage_disclaimer`) прямо называет границу: «no findings != safe
… Единственная граница — человеческий аудит ВСЕХ файлов бандла».

## §4. Механика `fork`: что реально сверяется, а что — ритуал

- Ветка `fork` (`update-upstreams.sh:477–502`) сравнивает **удалённые байты против записанного
  `sha256`** (`remote_sha == stored`). Локальный файл в сравнении НЕ участвует: `local_sha`
  вычисляется выше по общему коду и в fork-ветке не используется. Следствие: **дрейф апстрима
  отслеживается по `files[].url` + `files[].sha256`, а не по наличию локального зеркала.**
- `--apply` на дрейфе форка кладёт свежий апстрим в `skill_dir/upstream/<name>.incoming.<ext>` и
  ставит `review_pending=true`; зеркало и `SKILL.md` не трогаются.
- `body_path` — **опциональное** поле (`validate.sh:534–566`, комментарий «Аддитивное поле;
  отсутствие = тело в SKILL.md (back-compat)»). Единственное машинное требование: если поле
  есть, его значение обязано присутствовать среди `files[].path`.
- **Живой контрпример к «body_path обязателен»:** образец `packages/skiller/skills/ai/ai-agents/upstream.json`
  (`strategy=fork`, единственная запись `files[]` → `references/source.md`) поля `body_path`
  **не несёт вовсе** и валиден.

## §5. Пустой `files[].path` — поддержанный класс «провенанс-ссылка»

- `validate.sh:520–532`: проверка существования файла выполняется под `if path:` — запись с
  пустым `path` легальна, ключи `path`/`url`/`sha256`/`fetched_at` при этом обязаны
  присутствовать.
- `update-upstreams.sh:413–428`: запись с пустым `path` обрабатывается отдельной веткой с
  явным сообщением `reference-only provenance, sha не сверяется: <url>` и комментарием, что
  раньше `skill_dir / ""` ронял весь прогон `IsADirectoryError`'ом (яма закрыта).
- Живой носитель класса в реестре — `skills/voice-ai/voice-ai` (`findings/P5-vendored-audit.md`
  §3.6).
- **Цена класса названа честно:** у такой записи `sha256` **не сверяется ни с чем** — это
  запись о происхождении, а не гарантия целостности.

## §6. Что из бандла уезжает в проекты флота

`SKILL_IGNORE` (`packages/skiller/lib/skiller/common.py:41–42`) =
`("upstream.json", ".claude-plugin", "SKILL.*.md", "evals", "__pycache__", "*.pyc")`;
единый копир `safe_copy_skill` (`common.py:116–136`) делает `copytree` каталога скилла с этим
ignore-списком, и он общий для канала `vendor` и для `skillset.sync`.

Следствия, важные для вердикта:

1. **`references/**` НЕ исключён — весь каталог уезжает в каждый проект**, куда раздан бандл.
   То есть `references/source.md` — не внутренний артефакт репозитория, а файл, физически
   распространяемый по флоту вместе со скиллом.
2. `upstream.json` в проект **не уезжает** — значит `notes` с процедурой пере-пиновки и
   провенансом доступны только в этом репозитории; всё, что должен видеть агент в проекте,
   обязано лежать в `SKILL.md`.
3. `SKILL.ru.md` в проект не уезжает (перевод — репозиторный носитель для человека).

## §7. Внешний факт: файлы `references/` — часть поверхности поведения, а не инертный архив

**RAG:✅ 2026-08-01 (perplexity-web, запрос «Claude Code Agent Skills 2025–2026: progressive
disclosure, on-demand loading of bundled reference files, prompt-injection surface»).** Вердикт
источников: Agent Skills грузятся прогрессивно — сначала метаданные, затем `SKILL.md`, затем
**дополнительные файлы каталога скилла, когда на них ссылаются или когда они нужны задаче**;
Anthropic прямо предупреждает, что скилл может быть вредоносным, и рекомендует **аудит ВСЕХ
файлов бандла, включая скрипты и прочие ресурсы**, а текст в приложенных файлах способен влиять
на поведение, если агент их прочитает. Оговорка о доверии к источнику: выдача опиралась на
вторичные пересказы документации (dotzlaw, skywork), а не на страницу Anthropic напрямую;
вывод принимается потому, что он совпадает с внутренним репо-фактом — навигатор ЭТОГО бандла
сам предписывает агенту читать файл из `references/` (`SKILL.md:16` рабочего дерева:
«Read the rules from the vendored payload: references/web-interface-guidelines.md»), то есть
чтение файлов `references/` агентом здесь не гипотеза, а проектное поведение бандла.

## §8. `strategy=merge` / `origins[]`: механизм есть, живых потребителей в реестре нет

- Ветка `merge` (`update-upstreams.sh:370–412`) сверяет `sha256` КАЖДОГО `origins[]` **без
  какого-либо локального пути** — то есть технически позволяет держать удалённый источник под
  сверкой, не вендоря его байт.
- При `strategy=merge` массив `files[]` в `--check`/`--apply` **не обрабатывается вовсе**
  (`:413`, `[] if strategy == "merge" else data["files"]`), хотя `validate.sh:515–517`
  по-прежнему требует его непустым.
- `grep -rl '"strategy": "merge"' packages/skiller/skills/` → **ни одного** `upstream.json`;
  совпадения — только проза скилла `repository-bootstrap/skill-authoring`. Живого носителя
  класса в реестре нет.
