## 3. Мысли брифа, которые план сознательно НЕ исполняет (и почему)

1. **«DB-design agent-pack»** и **«агент освежения проекта»** — оба про заведение новых
   ролей. Владелец в том же брифе даёт вердикт «новых ролей не заводим»
   (`project-freshness-agent`). Единый вердикт по классу — **D7**; иначе план в одной фазе
   заводит роль, а в другой запрещает.
2. **«Доменная реструктуризация тел 229 скиллов»** — канон Anthropic подтверждён
   (`RAG §7`), но это работа объёмом с отдельный план; здесь фиксируется как правило
   авторинга и остаётся адресом в `roadmap/` (не «в ноль» — см. D7 о границе).
3. **Массовая перезапись 69 описаний одним батчем** — прямо противоречит собственному
   вердикту репо (`roadmap/skill-description-quality.md`: one-way burn-down, не батчем).
   P3.5 закрывает долг **по бакетам с замером активации**, а не сплошным проходом.

## 4. Coupling-поверхность (файлы/канон, трогаемые ≥2 фазами)

| Поверхность | Фазы | Риск |
|:--|:--|:--|
| `packages/skiller/lib/skiller/budget.py` | P1 (агрегатор), P2 (rules/MCP в счёте), P3 (листинг скиллов) | Три фазы читают один измеритель; менять его семантику вправе только **P1** |
| `roadmap/**` + `roadmap/README.md` | P1, P3, P5, P7 | Главный hotspot: пять фаз удаляют/правят записи одного каталога. Правило — **удаляет запись та фаза, что её закрыла**; P7 сводит остаток и проверяет ноль |
| `packages/harness/configs/common/instructions/**` | P2 (диета), P5.4 (провенанс/видимость) | Обе правят один SSOT инструкций; P2 идёт первой, P5.4 — дописывает |
| `packages/harness/lib/harness/cli.py` | P4 (`run`) | Одна фаза — конфликта нет, зафиксировано ради P6 |
| `core/**` | P6 (переезд), P4 (драйвер импортирует примитивы) | **P6 после P4**: переезд модулей во время написания драйвера ломал бы импорты на лету |
| `packages/task/lib/task/plan_lint.py` | P4.4 (гейт вызывает), P5.9 (`--conflicts`) | P4 только ВЫЗЫВАЕТ линтер, не правит его; правит только P5.9 |
| `docs/rejected-optimizations.md` | P5, P7 | Append-only; конфликта нет |

## 5. Порядок фаз — обоснование

`P1 → P2 → P3` — измеритель обязан существовать до диеты: «до/после» без базы измеримо
не бывает. `P4` независим от P1–P3 (другой пакет, другая поверхность) и потому может идти
параллельно волной, но **до P6** (см. coupling). `P5` независим целиком. `P7` — последний
по определению: он закрывает адреса, которые заводят P1/P3/P5.
