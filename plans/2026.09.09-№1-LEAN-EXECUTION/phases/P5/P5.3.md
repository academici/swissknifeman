### P5.3 — Lifecycle-aware Laravel parallel isolation

**Intent:** Make the canonical Laravel `test-isolation-guard` skill distinguish bootstrap, app-boot, parallel-DB and parallel-filesystem boundaries so every worker proves the exact framework-selected database and an owned local process root before its first write. RAG:— (repo-grounded: `artifacts/source-roadmap/2026.08.14-laravel-parallel-isolation-lifecycle.md`; `packages/skiller/skills/laravel-testing/test-isolation-guard/SKILL.md`).
**Why:** The current serial `createApplication()` plus `_test` suffix guidance cannot prove the token-selected database in parallel mode; the measured field incident showed that enforcing the token too early creates a false lifecycle conflict while relaxing the suffix can expose a non-test DB or shared filesystem. RAG:— (repo-grounded: `artifacts/source-roadmap/2026.08.14-laravel-parallel-isolation-lifecycle.md:10-53`).
**Scope Included:** One lifecycle decision table; canonical serial DB resolver; exact `setUpTestDatabaseBeforeMigrating()` comparison against the observed selected connection; process-scoped local filesystem configuration from `setUpProcess()`; normalized containment/symlink/remote-disk refusals; owned-only teardown; `FRAMEWORK_LIFECYCLE_CONFLICT` stop branch; canonical skill/snippets/index; deterministic PHP/stub lifecycle fixture; Skiller registry/publication regeneration and package/docs qualification.
**Scope Excluded:** Generic Task policy; project-specific database names; suffix/regex proof for parallel correctness; bypassing Laravel framework facilities; `Storage::fake()` as a global safety boundary; remote writable fallback; runtime Composer/npm dependency; writes to a consumer project; external rollout, release, tag or push.

**Implementation Rules:** Keep the serial fail-safe in `createApplication()` but require the exact parallel assertion only in `ParallelTesting::setUpTestDatabaseBeforeMigrating()`, after Laravel selects the worker DB and before migration/PDO writes. The project supplies the canonical serial resolver; observed database and token come only from the callback, never from a guessed `<app>_test_test_<token>` name. Missing seam/token/observed DB is the named `FRAMEWORK_LIFECYCLE_CONFLICT`, never a relaxed allowlist or silent skip. `setUpProcess()` must configure every app-owned writable disk under one normalized process root before use; reject remote drivers, `..`, symlink escape and cleanup outside that root. Preserve serial `RefreshDatabase` safety and keep `Storage::fake()` scoped to behavior tests. RAG:— (repo-grounded: source carrier lifecycle trace and package generator ownership).
**Code Guidance:** Start with the stub lifecycle fixture and assert the order `createApplication → setUpTestDatabaseBeforeMigrating → RefreshDatabase`; no code may special-case the fixture's DB names or token. Add negative cases for prod/dev DB, wrong-token suffix match, missing callback data, remote disk, path traversal and symlink escape, plus two workers with distinct roots and a sentinel outside cleanup. Keep snippets dependency-free and syntax-valid on the repository PHP baseline. Canonical skill/snippets change first; generated registry, graph and provider projections change only through `skiller registry`. Do not weaken an invariant to make a fixture green.
