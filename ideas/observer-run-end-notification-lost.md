# Идея: надёжное уведомление об окончании run — наблюдатель теряет конец и простаивает часами

Статус: идея. Источник: оркестрация PLAN3 (vaulter) B4, 2026-10-17/18. Связано: skill `orch-debug` (шаг «Watch»).

## Что произошло
- B4 (P5.7–P5.9) закончился `run end finished` в 22:20Z. Сессия-наблюдатель обнаружила это в 02:54Z: простой ≈ 4,5 ч,
  следующий шаг (правки ревью → B5) никто не запускал.
- Наблюдатель держал `Monitor` на `tail -F | grep`. Monitor живёт максимум 30 мин и умирает молча («expired, no events»),
  перезапуск зависит от того, что агент проснётся. Между сессионными лимитами/паузами пользователя агент не просыпается.
- `ScheduleWakeup` был поставлен на ожидание квоты, а не как страховка от потери конца run.
- Второй источник простоя — `PROVIDER_QUOTA` (≈3 ч за день): run останавливается «до сброса», резюме снова ручное.

## Почему механизм ненадёжен
1. Уведомление о конце — побочный эффект фильтра по логу в процессе, который сам истекает; нет «пока run не закончен — не молчать».
2. Нет события «run закончился, нужен следующий шаг» для сессии (push) — только poll логом.
3. Нет watchdog: нет правила «run мёртв/закончен, а следующий не запущен N минут» → тревога/авторезюме.
4. `PROVIDER_QUOTA` сообщает время сброса (`resume after …`), но кондуктор не умеет сам возобновиться в это время.

## Предложение
- `conduct run/resume --on-end CMD` (или цепочка `--then`): хук после `run end` (любой исход) с кодом, run id и путём к
  отчёту; через него можно запускать следующий батч или писать в очередь уведомлений. Для `finished` — следующий шаг,
  для `stopped` — причина.
- `conduct run --chain FILE` (очередь батчей): последовательность `[run options, items, post-actions]` с авто-коммитом
  правок группового ревью; остановка только на gate/ошибке.
- `PROVIDER_QUOTA`: опция `quota.wait: auto` — кондуктор сам спит до `resume after` и возобновляется (с лимитом ожидания).
- `orch watch RUN` — бессрочный блокирующий наблюдатель с heartbeat (строка раз в N минут «alive, step X») и обязательным
  финальным событием; Monitor не истекает по таймауту наблюдателя, а завершается только концом run.
- В `orch-debug`: обязательный шаг «страховка» — `ScheduleWakeup` на ≤ 2× оценки пункта, пока run активен; проверка
  `conduct runs` на каждом пробуждении; запись в журнал, если конец обнаружен позже, чем через 10 мин.

## Критерии приёмки
- Конец run (любой исход) доходит до сессии-наблюдателя ≤ 1 мин, независимо от срока жизни монитора.
- Квотная остановка с известным временем сброса автоматически возобновляется без участия агента.
- Цепочка «run → правки ревью → коммит → следующий run» выполняется одним запуском и не требует агента между шагами.

## Обход в сессии
`chain.sh`: правки RC → `git commit` индекса при `COMMIT_REFUSED` → следующий батч, одним фоновым скриптом + Monitor
на `CHAIN`-строки + `ScheduleWakeup` как страховка.
