## R21 · Эндпоинт `POST /v1/messages/count_tokens`: стоимость, аутентификация, лимиты

**Запрос (perplexity-web, 2026-08-07):** «Anthropic API /v1/messages/count_tokens endpoint 2026: is it free of
charge, does it require a paid API key, can a Claude Pro/Max subscription OAuth token be used for it, and what
are its rate limits?»

**Вердикт: RAG:✅ 2026-08-07.**

- Вызов **бесплатен**: Anthropic не тарифицирует счёт токенов, и трат инференса он не потребляет.
- Лимиты — **отдельные request-per-minute** для счёта токенов, независимые от лимитов `/v1/messages`;
  предзамер не съедает квоту генерации. Повышение — через Console → Limits.
- **Аутентификация обязательна**: ключ Console вида `sk-ant-api…` в заголовке `x-api-key`, либо
  короткоживущий bearer, полученный через Workload Identity Federation.
- Возвращаемый `input_tokens` — **оценка**: он может включать добавленные Anthropic оптимизационные токены,
  которые не тарифицируются.

**Источники:** `platform.claude.com/docs/en/build-with-claude/token-counting` ·
`platform.claude.com/docs/en/manage-claude/authentication`

## R22 · Подписка Pro/Max НЕ является учётной записью для `count_tokens`

**Тот же запрос, отдельный вердикт. RAG:✅ 2026-08-07.**

- Подписка Claude Pro/Max **сама по себе не даёт доступа к Console/API** — это отдельный продукт.
- OAuth-токен подписки (`claude setup-token` / `CLAUDE_CODE_OAUTH_TOKEN`) предназначен для аутентификации
  **Claude Code** и документирован как способный делать **только запросы модели**. `count_tokens` — отдельный
  служебный эндпоинт, не инференс, и на него этот токен не распространяется.
- Существует отдельный OAuth-маршрут для прямого доступа к API — **Workload Identity Federation** (обмен
  идентичности CI/облака на короткоживущий токен на `/v1/oauth/token`), но он не имеет отношения к личному
  входу по подписке и настраивается в Console.

**Источники:** те же + `docs.anthropic.com/en/docs/claude-code/iam`

**Значение для плана.** Владелец заявил (2026-08-07): «ключа у меня не будет, вход по подписке». Из R21+R22
следует, что канал доступа к настоящему токенизатору, назначенный D11/P0.1 (`POST /v1/messages/count_tokens`),
в среде владельца **недостижим в принципе**, а не «временно недоступен». Это не риск, а закрытая дверь.

## R23 · Настоящий токенизатор доступен без ключа — через `usage` собственных транскриптов Claude Code

**Класс факта:** environment-grounded (замер в этой сессии), не внешний.
**Вердикт: RAG:— (env-grounded: `~/.claude/projects/<slug>/<session>.jsonl`, замер 2026-08-07).**

Проверено на живом дереве:

```
$ env | grep -c ANTHROPIC        → 0        (переменных окружения нет)
$ which ant                      → not found (CLI Anthropic не установлен)
$ ls ~/.config/anthropic/        → нет каталога (профиля OAuth для SDK нет)
$ ls ~/.claude/.credentials.json → есть (учётные данные Claude Code)
```

При этом Claude Code пишет в транскрипт сессии по записи на КАЖДЫЙ ответ ассистента, и каждая несёт
фактический `usage` из ответа API:

```
{'input_tokens': 2, 'cache_creation_input_tokens': 31878,
 'cache_read_input_tokens': 20598, 'output_tokens': 378} | model: claude-opus-5
(записей с usage в одном файле сессии: 54)
```

Три входных поля — это **счёт настоящего токенизатора той модели, что названа в `model`**, полученный
по подписке, без ключа и без сети со стороны инструмента. Полный размер промпта равен их СУММЕ:
`input_tokens + cache_creation_input_tokens + cache_read_input_tokens` — правило зафиксировано справочником
`claude-api` (`shared/prompt-caching.md`, раздел «Verifying cache hits»: *«Total prompt size =
input_tokens + cache_creation_input_tokens + cache_read_input_tokens. If your agent ran for hours but
input_tokens shows 4K, the rest was served from cache — check the sum, not the single field»*).
Наблюдённая строка выше — прямая иллюстрация: `input_tokens: 2` при 52 476 токенах в кэш-полях.

**Ограничения источника, названные честно:**

1. Сумма покрывает ВЕСЬ промпт (системный промпт, инструменты, история), а не только измеряемый файл.
   Отсюда обязательность ДИФФЕРЕНЦИАЛЬНОГО замера: два прогона, отличающиеся ровно вложенным содержимым.
2. Границы кэша перераспределяют токены между тремя полями между прогонами — поэтому сравнивать можно
   только сумму, никогда отдельное поле.
3. По R21 счёт может включать неоплачиваемые оптимизационные токены; для гейта, который обязан оценивать
   СВЕРХУ, это смещение в безопасную сторону.
4. Шум выше, чем у `count_tokens`: константа обвязки вычитается замером пустой полезной нагрузки, но
   идеально не сокращается.

## R24 · Бюджет веса документа-инструкции агента и форма CI-гейта

**Запрос (perplexity-web, 2026-08-07):** «2026 best practice: enforcing a size/token budget on agent
instruction files (Claude Agent Skills SKILL.md, CLAUDE.md, AGENTS.md) — recommended max size, progressive
disclosure to reference files, and whether teams enforce a CI gate that fails when the entry document grows».

**Вердикт: RAG:✅ 2026-08-07.**

- **Вендорские числа названы явно:** Anthropic рекомендует держать `CLAUDE.md` **ниже 200 строк**, а
  `SKILL.md` — **под 500 строк**, вынося детальный материал в отдельные файлы. Импорты (`@docs/…`)
  организацию улучшают, но стартовый контекст НЕ уменьшают: импортируемое разворачивается при запуске.
- **Модель «инструкции агента — это context API с явным бюджетом»**, а не проектная вики: во входном
  документе только универсально нужные высокосигнальные правила, всё остальное — за файлами по требованию.
- **CI-гейт признан оправданным, но ДВУХПОРОГОВЫМ:**
  - *warning*-порог — рост сообщается в PR, автор обязан классифицировать добавленное (always-on правило /
    scoped-правило / workflow скилла / референс);
  - *fail*-порог — блокирует только на жёстком капе либо на запрещённых паттернах во входном файле
    (крупные примеры, скопированная документация API, новый импорт, молча раздувающий always-on контекст);
  - *исключение* — явно отревьюенная метка бюджета с **датой истечения** и follow-up;
  - *правило регрессии* — падать, если корневой файл вырос больше названного процента без сопровождающей
    записи (changelog/ADR), объясняющей, почему это обязано грузиться всегда.
- **Прямое предупреждение: «no growth ever» правилом делать НЕ следует** — файлы инструкций обязаны
  накапливать наблюдённые повторяющиеся ошибки агента; практика GitHub рекомендует то же (коротко,
  конкретно, из фактического поведения агента, без общей документации).
- **Мерить в токенах И строках, не в байтах**; число считать токенизатором ближайшим к используемому агенту
  и трактовать как приблизительное — ценность гейта в предотвращении крупных регрессий, а не в точном
  рантайм-счёте.
- Отдельно: линтить дубли и противоречия правил — **противоречие вреднее длины**, потому что весь
  найденный контент конкатенируется в контекст.

**Источники:** `docs.anthropic.com/en/docs/claude-code/memory` ·
`docs.github.com/copilot/tutorials/optimize-ai-usage`

**Значение для плана.** Заготовка «вес после ≤ веса до», рассматривавшаяся как форма правила D76
(«канон не толстеет»), — это ровно «no growth ever», который практика называет вредным. Гейт обязан быть
двухпороговым с правилом регрессии и датируемым исключением. Кроме того вендорский ориентир «SKILL.md под
500 строк» даёт независимый от этого плана якорь: сегодняшний `packages/skiller/skills/general/plan-protocol/SKILL.md`
— 91 329 байт, то есть кратно выше и вендорского ориентира, и измеряемого лимита одного чтения D15.
