# Framework Audit — периодический аудит каркаса (Perplexity)

> Роль в воркфлоу: **ревизор каркаса**. В отличие от [perplexity](./perplexity)
> (исследование с нуля под новую задачу), этот промт аудитит УЖЕ существующий
> agent-каркас и ищет ДЕЛЬТЫ: регрессии, несостыковки, новые официальные/OSS-решения.

Запускаешь периодически вручную. На вход даёшь два файла из
[agent-framework](../agent-framework/): `framework-overview` (что уже есть) и
`decisions-ledger` (что принято/отклонено) — тогда аудит не перепредлагает готовое.

## Настройки Perplexity

- **Длина**: `Detailed` (Длинный).
- **Режим**: Pro Search (свежие источники). `Academic` — для вопросов о внутренностях Claude Code.

## Цикл (куда девать результат)

1. Прогнал промт → сохранил вывод verbatim в `packages/skiller/docs/audits/<YYYY-MM-DD>-<тема>.raw.md`.
2. Триаж: создай `<YYYY-MM-DD>-<тема>.md` рядом — таблица absorb-now/later/reject + куда приземлилось.
3. Обнови `decisions-ledger.md` (чтобы следующий аудит не переспрашивал) и
   `packages/skiller/references/framework-audits.md` (ledger-строка).
4. Реализуй absorb-now → CHANGELOG пака + bump версии.
5. Обнови `framework-overview.md` → это вход СЛЕДУЮЩЕГО аудита. Петля замкнулась.

## Промт (вставлять в Perplexity)

```
Ты аудитируешь ЗРЕЛЫЙ, опинионированный agent-каркас для Claude Code — он УЖЕ
существует. Твоя задача — найти ДЕЛЬТЫ, а не проектировать с нуля и не
перепредлагать готовое.

## ТЕКУЩЕЕ СОСТОЯНИЕ КАРКАСА (v{{ВЕРСИЯ}}, на {{ДАТА}})
{{ВСТАВИТЬ: framework-overview.md — что уже есть (hub/skills-index, поле skills:
preload, роли-агенты, профили как ДАННЫЕ, review-gate хук, dev-loop воркфлоу с
уроками, разбивка пакетов skiller/harness/maind, статус Agent Teams)}}

## УЖЕ РЕШЕНО — НЕ перепредлагать (можешь оспорить, но только с НОВЫМ доказательством):
{{ВСТАВИТЬ: decisions-ledger.md — accept/reject/defer + обоснования. Среди reject:
Mustache-движок генерации агентов, нумерация файлов для приоритета, file-lock
протокол, формат tasks.json, complexity scoring, `extends:`/`@include` у агентов.}}

## ЗАДАЧИ
1. РЕГРЕССИИ И НЕСОСТЫКОВКИ (высший приоритет). Где каркас может молча сломаться:
   агенты/скиллы «не видны» (имена в skills: дают no-op, hub устарел, boost
   перезаписал CLAUDE.md), дрейф агент↔скилл, противоречия правил между
   CLAUDE.md / hub / агентами / .claude/rules/.
2. ПРОВЕРЬ условные пункты ТОЛЬКО по ОФИЦИАЛЬНЫМ докам (code.claude.com/docs,
   anthropic.com/engineering). По каждому: CONFIRMED / UNCONFIRMED / REFUTED + точный URL.
   Текущие открытые условности: {{ВСТАВИТЬ список, если есть}}.
3. НОВЫЕ решения с {{ДАТА_ПРОШЛОГО_АУДИТА}}: официальные фичи Claude Code и заметный
   OSS (субагенты, скиллы, хуки, оркестрация). Только то, чего НЕТ в ТЕКУЩЕМ
   СОСТОЯНИИ и УЖЕ РЕШЕНО.
4. По каждой находке — строка ДЕЛЬТЫ (формат ниже). Без общих best-practice эссе.
   Без пересказа того, что уже в ТЕКУЩЕМ СОСТОЯНИИ.

## ФОРМАТ ВЫВОДА (строго)
### A. Регрессии / несостыковки (приоритет)
| id | симптом | где бьёт | направление фикса | уверенность | источник |
### B. Проверка условностей
| пункт | вердикт (CONFIRMED/UNCONFIRMED/REFUTED) | офиц. URL | следствие |
### C. Новые дельты (фичи / OSS)
| id | что | куда ложится (hub/скилл/агент/harness/maind/данные) | absorb-now/later/reject (твоя рек.) | источник URL |
### D. Источники
| название | URL | почему важно |

Правила: каждое утверждение — со ссылкой; официальные доки приоритетнее блогов/видео;
помечай LOW confidence всё, что только из видео/блога; будь конкретен к ДАННЫЕ+СКИЛЛ
модели этого каркаса (НЕ движок-генератор); не предлагай Python-генератор, Mustache,
приоритет по нумерации файлов или file-lock — они явно отклонены.
```

## Правила формулировки

- **Всегда подавай `framework-overview` + `decisions-ledger`** — без них аудит
  скатывается в перепредложение готового (так было с первыми двумя аудитами).
- **Требуй проверки условностей по ОФИЦ. докам** — урок `.claude/rules/` (видео/блог
  ошибочно подавали как «не нативно»/«нативно»; истину дала офиц. дока).
- **Фиксированный формат дельт** — чтобы триаж был механическим.
- **LOW confidence на видео/блог** — не строить на них без офиц. подтверждения.

## Что получаем

Дельта-таблицы → триаж в `audits/` → обновление ledger/overview → реализация. См.
[agent-framework](../agent-framework/).
