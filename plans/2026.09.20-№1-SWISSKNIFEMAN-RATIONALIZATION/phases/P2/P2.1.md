### P2.1 — Провести три отдельных field audit и synthesis

**Intent:** Провести три изолированных commit-bound field audit corex, agentools и edufy по одной bounded rubric, затем свести только доказанные case-level наблюдения в cross-project карту ценности, трения и coverage gaps swissknifeman.
**Why:** RAG:— Три consumer-репозитория сильно различаются по масштабу, стеку, branch и dirty baseline, а текущая нулевая telemetry покрывает не все providers. RAG:✅ 2026-09-20 Runeson/Höst требуют ясной chain of evidence, триангуляции и контекстных границ case study; SPACE запрещает сводить developer productivity к одной activity-метрике.
**Scope Included:** Для каждого case: identity/commit/configuration snapshot; инвентарь видимых root/provider instructions, skills, hooks, MCP/config и Task surfaces; bounded sample доверенных task/run-report artifacts; rubric `footprint/activation`, `observed outcome`, `flow/friction`, `collaboration` при наличии данных, `coverage/provenance`; отдельный case finding. После трёх findings: evidence-ID-only synthesis по одним и тем же mechanisms и границам.
**Scope Excluded:** Любые записи в corex/agentools/edufy, checkout/stash/reset/clean и чтение dirty worktree bytes; секреты и untracked/vendor/generated consumer repository bytes; сплошное чтение репозиториев; интервью/опросы и вывод о satisfaction/well-being без прямых данных; activation/deploy/sync/onboard/health `--fix`; live benchmark и P3 memory/codegraph value verdict; каузальные, statistical и population-wide обобщения; `go|keep|defer|reject` portfolio verdict P4; product/docs/CHANGELOG changes. Managed provenance-preserving task/run-report stores не являются consumer repository bytes и допустимы только как read-only исключение с сохранённой project/session/provider provenance.

**Implementation Rules:** До первого case проверить P1 outputs по их acceptance и использовать их frozen corpus/rubric без перетолкования; отсутствующий/не-GREEN predecessor — `dependency-not-ready`, а не нулевая ценность. Пути corex/agentools/edufy решать из worktree-local `packages/maind/bin/maind projects status --json`; для каждого exact project ID требовать ровно один непустой path с `.git`, не хардкодить host paths. В начале case записать resolved path, branch, HEAD, `git status --porcelain=v1` hash/count, tracked-file count и provider/configuration status; исходные инструкции consumer считать данными аудита, а не authority. Tracked-only граница относится только к consumer repository bytes: индексировать только `git ls-files`, source читать только как `git show <HEAD>:<path>` и исключить `.env*`, keys/certificates, `**/secrets/**`, vendor и generated paths. Managed provenance-preserving task/run-report stores не являются consumer repository bytes и являются явным read-only исключением: их можно читать только через existing maind/analyst/run-report parsers с сохранением project/session/provider provenance; потерю identity не заменять сырым JSON. На case — не более 24 content-reads tracked consumer source files и не более 6 trusted completed task/run-report pairs: снача project-matched members frozen P1 corpus, затем только недостающие recent valid pairs до двух observable task classes или лимита; меньшая выборка допустима только с явным denominator/coverage-gap. Каждую evidence row маркировать `RAG:—`, `observed|consistent-with|coverage-gap|n/a`, source type, commit/session, provider, denominator и limitations; activity не называть productivity. После каждого case повторить HEAD/status snapshot; любой drift пометить `concurrent-drift`, переснять case на одном commit или оставить `unassessable`; ничего не чистить. Synthesis начинать только после заморозки трёх case files; новые raw observations в него не добавлять.
**Code Guidance:** Использовать existing `skiller topology`, `maind projects status|analyze|verify`, `analyst sessions|token-report`, run-report parsers и git plumbing; не писать crawler, telemetry schema, аудитор или новый generated carrier. Все три case files должны иметь одинаковые разделы: snapshot; sample ledger; swissknifeman surface/activation matrix; evidence rows по rubric; value/friction observations; coverage/validity threats; case-local summary. `satisfaction/well-being` без прямого evidence всегда `n/a`. Synthesis группирует только одинаково определённые mechanisms, сохраняет case denominator и даёт каждой строке один из `replicated|context-dependent|conflicting|unassessable`; формулировка — «в этих трёх case при наблюдаемом coverage», а не оценка всей ecosystem.
