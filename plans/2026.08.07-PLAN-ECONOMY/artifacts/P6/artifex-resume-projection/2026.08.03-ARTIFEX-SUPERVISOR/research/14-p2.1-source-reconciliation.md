## Three-source compiler model

| Manifest/input fact | Owner process | Reconciliation rule |
|:--|:--|:--|
| plan/phase/item identity, phase order, item status, all 16 raw fields | S1 `plan-lint --json` | exact required keys; S1 is the Task-owned plan model |
| Task Contract schema/content hash, route, evidence, cold reads, public acceptance, capabilities | S2 `task.task_contract build` | recompute content hash; consume semantics without copying predicates |
| phase order/status cross-check, exact `Exec`, independent route projection | S3 Harness dry-run | require `degraded=false`; compare order/status/route; do not treat `drivable` as authority |

For a valid `implementation/high` item, `Exec=manual` and Harness
`EXEC-NOT-PLAN-EXEC` are the expected pair. Artifex records `manual`; it neither asks Harness to
drive the item nor downgrades it to `plan-exec`.

## Exact scope projection

1. `scope.required_reads` comes from S2 `cold_start.reads`, resolved in order through S2
   `evidence`. The result is cross-checked against the ordered paths in S1 `Required Reads`.
2. `scope.files` comes only from S1 `Files`. Each entry must be one complete backticked
   repo-relative path; after removing tokens, only `·` separators and whitespace may remain.
   Empty, duplicate, absolute, parent-escaping, URL, symlink-escaping or residual prose refuses.
3. `scope.validation` is the ordered S2 `done.public_acceptance[].check` list and must reproduce
   S1 `Validation` under the same Task-owned `·` clause rule.
4. `scope.deliverables` is one exact S1 `Deliverables` string. Every S2 public-acceptance
   predicate must equal it; differing predicates refuse rather than being merged.
5. `scope.evidence_refs` is the ordered S2 public-acceptance ID list.

Required Reads are existing evidence and must resolve to contained regular non-symlink files.
`Files` are authorized write targets: an absent target is legal only when its nearest existing
parent is contained below the repository and has no symlink hop. The compiler never creates a
placeholder to make an output appear available.

## Source pins

All hashes use SHA-256 over exact UTF-8/file bytes or canonical JSON
(`ensure_ascii=false`, sorted keys, separators `,`/`:`, no insignificant whitespace):

| `source_hashes` key | Exact pre-dispatch material |
|:--|:--|
| `repository_root` | resolved repository-root identity string |
| `base_commit` | `git rev-parse HEAD` output string |
| `plan` | exact `plan.md` bytes |
| `phase` | exact `phases/Pn.md` bytes |
| `item` | canonical S1 item object including all 16 fields |
| `handoff` | exact `handoff.md` bytes |
| `task_contract` | recomputed S2 Task Contract content hash |
| `execution_policy` | exact execution-policy JSON bytes |

The process outputs are bounded observations, not durable truth by themselves. The compiler
cross-checks them, computes the manifest, then re-observes source pins immediately before
publication; any change returns `SOURCE_DRIFT` and writes no candidate manifest.

## Failure precedence

The frozen P1 refusal order remains authoritative. Process transport/shape failures are mapped to
the nearest existing refusal only when the contract already defines that semantic class; otherwise
the compiler raises a local typed source-unavailable error before manifest construction. It never
invents a new `slice-manifest-v1` refusal enum, treats missing JSON as an empty plan, or publishes a
partial manifest.

## Test strategy

Positive tests cover a conforming S1/S2/S3 triple, a manual route with expected Harness refusal,
an absent contained future File, deterministic repeated compilation and legal pending
supersession. Negative/mutation tests cover nonzero/timeout/oversize/malformed process output,
missing keys, field residue/duplicates, S1/S2/S3 order/status/route drift, external/symlink paths,
missing Required Reads, Task hash mismatch, unsupported capability, dependency error/cycle,
source drift and non-pending replan. Frozen P1 case expectations are read, never generated by the
candidate.

## Downstream impact

P2.2–P2.5 and P3 still consume the same immutable slice/run identities and compiler module.
No phase-output contract, roadmap route, package topology, provider surface, owner gate or frozen
P1 outcome changes. Therefore a new cross-phase finish is not required; the coupling change is
internal to P2.1's source acquisition and is fully recorded by D67.
