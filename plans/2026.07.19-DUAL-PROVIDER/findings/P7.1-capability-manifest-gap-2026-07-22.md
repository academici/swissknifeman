# P7.1 capability-manifest gap

**Date:** 2026-07-22
**Tree anchor:** `729c503f`
**Trigger:** второй execution-attempt P7.1 завершился escalation: named docs render/check
operation отсутствует, а ручная capability matrix запрещена.

## Frozen obligation

`root/contracts/provider-capability-contract.md` v1.0.0 и accepted
`root/adr/0001-provider-adapter-architecture.md` требуют один versioned capability manifest.
Он является источником support levels, native bindings, evidence, diagnostics, adapter gates
и generated docs. ADR отдельно возлагает на P1/P2 materialization versioned catalog и
fail-closed gate до downstream publication/deployment. RAG:— (repo-grounded:
`root/contracts/provider-capability-contract.md`, `root/adr/0001-provider-adapter-architecture.md`)

## Current-tree evidence

На anchored tree выполнены read-only scans:

```text
rg -l '"contract_version"' . --glob '*.json' --glob '!**/node_modules/**'
rg -n 'ProviderConfigCatalog\(' core packages --glob '*.py'
rg -n 'AdapterCatalog\(|capability_catalog=' core packages --glob '*.py' --glob '!**/tests/**'
rg -n 'plan_(codex|claude)_command_render\(' packages/task --glob '*.py'
```

Результат:

- нормативного JSON manifest carrier с envelope
  `contract_version/catalog_version/providers/capabilities/native_extensions` нет;
- production `ProviderConfigCatalog(...)` строится локально в `skiller` и `maind`, причём
  содержит только provider/capability ID и level, без contract-required intent, binding,
  limitations, evidence и diagnostic;
- `core.provider_registry.AdapterCatalog` использует supplied catalog, но production
  consumers его не вызывают — за пределами tests вызовов нет;
- task renderers принимают вызывающий `capability_support` mapping, а их текущие вызовы
  находятся только в tests; package-level reports/reference renderers существуют, но не
  образуют общий manifest и не являются источником support claims;
- `README.md` и `docs/provider-support.md` не имеют named manifest-backed render/check
  operation.

## Verdict

Это не локальная нехватка Markdown renderer. Генерация README из package outputs или
conformance reports была бы self-confirming и создала бы второй support canon. Простое
расширение исходного Files P7.1 только на README/script не выполняет frozen D3.

Owning hotspot — один repo-wide capability manifest + pure validator/projection + явная
передача его support projection в production adapter gates + deterministic docs
render/check. Семантика frozen contracts не меняется; P7.1 получает bounded fix-forward
этого hotspot, потому что без него release docs и последующий self-host не имеют
валидного входа.

**FOREMAN/fleet/live state:** не читались как design evidence и не менялись.
