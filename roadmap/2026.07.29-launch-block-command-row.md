# Roadmap: launch-block — команда должна быть строкой таблицы, а не отдельным code-block

**Статус:** ⬜ к внедрению — критерий уже сработал (см. ниже), это не «на будущее».
**Дом:** скилл `general/plan-protocol` (`snippets/launch-block-template.md`, `SKILL.ru.md`
§8 → регенерируемый `SKILL.md`) + `packages/task/lib/task/plan_lint.py` (гейт формата) +
`packages/task/commands/plan-exec.md`/`plan-close.md`/`plan-design.md`/`plan-run.md` +
их Codex-адаптеры (`packages/task/adapters/codex/skills/task-plan-*/command.md`,
`packages/skiller/adapters/codex/core/skills/general/plan-protocol/`) + golden fixtures
(`packages/task/tests/fixtures_data/claude-command-golden/commands/*.md`).

## Проблема

Живой канон launch-block (`snippets/launch-block-template.md`, `SKILL.ru.md` §8) требует
таблицу параметров ПЛЮС отдельный `code-block` ниже с provider-rendered invocation:

```markdown
**Next:** <kind>: task:<plan-command> <PLAN-ID> <arguments>

| Параметр | Значение |
|:--|:--|
| Model class | ... |
| Effort | ... |
| Context | ... |
| Суть | ... |

````
<invocation>
````
```

На практике (сессия `swissknifeman-next`, закрытие P0.1, 2026-07-29) это дважды подряд
привело к неверному выводу в чат:

1. Первый заход — агент вместо инлайна кода написал «см. `handoff.md` code-block Next» —
   пользователю пришлось лезть в файл, чтобы скопировать команду.
2. Исправление получилось избыточным в другую сторону: агент инлайнил ПОЛНЫЙ голый промпт
   (для manual-item'а) вместо короткой команды `/model` + `/effort` + `/task:plan-run` —
   хотя `plan-run` сам читает план/фазу с диска и промпт был не нужен.
3. Третий заход — агент положил в ячейку `Команда` строку `/model opus → /effort high →
   /task:plan-run ...`, дублируя параметры `Model`/`Thinking`, уже названные строками
   ВЫШЕ в той же таблице. Владелец переключает модель/effort сам по этим строкам;
   ячейка `Команда` — только сама команда, без повторного перечисления переключений.

Владелец работает над ~5 проектами параллельно и хочет копировать команду запуска БЕЗ
чтения сопроводительного текста — форма «таблица + отдельный code-block ниже» создаёт
лишний визуальный шаг и провоцирует обе ошибки выше.

## Решение (проект)

Таблица параметров сама несёт команду последней строкой:

```markdown
**Next:** <kind>: task:<plan-command> <PLAN-ID> <arguments>

| Параметр | Значение |
|:--|:--|
| Model | ... |
| Thinking | ... |
| Context | ... |
| Команда | `<provider-rendered invocation>` — ТОЛЬКО сама команда, без повторного
`/model`/`/effort` (они уже названы строками `Model`/`Thinking` выше в той же таблице) |
```

Отдельный `code-block` с голым промптом остаётся, но становится **опциональным** и
появляется ТОЛЬКО когда следующий шаг реально отличается от того, что команда сама
сделает по плану/handoff'у (manual-item без эквивалентной команды, реопен с находками —
существующий Scope-payload §8 D-канон 2026-07-17, корректирующая инструкция поверх
стандартного маршрута). Если отличий нет — строка `Команда` в таблице является всем
ответом, доп. блока нет.

**Гейт `plan_lint.py`** (сейчас грепает «есть строка `| Model class |` И code-block ниже»)
переписывается на «есть строка `| Model class |` И (строка `| Команда |` В ТОЙ ЖЕ таблице
ИЛИ code-block ниже, ровно один из двух)» — сохраняя существующее правило «Scope-payload
голым быть не может» (RED/ATTENTION аудита обязаны нести отдельный code-block с находками
независимо от этого изменения).

**Объём правки:** snippet + двуязычный канон (регенерация EN из RU, `check-translations.sh
--stamp`) + гейт линтера + 4 команды `plan-*.md` + их Codex-зеркала + golden fixtures +
version bump скилла (semver — форма правила меняется, потребители узнают по новой строке) +
`skiller registry`.
