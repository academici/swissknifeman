### P3.1 — Измерить memory и code graph на bounded pilot

**Intent:** Сначала доказать, что наблюдение memory/codegraph на выбранном execution provider достаточно для честного сравнения, затем на малом matched corpus отдельно измерить ценность maind memory и repository codegraph против обычного repository search.
**Why:** RAG:— В 96 последних reports счётчики нулевые, code MCP в наблюдаемых projects выключен, а Cursor/Codex/Claude capture различаются по глубине; нуль не доказывает нулевую ценность. RAG:✅ 2026-09-20 LongMemEval разделяет indexing/retrieval/reading и проверяет abstention; RepoGraph показывает возможную пользу graph navigation на публичных benchmark, но не доказывает её для swissknifeman.
**Scope Included:** Structural coverage/parity matrix для Claude Code, Codex и Cursor; один controlled telemetry probe каждого механизма на exact execution provider; две memory A/B пары на cross-session decision/failure-recall tasks; две codegraph A/B пары на cross-file navigation tasks; retrieval/navigation и downstream metrics; отдельные verdicts и applicability limits.
**Scope Excluded:** Full factorial/statistical benchmark; более двух valid pairs на mechanism; новая telemetry/schema/parser; permanent MCP/config/hook/skill changes; always-on rollout; изменение product, docs или consumer trees; смешивание maind federation graph с repository codegraph; combined capability verdict; P4 portfolio и P5 implementation.

**Implementation Rules:** До любого pilot потребовать GREEN P1/P2 outputs и запечатанный global-audit route; иначе `dependency-not-ready`. Сначала по tracked source/tests заполнить provider matrix по identity, mechanism exposure, calls, result/evidence quality, acceptance, tokens/time, ordinary reads/searches и unrelated writes, затем на exact provider провести по одному harmless controlled call с known nonempty result для memory и codegraph. Automatic report и task-local worksheet явно разделять; ненаблюдаемое — `n/a|coverage-gap`, не нуль. Если exact provider не связывает run identity, exposure, relevant evidence и downstream acceptance, paired runs не расширять, а оба mechanism получают `defer` с exact gap. Каждая A/B пара идёт в двух чистых temporary worktrees на одном commit с одинаковыми prompt, provider/model/effort, tool/sandbox/timeout/context budget и acceptance; меняется только mechanism availability, порядок A/B чередуется. Memory fact имеет committed source, доступный control через ordinary search; temporary seed использует unique non-secret key/scope, фиксирует store/recall/forget IDs и обязан исчезнуть до GREEN. Codegraph condition включается только в temporary/session-local config; ordinary-search control сохраняет `rg|find|read` и тот же acceptance. На mechanism ровно две valid pairs и не более одной replacement pair только по заранее описанной infrastructure-invalid причине; затем stop. Exact thresholds/reducer берутся из P1; incomplete, mixed или under-covered evidence не может дать `go`.
**Code Guidance:** Не писать benchmark runner и не менять telemetry. Использовать existing maind memory/MCP, provider hooks/run reports, analyst normalizer, codegraph usage scanner, git worktrees и P1 worksheet shape. Для memory отдельно оценить retrieval correctness/provenance, stale/irrelevant retrieval, missing-evidence abstention и downstream acceptance/cost. Для codegraph до запуска заморозить 1–4 required file/symbol anchors на task, затем сравнить anchor recall, wrong turns, files/reads/tool calls, time/tokens и downstream acceptance. Неиспользование available mechanism — measured adoption result, а не основание принудительно менять prompt. Выход по каждому mechanism: one-line verdict, effect/guardrail table, paired trace IDs, applicability, coverage limits и implication; `keep` означает сохранить current activation state, а `defer` не создаёт новую измерительную программу.
