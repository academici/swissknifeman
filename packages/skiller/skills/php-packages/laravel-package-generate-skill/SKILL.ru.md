# Скилл генерации скилла пакета

## Главная цель

Поддерживать встроенный в пакет Boost-скилл точным, лаконичным и сфокусированным на помощи Laravel-приложениям во внедрении пакета.

## Рабочий процесс

1. Изучите реализацию пакета перед редактированием Boost-скилла: сервис-провайдер, фасады, публичные классы, команды, конфиг, маршруты, миграции, события, представления (views), теги публикации (publish tags) и тесты.
2. Изучите документацию пакета: `README.md`, `docs/`, `docs/.vitepress/config.ts`, документацию для контрибьюторов, примеры и записи в changelog, описывающие пользовательское поведение.
3. Определите только публичную поверхность интеграции. Включайте указания по установке, настройке, публикации, командам, маршрутам, фасадам, хелперам, middleware, событиям и тестированию только тогда, когда пакет действительно их предоставляет.
4. Обновите `resources/boost/skills/*/SKILL.md` практическими шагами внедрения, ссылками, примерами и анти-паттернами для разработчиков Laravel-приложений, использующих пакет.
5. Сохраняйте front matter, метаданные пакета, плейсхолдеры в ненастроенных пакетах и структуру Boost-скилла: description (описание), primary goal (главная цель), workflow (рабочий процесс), references (ссылки), examples (примеры) и anti-patterns (анти-паттерны).
6. Проверьте, что Boost-скилл не описывает внутренности как публичный API и не документирует функции, которые не реализованы.

## Правила написания

- Пишите для потребителей, устанавливающих пакет в Laravel-приложение, а не для мейнтейнеров, меняющих внутренности пакета.
- Предпочитайте короткие, ориентированные на задачи шаги широким объяснениям.
- Указывайте на конкретные файлы только тогда, когда это помогает потребителю понять внедрение пакета.
- Держите примеры запускаемыми и согласованными с задокументированными именами пакетов, ключами конфига, командами и тегами публикации.
- Держите скилл достаточно небольшим, чтобы агент мог быстро его загрузить и применить.

## Примеры

- После добавления новой Artisan-команды обновите Boost-скилл: когда её запускать, обязательные опции, ожидаемый вывод и любой связанный конфиг.
- После добавления конфига и тегов публикации обновите Boost-скилл командами публикации и минимальным набором ключей конфига, которые пользователям нужно задать.
- После добавления фасада или публичного класса обновите Boost-скилл одним практическим примером интеграции и тестовым утверждением (assertion), которое следует использовать потребляющему приложению.

## Анти-паттерны

- Регенерация Boost-скилла из одной только документации без проверки реализации.
- Документирование приватных классов, тестовых хелперов, маршрутов только для workbench или деталей реализации как потребительского API.
- Добавление спекулятивных примеров для функций, которые пакет не предоставляет.
- Удаление безопасных для плейсхолдеров метаданных до того, как пакет был настроен.
