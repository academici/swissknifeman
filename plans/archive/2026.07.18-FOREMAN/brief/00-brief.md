# Бриф владельца — 2026.07.18 (сессия Brain, Fable)

Переформулировка входа владельца без потери мыслей.

## Проблема

Владелец ведёт многофазные мастер-планы в нескольких проектах параллельно (5 терминалов
с Claude Code). Основное время — простой: план проектируется десятками итераций
(вопросы, регрессии, повторные запуски команд), затем каждая фаза исполняется отдельной
командой. Владельцу приходится почти круглосуточно подтверждать шаги, хотя в 99% случаев
он просто соглашается — особенно когда основы проекта заложены.

## Философия владельца (директивы для автоматики)

- Никаких костылей — только самое чистое решение.
- Breaking changes допустимы, если улучшают проект.
- Всегда следовать философии уже реализованных проектов.

## Что хочет владелец

Автоматизировать прогон фаз/подфаз планов так, чтобы:

1. Каждая фаза/подфаза исполнялась **в новой сессии** → экономия токенов (в отличие от
   длинных Workflow-марафонов, где контекст оркестратора переполняется к концу — опыт
   FLEX-2: стоп по утечке токенов).
2. «Наблюдатель» следил за процессом: контроль переполнения контекста
   (автокомпакт/новая сессия), защита от зацикливания фаз при повторных запусках,
   рациональный расход токенов.
3. Спорные моменты → уведомление владельцу в Telegram («подойти к компьютеру»).
4. Владелец мог сам вклиниваться в процесс, когда у компьютера (синхронизация «как идёт»).
5. Рассматривался Claude Cowork как «водитель терминалов» — отвергнут в обсуждении:
   скрин-скрейпинг TUI хрупок; Claude Coder (cloud) не видит локальные скиллы/хуки.
   Требование: работать должен именно локальный Claude Code (CLI/VS Code расширение),
   где загружаются скиллы и хуки владельца.

## Решение, согласованное в обсуждении

Супервизор-пакет (рабочее имя **Artifex**) в экосистеме Swissknifeman:

- **CLI-драйвер**: цикл «очередь items → `claude -p` (fresh session) → parse
  handoff/JSON → next / retry / escalate».
- **Скилл supervisor-protocol**: поведение супервизора и воркеров (лимиты retry,
  критерии эскалации, «спорное не спрашивай — фиксируй ATTENTION в handoff»).
- **Hook-шаблоны**: TG-notify (Notification/Stop), PreToolUse auto-approve policy.
- **Settings-фрагменты** unattended-профиля (allowlist, permission-mode).
- **Раскатка выборочно** через skm bucket / agent-packs с lock-версионированием.
- **Policy-файл per project** = opt-in маркер (нет файла — супервизор проект не трогает);
  философия владельца — в декларативном конфиге, не в коде драйвера.
- **Контракт с plan-protocol** (handoff/статусы — API супервизора) — версионировать явно.
- **Граница с mAInd**: супервизор ≠ maind (execution vs память/граф), но каждый прогон
  обязан репортить факты в память mAInd.
- Утверждение плана (design) остаётся интерактивным/человеческим; автоматизируется
  exec-волна после «Утверждено».

## Поручение этому заходу

Создать мастер-план через план-протокол в vault-доме Swissknifeman (планы засинхронены —
работать можно из Brain). Первично занести проведённые исследования (headless-возможности
Claude Code + Perplexity-развед) в findings. Детальную проработку команд владелец
продолжит в самом SKM.
