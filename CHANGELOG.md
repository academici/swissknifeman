- planner: the plan store follows the project marker (portable workspace, PLAN6 P2.1). New stdlib module `planner.plan.workspace` (`workspace_root`, `state_dir`, `read_marker`, `read_bindings`, `resolve_plans_store`, `source_root_of`, `legacy_plans_present`) is a copy of the `aicore.workspace` rule and passes its shared vectors `resolution-vectors.json` (`tests/engine/test_workspace.py`, read through `AICORE_ROOT`, skipped without it). `store.find_plans_root` looks at `.swissknifeman/project.json` first in every directory it walks (`legacy` → `<root>/plans`, `workspace` → `<workspace>/projects/<id>/plans`) and falls back to `plans/` as before; in launcher mode `require_project_plans` accepts the plans folder the marker names (a foreign path is still `PROJECT_PATH_OVERRIDE_FORBIDDEN`). `Plan.source_root` is the checkout of a plan (launcher project, bound checkout, or the parent of `plans/`); `Plan.repo_root` returns it or raises `PLAN_SOURCE_UNBOUND`; settings (`project_root_of`) and `new` (`--repository` default, `ops.default_repository`) use it. `PlanLock` of a legacy plan folder refuses with `PLANS_MIGRATED` once the marker says `plans_store: workspace`. One stderr line `warning: LEGACY_PLANS_PRESENT: …` per process when the workspace is used and `<root>/plans` still holds plans; JSON stdout is unchanged. New refusal codes in the catalog and the `read-catalog` schema: `PROJECT_MARKER_INVALID`, `WORKSPACE_PROJECT_MISSING`, `WORKSPACE_LAYOUT_INVALID` (damaged `bindings.json`), `PLAN_SOURCE_UNBOUND`, `PLANS_MIGRATED`, `PROJECT_CONTEXT_CONFLICT`. A project without a marker behaves as before. `context`, `check`, `scout` and `refs` still read `repo_root` directly; they follow in P2.2.
