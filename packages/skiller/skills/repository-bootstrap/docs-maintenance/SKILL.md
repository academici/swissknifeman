# Docs maintenance after tasks

Internal skill (not exported). Activates as an **evaluation step** at the end of a task, not
necessarily an edit. CHANGELOG is not here (that's [release-discipline]).

[release-discipline]: ../release-discipline/SKILL.md
[package-architecture]: ../package-architecture/SKILL.md

## When to activate

At the end of every completed task, if the repo root has a `docs/`.

## "Worth documenting" criteria

**YES, update docs/:**

- A process changed (contribution, validation, releases, upstream sync).
- An install/distribution capability appeared/changed (install.sh flags, CLI commands,
  profiles, channels).
- A script gained new user-facing behavior or flags.
- A schema changed: skills.json, upstream.json, frontmatter (SKILL_TEMPLATE), buckets.json,
  `.swissknife.json`, projects.json.
- A roadmap item landed → also update `docs/roadmap.md`.

**NO, don't touch docs:**

- Individual skill content (skills.json and graph.md regenerate themselves).
- Typos, formatting, behavior-preserving refactors.
- Dependency bumps, test fixtures.

## Algorithm

1. List what the task changed (scope the git diff).
2. Run the criteria tree above.
3. **NO** → explicitly record in the response: "docs not needed: <reason>" — stop.
4. **YES** → update an existing page (extension preferred over a new page); a new page only for
   a genuinely new topic, adding it to the sidebar (`docs/.vitepress/config.mts`) in the same edit.
5. Unsure whether a topic deserves a page — propose it to the user, don't write silently.

## docs/ map by topic

Docs are grouped by package: each package owns its own under `packages/<pkg>/docs/`; the
umbrella site is assembled from them (`scripts/docs-sync.sh` → `docs/<pkg>/`, gitignored).
General info lives in the root `docs/`. Paths below are relative to the `skiller` package.

- Install/channels/CLI: `docs/guide/installation.md`, `docs/guide/cli.md`,
  `docs/guide/profiles.md`, `docs/guide/vendor-skills.md`.
- Registry and schemas: `docs/guide/registry.md`, `docs/guide/skill-anatomy.md`.
- External skills: `docs/guide/upstream-sync.md`.
- Skill creation: `docs/guide/creating-skills.md`.
- Adapters/scanner/CI: `docs/guide/adapter-deltas.md`, `docs/guide/scanner.md`,
  `docs/guide/ci.md`; workflows — `docs/workflows/*`.
- `docs/guide/graph.md` — **generated, do not edit**.
- `docs/boost-compatibility.md` — Laravel Boost compatibility.
- **Claude Code environment** (permissions/MCP/hooks/setup) — package
  `packages/harness/docs/` (configs/, integrations/, setup/, index).
- **Umbrella-wide** — repo root `docs/`: `index.md`, `routing.md`, `roadmap.md`.
