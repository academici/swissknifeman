# P0.1 — Codex-first калибровка с мультипровайдерным швом

**Дата:** 2026-08-08  
**Статус:** авторский синтез для `2026.08.07-PLAN-ECONOMY P0.1`  
**Основание:** уточнение владельца о Codex-first исполнении и обязательной мультипровайдерности;
D114–D117; `findings/18-codex-token-usage-2026-08-08.md`.

## 1. Архитектурная граница

Калибровка делится на три слоя:

| Слой | Знает | Не знает |
|:--|:--|:--|
| provider adapter | команду провайдера, raw event/usage, перевод в canonical record | классификатор, регрессию, порог бюджета |
| neutral calibration core | bracket-controls по `input_tokens_total`, контроль wrapper fingerprint, fitter, гейты bound/tightness | JSONL Codex, поля Claude, auth конкретного провайдера |
| artifact consumer | rates/classifier и qualified provenance `provider + model + protocol` | как запускался провайдер и как выглядел raw event |

Активный адаптер — `codex-exec-jsonl`. Будущий `claude-code-json` добавляется рядом и реализует тот
же контракт; он не заменяет общий слой и не меняет потребителей. Это прямое применение инварианта
provider parity: provider-specific файлы — additive adapters над общей семантикой.

## 2. Нормализованная запись пробы

Минимальный provider-neutral record:

```json
{
  "schema_version": "token-probe-record-v1",
  "provider": {"id": "codex", "adapter": "codex-exec-jsonl-v1"},
  "model": {"requested_id": "gpt-5.6-terra", "effective_id": null},
  "protocol_version": "differential-input-total-v2",
  "input_tokens_total": 13388,
  "usage_breakdown": {"cached_input_tokens": 9984, "cache_write_input_tokens": 0},
  "wrapper_sha256": "<sha256>",
  "environment": {"cli": "codex-cli", "cli_version": "0.147.0", "command_sha256": "<sha256>"}
}
```

Обязательные инварианты: `input_tokens_total` — неотрицательное целое; provider/model/protocol и
оба fingerprint непусты; неизвестные breakdown-поля допустимы, но не влияют на total; raw output
доступен только в plan-owned probe-log и не течёт в fitter. `effective_id: null` допустим, когда
провайдер не сообщает модель в terminal event; requested id тогда обязан быть явно пинован в
команде.

## 3. Активный Codex adapter

Базовая команда строится программно и пинуется в probe-log:

```text
codex -C <isolated-empty-dir> -m <requested-model> -c model_reasoning_effort="low"
  -a never -s read-only exec --ephemeral --ignore-user-config --ignore-rules
  --skip-git-repo-check --json -
```

Prompt поступает через stdin. Обёртка требует фиксированный короткий ответ и запрещает tools;
временный cwd пуст, поэтому содержимое репозитория и его AGENTS/skills не попадает в controls/payload.
Адаптер проверяет exit 0 и ровно один `turn.completed`, затем маппит
`usage.input_tokens → input_tokens_total`. Cache breakdown сохраняется, но не суммируется.
Команда не читает project rules/config, не сохраняет rollout и не требует Claude OAuth.

## 4. Differential semantics с bounded bracket-controls

Neutral core вызывает один adapter по короткому расписанию: пустой control, не больше трёх payload
probes, следующий пустой control. Для payload между соседними controls:

`true(f) = payload.input_tokens_total − mean(left_control, right_control)`.

Drift controls выше δ отбраковывает весь bracket. Provider, adapter version, requested model,
protocol, CLI version, wrapper hash и command contract hash совпадают; различается только payload,
thread id исключён из identity. Восемь provenance-qualified real samples (≤16 KiB каждый,
≤128 KiB суммарно) требуют максимум 12 calls при зелёных controls (D120–D121), а не три вызова на
каждый полный файл. Core запрещает смешивать qualified targets.

## 5. Артефакт и совместимость

Активный `token-estimate-calibration` v2 получает обязательный блок:

```json
{
  "calibration_target": {
    "provider": "codex",
    "adapter": "codex-exec-jsonl-v1",
    "requested_model_id": "gpt-5.6-terra",
    "probe_protocol_version": "differential-input-total-v2",
    "usage_semantics": "provider-reported-input-total-v1"
  }
}
```

Flat-поля v1 `source`/`tokenizer` сохраняются только в историческом snapshot. Новый загрузчик
fail-closed требует `calibration_target`, classifier v2 и полный набор пяти ставок. P0.5 и P3
используют коэффициенты, но при диагностике обязаны показывать qualified target; warning о
несовпадении сравнивает переданный session provider/model с обоими полями, не только model id.

Будущий Claude-артефакт не перезаписывает Codex evidence молча: он либо получает новый qualified
artifact id/version, либо заменяет active artifact отдельным D-решением и повторным прогоном всех
гейтов. Численное равенство между провайдерами не является критерием P0.1.

## 6. Поверхность реализации и доказательства

- Новый `task.token_probe` владеет immutable record validation и adapter protocol; отдельный
  `task.token_probe_codex` владеет `CodexExecProbeAdapter`. Калибратор зависит только от neutral
  interface и не импортирует raw Codex schema.
- `calibrate-token-estimate.py` владеет bounded corpus, bracket-controls, fitter и записью generated artifacts;
  provider выбирается явным CLI-аргументом, default для этого item — `codex`.
- `task.token_estimate` остаётся offline/stdlib-only и знает только qualified provenance артефакта.
- Юнит-тесты парсера: missing/duplicate terminal event, bad exit, missing/negative/non-int total,
  cache не удваивает total, стабильная сборка команды и fake adapter для доказательства
  независимости fitter от Codex.
- Интеграционный smoke-probe запускает один Codex turn в пустом cwd; bounded corpus из восьми
  samples восьми реальных файлов остаётся ручным acceptance шагом item'а, не CI. Log пинует
  source hash/range/sample hash; полный source затем проверяется offline без provider calls.

Сохранность D117 неизменна: v1 snapshot и исходный Claude probe-log не правятся; Codex пишет новый
`calibration-probe-log-v2.json`, где каждый record несёт qualified target и fingerprints.

## 7. DoR-вердикт

- Владелец не нужен: действующий провайдер и граница будущего Claude adapter заданы.
- Общий контракт отделён от Codex raw schema, а downstream не связан с provider CLI.
- Активный канал подтверждён официальной документацией и локальным probe; Claude-форма не
  load-bearing и честно отложена.
- Scope конечен: один neutral module, один active adapter, существующий fitter/оценщик и тесты.
