## 3. Opus 5 prompting guide (platform.claude.com, first-party, 2026-07-25)

Несущие пункты для экосистемы (полный текст — по URL в reference.md):
- Модель **сама верифицирует свою работу**: явные инструкции «include a
  final verification step», «double-check your answer» вызывают
  ОВЕР-верификацию — их надо УБИРАТЬ из промптов/команд для Opus 5.
- **Effort — главный рычаг цены**: low/medium дают сильное качество дешевле;
  рекомендован effort-sweep вместо унаследованных дефолтов; xhigh — для
  сложного agentic/coding.
- **Субагенты**: делегирует охотнее прежних моделей — нужны явные критерии
  «когда делегировать» и капы.
- **Verbosity/scope**: ответы и файлы-деливераблы длиннее — просить
  конкретную длину; scope constraint («deliver what was asked») для узких
  задач; в review-промптах «only report high-severity» модель понимает
  буквально → просить всё и фильтровать отдельно.
- 1M контекст по умолчанию; guidance частично общий для Claude 5 family, но
  анти-verification/subagent-caps — специфика Opus 5 (для остальных — общий
  best-practices док).

## 4. Perplexity-синтезы (2026-07-25)

### 4.1 Codex CLI на инструкционно-тяжёлых репо (web+social)

- «Больше AGENTS.md — хуже» НЕ подтверждено: исследование показало снижение
  runtime/токенов при наличии root AGENTS.md; проблема — раздутые/
  противоречивые/устаревшие монолиты (context budget + конфликт сигналов).
- Best practice: короткий root-файл (≤100–200 строк, только
  action-changing), слоёная память (spec/plan/status отдельными файлами,
  подгружаемыми по надобности) — наша структура (CLAUDE.md ≤200 +
  path-scoped rules + плановые файлы) ей соответствует.
- Claude Code «более зрелая модель памяти» (community), но не иммунен.
- Проекция на инцидент владельца (Codex тупил неделю): вероятные усилители —
  (а) 12 duplicate-identity коллизий root-адаптеров (доказано планом
  AGENT-RELIABILITY, чинит его P1), (б) отсутствие enforcement на границах
  (его P2). Спецнастройка Codex = тонкий AGENTS.md слой + dedup, НЕ отказ от
  SKM. Community-репорты о «severe regression GPT-5 Codex» существуют
  (community.openai.com) — деградация не уникальна для нашего сетапа.

### 4.2 Cross-machine память агентов (web)

- Консенсус: **гибрид** — durable общая память = self-hosted сервис
  (namespace, serialization, audit), hot/scratch — локально; markdown-vault
  git-синк хорош для human-curated знания, но при росте числа агентов
  merge-конфликты и staleness — главный отказ.
- Наш roadmap-стаб `roadmap/cross-machine-memory.md` (D12 CONTEXT-ECONOMY)
  уже содержит этот дизайн: вариант 1 = единственный живой демон agentmemory
  на always-on хосте + Tailscale/LAN MCP-клиенты (запрет file-sync живого
  SQLite подтверждён ранее). Критерий активации стаба СРАБОТАЛ: у владельца
  теперь несколько постоянных машин.
- obsidian-mind как механизм памяти НЕ нужен: его роль уже покрыта
  maind/agentmemory (агентная память) + Brain vault (курируемое знание,
  git). Полезный паттерн — MEMORY.md-указатели вместо копий (уже наш канон).

## 5. Claude Code first-party факт-лист (агент claude-code-guide, 2026-07-25)

- Statusline получает `context_window.used_percentage` /
  `remaining_percentage` / token-поля (code.claude.com/docs/en/statusline).
- Hooks НЕ получают context_window-полей; hook-событий PreCompact/PostCompact
  в актуальном перечне НЕТ (hooks.md); авто-compact включён по умолчанию
  (`autoCompactEnabled`), порог не конфигурируется (context-window.md).
- «Context-low warning» — UI-only. OS-уведомление о высоком контексте
  реализуемо ТОЛЬКО через statusline-скрипт (event-driven перерисовка,
  видит used_percentage, может дёргать notify-send с троттлингом).
- Модель изнутри сессии remaining context по доке не видит (`/context` —
  user-only) → «агент сам предлагает compact» возможен только эвристикой
  (по типу задачи), не по фактическому проценту.
