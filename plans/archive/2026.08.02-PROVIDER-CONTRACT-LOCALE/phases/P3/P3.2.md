**Intent:** Implement a provider-neutral reconciliation protocol and provider-scoped package adapters that perform `observe → diff → preflighted apply → readback` against the P3.1 desired snapshot, with every write controlled by existing artifact-lock/adoption rules. #### 2026-08-10 contract refinement

The adapter implementation follows `provider-skill-adapter-v1`: a provider registers discovery,
render/projection, invocation policy, capability negotiation, observation/readback and stable
limitations through one descriptor. Shared orchestration selects descriptors by registry data and
does not branch on `claude|codex` outside the registry/bootstrap boundary. Canonical skill bodies
are read-only inputs; an adapter may add provider-owned metadata or affordances but may neither
delete shared invariants nor infer another provider from rendered output. A minimal third-provider
fixture must pass registration, dry-run projection, isolation and unsupported-capability tests
without product-wide edits.
