# P1.1 — Skiller consumer-acceptance compatibility defect

`bash packages/task/scripts/validate.sh` passed (941 tests, one documented skip), as did the
focused P1.1 suite, provider projection check and Skiller registry check. The required
`packages/skiller/bin/skiller validate` fails only in `test_codex_consumer_acceptance` under Codex
0.153.4: `codex debug prompt-input` renders skill references as root aliases such as
`r3/task-plan-run/SKILL.md`, while the test asserts that the matched text begins with the isolated
absolute `CODEX_HOME` path. Repeating under an empty temporary HOME removes the user-level skills
but preserves the same three alias-format assertions; the assertion that repo-local skills appear
also still expects an unaliased absolute marker.

This is outside P1.1's declared Files and does not invalidate the P1.1 Task behavior, but it
prevents the required Skiller validation from being green. The owning compatibility test needs a
separate bounded update that resolves the emitted alias through its `Skill roots` table before
asserting cache/repository provenance.

After regenerating P1.1's bundle, `plan-lint` has one remaining plan-owned RED: it requires
`root/contracts/read-budget-v1.md`, but this Layout v2 plan deliberately has no `root/` directory
and P1.1 does not declare that contract among its Files. This is a plan-design contract conflict,
not a safe P1.1 implementation edit; it requires the next design/repair authority to align the
read-budget predicate with the v2 plan layout.
