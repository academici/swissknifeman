### P2.10 — Пересобрать read graph и доказать self-host admission

**Intent:** Применить P2.9 к каждому item этого плана: заменить aggregate/oversized reads bounded carriers, привязать будущие outputs к конкретным producer items, материализовать детерминированные plan-owned projections для канона, audit и ARTIFEX resume, переснять before/after и закрыть P2 только при отсутствии intrinsic D2(a)/D2(b)/unresolved failures. RAG:— (repo-grounded: D131; `research/20-p2.8-stage-aware-admission-redesign.md`).
**Why:** Machine semantics сама по себе не уменьшает вход. Текущий read graph содержит `_current.md`, монолитные code/test/canon/audit carriers и полный чужой `plan.md`; простое удаление их из Required Reads нарушит D74. Нужны bounded источники с provenance: direct immutable decisions, modules P2.9, content-preserving slices с manifest/hash и dry-run v2 projection донора. Финальный self-host verdict отделён от реализации P2.9, чтобы acceptance не подгоняла свой собственный predicate. RAG:— (repo-grounded: `findings/21-p2.8-read-admission-diagnosis-2026-08-08.md`).
**Scope Included:** Инвентарь всех Required Reads/Inputs и producer edges; direct decision files вместо `_current.md`; bounded plan-owned slice bundles для `plan-protocol` и design-audit с byte-reassembly/hash verifier; read-only `plan-migrate --dry-run --output` projection ARTIFEX для P6.9; обновление item specs/roadmap/index; regeneration всех state/status/decision views; full `plan-weight` report с состояниями; D74 aggregate/anti-displacement answer; final structural lint/citations/task-contract build.
**Scope Excluded:** Семантическая правка `plan-protocol` (P6.5); inplace миграция ARTIFEX или другого плана; изменение frozen numbers/unit; создание заглушек будущих deliverables; выполнение P3–P6; переписывание terminal specs или journal history; ручная правка generated views/artifacts.
**Inputs:** Deliverables P2.9 · baseline P2.8 (`artifacts/p2-weight-after.json`, `p2-weight-before-after.json`) · `findings/21-…` · item specs всех семи фаз · converter dry-run P2.8.

**Implementation Rules:** - Terminal-before-v2 specs не редактируются. Их non-pass остаётся `historical-pre-v2` в отчёте и не может быть использован как доказательство ready-path.
- `_current.md` заменяется только конкретными D-files, перечисленными в самом item; выбор «последние решения» запрещён как волатильный и неограниченный.
- Future missing допустим только как `pending-producer` с существующим earlier item и точным Deliverable path. Placeholder/empty file ради resolver запрещён.
- Slice bundle content-preserving: manifest несёт source path/hash, ordered ranges/headings, file hashes и reassembly check. Авторский summary может быть рядом, но не заменяет bytes, на которых стоит изменение.
- ARTIFEX source read-only: converter получает `--dry-run --output` и verified source hash; Required Reads P6.9 адресуют bounded projection. Source не меняется ни байтом.
- Aggregate после учитывает ВСЕ bounded slices и per-file overhead. Split, поднявший aggregate, не проходит D74 только потому, что per-item стал зелёным.
- Финальный отчёт отвечает на D74 вопрос дословно и перечисляет отдельно `historical`, `pending-producer`, `ready`, intrinsic failures. Зеленый verdict допустим только при intrinsic failures = 0 и ready failures = 0.
- Generated files создаются owning tools и затем `--check`; руками не правятся.
**Code Guidance:** Это acceptance item, поэтому запрещён самый удобный самообман: удалить большой путь и назвать его optional. Для каждой удалённой Required Read строки отчёт показывает замену и доказывает, что обязательное содержание осталось в measured graph либо стало ненужным по конкретному D#/Scope. Content slices проверяются hash/reassembly, direct decisions — exact IDs, future edges — exact producers. Если aggregate вырос, сначала убрать реальное дублирование; нельзя менять threshold или скрывать per-file overhead. Если P2.9 tool ошибся локально и причина однозначна — repair-now с тестом по D130; изменение semantics — обратно в plan-design, не патч acceptance.
