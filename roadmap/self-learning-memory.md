# Roadmap: самообучение через namespace-память mAInd

**Статус:** отложено. **Критерий внедрения:** появится потребность авто-накапливать «уроки»
прогонов И готовность держать guardrails (confidence-gating + ручное промо в скилл).

## Идея

Из доклада «Self-Improving Claude Code» — strike/praise scoring + автонакопление уроков. Но
**каноничной реализации нет** (talk-level), а наивный CSV-скоринг хрупкий. Безопасная форма:
уроки текут в **плоскость памяти mAInd** (namespace-изоляция, аудируемо), а не в перезапись
файлов.

## Безопасный дизайн (если дойдём)

- **Источник**: `SessionEnd`/`Stop`-хук фиксирует кандидат-урок (что сработало/провалилось) —
  но НЕ правит CLAUDE.md/скиллы (это и есть запрет skm2 Task7/Task8).
- **Хранение**: запись в `project:<id>` / `ns:<группа>` память mAInd с тегом `lesson:` и
  `confidence`. Изоляция и аудит — из коробки (намспейсы mAInd).
- **Поверхность**: при следующей сессии урок всплывает через уже существующий
  `memory-digest-hook` (`SessionStart.additionalContext`) — не навязчиво, in-memory.
- **Промо в скилл**: только **через человека** — урок с накопленной confidence предлагается к
  оформлению в скилл/правило по гейтам `skill-authoring`/`anti-drift`. Авто-промо запрещено.

## Почему отложено

- Нет upstream-реализации — пришлось бы изобретать формат скоринга и хрупкий цикл.
- Ортогонально текущей цели (субагенты/шаблоны).
- Требует непростых guardrails (ложные «уроки» опаснее их отсутствия).

## Зависимости

- Плоскость памяти mAInd и `memory-digest-hook` уже есть — фундамент готов, не хватает только
  безопасного цикла «зафиксировать → всплыть → ручное промо».
