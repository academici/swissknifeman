# P3 — Каталог патологий и детекторы (фаза C)

## Phase Context

Поверх телеметрии P2 строим детекторы патологий прогонов: чистый `core/pathology.py` —
`detect(run_report) -> [finding{code,severity:info|attention,metric,threshold,evidence}]`,
пороги — константы с docstring «эвристика, не откалибровано» (источники: LangSmith/AgentOps/
Helicone-эвристики). Слои: хук = сбор, pathology = оценка, потребители = маршрутизация.
Топ-5 к реализации: file-reread ((total−unique)/total>0.4 при ≥10) · tool-error-loop (≥3 подряд
is_error similar≥0.6) · no-op-run (≥20 tools, 0 файлов/тестов/retrieval) · no-verify
(files_changed>0 и bash.tests==[]) · cache-miss + overthinking (thinking_chars доля >0.6 на
haiku); также retrieval-stuffing, protected-write, static-context, fanout. scope-expansion
недетектируем до план-артефакта (честно пометить); pack-mismatch — в harness agent-packs doctor,
не здесь. Инвариант Detect ≠ Gate (D9): attention → reasons ATTENTION в maind analyze, info →
секция «Эффективность»; патологии никогда не дают RED. analyst digest берёт уроки только при
рецидиве ≥2 из 5 последних сессий (анти-шум). Зависимость: схема run-report SCHEMA=2 из P2.

### P3.1 — core/pathology.py + тесты

**Status:** ⬜ Not started
**Intent:** Реализовать `core/pathology.py`: схема finding + чистая `detect(run_report)` с порогами-константами + тесты.
**Why:** Оценка патологий — общий примитив трёх потребителей (maind analyze, analyst digest, будущие); живёт в core/ по правилу дедупа.
**Scope Included:** детекторы: file-reread, tool-error-loop, no-op-run, no-verify, cache-miss, overthinking, retrieval-stuffing, protected-write, static-context, fanout; схема finding {code,severity:info|attention,metric,threshold,evidence}.
**Scope Excluded:** маршрутизация findings (P3.2/P3.3); scope-expansion (недетектируем до план-артефакта — добор позже: declared paths из плана); pack-mismatch (место — harness agent-packs doctor).
**Inputs:** зависит от P2.2 (схема SCHEMA=2). Пороги: file-reread >0.4 при ≥10 чтений; error-loop ≥3 подряд similar≥0.6; no-op ≥20 tools и 0 новых данных; overthinking thinking>0.6 на haiku; retrieval-stuffing result_chars/4 > 0.25×in и repeated_queries≥2.
**Files:** core/pathology.py · core/tests/test_pathology.py
**Required Reads:** 1) схема run-report SCHEMA=2 (packages/harness/configs/claude-code/hooks/run-report/run-report.py) 2) core/usage.py 3) core/tests/test_usage.py (стиль)
**Implementation Rules:** ⭐ strong-model (opus). stdlib-only; чистая функция без I/O; каждый порог — именованная константа с docstring «эвристика, не откалибровано».
**Code Guidance:** Отсутствующие поля отчёта (SCHEMA=1) → детектор молча пропускается, НЕ исключение; evidence в finding — конкретные числа/имена файлов, не прилагательные; severity только из enum info|attention (никакого critical — Detect≠Gate); тест на каждый детектор + тест «SCHEMA=1 → пустой список без ошибок».
**Validation:** `PYTHONPATH=. python3 -m unittest discover -s core/tests` зелёный; SCHEMA=1-отчёт → пустой список.
**Deliverables:** core/pathology.py + test_pathology.py.

### P3.2 — maind analyze: findings → reasons/«Эффективность»

**Status:** ⬜ Not started
**Intent:** Подключить core.pathology к maind analyze: attention-findings → reasons (ATTENTION), info → секция «Эффективность».
**Why:** Вердикт — зона maind analyze; findings без маршрутизации никто не увидит.
**Scope Included:** вызов detect(); маппинг severity → reasons/секция; вывод.
**Scope Excluded:** изменение критериев RED (RED только от упавших проверок); новые детекторы.
**Inputs:** зависит от P3.1 и P2.4.
**Files:** packages/maind/lib/maind/analyze.py
**Required Reads:** 1) packages/maind/lib/maind/analyze.py (структура reasons/вердикта) 2) core/pathology.py
**Implementation Rules:** Инвариант Detect ≠ Gate: патологии не могут дать RED ни при каком количестве findings; info-findings вердикт не трогают вообще.
**Code Guidance:** Импорт core.pathology с ImportError-фолбэком (standalone) — блок опускается; секция «Эффективность» компактная: code + метрика + порог одной строкой на finding; тест-фикстура с attention-finding → вердикт ATTENTION, с десятью findings → всё равно не RED.
