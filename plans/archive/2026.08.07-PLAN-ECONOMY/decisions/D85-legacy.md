## Решение

**Два ОСТАВШИХСЯ fail-open потребителя раскладки переводятся на резолвер в P2.1 вместе с компилятором:** (а) `packages/task/lib/task/review_policy.py:188` — `except OSError: return budget, "unknown"` заменяется внятным отказом, потому что нерезолвленный носитель под ОБЪЯВЛЕННОЙ раскладкой есть дефект, а не неизвестность; (б) `packages/harness/lib/harness/run/gate.py:168` — множество `required` берётся из спецификации пути по версии раскладки, а не литералом. `## 0. Meta` → `Related Packages` пополняется пакетом `harness`.

## Почему

Оба молчат, а не падают, и оба стоят на живом пути. `review_policy` питает потолок аудит-раундов и `SAME_FINDING_MAX`, то есть ровно тот механизм, который фаза P4 строит заново; собственное решение плана D51 уже объявило, что «`unknown` не является группой», — значит правка есть применение уже принятого правила, а не новое. `harness/run/gate.py` под v2 не увидит НИКОГДА ни фазового файла, ни `handoff.md` (последний уходит с пути исполнителя по D26), поэтому `signature_complete` становится вечно ложным — гейт подписи коммита превращается в декорацию. Молчаливая деградация — тот самый класс дефекта, который план объявил своим главным врагом (P3.6, D47).
