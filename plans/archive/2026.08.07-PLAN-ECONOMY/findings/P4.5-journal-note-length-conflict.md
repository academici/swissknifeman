# P4.5 — конфликт append-only journal и closing lint

> ✅ RESOLVED 2026-08-08 by D141: historical journal bytes сохранены; writer теперь
> отказывает на новой `note > 300` до I/O, а layout-v2 status/linter используют одну
> bounded-проекцию с точным указателем `journal.jsonl:<line>`.

## Наблюдение

После handoff и generated views канонический прогон
`python3 packages/task/scripts/plan-lint.py plans/2026.08.07-PLAN-ECONOMY --baseline HEAD`
дал `0 ERROR / 8 WARN — новых от рабочего дерева: 1`. Новый warning адресует финальную запись P4.5:
поле `note` длиннее лимита Update Log.

Сама запись schema-valid и уже добавлена штатным `task.journal append`. Writer не ограничивает note
до лимита linter'а. Канон журнала запрещает переписывать или удалять существующую строку; sidecar
`journal exception` применим только к historical schema-invalid `friction` и не является механизмом
коррекции prose/длины.

## Что уже сдано

Item-коммит `39bd5e2a` заморозил документ и JSON Schema `return-judgement` v1 и добавил внешние
источники в `docs/reference.md`. Все item Validation команды, структурная проверка schema example и
umbrella docs build прошли. Pre-mutation и pre-final Task Contract дали `allow`.

## Нужное решение

`plan-design` должен выбрать forward-only совместимую семантику: либо добавить объявленный carrier
коррекции/сокращённой Update Log projection без переписывания journal, либо оформить иной
владельческий exception, который не превращает baseline в способ скрыть новый warning. Простое
редактирование строки journal и коммит с `K > 0` запрещены обоими конфликтующими канонами.
