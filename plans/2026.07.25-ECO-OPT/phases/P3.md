### P3.1 — Диагноз листинга: какие скиллы молча не работают (экс-P7)

**Status:** 🟢 Done
**Intent:** Установить, **какие скиллы молча не работают** — то есть чьи описания клиент фактически
выбрасывает из листинга, — и назвать самый дешёвый рычаг починки. Инструмент: фактическая стоимость
листинга и её крупнейшие вкладчики (`/doctor`), пост-бюджетный размер листинга (строка Skills в
`/context`), warning переполнения (`claude --debug`) на 2–3 представительных проектах флота, включая
`flexcrm`. Результат — финдинг с числами, оценённым/снятым списком дропа и зафиксированным порядком
рычагов. Правки текстов описаний в этот item НЕ входят (обоснование — Scope Excluded).
**Why:** Правило D22 отработано, и ответ владельца по OQ-6 (D74) снял премису L2: рычаг — **не**
сжатие описаний. Основание — first-party механика: «The budget scales at 1% of the model's context
window… When the listing overflows, Claude Code **drops descriptions starting with the skills you
invoke least**, so the skills you use most keep their full text» (RAG:✅ 2026-07-25 first-party
`/docs/en/skills` → `findings/P3-skill-desc-and-mcp-limits.md` §1). Замер 2026-07-25: фактический
листинг `flexcrm` — 142 записи / ≈33 026 симв против бюджета ≈10 000 ⇒ **×3,3**; в бюджет влезает
≈43–46 записей, то есть **≈96–99 из 142** идут в модель без описания (RAG:— repo-grounded:
`findings/P3-listing-hygiene-and-vendoring-facts.md` §2 + арифметика
`research/20-P3-listing-hygiene-target-design.md` §1). Дефект, который из этого следует, —
**качества, а не экономии**: исчезают описания РЕДКО вызываемых скиллов, то есть ровно тех, что
держат «на точечный момент». Полевая практика независимо описывает тот же отказ: «large skill
catalogs create description dilution and unstable activation», «the decreased probability of the AI
calling the intended skill» (RAG:✅ 2026-07-25 perplexity-web →
`findings/P3-listing-hygiene-and-vendoring-facts.md` §3). Поэтому item становится **диагностическим**:
без списка (или честной оценки) фактического дропа любой рычаг выбирается наугад. Единственный
носитель истины о пост-бюджетном листинге — клиент: `/doctor` даёт «an estimate of the listing's
context cost and its biggest contributors», строка Skills в `/context` — «the size of the listing
**after the budget is applied**», `--debug` — warning о переполнении (RAG:✅ там же §1).
**Scope Included:** снятие клиентской истины на 2–3 представительных проектах флота, обязательно
включая `flexcrm` (самый нагруженный: 23 плагина) и один малый для контраста: вывод `/doctor`
(стоимость листинга + крупнейшие вкладчики), строка Skills в `/context` (пост-бюджетный размер),

проекта) с приведением ОДНОЙ воспроизводимой команды; список скиллов, чьи описания фактически
дропаются, — снятый из клиентской истины, либо честная оценка «сколько записей теряет описание» с
