# Plan tooling: сверочные гейты `plans/`

Два stdlib-скрипта в `plans/` (не в `packages/task/lib/`, не встроены в `plan_lint.py` —
у каждого свой предмет): `cross-plan-files.py` (межплановые пересечения `Files`) и
`verify-citations.py` (ссылки-доказательства резолвятся до факта). Оба — CLI одной формы:
человекочитаемый отчёт всегда, `--strict` переключает только exit-код.

## `plans/verify-citations.py`

Проверяет ссылки-доказательства вида `` `path:line` ``/`` `path::symbol` `` в `plan.md` и
`phases/*.md` живого плана: файл существует, номер строки внутри файла, символ после `::`
встречается в файле (поиск по имени, БЕЗ AST-разбора).

```bash
python3 plans/verify-citations.py                        # все живые планы
python3 plans/verify-citations.py plans/<PLAN-ID>         # один план (путь ИЛИ голый ID)
python3 plans/verify-citations.py plans/<PLAN-ID> --strict   # exit 1 при любой находке
python3 plans/verify-citations.py --include-archive          # + архивные планы
python3 plans/verify-citations.py --selftest                 # embedded unittest
```

**Читать exit-код:** без `--strict` скрипт всегда возвращает `0` (отчёт — для чтения глазами
или CI-лога, не гейт); с `--strict` — `1`, если хотя бы одна ссылка не резолвилась, иначе `0`.

**Проверяемые формы** (ссылка — ОДИН токен внутри одинарных бэктиков):
- `` `path/to/file.ext:123` `` — строка внутри файла;
- `` `path/to/file.ext:123-145` `` — диапазон строк;
- `` `path/to/file.ext:123,145` `` — пара несмежных строк;
- `` `path/to/file.ext::symbol` `` — имя символа есть в файле. `a::B::c` — гейт грепает
  ТОЛЬКО лист `c` (без разбора вложенности класс/метод) — граница инструмента, а не баг:
  «валидация символа» здесь означает «имя встречается в файле», не «сигнатура совпадает».

**Путь обязан содержать `/`.** Короткая форма без каталога (например, `` `phases/P1.md:80` ``
как продолжение перечисления после полного пути чуть раньше в прозе) НЕ резолвится
эвристикой восстановления подразумеваемого контекста — гейт находит её отсутствующей и
печатает как находку. Это осознанная граница (Code Guidance P10.2, анти-подгонка): машина не
угадывает, что имел в виду автор прозы.

**Известные исключения** — ссылки на пути ВНЕ репозитория (например, файл npm-зависимости,
прочитанный напрямую при RAG-верификации) или на деливерабл БУДУЩЕГО item'а, которого на
этом дереве ещё нет по построению. Данные, не код: `plans/verify-citations-known-exceptions.json`
(если файла нет — исключений нет, что и означает пустой отчёт по умолчанию):

```json
{
  "exceptions": [
    {"citation": "path/to/file.ext:123", "reason": "почему это не дефект"}
  ]
}
```

**Тесты** — `python3 plans/verify-citations.py --selftest` (embedded `unittest`, отдельного
файла в `packages/task/tests/` нет: скрипт stdlib-only и самодостаточен, той же формы, что
`plans/cross-plan-files.py`).

## `plans/cross-plan-files.py`

См. докстринг файла — сверка `Files` между живыми планами, `--strict` baseline-режим против
`cross-plan-known-intersections.json`.
