# P3 — Implement control-plane, provider-skill adapters, and evidence boundaries

## Phase Context

P3 implements the frozen P1/P2 semantics without letting either provider become a source of
canonical intent. P0–P2 and the files `provider-control-plane-v1.md`,
`locale-resolution-v1.md`, `english-authoring-overlay-v1.md`,
`locale-authoring-review-v1.md`, `skill-core-v1.md`, `provider-skill-adapter-v1.md` and
`skill-evidence-v1.md` are terminal/frozen. P3.1 is the active producer; P3.2 may start only
after its terminal readback and P3.3 only after P3.2 terminal readback. The existing
`core/provider` config, manifest, registry and artifact-lock modules remain authoritative for
the semantics they already own. A new control-plane layer composes their typed results into an
immutable desired snapshot, while each package adapter observes and applies only its own
projection. Items are sequential: P3.2 consumes P3.1's resolver, and P3.3 consumes the
readbacks from P3.2. The phase writes no fleet migration, locale content, credential, user
override or cross-provider target.

P3.2/P3.3 are one logical item each but not one-cwd sessions. Their root coordinator follows
`roadmap.md` «Per-cwd execution and evidence carrier»: core/integration stays at repository root,
each Harness/mAInd/Skiller/Task mutation is executed from a fresh package cwd, and only the
coordinator can integrate evidence or close the item.

P3.2 implements additive skill adapters: shared meaning enters once, provider-owned renderers map
discovery/invocation/layout and a registration fixture proves a third provider can join without
editing Claude/Codex adapters. P3.3 replaces single-precedence audit verdicts with typed
observations, connected overlap clusters, independent multi-label signals, evidence-backed
recommendations, typed batch errors, longitudinal residency evidence and provider-qualified
measurement ranges.

**Scope Included:** pure canonical resolver/schema validation; no-write adapter
observe/diff/apply/readback protocol and package-owned provider-skill implementations; generic
provider registration; typed multi-label skill evidence/audit graph; redacted, adapter-scoped
status/drift/ownership/migration diagnostics with deterministic conformance tests.

**Scope Excluded:** changing the P1/P2 contract text or their generated artifacts; creating or
editing canonical project/user configuration; broad consumer migration (P5); Brain/fleet health
claims (P6); localized message content (P4); implicit repair/adoption/revocation; any provider
writing another provider's target.

> **Контракт фазы (contract-first).** Потребляет: terminal P0 evidence; frozen P1/P2 provider-control-plane/Skill Core/adapter/skill-evidence/locale contracts; existing `core/provider` semantics and package projections · Производит: immutable desired snapshot/resolver, additive provider-skill reconciliation/registration boundary, typed audit/status store/diagnostics and conformance evidence for P4–P7 · Границы: no contract rewriting, no provider control in canonical bodies, no semantic action from one heuristic, no fleet migration, translation/content rewrite, credential action or cross-provider filesystem write.
