# P2 — wf-status: консольный статус-репортер workflow-прогонов

## Phase Context

Фаза даёт детерминированную команду `swissknifeman wf status` вместо двух повторяющихся
трений (спека `roadmap/workflow-status-cli.md`): агенты советуют владельцу несуществующую в его
окружении команду `/workflows`, а на запрос «дай детальный статус» каждая сессия заново пишет
импровизированный парсер (жжёт токены, формат каждый раз разный).
Дом движка — пакет **harness** (`lib/harness/wf_status.py`, CLI `harness wf status`), фасад —
корневой router `swissknifeman wf status` → harness (D17, owner-confirmed; зеркалит D10). НЕ копия
bash-артефакта по пакетам: копии дрейфуют (D8).
Формат прогона внутренний и недокументированный, но стабильный — сверен эмпирикой
(`findings/P2-workflow-transcript-format.md`): `journal.jsonl` (события `started`/`result`, БЕЗ
timestamp/label/phase) + `agent-*.meta.json` (мета без метки) + скрипт-sibling
`<session>/workflows/scripts/*-wf_<id>.js` с `export const meta` (декларация фаз). Два расхождения
со спекой закрыты решениями: **D18** — per-agent→phase attribution журналом не выводится, отчёт
показывает декларации фаз + общий прогресс агентов (per-phase счётчики опущены осознанно);
**D19** — скрипт лежит НЕ в директории прогона, а в sibling `workflows/scripts/`.
Реализация механическая (парсер + фиксированный шаблон + тесты на фикстуре), но парсер обязан быть
защищённым: unknown-поля игнорировать, при несовпадении формата печатать честное «формат не
распознан», а не трейсбек. Фаза закрыта, когда команда выдаёт стабильный отчёт и `--json`,
интеграционный тест на фикстуре зелёный, а скиллы `task:*` перестали советовать `/workflows`.

**Scope Included (фаза):** защищённый парсер одной transcript-директории (journal + agent-meta +
`export const meta` скрипта) · discovery прогонов (свежие по mtime, `--run`, `--project`) ·
фиксированный текстовый шаблон + `--json` + `--watch` · CLI `harness wf status` + фасад
`swissknifeman wf status` · фикстурная transcript-директория + интеграционный тест ·
прошивка подсказки «статус — `swissknifeman wf status`, НЕ `/workflows`» в существующие скиллы
`task:*` и конструктор workflow · строка статуса в `roadmap/README.md` + корневой CHANGELOG.

**Scope Excluded (фаза):** per-agent→phase attribution (D18 — журнал/мета его не несут; парсинг
`agent-*.jsonl` 0600-транскриптов дорог и хрупок) · чтение тел `agent-<id>.jsonl` · история
прогонов/аналитика (команда про «что сейчас», не журнал плана) · прогоны других машин/сессий
(только локальная FS — ок) · создание скилла `workflow-craft` (это P3; cross-ref в него добавит
P3) · правка самого Workflow-тула Claude Code (вне репо) · авто-вывод grand-total числа агентов
из meta (meta фазы декларирует, не нумерует — % считаем от стартовавших).

### P2.1 — Парсер transcript-директории прогона (journal.jsonl + agent-meta + meta скрипта)

**Status:** 🟢 Done
**Intent:** stdlib-only чистая функция: путь к одной директории `wf_<id>/` → структура статуса
(run id, счётчики агентов started/done/inflight, последние N результатов по 1 строке, флаг
degraded, источники-пути) + локализовать и распарсить sibling-скрипт `export const meta`
(name, description, phases[{title,detail}]).
**Why:** детерминированный парс заменяет одноразовые LLM-импровизации (трение №2 спеки) —
формат внутренний, потому парсер защищённый: несовпадение → «формат не распознан», не трейсбек.
RAG:✅ 2026-07-10 эмпирика (`findings/P2-workflow-transcript-format.md`).
**Scope Included:** чтение `journal.jsonl` (типы `started`/`result`, счёт по `agentId`); чтение
`agent-*.meta.json` (счёт агентов, `agentType`); локализация скрипта по `../../workflows/scripts/
*-<wf_id>.js` (D19) и извлечение `phases[].title/detail` регуляркой; сборка результата (dict);
1-строчная выжимка каждого `result` по упорядоченному fallback (`summary` → `title` → первый ключ
объекта → усечённый repr).
**Scope Excluded:** discovery прогонов (P2.2); рендер/шаблоны/печать (P2.3); CLI (P2.4);
per-agent→phase attribution (D18 — журнал его не несёт); чтение тел `agent-<id>.jsonl` (0600,
дорого, хрупко); `eval`/`exec` JS-скрипта.
**Inputs:** `findings/P2-workflow-transcript-format.md` (раскладка, схемы событий);
`roadmap/workflow-status-cli.md` (§Парсинг, §Ограничения); D18/D19.
**Files:** `packages/harness/lib/harness/wf_status.py` (новый).
**Required Reads:** (1) `plans/SKM-ROADMAP-005/findings/P2-workflow-transcript-format.md`;
