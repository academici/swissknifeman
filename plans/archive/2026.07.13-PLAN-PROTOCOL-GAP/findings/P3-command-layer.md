## 1. Внешний факт: команда БЕЗ пина модели наследует сессию (RAG:✅ 2026-07-14)

Несущий факт item'а **P3.5** (`/task:plan-run` — команда без `model`/`effort`): вся конструкция
стоит на том, что ОМИССИЯ ключей = наследование модели/effort сессии, а не откат к какому-то
дефолту. D18 ссылался на `findings/P0 §1`, где прямо этот случай (омиссия) не проверялся —
выводился из «`model` пинит модель на исполнение команды». Проверено отдельно.

- **Движок:** `perplexity-web` (`search_advanced`, sources=web), 2026-07-14.
- **Запрос:** «Claude Code custom slash command frontmatter: is `model` optional? If frontmatter
  omits `model`/`effort`, does the command run under the current session's model and effort?»
- **Источник:** https://www.buildthisnow.com/blog/guide/mechanics/claude-code-custom-slash-commands
  (цитирует официальную frontmatter-таблицу skills/commands docs.claude.com).

| Факт | Вердикт | Следствие для дизайна |
|:--|:--|:--|
| `model` во frontmatter команды/скилла — **необязателен** (Required: No; из всех полей рекомендован только `description`) | ✅ подтверждено | `plan-run.md` легален без `model` |
| Омиссия `model` ⇒ **override не ставится, сессия продолжает работать на своей модели** (док: override действует «for the rest of the current turn», не сохраняется; при недоступной модели «the session keeps its current model») | ✅ подтверждено | Гейт `plan-run` сверяет ФАКТИЧЕСКУЮ модель сессии — это и есть модель исполнения |
| `effort` — док прямо: «Overrides the session effort level. **Default: inherits from session**» | ✅ подтверждено | Омиссия `effort` ⇒ effort сессии |
| `model: inherit` — **документированное явное значение** («Accepts the same values as /model, or `inherit` to keep the active model») | ✅ подтверждено (новое к P0 §1) | Развилка «омиссия vs `model: inherit`» — решена в пользу омиссии (D43): у `effort` литерала `inherit` нет, симметрия дороже явности; омиссия верифицирована обоими полями |

**Не изменилось** относительно `findings/P0 §1` (RAG:✅ 2026-07-13): API смены модели сессии
изнутри команды/агента по-прежнему нет ⇒ routing-гейт остаётся ОТКАЗОМ, а не переключением
(D1/D3 в силе).

## 4. Repo-grounded: манифест плагина команды не перечисляет

`packages/task/.claude-plugin/plugin.json` → `"commands": ["./commands"]` — КАТАЛОГ, не список.
Новый файл `commands/plan-run.md` регистрируется автоматически; правки манифеста для регистрации
НЕ требуется. Но поле `description` манифеста перечисляет команды прозой
(`/task:plan-design|plan-exec|plan-close|plan-audit`) — его дописать нужно (иначе провенанс врёт).

Та же правда о SSOT: `SKILL.ru.md` §13 «Командный протокол» — таблица ЧЕТЫРЁХ команд. Пятая
команда, не попавшая в §13, = расхождение SSOT (правило двух SSOT, §2 Execution Rules плана) ⇒
правка скилла + регенерация EN-канона + `skiller registry` — терминальный item фазы (P3.6, D42).
