### O1 — отказ по РАЗМЕРУ файла (жёсткий, ноль контента)

Файл: `plans/2026.08.07-PLAN-ECONOMY/plan.md`, **306751 байт**. Вызов: чтение целиком, без
`offset`/`limit`.

```
File content (299.6KB) exceeds maximum allowed size (256KB). Use offset and limit parameters to read specific portions of the file, or search for specific content instead of reading the whole file.
```

Контента не возвращено вовсе. Арифметика единицы: `306751 / 1024 = 299.56` → «KB» сообщения есть
**KiB (1024 байта)**, значит заявленный кап `256KB` = **262144 байта**. Проверка на втором файле
прошлой сессии: `321084 / 1024 = 313.56` → сообщение «313.6KB» (совпало).

## 4. Воспроизведение пробных файлов

```python
import hashlib, pathlib
# многострочный плотный (O3): 169000 байт, 2601 строка
pathlib.Path("probe-token-dense.txt").write_text(
    "\n".join(hashlib.sha256(str(i).encode()).hexdigest() for i in range(2600)) + "\n")
# однострочный плотный (O4, O5): 128001 байт, 1 строка
pathlib.Path("probe-single-line.txt").write_text(
    "".join(hashlib.sha256(str(i).encode()).hexdigest() for i in range(2000)) + "\n")
```

## 5. Пары «файл → счёт среды» (cross-check, НЕ калибровочные точки)

Счёт берётся счётчиком СРЕДЫ ЧТЕНИЯ и по D15 остаётся перекрёстной проверкой: калибровать по нему
оценщик P0.1 запрещено (P0.1 откалиброван против `usage` транскриптов — другой измеритель).

| Файл | Байт | Символов | Счёт среды | Оценка `task.token_estimate` | Отношение факт/оценка |
|:--|--:|--:|--:|--:|--:|
| `probe-token-dense.txt` (hex, 2601 стр.) | 169000 | 169000 | 111254 | 56415 | **1.972** |
| `probe-single-line.txt` (hex, 1 стр.) | 128001 | 128001 | 82901 | 41095 | **2.017** |
| `phases/P0.md` (русский markdown) | 77935 | 51060 | ≤ 25000 (прочитан целиком) | 26143 | ≤ 0.957 |

Счёт среды относится к ОТРЕНДЕРЕННОМУ выводу чтения (строки идут с номерами), а не к сырому байтовому
содержимому файла; для многострочного файла префиксы номеров входят в счёт.

**Наблюдение, опровергающее границу вне корпуса калибровки:** на плотном ASCII (hex-прогоны без
пробелов) оценщик P0.1 ЗАНИЖАЕТ счёт примерно вдвое, тогда как его заявленное свойство —
«никогда не занижает». На реальной прозе плана граница держится (третья строка). Класс контента, а не
модель, объясняет разрыв: калибровочный корпус P0.1 — 14 файлов планов флота (проза + таблицы), ставка
класса `ascii_word` = 0.295 токена на символ, тогда как случайный hex токенизируется примерно
1 токен на 1.5 символа.

## 6. Что этот замер НЕ доказывает

- Не доказывает, что гейтов ровно два: наблюдались два, третий (например, по числу строк) зондом не
  искался.
- Не даёт точного счёта среды для файлов НИЖЕ капа — среда его не сообщает (O6).
- Не переносится на другую среду и другую дату: и `262144`, и `25000` — свойства ЭТОГО харнеса на
  ЭТОТ день (ровно поэтому D15 требует артефакт, а не литерал).
- Не является калибровкой: пары §5 сняты счётчиком среды чтения, а не токенизатором модели.
- Не измеряет долю плотного ASCII на реальных обязательных путях чтения флота — это предмет P0.3/P0.4.
