### P5.5 — Доказать queue semantics исполняемым producer-based acceptance

**Intent:** После D146 и финального owner-authorized remediation расширить executable P5.5 acceptance так, чтобы fresh-copy producers доказывали не только happy path policy/owner, но и single-use terminal auto-answer (никаких последующих claim/response) при сохранении единственного разрешённого owner-flow `pending-authorization`, authorization reclassification, обе substantive-option границы, mandatory-only reject и one-shot request/resolve projection failure с exact retry; затем детерминированно проверить queue/journal/item/status/owner-gate/join observations и повторить detached item-tree replay. RAG:— (repo-grounded: Audit P5, заход 3; `P5.md` finding 1).
**Why:** Четыре прежних scenario зелёны, но не различают blocked state от pending owner/join truth, не входят в option bounds и не проходят error→retry path. P5.5 остаётся closing consumer P5.4 и должна доказать одно semantic состояние на всех публичных surfaces, не меняя frozen P4/P5 contracts. RAG:— (repo-grounded: последний Audit P5 findings 1–3; current `artifacts/P5/validate_acceptance.py`).

**Implementation Rules:**
- Acceptance начинает каждый scenario с новой временной копии baseline fixture и вызывает реальные producers. Чтение заранее решённой committed queue допустимо только как вход regression fixture и никогда не удовлетворяет acceptance predicate. RAG:— (repo-grounded: Audit finding 4).
- Policy scenario вызывает `plan_authority.auto_answer_clarification()` и `plan_requests.append_auto_answer()` полной contract pair; проверяет `resolver=policy`, verified provenance, before/after/reclassification digests, semantic resolution и свежие views. Ручная запись auto-answer JSON запрещена. RAG:— (repo-grounded: frozen clarification contract; D144).
- Terminal policy auto-answer с semantic outcome `apply|park|reject|escalate` одноразовый: public `claim()` и `resolve()` отвергают последующие owner ingress без queue delta, а reducer отвергает hand-written поздние `claim`/`response` как corrupted carrier. P5.5 producer acceptance доказывает реальный policy `apply`; unit regression обязан перебрать все четыре terminal outcome. Только `reclassified_to=authorization` остаётся `pending-authorization` и сохраняет owner claim→response flow. RAG:— (repo-grounded: Audit P5, заход 3 finding 1; frozen decision-request v1 single-use rule).
- Отдельный policy scenario подаёт producer input, который после ответа переклассифицируется в `authorization`; он обязан остаться blocked и одновременно присутствовать в `pending_groups()`, `unresolved_for_phase()`, `decisions/_gates.md` и opt-in phase join. Проверить лишь `.state.md` недостаточно. RAG:— (repo-grounded: D146; audit-2 finding 1).
- Owner scenarios создают реальный return-loop request через P4→P5 adapter, claim и `resolve()` для отдельных свежих copies: `continue/apply` возобновляет exact root и ставит subject `in-progress`; `park` и `reject` не возвращают continuation и оставляют ровно target subject blocked; unrelated subject не меняется. RAG:— (repo-grounded: D144 outcome table).
- Option-bound scenarios создают requests реальным writer: ровно 2 и 5 substantive + mandatory проходят, mandatory-only падает до append. Results отдельно несут `substantive_count`, `mandatory_ids` и queue delta. RAG:— (repo-grounded: D146; frozen schema options).
- Error scenarios инъецируют one-shot failure только в projection seam: request retry оставляет ровно один request и восстанавливает blocked state/gates; resolve/apply failure не возвращает/не сохраняет continuation, exact retry оставляет ровно один response и только после свежести трёх views возвращает continuation. Другой payload под тем же id обязан по-прежнему падать.
- Results JSON содержит scenario ids, observed outcomes, substantive/mandatory counts, queue event counts, latest journal result, subject statuses, pending/unresolved/join verdicts, gate freshness, retry count, continuation modes и frozen input digests; report строится только из results. Embedded artifact version поднимается; оба файла детерминированы, `--check` пересчитывает fresh copies и сравнивает bytes. Wall-clock/temporary paths/random ids в output запрещены.
- Volatile `at` и temp paths проверяются на форму/связность, но не попадают в normalized results; producer-call assertions и pinned input digests не дают детерминизму превратиться в чтение статического fixture. RAG:— (repo-grounded: `research/22-…` pre-mortem).
- Первая строка report честно называет границу: synthetic Layout-v2 scenarios доказаны; P6 command integration/live fleet не доказаны. Метрики остаются раздельными, без вывода «весь протокол работает».
- Validator/bootstrap явный: `PYTHONPATH="$PWD:$PWD/packages/task/lib"`; cwd — repository root. Все acceptance artifacts входят в item commit P5.5 до bookkeeping. Detached replay использует этот hash и не читает последующий tree.
- Frozen contracts/config D143/P4 artifacts, P6, чужие планы и `packages/artifex` read-only. Несовпадение frozen форм — escalation, не fixture edit.
**Code Guidance:** Acceptance script — исполняемый oracle, не generator prose. Каждый claim обязан происходить из assertion над real producer events, journal и тех же generated views. One-shot failure вводится monkeypatch'ем projection function, не ручной queue/journal записью. Старый committed queue остаётся только regression input.
