## 4. Сверка обнаружения (машинная, перед сокращением)

Скилл уходит из блока, только если подтверждён ДВУМЯ независимыми условиями:

1. он в активном наборе ИЗМЕРИТЕЛЯ — `budget.resolve_active_set` (источник, названный ТЗ);
2. он доставлен КАНАЛОМ, который Claude Code перечисляет нативно: включённый плагин
   маркетплейса (состав скиллов берётся из `.claude-plugin/marketplace.json` — того же
   файла, что читает клиент, а НЕ из отображения «бакет → реестр», по которому строится
   сам индекс: иначе сверка проверяла бы себя) либо физическая копия в `.claude/skills`.

Конъюнкция строго сильнее требования ТЗ. Неподтверждённые скиллы **остаются перечисленными**
разделом «Скиллы вне нативного листинга», а расхождение печатается в вывод команды.

**Внешняя проверка источника 2 на живом клиенте** (`claude plugin details core@swissknifeman`,
cwd = agelto): `Skills (9)  anti-drift, compact-responses, context-economy, gh-review,
mcp-advisor, plan-protocol, query-craft, session-handoff, verify-claims` — ровно тот же
набор из девяти имён, который даёт наш офлайн-резолв плагина `core` по `marketplace.json`.
Плагин `task@swissknifeman` клиент показывает как `Skills (11) design, dev, fix, …` — это
команды пакета `task`, в `skills.json` их нет, и в индекс блока они не попадали никогда.

**Что ушло из блока agelto и где оно теперь.** Из 128 имён старого блока в нативном наборе
проекта сегодня присутствуют 9 (перечислены выше, канал — плагин `core`); остальные 119
не доставляются в проект НИ ОДНИМ каналом — их плагины выключены, поэтому они исчезают и
при полной форме (п. 3, контрольный прогон `--full-index`), а не из-за сокращения.
Форм-зависимого удаления на пилоте не было: сегодняшний индекс пуст, множество
«сокращено формой» = ∅. Непустая сверка предъявлена на flexcrm/dterema/app (п. 3).

## 5. Найденные дефекты (вход для P2.6/P3, здесь НЕ чинились)

1. **`resolve_active_set` слеп к каналу плагинов.** Он резолвит vendor-выборку по конфигу
   проекта и не читает `enabledPlugins`: у agelto даёт 86 скиллов против 20 фактически
   доставленных клиентом; у flexcrm из-за этого 42 из 116 подтверждённых плагином скиллов
   остаются перечисленными в краткой форме (безопасный ложноотрицательный исход — цена
   консервативности). Пока это не починено, экономия P2.6 на connect-проектах будет ниже
   потенциальной.
2. **Курируемые/пакетные плагины не разворачиваются в бакеты реестра.** `core@` и `task@`
   не являются бакетами `skills.json`, поэтому индекс блока для проекта, подключённого
   ТОЛЬКО ими (agelto), пуст, а прежний генератор на таком проекте падал
   («не найдено установленных скиллов») — то есть хаб agelto нельзя было перегенерировать
   вообще. Гейт стал КАНАЛЬНЫМ (раздача есть → блок пишем, индекс может быть пуст;
   пустой индекс у цели БЕЗ нативного листинга даёт WARNING).
3. **16 проектов реестра держат протухший штамп хаба** (`skiller doctor`: flexcrm, sova,
   corex, memster, cms, edufy, dterema, app, chatom, perplexity-web-mcp, loqum и дубли
   записей) — предмет P2.6, здесь не трогалось. agelto из этого списка вышел.

## 6. Вердикт для P2.6

Раскатка на флот **разрешена** с оговорками:

- эффект формы реален и велик там, где индекс непуст (−52 % / −80 % блока на двух
  измеренных проектах); на проектах с протухшим или пустым индексом основную дельту даёт
  сама перегенерация — в отчёте P2.6 эти два эффекта обязаны стоять разными колонками;
- проекты с раскладкой без плагинного канала (`.ai/skills`/`.cursor/skills` без
  `enabledPlugins`) сокращения не получают автоматически: их скиллы не подтверждаются
  условием 2 и остаются перечисленными — отдельный класс строки отчёта, а не «пропущен»;
- откат на всём флоте — одной командой `generate-hub.sh --target <проект> --full-index`.
