## 1. Layout v2 carrier repair

Layout v2 keeps identity/context/rules/routing plus decision and contract pointers in
`plan.md`. Item outcomes and the Update Log are journal-backed generated views in `status.md`.
The inline `## 6. Update Log` is therefore removed from `plan.md`; its last semantic event is
already present in the append-only journal/status projection and is not copied elsewhere.
RAG:— (repo-grounded: `packages/task/lib/task/plan_migrate.py:_render_core`,
`packages/task/lib/task/plan_lint_checks/parsing.py`)

## 2. Bundle freshness order

P0.8 has already appended four P0.1–P0.4 correction events. Those rows changed bundle inputs,
so bundle regeneration must happen only after the new P0.6 correction event is appended and the
P0.6 declaration is final. The owner command is `plan-views.py bundle --item`; the exact stale
set is resolved by lint and regenerated individually, never by editing JSON. State/status and
decision projections follow the same owner-only rule. RAG:— (repo-grounded:
`packages/task/lib/task/plan_gates.py:lint_bundle_freshness`,
`packages/task/scripts/plan-views.py`)

## 4. D74 anti-displacement verdict

**Verdict: no displacement.** The before graph duplicated the full P0.2 corpus as P0.6 model
context even though P0.6 neither adjudicates paths nor consumes their bodies. The after graph
retains every fact used by P0.6, keeps the full corpus in machine validation with the same digest,
and leaves row semantics under P0.2. Acceptance must print the measured before/after aggregate;
if the consumer read-set expands or machine validation stops reading the full corpus, this verdict
becomes false and P0.8 must block. RAG:— (repo-grounded: `root/contracts/read-budget-v1.md` §5,
consumer read-set in §3)

## 5. Forward provenance

Changing P0.6's model-facing declaration after its terminal event is visible provenance, not a
historical rewrite: D69 records the reason and cost; P0.8 appends one correction event carrying
old/new declaration digests and the original item commit; generated state and bundle views then
reconcile from the journal. The old bytes remain reachable in Git and the P0.8 ledger.
RAG:— (repo-grounded: D66, `artifacts/P0.8/execution-provenance-v1.json`, append-only journal)
