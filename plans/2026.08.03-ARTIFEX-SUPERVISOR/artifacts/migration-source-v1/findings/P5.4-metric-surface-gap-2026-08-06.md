## F9 — the candidate lane records provider usage as BOOLEANS, not integers

`root/contracts/economy-evidence-v1.md` (`declared-set: metric_fields`) requires, per attempt and
per lane, seven values on BOTH `worker` and `coordinator`:

```text
input_tokens · cached_input_tokens · output_tokens · reasoning_tokens
cost_microunits · duration_ms · turns
```

with «A measured value is a non-negative integer. An unavailable value is null and requires one
non-empty, source-specific entry in `unknown_reasons`. Unknown is not zero.»

The candidate lane, as built and frozen into G2B, exports none of them. Both provider folds
reduce the provider's own usage object to a presence flag:

```
$ grep -rn "usage" packages/artifex/lib/artifex/providers/*.py
providers/codex.py:103:    return {"event_type": event_type, "usage_observed": isinstance(record.get("usage"), dict), ...
providers/codex.py:121:            "usage_observed": any(row.get("usage_observed") for row in normalized)}
providers/claude_code.py:154:        "usage_observed": isinstance(record.get("usage"), dict),
providers/claude_code.py:155:        "cost_observed": isinstance(record.get("total_cost_usd"), (int, float)),
providers/claude_code.py:211:            "reason_code": "OK", "event_count": 1, "usage_observed": ..., "cost_observed": ...,
```

`fold_records` / `fold_business_records` return `usage_observed`, `cost_observed`,
`session_observed`, `turn_observed` — four booleans. No token count, no cost value, no duration,
no turn count reaches evidence. The `usage` key on a D105/D122 admission
(`business_dispatch.py:119`) is slice bookkeeping (`{"used_slices", "max_slices", "reusable"}`),
not tokens. `artifacts/P5/repository-pilot-results-v2.json` confirms the end state: every slice
carries `"dispatch_business": {"intent_written": false, "usage": 0}` and no metric object at all.

Consequence: a P5.4 wave dispatched through the current G2B seam produces **zero** integers for
`economy-evidence-v1`. Every metric field is null → `unknown_reasons` → «A missing token/cost
input disables only the dependent branch» → `BRANCH1_UNKNOWN` **and** `BRANCH2_UNKNOWN` →
terminal `NO-GO`, exactly as D25 froze. This is a producer-side gap, not a privacy rule: the same
contract's privacy section explicitly names «typed counts, units, source references, hashes,
stable IDs, exit-class references, and unknown reasons» as durable, so token and cost integers are
permitted evidence. The paths that would have to change (`providers/{codex,claude_code}.py`,
`activity.py`) are literal members of D108's own `exact scope` list and therefore P5.5-owned
producer surface (D119: any `packages/artifex/**` byte is by construction part of the G2B
generation), never P5.4's.

## F10 — no single provider exports all seven fields, so `parity` mode can never be complete

RAG:✅ 2026-08-06 (`perplexity-web`, official non-interactive-mode docs for both CLIs; sources:
`learn.chatgpt.com/docs/non-interactive-mode` for Codex, Claude Code session/JSON usage-object
documentation) cross-checked against first-party local evidence
(`.claude/runs/*.json` usage objects on this machine export exactly
`{in, out, cache_read, cache_creation}` — no reasoning field, no cost field) and against
`packages/artifex/lib/artifex/providers/claude_code.py:15,155`, which reads `usage`,
`total_cost_usd`, `num_turns` from the Claude result record.

| `economy-evidence-v1` field | claude-code (`-p --output-format json`) | codex (`exec --json`) |
|:--|:--|:--|
| `input_tokens` | ✅ `usage.input_tokens` | ✅ `usage.input_tokens` |
| `cached_input_tokens` | ✅ `usage.cache_read_input_tokens` | ✅ `usage.cached_input_tokens` |
| `output_tokens` | ✅ `usage.output_tokens` | ✅ `usage.output_tokens` |

| `cost_microunits` | ✅ `total_cost_usd` | ❌ **not exported** — no cost field in `turn.completed.usage` |
| `duration_ms` | ✅ `duration_ms` (also wrapper-measurable) | ⚠️ wrapper-measurable only |
| `turns` | ✅ `num_turns` | ⚠️ event-derived only |

Each provider is missing exactly one field the other has, and the two gaps are structural, not
configuration:

- Claude's missing `reasoning_tokens` cannot be recovered — the Anthropic surface does not
  separate it; it is definitionally a subset of `output_tokens`.
- Codex's missing `cost_microunits` cannot be recovered without a price lookup, which P5.4's own
  Scope Excluded («price lookup or imputation») and D25 («ноль не импутируется») both forbid.

Consequence: under `provider_scope.mode = parity` (which P5.4's Implementation Rules require for
terminal success — «Terminal success requires both providers … и literal `GO`»), the pooled
candidate lane always carries at least one null token field and one null cost field, so both D14
branches are disabled by the contract's own unknown rule. **`GO` is unreachable in parity mode by
construction**, with any budget, any gate repair and any incumbent lane.

The contract does provide the escape: `provider_scope.mode = single-provider` is «eligible only
with a non-empty prior Owner D# reference and never implies parity». A claude-code-only economic
lane supplies six of seven fields as measured integers, with `reasoning_tokens` the sole gap —
and that gap is a *definitional* one (the tokens are inside `output_tokens`, so the token TOTAL,
which is what both D14 formulas actually divide, is complete and correct). Declaring that
semantic is nevertheless a change to the contract's unknown rule, which its own change policy
classifies as MAJOR («A major change adds, removes, or renames a required field, formula,
verdict, reason class, privacy class, denominator, threshold, or **unknown rule**») — i.e. an
owner-authorized `economy-evidence-v2`, not an executor's reading.

## F11 — the codex sandbox mitigation that would have preserved `network-disabled` is unavailable here

F7 left the codex lane on an owner security decision: the only verified path to a working codex
write is `--dangerously-bypass-approvals-and-sandbox`, which forfeits the `network-disabled` /
`SEC-WORKTREE` guarantee on a host with confirmed outbound network. The obvious compensating
control — running the codex process inside an externally-created network namespace so the
guarantee holds without codex's own bwrap — was tested first-party on this host and does not work:

```
$ unshare -rn true
unshare: write failed /proc/self/uid_map: Operation not permitted   (rc=1)
$ unshare -n true
unshare: unshare failed: Operation not permitted                     (rc=1)
```

Same root cause as the recorded `bwrap: loopback: Failed RTM_NEWADDR: Operation not permitted` —
unprivileged user/network namespaces are restricted on this kernel. So F7 is a genuine binary
owner trade-off (accept the bypass and lose the network guarantee, or exclude the codex lane);
there is no third technical option to recommend.

## What this changes for the P5.4 re-design

F8 asked «who produces the incumbent side». F9/F10 establish that the **candidate** side has no
numbers either, and that no provider pair can fill the frozen field set. The ordering of the
forward path therefore changes: a baseline-lane grant is worthless until the candidate lane
exports integers (P5.5 producer scope, D108) and until the owner rules on the parity/field gap
(frozen-contract scope, P1.5). Both are upstream of every dispatch, and neither is inside P5.4.
