## 3. Proof-class enforcement demonstrated against the two named pinned quantities

`reliability-acceptance-v1.md` § "The proof-class rule, enforced rather than restated"
names exactly two quantities as `pinned-not-recomputable`/excluded-by-construction:
`journals.classified_lifecycle_events` (550) and `dedup_correction.corrected` (135 110 000
input tokens and siblings), both from
`artifacts/source-evidence/precomputed/baseline.json`. Building a `MetricRecord` for
`classified_lifecycle_events` with `baseline_proof_class="pinned-not-recomputable"` and
attempting to pair it against any candidate raises
`METRIC_PINNED_BASELINE_FORBIDDEN` — verified live against this tree:

```
$ PYTHONPATH=packages/analyst/lib python3 -c "
from analyst.metrics import build_metric_record, pair_metric, MetricError
pinned = build_metric_record('classified_lifecycle_events', numerator=550, denominator=591,
                             baseline_proof_class='pinned-not-recomputable')
candidate = build_metric_record('classified_lifecycle_events', numerator=1, denominator=1,
                                baseline_proof_class='recomputed')
try:
    pair_metric(pinned, candidate)
except MetricError as exc:
    print('REFUSED:', exc)
"
REFUSED: METRIC_PINNED_BASELINE_FORBIDDEN: 'classified_lifecycle_events' baseline is 'pinned-not-recomputable'; cannot be a recomputed comparator (D30)
```

This is the same discipline `task.task_contract.DETERMINISTIC_PROOF_CLASSES =
("recomputed", "cross-checked")` already enforces on a different boundary
(pre_mutation/pre_final evidence, not metric pairing) — `analyst.metrics` defines its
own closed `PROOF_CLASSES`/`COMPARABLE_PROOF_CLASSES` rather than importing `task`
(analyst does not depend on `task` hard, mirroring `doctor.py`'s existing optional
`task.route_evidence` check), because the two boundaries are distinct and this
contract's own reason codes (`METRIC_*`) are never re-minted from another module's
(`unified-agent-trace-v1.md` § "Reason codes are never re-minted" — the same principle
applied one level down).

## 4. Slicing and digest shape

`slice_by(entries, axis)` groups `{'project_id', 'trace'}` entries by `project`/`plan`/
`item` — the three axes Scope Included names. `project_id` is **not** a field of the
frozen `TraceRecord` (`unified-agent-trace-v1.md` § Field set closes the set at 13 keys;
`project_id` is consumed one-way into `trace_id`'s hash and never stored), so this
module's slicing operates on its own aggregation wrapper rather than widening the frozen
schema — a real design constraint discovered while implementing this item, resolved
without a D# because it does not touch `unified-agent-trace-v1.md`'s closed field set
(a widening would have needed one; a caller-side wrapper does not).

`build_digest(pairs, generated_at=..., slices=..., regression_tolerance=...)` returns the
one compact JSON shape Code Guidance asks for ("One CLI/digest, no dashboard"):
`schema_version`, `generated_at`, `pairs`, `slices`, `anomalies`, `overall_completeness`.
`find_anomalies` never flags a `deferred` pair (no candidate ⇒ nothing to compare), so an
all-deferred digest — exactly what this tree can produce today — reports zero anomalies
rather than a false regression signal.
