# P3.2 provider projection scope conflict — 2026-08-12

## Signal

The declared `bash packages/task/scripts/validate.sh` validation was reproduced after
the canonical P3.2 command flow and focused tests changed. It failed in three generated
provider-parity tests:

- `test_claude_command_adapter.ClaudeCommandAdapterTests.test_independent_golden_equals_the_committed_claude_surface`;
- `test_claude_command_adapter.ClaudeCommandAdapterTests.test_invocations_and_projection_bytes_are_exact`;
- `test_provider_command_parity.ProviderCommandParityTests.test_generated_operator_reference_matches_validated_report`.

The failures compare the changed canonical `packages/task/commands/plan-*.md` sources
with stale generated Claude command projections and the operator reference.

## Classification

This is not a test-environment failure: the focused P3.2 command suite passed 85 tests,
while the package validator deterministically rejects stale generated outputs. Regenerating
those artifacts is a protected generated-asset write outside P3.2 `Scope Included`; P3.2
explicitly excludes provider generated files and P5.3 owns their parity release.

The required validation and the item scope therefore conflict. A local repair cannot expand
P3.2 into a provider-projection change. The candidate is nonterminal and requires a
plan-design decision that either brings the generation into the owning item or changes the
validation boundary without weakening provider parity.

## Reproduction

```bash
bash packages/task/scripts/validate.sh
```

Result: `Ran 843 tests in 11.847s`, `FAILED (failures=3, skipped=1)`; all three failures
above are byte-parity mismatches. The source changes are intentionally retained in the
worktree and have not been committed because P3.2 requires green package validation before
its product commit.
