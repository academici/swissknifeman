# Вес обязательного чтения по флоту планов — первичный замер (2026-08-07)

**Слой 1 (сырьё, first-party).** Сессия: claude-opus-5[1m]/high. Все числа получены в этой сессии
командами, приведёнными ниже, и воспроизводимы на том же дереве. Внешних фактов здесь нет.

RAG:— (repo-grounded: замеры выполнены по файловой системе рабочих каталогов владельца).

## 1. Что такое «пол холодного старта»

`packages/task/commands/plan-exec.md` п.1 задаёт порядок чтения исполнителя ДОСЛОВНО и запрещает
что-либо сверх:

```
1) plans/<PLAN-ID>/plan.md — Context, Execution Rules, §3 Routing, Status Board;
2) plans/<PLAN-ID>/handoff.md — где мы;
3) plans/<PLAN-ID>/phases/Pn.md — Phase Context + твой item Pn.m целиком;
4) файлы из Required Reads item'а — в указанном порядке.
Повторное чтение уже прочитанного ЗАПРЕЩЕНО (экономия контекста) […]
Всё нужное обязан нести план
```

Первые три позиции не зависят от того, ЧТО делает пункт: их платит каждый срез. Это и есть пол.
Оценка в токенах — деление байтов на 3.5 (смешанный RU/EN markdown); точность оценки ±15%, для
порядка величины достаточно, а точный счёт — работа P0 этого плана (`count_tokens`, не эвристика).

## 5. Required Reads не ограничены ничем

`2026.08.03-ARTIFEX-SUPERVISOR` P5.4: **28 позиций, ≈380 КБ** суммарно. Пишутся прозой руками, без
хешей, без проверки существования, без потолка. Средний вес Required Reads по 93 пунктам
EDUFY-BUILD — 50 КБ; у 13 пунктов — выше 150 КБ, причём не из-за длины списка (максимум 6 позиций),
а потому что позиции указывают на сам фазовый файл и `plan.md`.

## 6. Линтер размера не видит

`python3 packages/task/scripts/plan-lint.py plans/2026.08.03-ARTIFEX-SUPERVISOR --baseline HEAD`
на плане с полом 585 КБ печатает:

```
plan-lint: OK (1 план(ов), 0 ошибок, 0 предупреждений; новых от рабочего дерева: 0)
```

Ни веса чтения, ни размера отдельного файла, ни разрешимости Required Reads линтер не проверяет.

## 7. Дефект КОРРЕКТНОСТИ, а не только экономии

Инструмент чтения этой среды отказывает на файле больше ~25к токенов:

```
File content (59596 tokens) exceeds maximum allowed tokens (25000).
Use offset and limit parameters to read specific portions of the file […]
```

`plan.md` ARTIFEX — 91к токенов, EDUFY-BUILD — 103к, `phases/P0.md` EDUFY-BUILD — 45к. То есть
предписанное «прочитай `plan.md`» физически неисполнимо на этих планах: исполнитель читает
ВЫБОРОЧНО, на своё усмотрение (в этой сессии — грепом по заголовкам плюс срезы строк). Гарантия
протокола «всё нужное обязан нести план» тихо не выполняется, разные исполнители одного плана видят
разные подмножества, и ни линтер, ни аудит этого не ловят.

Лимит 25к — наблюдаемое свойство ЭТОЙ среды на эту дату, а не константа протокола: в целевом решении
он обязан быть измеряемым параметром, а не литералом.

## 8. Что этот замер НЕ доказывает

Он не доказывает, что пол стоит денег пропорционально своему размеру: значительная часть пола
попадает в кэш промпта и перечитывается по ставке 0.1× (см. `findings/02-prompt-caching-economics-2026-08-07.md`).
Ущерб от пола — прежде всего окно контекста и деградация качества на длинном контексте
(`findings/01-rag-context-engineering-2026-08-07.md`), и только частично деньги. Первоначальная
формулировка «пол × число ходов = стоимость», высказанная в этой же сессии до RAG-проверки, была
завышена и здесь не воспроизводится.
