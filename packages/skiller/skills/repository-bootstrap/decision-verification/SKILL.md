# Decision verification discipline (work ON the package)

Internal skill (not exported). This is **governance for my own work on swissknifeman**: verdicts
and decisions here must not rest on stale knowledge. **Full canon** (engine ladder, confidence,
output format) — registry skill `general/verify-claims`
([packages/skiller/skills/general/verify-claims/SKILL.md](../../../../../packages/skiller/skills/general/verify-claims/SKILL.md));
here only the repo-work activation, **no duplication** of the ladder.

## When to activate

- **Reviewing someone else's audit/plan** (e.g. Perplexity audits in `research/`): any
  verdict/**rejection** on an external fact — even if the audit looked complete.
- **Forming a plan / big planning/design** of a change: choice of approach, library, format,
  integration. A plan rests 100% on fresh data → RAG-confirm external facts BEFORE finalizing;
  close the plan with a "Проверка" footer (unverified → repeat pass).
- **Choosing or updating a dependency/tool/MCP server** (package name, command, still supported).
- **Claiming** "this is current best practice / standard / not done that way anymore".

## Rule (claim classification)

- **Repo/code-grounded** (present in this repo's code/config, "implemented in file Y") →
  confirm by **reading code**, authoritative. No RAG needed.
- **Stable general knowledge** (syntax, established patterns, math) → no verification.
- **External + staleness-sensitive** (versions/APIs, "still current", market, another
  service/MCP, prices) → **verify via RAG** by the canon ladder: `context7` (exact library
  APIs) → on a context7 miss, or anything outside docs — **aggressively `perplexity-web`**
  (flat-rate, token-cheap; native Perplexity MCP with `PERPLEXITY_API_KEY`) →
  `WebSearch/WebFetch` as last fallback → `research/research` for deep dives. Cite source +
  date + confidence; `low` — flag "needs confirmation".
- **Don't drop the ladder on delegation:** delegating verification to a subagent — it
  inherits the ladder AND its engines; a tool-poor delegate (only `WebSearch`, e.g. a
  "Claude Code" agent) silently drops the rung → keep RAG in the main context or give the
  delegate `perplexity-web` (canon: `verify-claims` §"Delegation: don't drop the rung").

Scope: anything that is **not** pure execution of an already-planned-and-verified spec needs
data backing.

## "Проверка" footer + honesty (format — `verify-claims` canon)

- A plan/design/verdict with external facts closes with a **"Проверка"** footer: `RAG:`
  (engines+queries) · `Непроверено → ПОВТОРНЫЙ ПРОХОД:` (engine unavailable — `perplexity-web`
  locked/`TIMEOUT`, MCP down, `context7` empty) · `Обходки/[POSSIBLE-DEFECT]:`. Empty sections
  stated explicitly; silence ≠ "everything verified".
- **No edits for edits' sake:** verification shows a fix isn't needed → drop it from the plan.
  No real solution exists → name the workaround a workaround (`[POSSIBLE-DEFECT]`), don't pass
  a crutch off as a solution.

## Special clause: audit review

For EVERY point decide — is the verdict repo-grounded or external? repo-grounded → confirm by
code; external ("the library/server/market already does this", "outdated") → **verify by the
ladder BEFORE finalizing**, even if the audit was "complete". Better safe than rejecting on
stale knowledge.
