### P4.1 — Terminal admission, lease and transcript contract

**Intent:** Introduce one versioned Task terminal-admission state machine that binds an active plan run, its lease/progress, P1.3 continuity result, current delivery receipt and exact proposed final message before allowing terminal output. RAG:— (repo-grounded: `packages/task/lib/task/plan_delivery.py`; `packages/task/docs/continue-first.md`; `decisions/D5-terminal-provider-boundary.md`).
**Why:** `plan-delivery.py` proves that repository bookkeeping and the persisted recommendation are current, but no repository component owns an active-run lease or verifies the actual last assistant message at a stop boundary; a caller can therefore obtain a valid receipt and still emit a false terminal response. RAG:— (repo-grounded: `findings/05-p4-design-baseline.md`; `artifacts/source-roadmap/2026.08.14-p10.6-provider-final-incident.md`).
**Scope Included:** `terminal-admission-lease/v1` and `final-admission-event/v1`; project-local ignored state under `.swissknifeman/task-terminal/`; arm/refresh/check/release CLI; plan/run/session/turn/subject/command identity; monotonic sequence and bounded lease expiry; progress fingerprint; P1.3 `continue-root|cold-start|waiting-owner|terminal` consumption; current terminal/handoff receipt rebuild; exact required final-message comparison; deterministic allow/continue/capability-gap reasons; crash/stale/ambiguous recovery; append-only privacy-minimal event evidence; command/lint/delivery/docs/provider-command integration.
**Scope Excluded:** Provider-specific hook payloads or response JSON (P4.2); a second session-continuity/work-estimate reducer; storing raw transcripts or secrets; parsing free prose to infer plan state; blocking ordinary conversations without an applicable Task lease; unlimited retry loops; automatic owner decisions; claims that repository code intercepts output outside its call sites.

**Implementation Rules:** `terminal_admission.evaluate()` is the only policy owner; provider adapters may normalize inputs and render its verdict but cannot decide terminality. The lease key is the normalized provider session plus Task run identity, never a PID or free-form transcript. Arm occurs only after command/run admission; refresh follows material progress or an explicit waiting-owner decision; release follows an allowed terminal event or named abort. With no applicable lease, a hook returns `not-applicable` and does not block ordinary chat. With an applicable but invalid, ambiguous or stale lease, it records a capability/error verdict and refuses to fabricate `final_allowed=true`; recovery is a named re-arm/resume action. `final_allowed=true` requires a terminal P1.3 result, a freshly rebuilt valid delivery receipt, exact plan/subject/command identity and byte-exact normalized required final response. A non-terminal P1.3 result supplies the continuation action; P4 never recalculates session work or chooses another session. Events store hashes, identities, verdicts and reason codes, not raw assistant transcripts. RAG:— (repo-grounded: D5; P1.3 contract; existing delivery/session modules).
**Code Guidance:** Build immutable dataclasses plus total schema-backed reducers before filesystem/CLI adapters. Use atomic replace for one current lease and append-only JSONL for events; lock or compare-and-swap on sequence/fingerprint so concurrent stop attempts cannot both admit. Canonicalize only the machine-authored final template—do not trim or keyword-match arbitrary prose. Keep pre-final verification read-only over plan artifacts so the bookkeeping commit remains clean. Start with tests for no lease, active progress, waiting owner, terminal exact match, mismatched transcript, stale receipt, expired/ambiguous lease, duplicate stop, crash-resume and release. Inject clock/store/receipt/continuity readers; do not shell from policy code. One invalid state yields one stable code and recovery command.
