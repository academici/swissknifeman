## Синтез

P1.5 должен удалить live v1 execution path, но не переписывать
историю уже закрытых items. Поэтому bundle имеет две разные роли:

1. для nonterminal/executable item — live digest-qualified executor input, который
   обязан резолвиться и быть byte-fresh;
2. для terminal item — closure-time manifest/evidence. Его schema и сами байты
   остаются проверяемыми, но live path/digest re-resolution после
   намеренного retirement его input не разрешается и не нужна.

Терминальность берётся из generated item state/journal projection, а не
из предположения по пути. Structural plan checks не отключаются; сужается
только live executor/read-budget freshness predicate. RAG:— (repo-grounded:
`findings/09-P1.5-retirement-preflight.md`, current `plan_gates.lint_read_budget()`).

Для shared tests canonical fixture всегда создаёт Layout v2. Тест retired
input создаёт минимальный explicit raw missing/v1 carrier и проверяет
`PLAN_LAYOUT_V1_RETIRED`; он не запускает generated views и не реанимирует
v1 compatibility helper. Hard-coded `phases/P1.md` в общих lint/contract tests
заменяется на v2 carrier addresses. RAG:— (repo-grounded:
`packages/task/tests/fixtures.py`, failure inventory in findings/09).

## Альтернативы

- Переписать specs/bundles P1.1–P1.4: отклонено — это меняет
  закрытую историю и маскирует факт retirement.
- Оставить migrator/test tombstones в live package: отклонено — нарушает
  D7 и позволяет compatibility path вернуться.
- Отключить все checks terminal items: отклонено — schema,
  projection и closure consistency остаются важной; исключается только
  live input re-resolution.
