# Roadmap: обновление Swissknifeman должно сходиться к компактному контексту проекта

**Статус:** воспроизведённая полевая регрессия; compact root hub уже исправлен в
`v0.23.0`, но end-to-end rollout и диагностика не гарантируют итоговое состояние.

**Критерий запуска ремонта:** сработал 2026-09-21 на Insiders. После обновления
Swissknifeman проект сохранил устаревший resident hub, лишний plugin bucket,
дублирующие project skills и шесть optional-агентов. Обычные `status`/`doctor`
не свели эти поверхности к выбранному профилю и не объяснили полный расход
контекста.

## Полевой результат

После ручной сверки и безопасной очистки Insiders:

| Поверхность | До | После |
|:--|--:|--:|
| Первый ход, оценка `skiller budget --first-turn` | 6 138 токенов | 4 283 токена |
| Root instructions + rules | 1 112 | 354 |
| Skills metadata, измеренная текущим budget | 2 147 / 52 skills | 1 594 / 41 skills |
| Agent metadata | 945 / 10 agents | 401 / 4 agents |
| `CLAUDE.md` | 58 строк / 4 436 байт | 14 строк / 1 018 байт |
| `AGENTS.md` | 22 строки / 1 388 байт | 13 строк / 871 байт |

Экономия по текущему прибору — 1 855 токенов, около 30%. Это нижняя граница:
`_measure_skills()` считает набор из `resolve_active_set()`, но не добавляет
проектные `.claude/skills`/`.cursor/skills`. До ремонта в этих каталогах были
локальные ссылки с именами, уже раздаваемыми marketplace.

Source remediation для корневого hub уже существует: commit `b2543bf8`
перевёл `CLAUDE.md` и `AGENTS.md` на comment-only stub по умолчанию. Этот carrier
не предлагает повторять исправление hub. Он фиксирует разрыв между исправленным
источником и фактическим состоянием consumer-проекта после update/sync.

## Карта причин

### 1. `skiller connect` не является desired-state операцией

`packages/skiller/lib/skiller/connect.py` добавляет выбранные plugins, но
оставляет любой ранее включённый plugin с сообщением `включены сверх профиля
(не трогаю)`. Поэтому удаление `devops` из `.swissknife.json` не отключило
`devops@swissknifeman`; потребовалась отдельная ручная правка
`.claude/settings.local.json`.

Merge-only поведение безопасно как legacy default, но команда не даёт режима,
который атомарно приводит **managed** selection к объявленному профилю. Более
того, project-facing `ecosystem-setup` говорит, что `skiller connect --plugins`
«перезаписывает» набор, что расходится с реализацией.

### 2. Локальный каталог skills может дублировать marketplace незаметно

Insiders-проект сам генерировал ссылки на все `.ai/skills` одновременно в
`.claude/skills` и `.cursor/skills`. Часть имён уже поставлялась подключёнными
bundles. Это дефект project-owned генератора, но Swissknifeman не показал
коллизии и не смог отличить уникальные project skills от повторной раздачи.

Текущий channel-drift охватывает connect/vendor provenance, но не полный
provider-visible каталог: marketplace plugins, локальные skills, symlinks,
generated copies и одинаковые `name` из разных источников.

### 3. `maind sync` способен снова раздуть компактный root

`packages/maind/lib/maind/provision/sync.py` включает `health-doc` в обычный
`ORDER`, а `packages/maind/lib/maind/health.py::apply_health_doc()` добавляет в
`CLAUDE.md` большой блок `templates/health/priority-block.md`. При уже
установленном non-blocking health hook этот resident текст повторяет
операционные инструкции и конкурирует с provider-owned root generation.

### 4. Optional agents ставятся автоматически

В backend Laravel pack шесть ролей помечены `optional: true`, однако
`render_pack()` устанавливает любой optional-файл, если source существует.
Параметр `auto` передаётся в `do_render()`, но не участвует в выборе файлов.
`removed_optional` защищает только ранее вручную удалённые роли при upgrade и
не имеет публичного selection workflow. В результате auto rollout установил
все десять агентов, хотя проекту были нужны четыре.

### 5. Budget и документация не описывают фактический resident set

- `_measure_skills()` не включает provider-local project skills и не сообщает
  name collisions; показанные 41/52 skills — только часть каталога.
- Код и CLI используют пороги `16K/23K`, а `ecosystem-setup`,
  `package-architecture` и `project-tooling-runbook` всё ещё обещают `7K/10K`.
- Успешный budget сам по себе не доказывает, что native provider принимает MCP,
  hooks и generated roots. На Insiders отдельный `claude doctor` нашёл
  некорректную HTTP MCP-запись, которую экосистемный rollout не поднял.

## Предлагаемый контракт ремонта

### A. Reconcile выбранного plugin profile — владелец `skiller`

Добавить явный режим `skiller connect --reconcile` с обязательным dry-run plan:

1. desired set берётся из явных `--plugins` либо project config;
2. добавляются отсутствующие managed plugins;
3. лишние `*@swissknifeman` переводятся в `false` или удаляются согласно одному
   документированному правилу;
4. foreign marketplaces и чужие settings keys не меняются;
5. повторный запуск возвращает no-op.

Legacy `connect` остаётся merge-only до отдельного migration decision. Вывод
обычного режима должен давать точную reconcile-команду, а документация — больше
не называть merge-only операцию перезаписью.

### B. Полный provider-visible skill inventory — владелец `skiller`

Doctor и budget должны строить один каталог из active marketplace plugins,
managed vendored skills и локальных provider skills. Для каждой записи нужны
`name`, provider, source/provenance, managed/unmanaged и resident metadata cost.

Одинаковое имя из разных источников становится typed diagnostic. Автоочистка
допустима только для файла/ссылки с доказанной Swissknifeman provenance;
уникальные project skills и foreign entries остаются нетронутыми. JSON-вывод
должен позволять проектному генератору построить allowlist без парсинга prose.

### C. Health без resident root block — владельцы `maind` + `harness`

`health-doc` нужно убрать из default sync для проектов, где health уже выражен
hook'ом или provider instruction contract. Старый блок должен иметь
детерминированную миграцию: распознать собственные markers, удалить только
managed bytes и сохранить остальной `CLAUDE.md`.

Если resident health policy действительно нужна, она включается явным project
capability/config и проходит через provider instruction renderer, а не через
прямой независимый writer корневого файла.

### D. Явный состав agent pack — владелец `harness`

`optional: true` должен означать opt-in. `render --auto` устанавливает required
roles и ранее выбранные optional roles; новый optional при upgrade не появляется
сам. Нужен публичный selector (`--with-role`, manifest answer или эквивалент),
сохранённый в lock, а также команда безопасного prune для неизменённых managed
optional files.

Doctor показывает цену agent metadata и предлагает удалить неиспользуемые роли,
но не удаляет локально изменённый или foreign agent.

### E. Один post-rollout conformance receipt — владельцы всех трёх пакетов

`maind doctor --context` (либо эквивалентный агрегатор существующих API) после
update/sync должен собрать:

- effective plugin selection и drift к desired profile;
- полный skill/agent/root/hook/MCP first-turn budget;
- duplicate names и provenance conflicts;
- compact-root invariant и отсутствие competing writers;
- результаты provider-native config validation, когда CLI доступен;
- before/after и idempotence для выполненного rollout.

Receipt должен быть доступен как JSON и не создавать новый tracked artifact в
consumer repo. Нативный doctor остаётся финальным oracle provider-конфига;
отсутствующий CLI даёт `not-observed`, а не ложный GREEN.

## Границы

- Не удалять foreign или уникальные project skills/agents по совпадению имени
  без provenance.
- Не делать legacy merge-only `connect` разрушительным без нового явного режима
  и release note.
- Не возвращать полный индекс skills в root instructions: native discovery и
  on-demand docs остаются источником навигации.
- Не считать один универсальный набор plugins или agents правильным для всех
  проектов; desired state задаёт профиль и локальный config.
- Не выполнять fleet rollout до проверки на Insiders и ещё одном consumer с
  иным стеком.

## Acceptance

- Fixture со старым включённым `devops` и новым профилем без него: обычный
  `connect` только диагностирует drift; `connect --reconcile --dry-run`
  показывает точную managed mutation; apply отключает `devops`; второй apply —
  no-op; foreign plugin сохранён.
- Marketplace skill и одноимённая локальная ссылка видны как collision в doctor
  и оба входят в inventory/budget. Уникальный project skill не предлагается к
  удалению.
- Compact generated `CLAUDE.md` после двух полных `maind sync --project …`
  байт-в-байт стабилен и не получает `priority-block.md`; migration удаляет
  только старый marked block.
- Fresh `harness agent-packs render --auto` ставит required roles без optional.
  Явно выбранная optional role сохраняется через upgrade; новая optional role
  не приезжает молча; managed prune не трогает local-modified file.
- First-turn report включает active local skills, показывает collisions и
  использует те же `16K/23K`, что все раздаваемые инструкции и docs.
- Provider-native doctor failure делает aggregate non-green или
  `not-observed`, но никогда GREEN. Диагностика указывает конкретный artifact и
  команду ремонта.
- Полевой прогон на Insiders сохраняет восемь выбранных project-owned skills,
  два hub-owned ecosystem skills, четыре выбранные agent roles и compact roots;
  полный sync/update повторно не увеличивает footprint.
- Второй consumer с другим профилем проходит тот же rollout без ручной правки
  provider settings и без удаления собственных skills.

## Обсуждение

1. **Когда включать reconcile по умолчанию.** Рекомендация: сначала отдельный
   `--reconcile` и предупреждение merge-only режима; смену default оценить после
   двух field acceptance, потому что ранее лишний plugin мог быть осознанным.
2. **Судьба `health-doc`.** Рекомендация: default-off при наличии health hook и
   provider instructions; явный opt-in оставить для клиентов без hook surface.
3. **Модель optional roles.** Рекомендация: required-only для fresh auto render,
   lock-backed explicit selection для остальных. Само наличие template не
   является пользовательским выбором.
