# 2026-08-13 — terminal deviation must not replace repair

## Наблюдённая проблема

В проекте `insiders`, план `2026.07.30-SITE-HARDENING`, item `P5.6`
«Канон графа в docs и инвариант `tech-policy`» был закрыт как `🟠 Done with deviations`,
хотя обязательная Validation `pnpm docs:build` была красной. Сборка остановилась на
`EACCES` при очистке `docs/.vitepress/dist/ai`: каталог был создан root-процессом
`docs-init` Compose-сервиса и принадлежал `root:root`.

Трассировка решения:

- item требовал обновить `docs/workflow/question.md`, `docs/workflow/glossary.md`,
  `docs/dev/tech-policy.md` и подтвердить VitePress-сборку;
- содержательные grep-гейты, bundle и generated workflow diff были зелёными;
- после `pnpm docs:build` с `EACCES` исполнитель ошибочно классифицировал проблему как
  внешний блокер, не исчерпал локальный repair через доступный Docker-контур и не запросил
  owner-gate для `sudo`;
- status-rule команды допустил `closed-deviations`, а terminal journal event и handoff были
  записаны до восстановления build-артефакта.

Это не корректное применение статуса отклонения: незелёная обязательная Validation означает,
что acceptance ещё не достигнут. Она не должна превращаться в terminal result лишь потому,
что остальные проверки зелёные или ошибка выглядит инфраструктурной.

## Улучшение

Усилить `task:plan-exec`, `task:plan-run` и общий `plan-protocol` правилом
**acceptance-before-terminal**:

1. Пока хотя бы одна команда из `Validation` красная, item остаётся nonterminal (`🟡 In progress`)
   и исполнитель обязан продолжать repair-loop: воспроизвести, определить владельца состояния,
   выполнить все безопасные локальные способы восстановления и повторить именно исходную команду.
2. `🟠 Done with deviations` допустим только после зелёной обязательной Validation; он описывает
   остаток, не отменяет acceptance. Исключение — явная owner-authorized смена/снятие acceptance,
   записанная D#-решением и синхронизированная с item-spec.
3. Если действие требует недостающего owner authority, до terminal event создаётся
   `DecisionRequest`; обычная нехватка прав на локальный generated/build-артефакт сначала
   проверяется через доступный проектный контейнер/генератор, а не сразу считается external block.
4. Linter и delivery receipt должны отклонять terminal journal result, если latest recorded
   Validation содержит failure без D#-override, и требовать exact retry/repair Next в handoff.

## Проверяемый результат

Добавить unit/fixture-кейсы для `plan_lint.py` и terminal delivery:

- `closed-deviations` при красной обязательной Validation → ERROR;
- красная Validation + D# override → разрешено только при отражённой обновлённой spec;
- `EACCES` на generated output при доступном Compose repair не даёт terminal status до повторного
  зелёного запуска исходной команды.
