# Q14

Запрос:

```text
October 2026: awslabs/cli-agent-orchestrator (CAO) agent profile format, current main and latest release. 1) Exact file format of an agent profile (Markdown with YAML frontmatter?): every frontmatter field (name, description, provider, model, skills, allowedTools / tool restrictions, mcpServers, claudeConfig.effort, codexConfig.model_reasoning_effort, codexProfile, prompt/system body) and which are required. 2) Provider ids for Claude Code, Codex, Grok (claude_code, codex, grok_cli?). 3) How a profile is installed or referenced (cao install, agent store path, --agents), and whether a profile can be generated programmatically and validated offline without starting tmux or the CAO server. 4) Breaking changes to the profile format between v2.3 and v2.5.x. Cite exact primary-source URLs (docs/agent-profile.md, providers/*.py, release notes). Answer in Russian, max 700 words.
```

Ответ (как вернул сервис, 2026-10-05):

Проверил main и теги релизов: latest release — v2.5.1 (11 сентября); для профилей main описывает формат Markdown с YAML frontmatter, а тело Markdown используется как system prompt.

## Формат и поля

```
--- name: developer description: Implements scoped code changes provider: claude_code --- Системный prompt агента.
```
В документации обязательными названы name и description; при загрузке именованного профиля CAO может подставить имя из файла и пустое описание, если поля отсутствуют. Практически профиль всё равно стоит задавать явно.
Также допустимы prompt как дополнительный provider prompt, tools, toolAliases, toolsSettings, resources, hooks и другие provider-specific поля. tools — не allowlist CAO: для ограничений используйте allowedTools или role.

## Provider ids

- Claude Code: claude_code
- Codex CLI: codex
- xAI Grok CLI: grok_cli — добавлен в v2.5.0.

## Установка и офлайн-проверка

cao install принимает встроенное имя, локальный Markdown-файл или HTTPS URL. По умолчанию установленная копия попадает в ~/.aws/cli-agent-orchestrator/agent-context (настраивается через agents.dirs.cao_installed); команда также поддерживает --provider. Для запуска профиля используется cao launch --agents <profile>.
Сгенерировать файл программно можно: это текстовый Markdown плюс YAML frontmatter. Офлайн-валидация без tmux и CAO server также возможна в принципе — например, локально проверить YAML и поля/ограничения схемы. Но имеющиеся источники не подтверждают отдельную CLI-команду офлайн-валидатора: в v2.5.0 добавлены валидация frontmatter и schema endpoints, не свидетельство автономного валидатора.

## Что изменилось с v2.3

Это не выглядит как полная несовместимая смена синтаксиса профиля, но формат и его возможности расширились:
- v2.3 добавил skills как allowlist skill-каталога и codexConfig; в релизе v2.2 уже появились codexProfile и Claude permission_mode.
- К v2.5.0 добавлены frontmatter validation/schema endpoints и claudeConfig для effort.
- v2.5.0 добавил Grok provider grok_cli; значит grok_cli — корректный идентификатор для актуальной ветки, не для старой v2.3.
- В v2.5.0 cao install получил security fix: name с разделителями пути больше не допустим.
