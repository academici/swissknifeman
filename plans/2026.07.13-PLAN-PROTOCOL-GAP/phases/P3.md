# P3 — Команды plan-*: гейты и порядок закрытия

## Phase Context

Фаза переносит канон фаз P1/P2 (скилл `plan-protocol` **2.5.0**) в исполнительный слой — четыре
существующие slash-команды `packages/task/commands/plan-{exec,close,audit,design}.md` плюс пятая,
новая (`plan-run`, D18). Команды самодостаточны (агент читает их целиком, скилл — только по явной
ссылке из плана), поэтому правила формулируются В ТЕЛЕ команды, а не ссылкой «см. скилл».
Frontmatter-пины моделей команд НЕ меняем (отдельное SSOT-решение, `packages/task/CLAUDE.md`) —
исключение только у новой `plan-run`, чей смысл и есть отсутствие пина.

Замер этой сессии (`findings/P3-command-layer.md` §2): исполнительный слой не несёт **ни одного**
правила фаз P1/P2 — ни routing-гейта (F7), ни топологии двух коммитов (D26), ни честного lint'а с
атрибуцией (B1/D5/D6), ни status-rule (A5/D9), ни якоря дерева для чисел (D36), ни enum'а форм
`Next` (D4). Хуже: три строки команд ПРОТИВОРЕЧАТ канону 2.5.0 (один коммит вместо двух;
`Context: fresh session` вне enum'а трёх значений; RAG-enum из двух маркеров вместо трёх) —
исполнитель, следующий команде буквально, воспроизводит ровно те дефекты, которые фаза P2 чинила
в SSOT. До закрытия P3 гейты держатся дисциплиной исполнителя, а не текстом команды.

Items правят РАЗНЫЕ файлы, но зависят от общих формулировок (порядок закрытия обязан совпадать
в `plan-exec` и `plan-close` ДОСЛОВНО) → исполняются последовательно, workflow-скрипт не заводится
(критерий §7 скилла не сработал: Inputs P3.2/P3.5 ссылаются на Deliverables P3.1). Тир (§3 Routing,
D45): **P3.1, P3.3, P3.6 — opus/high, `Exec = manual`** (сведение правил под потолок объёма; новая
семантика правил остановки; канон + регенерация EN); **P3.2, P3.4, P3.5 — sonnet/medium,
`/task:plan-exec`** (копипаст блока с diff-сверкой формулировок как Validation).

**Scope Included фазы:** тексты пяти команд `/task:plan-*`, §13 скилла (таблица команд), EN-канон,
`packages/task/CLAUDE.md`, `description` манифеста плагина.
**Scope Excluded фазы:** `plan_lint.py` (закрыт фазами P1/P2 — новых правил линтера фаза не вводит);
frontmatter-пины существующих команд; миграция живых планов флота на канон-формы (back-compat,
не трогаем); правка чужих планов (P4.2); CHANGELOG/docs пакетов (P4.3).
