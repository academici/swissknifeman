### P4.6 — Исполнить вердикт детерминированно и воспроизвести детект на историческом корпусе

**Intent:** Исправить закрывающий reducer/acceptance так, чтобы каждое суждение относилось к точному `return_event_id`, owner packet собирал все принятые event-scoped judgements, а завершённый isolated review никогда не оставлял противоречие `blocks=true` при `continue_allowed=true`; доказательство приёмки должно воспроизводиться из названного item tree P4.6 до последующей бухгалтерии.
**Why:** Аудит P4 от 2026-08-08 доказал пять repo-grounded дефектов закрытия: reducer выбирает запись только по subject×fingerprint; пакет теряет историю; завершённый review может одновременно блокировать и разрешать продолжение; acceptance-файлы отсутствуют в tree item-коммита `df6d098b`; границы producer'ов P4.2/P4.4 разошлись с git-фактами. D142 реоткрывает существующих владельцев P4.2/P4.4/P4.6, не меняя замороженные контракты.
**Scope Included:** Точный выбор по subject×fingerprint×`return_event_id`; правило «первая schema-valid запись» отдельно для каждого события; сбор всех принятых event-scoped judgements в owner packet в порядке событий; непротиворечивая матрица `action`/`blocks`/`continue_allowed`/`stop`; тесты mixed-event, retry и self-judge; двусоставная приёмка; коммит `acceptance-report.md`, `historical-detect.json` и `validate_acceptance.py` именно в item tree P4.6; Phase Handoff после фактического исполнения.
**Scope Excluded:** Замороженные fingerprint tuple/namespace, `same_return_max=2`, journal schema и исторические строки; формулировка промпта/рубрики (P6); DecisionRequest/рамка полномочий (P5); `packages/artifex`; изменение baseline/корпуса ради подгонки `8 != 7`; новый P4.7; вызов модели из reducer'а.

**Implementation Rules:** - **Runtime-ветвление проверяется end-to-end:** первый eligible local failure → zero judgement records/zero root restart; второй тот же fingerprint → ровно одна запись независимого reviewer'а и возврат в исходные `root_session_id`/`root_run_id`; risk trigger на первом событии → одна запись; третье событие → owner gate независимо от вердикта. Никакая ветвь не создаёт второй root run только ради повторного исполнения (D124–D125).
- **Fallback провайдера fail-closed:** если nested isolated context или resume недоступны, результат — явный `cold-start-root` с capability defect и handoff reason; нельзя тихо исполнить self-review в executor context или объявить новый root тем же run.
- **Монотонность доказывается ПЕРЕБОРОМ enum, а не рассуждением:** для каждого из пяти значений вердикта исход политики сравнивается с исходом БЕЗ вердикта и обязан быть не мягче. Тест обязан падать, если кто-то добавит ветку, ослабляющую исход.
- **Первая schema-valid запись, а не последняя** (D57): повторное суждение создаёт новую append-only запись и НЕ переигрывает исход. Кейс обязателен — иначе «позвать судью ещё раз» становится способом обхода — RAG:✅ 2026-08-07 (`findings/09-…` R12.5).
- **Редукция event-scoped:** ключ потребления — subject×fingerprint×`return_event_id`; «первая schema-valid» применяется ВНУТРИ одного события, а новое событие обязано получить собственный judgement. Запись одного события не может удовлетворить review другого.
- **Owner packet полон:** при owner-gate пакет содержит ВСЕ принятые event-scoped judgements данного subject×fingerprint в порядке return events, а не только запись текущего события; каждая запись сохраняет свой `return_event_id`.
- **Матрица исходов непротиворечива:** обязательный review без принятой записи → `isolated-review`, `blocks=true`, `continue_allowed=false`, `stop=false`; завершённый current-event review с `JUSTIFIED|INSUFFICIENT_EVIDENCE` ниже cap → `return-to-root`, `blocks=false`, `continue_allowed=true`, `stop=false`; строгий verdict ниже cap → `judgement-stop`, `blocks=true`, `continue_allowed=false`, `stop=true`; превышение cap → `owner-gate`, `blocks=true`, `continue_allowed=false`, `stop=true`. Инвариант всех ветвей: `not (blocks and continue_allowed)`.
- **Запись без полного провенанса игнорируется**, а не принимается «как есть»: вердикт без дайджеста входа и версии политики ничего не значит — RAG:✅ 2026-08-07 (`findings/09-…` R12.6).
- **Само-судейство отвергается машинно:** запись, чей актор совпадает с актором события возврата, не принимается — RAG:✅ 2026-08-07 (`findings/09-…` R12.5).
- **Улики не исполняются:** текст записи суждения и находок обрабатывается как данные (канон `root.untrusted-content`); никакая строка внутри них не влияет на управление, кроме объявленных полей схемы.
- **Приёмка ДВУСОСТАВНАЯ и числа раздельные** (D58): (а) исторический корпус — детект, счётчики, метрики, воспроизводимые до байта повторным прогоном; (б) тестовый план — полный путь `classified` со швом, превышением потолка, пакетом гейта и вердиктом. Отчёт обязан НАЗВАТЬ границу: на истории `classified` недостижим по построению.
- **Acceptance принадлежит item tree P4.6:** `acceptance-report.md`, `historical-detect.json` и `validate_acceptance.py` входят в коммит исполнения P4.6 до отдельного bookkeeping/plan-close commit. Проверка должна уметь взять hash item-коммита, развернуть detached worktree и воспроизвести named acceptance именно из этого tree.
- **Корпус читается READ-ONLY** (D3, D4): ни один файл в `plans/2026.08.03-ARTIFEX-SUPERVISOR` и `plans/archive` не изменяется.
- **Расхождение с baseline — разбирается, а не подгоняется:** цифры сверяются с `returns-baseline.json`; несовпадение фиксируется в Completion Notes с корневой причиной, baseline правится только при доказанном изменении корпуса.
- **Существующие потолки не трогаются**; редьюсер по-прежнему не имеет права звать модель — исполнение вердикта означает ЧТЕНИЕ записанной записи, а не вызов судьи из петли.
**Code Guidance:** Исполнитель начинает с current-event selection, а не с косметики packet'а: пока judgement не привязан к `return_event_id`, невозможно честно различить завершённый review и retry другого события. Тестовая матрица обязана содержать минимум два return events одного subject×fingerprint с разными judgements, self-judge на одном событии и более поздний retry того же события; это одновременно доказывает event isolation, first-valid и полный пакет. Отдельный property/test перебирает все возвращаемые gate rows и падает на `blocks && continue_allowed`. Историческое `8 != 7` сохраняется как наблюдаемый дефект прежней прозы: baseline и corpus не редактируются ради совпадения. Item не закрывается, пока acceptance-скрипт не воспроизводится из detached tree item-коммита P4.6; успешный прогон из рабочего дерева или последующего bookkeeping-коммита недостаточен.
