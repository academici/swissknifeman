# P7 — Validate provider strengths, release, and operationalize

## Phase Context

P7 is the release boundary for the provider-control-plane and locale programme. It starts only
after P0–P6 are terminal and their frozen contracts, repository acceptance, migration results and
two-run fleet-health bundle exist at the exact identities named by those phases. It distinguishes
shared semantic parity from provider-native strengths: Claude Code and Codex are evaluated against
the same desired capability IDs, while provider-exclusive or unsupported surfaces keep their own
declared expectations. A complete but non-green P6.3 fleet report remains release-blocking unless a
later Owner D# names the exact exception and its consequences. P7 may assemble a release candidate
and operational documentation, but it may not tag, push, publish, mutate consumers or repair Brain.

P7.4 attempt 1 is an append-only RED audit baseline. D90 routes its local F2–F6 delta through
P7.5–P7.6: repair the exact audit verifier, seal candidate/foreign membership, commit only the
candidate set and regenerate cold-start carriers. F1/F5 remain external deferred gates under
D88/D89. After P7.6, successor P7.7 performs one bounded independent delta audit; P7.4 is not
reopened, its RED baseline is not erased, and no item authorizes release.

P7.2/P7.3 follow the D39 per-cwd carrier in `roadmap.md`: a root coordinator owns the
regression/release manifest and close, while each affected package mutation is performed from
its own fresh cwd and yields a scoped evidence record. Deterministic blocker predicates are
machine stop conditions in P7.1/P7.3 Validation, not Owner decisions.

Skill acceptance is behavior-led. P7.1 first replays representative real Claude Code and Codex
workflows against no-skill, minimum shared Skill Core and provider-tuned adapter variants, then
ablates each non-core instruction. Deterministic unit/integration tests in P7.2 preserve failures
already demonstrated by those workflows; they are supplementary guards and cannot by themselves
prove that a skill improves current-model behavior. A future provider enters through the same
fixture and adapter contract without changing the shared Skill Core.

**Scope Included:** exact-set provider acceptance; real-provider no-skill/minimum/provider-tuned
workflow replay and instruction ablation; negative and supplementary regression suites for shared
semantics, native strengths, skill invocation, drift, locale independence and state isolation;
third-provider conformance fixture; operational/migration/rollback documentation; generated-doc
and package validation; release-candidate manifest; independent adversarial audit and explicit
Owner release decision; D90 exact verifier repair, candidate/foreign path partition,
candidate-only integration and one bounded P7.7 delta-recheck.

**Scope Excluded:** new provider or locale semantics; weakening frozen P1/P2/P6 contracts; accepting missing/unsupported required rows as green; live consumer/Brain repair; quarantine deletion; tag, push, package publish or release announcement; claiming provider equivalence beyond measured semantic capability IDs.

> **Контракт фазы (contract-first).** Потребляет: terminal P0–P6 commits; frozen `provider-control-plane-v1`, `skill-core-v1`, `provider-skill-adapter-v1`, `skill-evidence-v1`, `locale-resolution-v1`, `provider-recovery-gates-v1` and `provider-health-v1`; P4 repository acceptance; P5 convergence/unresolved sets; P6 two-run exact-set fleet evidence; P7.4 RED findings · Производит: minimized real-provider replay/ablation bundle, provider acceptance bundle, supplementary permanent regression gates, operator/migration/rollback docs, release-candidate manifest, exact audit verifier, candidate-only committed anchor and independent Owner-facing audit/delta verdict · Границы: no synthetic-test-only efficacy verdict, no new semantics, no foreign-worktree staging, no fleet/Brain mutation, no destructive cleanup and no tag/push/publish.
