# Идея: число кругов ревью по размеру/риску батча; круг без подтверждённых ≥Major завершает ревью

Статус: идея. Источник: оркестрация PLAN3 (vaulter) P5.3–P5.6, 2026-10-17. Связано: `conductor-ignores-plan-review-policy.md`.

## Требование владельца
Не тратить время на лишние круги. Политика «комбинированная»:
- 1 круг по умолчанию;
- 2 круга только для сложных пунктов/батчей с большим объёмом правок (frontier + xhigh, concurrency/durability/destructive);
- ревьюер чекпоинтов — `codex/gpt-6.1-sol/xhigh`.

## Данные
- P5.3 (grok-4.7/high): круги 16+10+6 мин; подтверждено 8 из 9 находок; круг 3 — одна находка, отклонена триажем.
- P5.4: второй круг (143k токенов на входе) после 4 подтверждённых находок.
- B3 (P5.5+P5.6, групповое ревью codex xhigh, один вызов): 217 с, 0 Blocker / 3 Major / 1 Minor — один дешёвый вызов
  нашёл столько же по существу, сколько 3 круга по пункту.

## Что не хватает
1. `review.max_rounds` — одно число на run (в options), не зависит от пункта. Нужно: правило по признакам батча
   (route frontier/xhigh, размер diff, теги риска) или значение из плана (`review.rounds_max` в пункте).
2. Круг, в котором триаж подтвердил 0 находок уровня ≥ `correct_min_severity`, завершает ревью (не запускать следующий).
3. Круг 2 читает только исправленные места (`audit_scope: corrected`) — это уже есть; оставить по умолчанию.
4. `--dry-run` печатает: кто ревьюит, какие пункты, максимум кругов.

## Критерии приёмки
- Батч из простых пунктов: ровно 1 круг даже при находках (правки без повторного ревью, примечание в плане).
- Сложный батч: до 2 кругов, второй только если остались подтверждённые ≥Major.
