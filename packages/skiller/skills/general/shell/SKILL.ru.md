# Shell (совместимость с хуками окружения)

Единый растущий скилл о том, как писать shell-команды так, чтобы их пропускали
хуки этого окружения, а не блокировали. Сейчас раздел один — `rm`/`rmdir` vs
`safe-dirs`-хук `auto-approve`; по мере находки новых паттернов (других команд,
других хуков) сюда добавляются новые разделы — не заводи отдельный скилл на
каждый следующий паттерн.

## rm/rmdir vs safe-dirs auto-approve

### Когда активировать

- Прилетело `Заблокировано: опасная операция (deny_hard). Выполните вручную при
  необходимости. rm в доверенных папках можно разрешить: harness safe-dirs` —
  ДО повторной попытки той же команды.
- Перед тем как писать ЛЮБУЮ команду с `rm`/`rmdir` в доверенном дереве
  (`~/projects`, `~/Vaults`, зарегистрированные проекты — см. `safe-dirs.json`).
- Перед тем как обернуть `rm`/`rmdir` в `for`/`while`/`if`/`case`, `xargs`,
  `sudo`, `env VAR=x`, или вызвать их из функции/алиаса.

### Почему это вообще нужно

Хук `~/.claude/hooks/auto-approve` перед `deny_hard` спрашивает вердикт у
`lib/safedirs.py`: команда безопасна, если ВСЕ вхождения `rm`/`rmdir`
провалидированы против allowlist доверенных директорий (`safe-dirs.json` —
MACHINE-OWNED конфиг в корне монорепо swissknifeman, project-override
`.claude/auto-approve.config.json` его не видит — иначе враждебный репозиторий
разрешил бы себе `rm`).

**Ключевое ограничение анализатора (сам документирует это): «не эмулируем
shell — отвергаем непонятое».** Токенайзер режет команду на сегменты ТОЛЬКО по
пунктуации `;|&<>()` — ключевые слова `for`/`do`/`done`/`if`/`then`/`else`
сегмент не начинают. Из-за этого `rm`/`rmdir` внутри `for ... do rm ... done`
физически не может оказаться «первым токеном сегмента» — тем же правилом,
которым анализатор ловит `sudo rm`/`xargs rm`/`FOO=x rm` (эвристика: «rm не в
голове сегмента → небезопасно, кто-то может быть перед ним»). Итог: **цикл с
`rm`/`rmdir` внутри ВСЕГДА получает `deny_hard`, даже если пути внутри
allowlist** — containment-проверка до этого просто не доходит.

### Алгоритм

1. **`rm`/`rmdir` — ПЕРВЫЙ токен своего сегмента.** Сегмент = кусок команды
   между `;`/`|`/`&`/`&&`/`||`/`(`/`)`. Единственное разрешённое исключение —
   `git rm` (замаскирован отдельно, `j==1` при `toks[0]=="git"`).
   - ❌ `for f in a b c; do rm -rf "$f"; done` — `rm` вторым токеном после `do`.
   - ❌ `sudo rm -rf x`, `xargs rm -rf`, `FOO=1 rm -rf x` — то же правило.
   - ✅ `rm -rf a b c` — один вызов, несколько путей аргументами.
   - ✅ пять раздельных вызовов `rm -rf <path>` (по одному Bash-тулу на путь),
     если объединить одной командой почему-то нельзя.
2. **Флаги — строго из белого списка.** `rm`: `-r -R -f -v -d -i -I` (короткие,
   в любой комбинации) либо `--recursive --force --verbose --dir` (длинные).
   `rmdir`: `-v` либо `--verbose --ignore-fail-on-non-empty`. `--parents`/`-p`
   у `rmdir` ЗАПРЕЩЕНЫ (лезут к родителям пути). Любой другой флаг → unsafe.
3. **Пути — без обфускации.** Запрещены `$`, `` ` ``, `{`, `}` в пути (не
   только не раскрываются — сам символ уже unsafe); запрещён компонент `..`
   (лексически, до `realpath`); голый `~`/`~user` не раскрывается (только
   `~/подпуть` — от `$HOME`).
4. **Containment — realpath внутри allowlist.** Путь (после `realpath`, с
   учётом cwd для относительных — включая пере-cd внутри `&&`-цепочек) обязан
   лежать СТРОГО внутри одного из `roots` (`safe-dirs.json`), не быть самим
   корнем (кроме `root/*`-глоба — детей можно), не пересекать `excludes`, не
   заходить в компонент `.git` (`protect_git`).
5. **Глобы — можно, если не трогают `.git`.** `rm -rf path/*` разрешён (детей,
   не сам `path`), но `.git`-литерал или dot-глоб (`.git*`, `.*`) в любом
   компоненте паттерна — unsafe.
6. **Если легитимный `rm` всё равно заблокирован** — НЕ повторяй ту же
   команду (анти-паттерн). Перепиши в форму по п.1 (без цикла/обёртки,
   multi-arg или раздельные вызовы). Если и это не проходит — попроси
   пользователя выполнить вручную (`!`-префикс в промпте).
7. **Многострочные команды (`\n`/`\r` в теле) — всегда unsafe** (сегментация
   ненадёжна). Держи `rm`/`rmdir`-команды однострочными.

### Растущий cookbook: заблокировано vs безопасно

Таблица конкретных конструкций — `snippets/blocked-vs-safe.md`. Пополняй её по
факту нового найденного паттерна (найден новый анти-паттерн парсера → строка в
таблицу), не переписывай тело SKILL — cookbook специально вынесен в снippet,
чтобы расти без раздувания тела скилла.

### Чеклист

- [ ] `rm`/`rmdir` — первый токен сегмента (нет `for/if/sudo/xargs/env=` перед ним).
- [ ] Флаги только из белого списка (нет `-p`/`--parents` у `rmdir`).
- [ ] В путях нет `$`/`` ` ``/`{`/`}`/`..`-компонента.
- [ ] Путь(и) лежат под известным доверенным корнем (`safe-dirs.json`), не
      пересекают `exclude`, не задевают `.git`.
- [ ] Однострочная команда (без `\n`/`\r` внутри).
- [ ] Если заблокировано — не повторяю ту же команду, переписываю форму либо
      прошу пользователя выполнить вручную.
