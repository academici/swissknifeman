### P5.4 — Принудить frozen queue contract и fail-closed outcome semantics

**Intent:** Исправить P5 runtime consumer после RED-аудита D144: каждый request/response/auto-answer ingress валидируется по frozen `decision-request` v1 до append/application; выбранный option применяется по его `outcome`, и только `apply` возобновляет root, тогда как `park`/`reject`/`escalate` сохраняют `🔴 Blocked`; после любого subject transition item-state и status views регенерируются. RAG:— (repo-grounded: Audit P5 findings 1–3,5; `root/contracts/decision-request-v1.{md,schema.json}`).
**Why:** Текущий `_request_errors()` проверяет лишь верхний слой, `resolve()` принимает неполный response и всегда пишет `in-progress`, а `append_auto_answer()` допускает запись без contract provenance; воспроизводимые audit probes тем самым обходят owner gate. Это дефект consumer enforcement, не недостаток frozen форм, поэтому D144 оставляет P5.1/P5.2 и D143 неизменными и возвращает ownership в P5.4. RAG:— (repo-grounded: `packages/task/lib/task/plan_requests.py:48-337`; `phases/P5/P5.md` Audit findings 1–3,5; `research/22-p5-audit-reopen-2026-08-09.md`).
**Scope Included:** Contract-driven validation request/response/auto-answer sections, включая closed fields, enum/const/ref, type/range/pattern/date-time, option uniqueness/bounds и обязательные `escalate`/`reject`; cross-field сверка authority-frame assigned fields, timeout envelope, canonical action/material fields/action digest/policy digest; fail-before-append для каждого ingress; semantic reducer результата решения; `apply` continuation с повторной проверкой identity и digest; blocked state для `park`/`reject`/`escalate` и auto-answer, переклассифицированного в authorization; единая journal→state/status regeneration boundary; negative tests на invalid kind, timeout, option set/outcome, timestamps, digest, provenance, missing response/event, чужую continuation и repeated response; восстановление канонической `write-site: pre_mutation: allow · pre_final: allow` в новом terminal event.
**Scope Excluded:** Любая правка frozen `decision-request-v1.{md,schema.json}`, `authority-frame-v1.{md,schema.json}` или owner instance/hash D143; изменение P4 packet/fingerprint/`same_return_max`; reader-contract carrier paths и queue placement; включение join gate; P6 command integration; исправление write-scope `plan-audit`; `packages/artifex`; новые зависимости или третий decision kind.

**Implementation Rules:**
- Frozen schema — единственный словарь формы: validator читает `request`/`response`/`auto_answer_event`, `kinds`, `reason_codes`, `options`, `timeout_policy`, `constants` и `canonical_action.material_fields` из JSON; второй ручной required/enum список запрещён. Domain-specific cross-field rules допускаются только там, где schema ссылается на authority frame или tool computation. RAG:— (repo-grounded: D29, frozen schema).
- D145: `action` — только construction input детерминированного writer, не durable request field. Writer обязан свернуть его в `canonical_action.action`, пересчитать доверенные поля и удалить до closed-shape validation/append; stored request не может нести extra `action`. RAG:— (repo-grounded: D145; frozen `request.additional_properties: false`).
- Schema dialect fail-closed: interpreter явно перечисляет поддержанные keywords/refs и отвергает неизвестный или непроверенный keyword вместо молчаливого пропуска; тест сверяет покрытие фактического frozen schema. RAG:— (repo-grounded: `research/22-…` pre-mortem).
- Request до append обязан пройти closed-shape и cross-field проверку: `decision_class` существует в действующем frame; `on_timeout` совпадает с классом и envelope вида; `material_fields`, `canonical_action`, `action_digest`, `policy_digest` пересчитаны инструментом; substantive options 2–5, ids уникальны, `escalate`/`reject` присутствуют. Любое расхождение — `RequestError`, queue/journal/views byte-identical до/после. RAG:— (repo-grounded: audit finding 1; contract §§Canonical action/Options/Timeout).
- Response до append/application проходит closed response schema, identity/version/digest, ISO time, resolver/reason/provenance и selected option. Для clarification обязателен `reclassified_to`; повторное применение exact decision/action запрещено. RAG:— (repo-grounded: audit finding 2; frozen response section).
- Outcome берётся из объявленного option: только `apply` строит `resume-root`/объяснённый `cold-start-root` и пишет `in-progress`; `park`/`reject`/`escalate` не получают continuation, пишут blocked terminal decision state и не исчезают из owner/status truth. Факт наличия response не равен permission. RAG:— (repo-grounded: D144; research/22 §3).
- Auto-answer принимается только целой парой `response` + `auto_answer_event`, произведённой policy path, с `resolver=policy`, verified provenance, before/after/reclassified digests и reclassification. `response=None`, неполный event или authorization после reclassification остаются fail-closed. `states()`/`pending_groups()`/`unresolved_for_phase()` редуцируют semantic outcome, не `bool(auto_answers)`. RAG:— (repo-grounded: audit finding 3; contract §Clarification reclassification).
- Все subject transitions проходят одну функцию: append journal result → regenerate ровно target `.state.md` → regenerate `status.md`; ошибка генерации не объявляется успешным resolve. Generated views руками не правятся. RAG:— (repo-grounded: root.generated-artifacts; audit finding 2).
- Continuation публикуется caller'у только после regeneration и `--check` обоих views. Инъецированный сбой генератора обязан вернуть ошибку, не вернуть continuation и записать fail-closed blocked compensation в journal; повтор безопасно доводит тот же decision до согласованного состояния. RAG:— (repo-grounded: `research/22-…` pre-mortem).
- Frozen P5/P4 contracts, D143 hash, carrier registry, P6 и `packages/artifex` read-only. Если исправление требует их изменения — STOP и escalation к plan-design; молча расширять scope запрещено.
**Code Guidance:** Никакого спец-кода «под audit probe»: mutations invalid kind/timeout/options/date/digest/provenance должны краснеть общим schema-driven путём. Расхождение validator с frozen schema = сигнал: исправить интерпретацию schema или эскалировать, но не подогнать один кейс. Outcome table реализуется одним reducer'ом; четыре разрозненные ветки, каждая сама решающая status/continuation, запрещены. Negative tests обязаны сначала доказать красноту старого кода для findings 1–3 и только затем зелень fix. ЗАПРЕЩЕНО помечать item 🟢, пока (а) любой invalid ingress пишет 0 bytes, (б) non-apply не пишет `in-progress` и не возвращает continuation, (в) policy event без provenance не снимает gate, (г) state/status views свежи после каждого валидного перехода, (д) новый P5.4 terminal event несёт точную строку обеих write-site границ.
