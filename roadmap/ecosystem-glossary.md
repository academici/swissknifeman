# Roadmap: ecosystem-glossary — единый язык экосистемы без мега-глоссария

**Статус:** ⬜ к внедрению (идея Owner 2026-07-10, RAG-подтверждена в тот же день).
**Дом:** скилл `architect/domain-modeling` (канон CONTEXT.md уже есть) + ревью-паки +
vault-страница `02-Knowledge` (тонкий term-index).

## Проблема

Экосистема многоязычна (PHP/Dart/Python, 15+ проектов) — Owner хочет «код как будто одного
человека»: единая стилистика, одни термины. Вопрос был: вести ли глоссарий и когда с ним
сверяться. Интуиция Owner «большой глоссарий — стрёмно» RAG-подтверждена: документированные
failure modes центральных глоссариев — протухание после первого месяца, выхолащивание
терминов до общих слов, отсутствие владельца, semantic drift между командами (RAG:✅
2026-07-10, консенсус DDD-практики 2025–2026).

## Решение — трёхслойка (все тезисы RAG:✅)

**Слой 1. Стилистика кода = механика, не документ.** Идиомы каждого языка НЕ выравнивать
(единый casing поверх PHP+Dart+Python — документированная ловушка: борьба с линтерами,
конфликт с SDK/codegen, дрейф). Форматтеры/линтеры per язык обязательны в CI: Pint/PSR-12,
`dart format`+analyzer lints, ruff. Кросс-языковое — только дисциплина «имя раскрывает
намерение» (скилл `naming-conventions` есть) и стиль докстрингов (`writing-style` есть).

**Слой 2. Домен per пакет — CONTEXT.md** (канон `domain-modeling` уже предписывает inline-
запись терминов по мере кристаллизации). RAG-усиление к внедрению: (а) триггер обновления —
новый агрегат/сущность/переименование = правка глоссария в том же PR; (б) пункт
«Glossary impact?» в ревью-чеклист паков; (в) правило «спросил, что значит термин, — глоссарий
устарел».

**Слой 3. Тонкий Ecosystem Glossary (term-index), НЕ мега-глоссарий** — одна страница в
`02-Knowledge`: только термины, пересёкшие границу 2+ пакетов (Rule of Two, по образцу
package-contribution-protocol). Формат записи: термин → пакет-владелец (чей CONTEXT.md
нормирует) → коллизии/омонимы (одно слово — разные смыслы в разных пакетах) → deprecated-
синонимы. Живой материал уже есть: Entitlement ≠ Tariff ≠ Quota (бриф P3.1), UsageEvent/
OverageEvent, panel, privacy-scope.

**Несущий механизм кросс-языковой согласованности — контракты, не стайлгайд** (RAG:✅):
замороженные JSON Schema с русскими description — и есть межъязыковой словарь; casing-маппинг
явной таблицей (`tenant_id` → `tenantId` Dart / `$tenantId` PHP); контрактные векторы
(fixtures AgenTools — прецедент) верифицируют согласие языков тестами, а не ревью-полицией.

## Где что живёт (решение Owner + прецедент радара, 2026-07-10)

Раскладка «механизм в SKM, содержимое в Brain» — по шаблону Ecosystem_Tech_Radar:

| Слой | Дом | Прецедент |
|:--|:--|:--|
| Term-index (маркдаун-канон, НЕ скилл) | Brain `02-Knowledge/00-Strategy/` | радар |
| CONTEXT.md пакетов | репо каждого пакета | domain-modeling |
| Механизм проверки (скиллы, обработка) | SKM: `domain-modeling` + conformance-линза ревью-паков (+ `analyst`, если появится скан терминов по коду) | ecosystem-reuse-gate |
| Указатель на живой канон | бакет `axioma` (путь-параметр, без вшитой копии) | axioma-stack |

**Ревьюер — существующий, не новый:** «проверь соответствие переменных парадигме» =
дополнительное измерение conformance-finder'а Stage B в `task:review` (конституция-документ =
CONTEXT.md + глоссарий; слот «конституция» уже есть в wf-audit-adversarial). Новый агент/пак
НЕ заводится.

**Новая линковка Brain↔проекты НЕ нужна:** ревьюер в репо проекта работает от локальных
источников — CONTEXT.md пакета + замороженные контракты (JSON Schema с ru-description лежат
в репо и уже несут кросс-пакетные термины). Term-index в Brain нужен только дизайн-сессиям
vault. Brain остаётся «линки + документация + планы».

## Реализация

1. Правка `domain-modeling`: триггеры обновления CONTEXT.md + ссылка на term-index +
   Rule of Two входа в общий глоссарий.
2. Строка «Glossary impact?» в чек-листы ревью-паков.
3. Vault: страница `02-Knowledge/00-Strategy/Ecosystem_Glossary.md` (первичное наполнение —
   из брифа P3.1 и замороженных контрактов волны P4).
4. Steward-модель: владелец термина = пакет-владелец; правка определения — через его
   CONTEXT.md, term-index только указывает.

## Критерий внедрения

Вместе с пакетом SKM-плана (те же скиллы/паки). Наполнение term-index — после dev-волны
P4 (термины закрепятся кодом).
