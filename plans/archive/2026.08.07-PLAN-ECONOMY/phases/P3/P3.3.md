### P3.3 — Включить гейт бюджета чтения и читаемости файлов

**Intent:** Включить в `plan-lint` оба условия приёмки D2 как отказывающие проверки — вес обязательного чтения любого пункта ≤ порога `read-budget` v1 и ни один обязательный к чтению файл не превышает измеренный `read-limit`, — обязательно для планов раскладки v2; планы v1 безусловно вне области по D115, без opt-in/legacy-ветви, совещательного режима и второго счётчика веса. Гейт — shared deterministic core, поэтому отдельная provider matrix ему не нужна (D122). RAG:— (repo-grounded: D2, D113–D122; контракт фазы выше).
**Why:** Замер показал, что линтер размера не видит вовсе: на плане с полом 585 КБ он печатает «OK (0 ошибок, 0 предупреждений)» — RAG:— (repo-grounded: `findings/00-plan-read-weight-2026-08-07.md` §6). Это и есть механизм, из-за которого разбухание невидимо при авторинге и обнаруживается только исполнителем, который физически не может прочитать предписанное — RAG:— (там же §7). Гейт превращает «пункт стал слишком тяжёлым» из ощущения в отказ сборки. Дисциплина раскатки взята из практики, а не изобретена: для НОВЫХ стандартов дефолт — enforcement по новым/изменённым единицам, покогортный opt-in допустим как механизм раскатки, но обязан нести критерий входа и срок, иначе становится постоянной лазейкой; hard-fail с первого дня в своей области, а не warning-режим — RAG:✅ 2026-08-07 (`findings/08-…` R9.1, R9.4).
**Scope Included:** Новый модуль гейтов пакета `task` (дом всех проверок этой фазы) и его подключение к `plan_lint`; проверка D2(а) веса пункта против порога; проверка D2(б) каждого обязательного файла против `read-limit`; область применения — обязательность под раскладкой v2 и безусловное молчание под v1 (D115); fail-closed на отсутствии артефактов порога/калибровки/лимита; диагностика, называющая пункт, число, порог и единицу; тесты, включая красное на заведомо тяжёлом пункте, зелёное на перестроенном и полное отсутствие новых диагностик на v1; раздел справки.
**Scope Excluded:** Разрешимость bundle и свежесть производных (P3.4); предикат порядка и границы путей (P3.5); переезд существующих проверок (P3.6); гейт потребителя (P3.7); ПЕРЕСМОТР порога или его единицы (P0.5 — не проходит значит эскалация, а не подкрутка); изменение области применения, заданной контрактом `read-budget` v1; правка команд (P6); любые требования, opt-in, миграционная когорта или срок для планов v1 (D115).

**Implementation Rules:** - **Гейт зовёт `plan_weight` и НЕ заводит второго счётчика веса.** Определение «вес обязательного чтения пункта» имеет ровно один носитель (D25); собственный подсчёт в линтере разошёлся бы с инструментом бесшумно — ровно дефект, который чинит план.
- **Гейт зовёт `plan_admission.classify` и применяет hard error только при `admission_state=ready` + `admission_pass=false`.** `historical-pre-v2` остаётся baseline evidence, `pending-producer` — deferred с валидным predecessor edge; собственный enum состояний/producer parser в `plan_gates.py` запрещён.
- **Область применения:** под layout v2 обе проверки обязательны; под v1 они молчат ЦЕЛИКОМ и безусловно. Opt-in-поле не вводится и не распознаётся (D115). Ни одной новой диагностики на v1 — инвариант обратной совместимости Validation.
- **Совещательного режима нет.** Флага «предупреждать вместо отказа» не существует; единственный законный способ не подпасть под гейт — объявленная область применения, видимая в диффе Meta и проходящая ревью — RAG:✅ 2026-08-07 (`findings/08-…` R10.5: `--dry-run` — документированный способ превратить гейт в информационный).
- **Baseline не заводится** (D42): область применения структурна, grandfathered-множества по построению нет, и baseline был бы вторым носителем области рядом с `Layout`.
- **Fail-closed на входах гейта:** отсутствует или невалиден контракт порога, артефакт калибровки или артефакт лимита — внятная ERROR-диагностика, а не пропуск проверки. Пропуск при отсутствии артефакта — фальшивое зелёное; литеральных дефолтов (в т.ч. наблюдённых ранее 25000) нет — RAG:— (repo-grounded: `phases/P0.md` P0.2, D15).
- **Диагностика называет всё, что нужно для действия:** id пункта, посчитанный вес, порог, единицу (`calibration_id` + `model_id`) и — для D2(б) — конкретный файл и его размер против лимита. «Пункт слишком тяжёлый» без чисел не является диагностикой.
- **Обязательный путь берётся из спецификации `read-path` v1 по версии раскладки** (D25, D36), а не из прозы команд: иначе гейт померяет не то, что читает исполнитель.
- Проверки живут в `plan_gates.py` и подключаются к `plan_lint` одной точкой: `plan_lint.py` — 2754 строки живого кода, которым линтуется весь флот (RAG:— repo-grounded: `packages/task/lib/task/plan_lint.py`), и наращивание его четырьмя новыми семьями проверок делает следующую правку опаснее предыдущей.
- Ни один файл в `plans/` других проектов этим item'ом не изменяется (D3).
**Code Guidance:** Главный риск назван внешней практикой прямо: гейт, покрасивший всех, выключают целиком, и обходные механизмы для этого уже существуют (RAG:✅ `findings/08-…` R9.2 — с честной оговоркой источника, что причинная частота не измерена). Поэтому область применения — не настройка удобства, а несущая конструкция: расширять её «чтобы сразу пользу приносило» ЗАПРЕЩЕНО. Симметрично запрещено и ослабление: сделать проверку WARNING «на время», добавить флаг обхода, ввести список исключений по пути — каждое из этого превращает гейт в информационный. ЗАПРЕЩЕНО помечать item 🟢 при незакрытых предусловиях: (а) на тестовом плане с заведомо тяжёлым пунктом линтер даёт ERROR с числом, порогом и единицей; (б) на перестроенном пункте — зелёное; (в) файл выше `read-limit` даёт отдельную ERROR с именем файла; (г) на планах v1 без opt-in ни одной новой диагностики — `diff` пуст; (д) отсутствие каждого из трёх артефактов входа даёт внятную ERROR отдельным кейсом. Обходить гейты («порог поднимем в P6», «пока предупреждение», «исключим этот пункт») запрещено — не пройден → статус остаётся 🟡/🔴 + Pending Work с точной причиной. Прохождение подтверждается выводом команд из Validation, не словами. Если окажется, что пункты ЭТОГО плана после миграции не проходят собственный порог, — НЕ править порог и НЕ сужать путь самовольно: остановиться, показать владельцу числа и эскалировать, это меняет основание D2 и D17.
