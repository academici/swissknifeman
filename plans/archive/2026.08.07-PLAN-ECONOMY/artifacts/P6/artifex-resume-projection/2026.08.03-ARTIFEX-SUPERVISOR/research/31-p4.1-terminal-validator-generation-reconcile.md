## Reproduced facts

RAG:— (repo-grounded: the commands and commits below).

- Running the frozen P1.6 validator on the current plan fails with `PARENT_ITEM_AS_TASK`, because
  `p3-smoke-codex-v1.parent_task_contract_hash=72553d…` while the live P3.4 Task Contract has a
  successor hash. This remains the recorded P3.4 deviation.
- The same validator also fails in the isolated item-commit snapshot `140a9b53`: that commit owns
  the P1.6 deliverable bytes but predates the bookkeeping commit that stored the matching P3.4
  plan specification.
- The complete snapshot `89c4b3fe` is the first P1.6 bookkeeping snapshot and the exact validator
  exits 0 there with `2 tasks; 2 grants; 24 independent cases`. `140a9b53` is an ancestor of
  `89c4b3fe`, and the P1.6 contract/cases/validator/task/grant paths have no byte diff between the
  two commits.

## Alternatives

1. Rewrite the frozen task hash or validator. Rejected: destroys P1.6 evidence and violates the
   owner's anti-scope.
2. Treat the current-tree P1.6 failure as GREEN. Rejected: weakens the fail-closed validator and
   erases the P3.4 deviation.
3. Reopen P1/P2 and mint another successor contract. Rejected: no missing product authority or
   schema was observed; current P2/P3 successor validators already own the evolved generation.
4. Validate each generation at its owning snapshot. Selected: P1.6 is GREEN only in the complete
   `89c4b3fe` snapshot, while current P2/P3 admission/runtime/package successors must be GREEN on
   the live pre-P4 tree. This is the existing D81/D89 generation pattern applied to the P1.6
   validator.

## Executable gate

Before P4.1 creates any P4 artifact or edits `packages/artifex/**`:

1. Prove `git merge-base --is-ancestor 140a9b53 89c4b3fe` and a zero diff between those commits
   for the P1.6 contract/cases/validator/task/grant paths.
2. Extract the complete `89c4b3fe` repository snapshot into a fresh temporary directory and run
   that snapshot's `validate-dispatch-admission.py` with its snapshot-local contract, cases,
   tasks, grants, P3 phase and `packages/task/lib`; require exit 0.
3. Run the current P3.6 two-generation adapter validator and P3.8 G1 promotion validator in the
   mode prescribed by D89 (current before the first P4 package mutation, historical afterward),
   plus the remaining named terminal fan-in checks; require every applicable gate to exit 0.
4. Run the current-tree P1.6 command only as a negative drift probe and require the exact
   `PARENT_ITEM_AS_TASK` refusal. It is never counted as GREEN and never replaces steps 1–3.

The gate changes validation mode, not evidence bytes, provider readiness, P3.4/P3.5 status, or
the recovery acceptance contract.
