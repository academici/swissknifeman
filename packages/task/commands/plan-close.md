Это РЕКОНСИЛЯЦИЯ/ЗАКРЫТИЕ по plan-протоколу. Ввод пользователя: «$ARGUMENTS».
Модель/effort запинены (Sonnet/low — механическая сверка, thinking тут жжёт токены без
пользы) — не переключай вручную. SSOT схем/статусов — скилл `plan-protocol`.
Статусы — 6 канонических строк байт-в-байт; правки статусов ТОЛЬКО по фактам.

## Режим `Pn.m` — реконсиляция item'а

1. Прочитай `plans/<PLAN-ID>/plan.md` (Status Board) и item Pn.m в `phases/Pn.md`.
2. Сверь заявленное с git-фактами: `git log --oneline -- <Files item'а>` ·
   `git diff <до>..<после> -- <Files>` — правки реально есть и соответствуют Scope Included?
3. Прогони команды из **Validation** item'а, зафиксируй результат.
4. Вердикт по фактам: подтверждено → `🟢 Done` (или `🟠 Done with deviations` + Known
   Deviations); **нет подтверждения (нет коммитов/диффа, Validation красная) — НЕ 🟢**:
   оставь/верни `🟡 In progress` или `🔴 Blocked` и напиши почему в Completion Notes.
   Файлы item'а НЕ закоммичены (в `git status` как modified/untracked) → item ещё не
   `🟢`: либо дождись коммита, либо явно допиши в Completion Notes «не закоммичено,
   коммит — за оркестратором волны» (иначе cold-start по git-истории не увидит работу).
5. У `🟠`-item'ов перечитай Known Deviations: deviation могла быть устранена ПОЗЖЕ
   соседним коммитом (проверь git-историей) — устаревшую пометь «(устранено) … коммитом
   <sha>», не оставляй пугать несуществующим долгом.
6. Синхронизируй Phase Status и Status Board в `plan.md`; перезапиши `handoff.md`,
   если статус изменился.

## Режим `Pn` — закрытие фазы

1. Все items фазы терминальны (`🟢`/`🟠`/`⛔`)? Нет — перечисли нетерминальные
   с их статусами и ОСТАНОВИСЬ (фаза не закрывается частично).
   Затем `git status --short`: файлы в дереве ВНЕ объединения Files всех item'ов фазы —
   предупреждение «незапланированные/грязные файлы в дереве закрываемой фазы» с их
   списком (не закрывай молча: это либо чужая незакоммиченная работа, либо регресс —
   маршрутизируй оркестратору).
2. Сведи таблицы: `## Phase Status` фазы ↔ статусы items ↔ строка фазы в
   `## 4. Phase Index & Status Board` (`Items 🟢/всего`, статус фазы) — без расхождений.
3. Заполни `## Phase Handoff` в `phases/Pn.md`: что сдали, известные отклонения
   (агрегат Known Deviations items), что дальше.
4. Перезапиши `plans/<PLAN-ID>/handoff.md` (Next: первый item следующей фазы или
   закрытие плана); добавь строку в `## 6. Update Log`.
5. Если ВСЕ фазы плана теперь терминальны (`🟢`/`🟠`/`⛔` — по строке статуса каждой фазы
   в `## 4. Phase Index & Status Board`) — план закрыт ЦЕЛИКОМ: обнови `plans/ACTIVE.md`
   (в корне `plans/`; файла нет — создай) на канонический формат 4 строки: `# ACTIVE`,
   пустая строка, `**Active:** —`, `**Updated:** <YYYY-MM-DD>`; обнови `Status` в
   `## 0. Meta` plan.md (агрегат фаз: все 🟢 → `🟢 Done`, есть 🟠 → `🟠 Done with
   deviations`); в `Next:` handoff'а пиши «план закрыт» (линт это допускает только при
   полностью терминальном плане); добавь строку об этом в `## 6. Update Log` плана. Закрывается ОДНА фаза, а другие фазы плана ещё нетерминальны —
   `plans/ACTIVE.md` НЕ трогай.
6. Прогони `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/plan-lint.py" plans/<PLAN-ID>`
   (нет переменной/скрипта — предупреждение и пропуск); красное почини.

**Expected output:** таблица сверенных статусов (`ID | было | стало | основание`) +
финальная строка «PHASE-CLOSED: Pn» (фаза закрыта) либо список блокеров, почему фаза
не закрыта. Фаза закрыта — сразу после строки PHASE-CLOSED допиши строку:
`Context: handoff свежий — рекомендован /clear перед следующим item`
