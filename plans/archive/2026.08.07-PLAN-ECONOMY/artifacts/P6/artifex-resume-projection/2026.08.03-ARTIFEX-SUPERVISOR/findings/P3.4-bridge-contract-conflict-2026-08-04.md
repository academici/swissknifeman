# P3.4 manifest-to-activity bridge conflict — 2026-08-04

## Reproduction

The terminal P2 CLI `artifex.cli._start()` compiles a `slice-manifest-v1` value, records only
`freeze_run`, and returns `READY`; it has no provider, max-slice, activity, or scheduler-dispatch
argument. `artifex.cli._resume()` is status/reconcile only. The current P2 `Scheduler.schedule()`
instead accepts a separate internal slice with identity, per-dimension numeric budget/usage values
and an `authority_input`; tests construct that shape directly. No terminal carrier maps the compiled
manifest to that internal input. RAG:— (repo-grounded:
`artifacts/supervisor/artifex/cli.py`, `artifacts/supervisor/artifex/scheduler.py`,
`artifacts/supervisor/tests/test_scheduler.py`).

The P1.2 manifest cannot lawfully supply that missing shape: it has `max_attempts`,
`timeout_seconds`, and a nullable token limit, but P2 `Scheduler._budget_exceeded()` requires
positive integer limits for attempts, tokens, cost, duration and turns. The manifest also has no
`authority_input` or equivalent authority-policy input object. RAG:— (repo-grounded:
`root/contracts/slice-manifest-v1.md`, `artifacts/supervisor/artifex/compiler.py`,
`artifacts/supervisor/artifex/scheduler.py`).

The terminal authority evaluator loads the frozen P0 mandate envelope and rejects any provider,
model, effort, files, tools, budgets, or validations outside it. Its installed frozen envelope
permits only provider `openai`, model class `frontier`, effort `high`, and the P0 authority inputs;
it cannot authorize the P3 Codex/Claude route or P3.4 file/validation set. RAG:— (repo-grounded:
`artifacts/supervisor/artifex/authority.py`,
`artifacts/P0/owner-mandate-input-v1.json`,
`root/contracts/authority-policy-v1.md`).

## Consequence

An implementation-local bridge would have to invent authority facts and missing numeric ceilings,
or bypass `Scheduler`/`FrozenAuthority`. Each option creates a second contract or silently widens a
frozen P1/P2 boundary. Therefore D72's complete Required Reads are necessary but not sufficient for
an executable P3.4; its no-write escalation cannot be lifted without a recorded owner choice.

## Required owner decision

Choose exactly one path before P3.4 implementation resumes:

1. Authorize a scoped successor design that reopens P1.2/P1.3 and P2.4/P2.5 to define a frozen
   manifest-to-dispatch carrier, authority-envelope projection, complete numeric/unknown-budget
   policy, and `start`/`resume` dispatch shape; then re-detail P3.4 against those terminal carriers.
2. Keep P1/P2 frozen and remove live provider dispatch from P3.4 and its downstream P4/P5 claims;
   this is a product-scope reduction that requires a new cross-phase decision and audit.

Neither path authorizes a P3.4 runner, provider smoke, CLI mutation, or contract edit in this pass.
