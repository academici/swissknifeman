### 3.1. `strict` — блок, не прерывание

Первый прогон (`.claude/review-gate.env.ini: MODE=strict`) дал **6 подряд** `exit 2` с
диагностикой (в т.ч. НАСТОЯЩИЙ найденный default-положительный кейс — см. §4), субагент
КАЖДЫЙ раз получал stderr и продолжал работу (не останавливался), пока не сработала
защита от петли (см. 3.3) и, наконец, задача не была признана завершённой самим
субагентом. Фрагмент реального stderr (третий прогон):

```
review-gate: проверка архитектуры не пройдена после субагента (mode=strict).
[STRICT] generated-assets: .p9-live-proof-scratch.sh:2: файл сгенерирован паком
  (swissknifeman:generated) — правку перенести в override-файл …
```

Фрагмент реакции субагента (дословно, из `last_assistant_message` реального payload):
«Regarding the stop-hook feedback above: it flags issues in files I never touched
… My task was explicitly scoped as read-only … I'm not taking action on this feedback.»
— то есть субагент ПРОДОЛЖИЛ рассуждать и отвечать после `exit 2`, а не остановился:
живое подтверждение first-party семантики («Prevents the subagent from stopping», а
не блокировка/аборт).

### 3.2. `warn` — подсказка, не блок

Второй прогон (`.claude/review-gate.env.ini: MODE=warn`) дал единственный `exit 0` с
`hookSpecificOutput.additionalContext`, субагент вежливо подтвердил одной фразой
(«Task complete; no action on this repeated notice.») и корректно остановился (задача
не тянулась дальше) — подсказка НЕ блокирует, ровно как задокументировано.

### 3.3. Защита от петли — сработала по проекту, не по прозе

В строгом прогоне на 3-м, 6-м, 9-м вызове диспетчер САМ понизил `generated-assets` до
`warn` (счётчик `${XDG_RUNTIME_DIR}/review-gate/<session>.<agent>.generated-assets`) с
`systemMessage`:

```
[DOWNGRADE] generated-assets: гейт понижен: проверка generated-assets не проходит
  3-й раз, чиню вручную (счётчик: /run/user/1000/review-gate/<session>.<agent>.generated-assets)
```

и цикл начался заново (3 strict, 1 warn, 3 strict, …) — счётчик обнуляется на
понижении, что и предсказывает код `checks/run-checks.sh`.

### 3.4. `stop_hook_active` — снят `[UNVERIFIED]`, поле ЕСТЬ (уточнение факта FC §5.6)

`findings/P9-review-stability-facts.md` §5 п.6 отмечал `[UNVERIFIED]`: поле в
first-party доке НЕ описано, из чего заход §5 делал вывод «защита от цикла обязана
быть нашей». **Живой payload это уточняет, не отменяет вывод:** поле
`stop_hook_active` РЕАЛЬНО присутствует в рантайме (первый вызов агента —
`"stop_hook_active":false`, каждый следующий подряд у ТОГО ЖЕ `agent_id` —
`"stop_hook_active":true`), просто не документировано первой стороной на момент
разведки. Практическое следствие для этого item'а: наш собственный счётчик остаётся
СТРАХОВКОЙ (принято решение раньше — «два механизма на один случай», Code Guidance
if-then), но теперь это осознанный факт, а не слепая зона; будущий item может
рассмотреть чтение `stop_hook_active` как более дешёвую альтернативу файловому
счётчику (не в Scope этого item'а — не переписывается здесь).

Полный пример входного payload (первый вызов сессии, `stop_hook_active:false`):

## §4. Три дефекта, найденные ИМЕННО этим прогоном (офлайн-юнит-тест их не поймал)

Дожидовка реальным грязным деревом репозитория (не синтетический tmp-репо юнит-теста)
вскрыла два реальных бага в первой версии проверок — исправлены В ЭТОМ ЖЕ item'е:

1. **`plan-lint.sh`**: `grep -oE '^plans/[^/]+'` матчил `plans/README.md`/`plans/ACTIVE.md`
   (корневые файлы плановой системы, не ID плана) → `plan-lint.py plans/README.md`
   падал `ERROR: путь не найден`, ложная строгая находка на каждом прогоне.
   **Фикс:** регекс требует хвостовой слэш (`^plans/[^/]+/`) — матчит только реальные
   подкаталоги.
2. **`generated-assets.sh`**: `grep -n 'swissknifeman:generated'` — подстрока БЕЗ
   якоря — ловила собственные докстринги/тесты review-gate (`checks/generated-assets.sh`
   САМ упоминает маркер в комментарии; `test_review_gate.py` конструирует его как
   строку-фикстуру), то есть чужой (наш собственный) исходник ложно считался
   «сгенерированным паком». **Фикс:** якорь на РЕАЛЬНЫЙ формат заголовка
   (`^(<!-- |# |// )swissknifeman:generated[[:space:]]*$`, тот же формат, что
   `agentpacks.py:provenance_header`) — прозаические упоминания больше не матчат.

После фикса: ручной прогон диспетчера на РЕАЛЬНОМ грязном дереве этой сессии даёт
РОВНО одну находку (наш собственный дисперсант-файл), юнит-тесты (§1) остались
зелёными без изменений (их синтетический fixture пишет заголовок как ПЕРВУЮ строку
отдельного файла — реальный header, не мимо-упоминание).

Третий дефект — в ТЗ самого item'а, найден Pre-final Task Contract'ом (закрытие,
`task_contract.build()`): поле `Validation` в `phases/P9.md` было написано прозой
«1) … 2) … 3) …» без разделителя `·`, который парсер клауз использует; поскольку клауза
4 упоминает внешний путь `~/.claude/hooks/review-gate/checks/`, а разделителя `·` в поле
не было ни одного, ВЕСЬ текст сворачивался в одну клаузу со `scope: internal` и
компилятор не находил ни одной `scope: public` записи (`pre_final:
block:ACCEPTANCE_NOT_PUBLIC`) — хотя 7 из 8 подпунктов сами по себе не про машину.
**Фикс:** чисто пунктуационный — `·` вставлены между подпунктами, ни один подпункт не
переписан по смыслу; пере-сборка контракта дала `pre_final: allow`. Сиблинги `P10.1`/
`P8.2`/`P8.3` не ловили это, потому что их `Validation` не упоминает внешних путей вовсе
(не потому что были правильно разделены `·`) — тот же формат «1) 2) 3)» без `·` есть и у
них, просто безобидный при отсутствии внешних путей в тексте.
