# Common plan principles

This layer applies only after an explicit Task invocation. The current Task command selects one
adjacent mode reference; the full `../SKILL.md` remains the schema canon and is read only
when a named schema/detail is actually needed.

1. Deliver the complete owner-authorized result to its acceptance boundary.  A GREEN
   item, a successful check, or an empty open-run list is not completion of a larger
   admitted workset.
2. Repair deterministic, reversible, plan-owned drift locally and verify it.  A failed
   protected operation stays fail-closed, but that refusal is not by itself a terminal
   response to the owner.
3. Use the runtime facade to reconcile durable truth before Next or final: journal, item state, decision/status
   views, the selected frontier bundle, handoff, and receipt must agree.
4. Escalate only a reproduced safety, authority, irreversible, external, or product-
   decision boundary.  Continue independent authorized work when one branch is bounded.
5. Never manufacture evidence.  Stale, foreign, or incomplete evidence lowers confidence
   and triggers recovery; it does not prove product RED or GREEN.
6. Owner budget constrains method and research breadth. Prefer one focused validation and
   reuse unchanged evidence; do not add proofs, phases or reviews to optimize formal completeness.
   This economy rule does not permit hiding execution-critical design reasoning: a finished plan
   preserves the code map, algorithms, examples, failure modes and verification boundary in linked,
   digest-bound supporting artifacts.

Preserve unrelated work and provider parity.  Schema names, status literals, carrier
layout, and compatibility rules are owned by `../SKILL.md` and its layout reference, not
redeclared here.
