## 1. `2026.07.15-TELEMETRY-OPT` OQ-4 — пин `task:research`: оставить `opus/high` или A/B на `sonnet/high`

### 1.1 Постановка (repo-grounded)

`plans/archive/2026.07.15-TELEMETRY-OPT/findings/P3-routing-audit.md` §3, вердикт **needs-Owner**:
«Opus-пин = reduce/синтез-мозг. Sonnet 5 near-par на retrieval+синтез, но **fidelity цитат +
кросс-источниковое reasoning** — зона, где Opus чуть впереди. Tradeoff: плохой синтез → плохие входы
`design` (но ловится downstream) → risk **MODERATE**, приоритет низкий.»

Предмет вопроса **узкий**: fan-out `task:research` уже на implementation-классе, Opus держит только
reduce-слой. Вопрос ровно про понижение оставшегося reduce-слоя, а не про «перевести research на
Sonnet» целиком.

### 1.2 Что изменилось с 2026-07-15

- `[ФАКТ]` **Вердикт написан против Opus 4.8, а не против сегодняшней пары.** Сегодня выбор —
  Opus 5 vs Sonnet 5; дословный перенос сравнения «Sonnet 5 vs Opus 4.8» к этой паре неверен (D25).
- `[ФАКТ]` **Цены и окна** (бандл-скилл `claude-api`, кэш 2026-06-24, сверено 2026-07-28):

  | Модель | ID | Вход $/1M | Выход $/1M | Контекст |
  |:--|:--|--:|--:|--:|
  | Opus 5 | `claude-opus-5` | 5.00 | 25.00 | 1M |
  | Sonnet 5 | `claude-sonnet-5` | 3.00 (интро **2.00 до 2026-08-31**) | 15.00 (интро 10.00) | 1M |

  Дельта Opus 5 → Sonnet 5: **−40 % вход / −40 % выход** по списку; **−60 %/−60 %** на интро-цене,
  которая истекает **через месяц с небольшим** (2026-08-31).
- `[ФАКТ]` **Дельта цены переводится в дельту счёта напрямую — токенизатор один.** Sonnet 5
  использует тот же токенизатор, что Opus 4.7/4.8 (и, соответственно, Opus 5): «Claude Sonnet 5 uses
  the same new tokenizer as Opus 4.7/4.8» (`claude-api` → `shared/model-migration.md`). То есть
  одинаковый текст даёт сопоставимое число токенов на обеих моделях, и наивный расчёт «−40 %»
  не съедается разной токенизацией. (Это НЕ верно для сравнения с Sonnet 4.6: там +30 %.)
- `[ФАКТ]` **Effort `high` доступен на обеих** — понижение `opus/high → sonnet/high` не требует
  менять ось effort (Sonnet 5 несёт полную лестницу `low…max`).
- `[ФАКТ]` **Позиционирование вендором**: Sonnet 5 — «The best combination of speed and intelligence
  in the Sonnet tier; **near-Opus quality on coding and agentic work**». Формулировка про **coding и
  agentic**, не про research/цитаты.
- `[ФАКТ, отрицательный результат]` **Вендорского (и независимого) замера citation fidelity
  Opus 5 vs Sonnet 5 НЕ существует** — проверено 2026-07-25 (`findings/P3-oq4-oq5-decision-inputs.md`
  §1) и **переподтверждено 2026-07-28** (RAG ✅ perplexity-web): опубликованного head-to-head нет.
  Что есть — публичные харнесы класса **L-CiteEval** (2025) и смежные citation-attribution
  бенчмарки; они не дают пары Opus 5 ↔ Sonnet 5, но дают **готовую методику**, если владелец
  закажет собственный замер.
- `[СИНТЕЗ]` Типовые деградации при переводе research/synthesis-агента на Sonnet-класс (из
  разведки 2026-07-25, свидетельство косвенное): сверка документов между собой при **противоречащих**
  источниках; удержание ограничений на длинных прогонах; надёжность связки «почему этот источник
  подтверждает это утверждение». Держится: first-pass retrieval, суммаризация одного источника,
  латентность и стоимость.

### 1.3 Неудобные факты (обязаны быть в пакете, Code Guidance «анти-подгонка»)

- Fan-out `task:research` **уже** на implementation-классе → потенциал экономии от понижения
  ограничен reduce-слоем; «−40 % на research» — это −40 % на **одном** (пусть и самом дорогом
  по токенам выхода) слое, а не на команде целиком.
- Наш собственный контур **не измеряет качество research** ничем: `skiller eval` тестирует СКИЛЛ,
  а не команду; корпуса citation-fidelity у нас нет. Значит downgrade будет решением **без
  обратной связи** — деградация синтеза проявится не алертом, а плохим планом.
- Обратное тоже честно: **сохранение Opus-пина тоже ничем не обосновано численно** — «Opus чуть
  впереди на цитатах» остаётся косвенным синтезом с 2026-07-15, повторно не подтверждённым.
- D16 действует: изменить пин легально **только** (а) с приложенным замером, либо (б) явной
  owner-D-записью, называющей себя таковой. Второй носитель пина —
  `packages/task/configs/command-routing.json`; правка frontmatter без него = красные parity-тесты.

### 1.4 Варианты

| # | Вариант | Цена | Риск | Что закрывает |
|:--|:--|:--|:--|:--|
| **A** | **Оставить `opus/high`** (статус-кво) | 0 работы; продолжаем платить Opus-ставку на reduce | нулевой новый; сохраняется «дорого без доказательства» | закрывает вопрос как «решено сознательно», снимает pending |
| **B** | **Понизить до `sonnet/high` owner-D-записью, БЕЗ замера** (легально по D16(б)) | −40 % (сейчас −60 %) на reduce-слое research | MODERATE: тихая деградация синтеза, ловится только downstream в `design`; отката по метрике нет — только по ощущению | закрывает вопрос и даёт экономию сразу |
| **C** | **Заказать A/B и решать числом** | 1 item: корпус из 8–12 research-задач с известными источниками + разметка «утверждение ↔ источник» (методика — класс L-CiteEval), 2 прогона на модель | низкий; но это **работа**, которой сейчас нет носителя (кандидат `roadmap.md`, не эта фаза) | закрывает вопрос доказательно, но позже |

### 1.5 `[РЕКОМЕНДАЦИЯ]` — **вариант A (оставить `opus/high`)**, с оговоркой

Причины, по порядку веса:
1. Предмет экономии **мал**: fan-out уже дешёвый, понижается один reduce-вызов на прогон.
2. Ошибка **асимметрична**: плохой синтез research течёт в `design` → в план → в исполнителей;
   цена ловли поздняя, цена Opus-ставки — копеечная относительно этого.
3. Свидетельство про «Sonnet 5 near-Opus» относится к **coding/agentic**, а не к нашей нагрузке
   (кросс-источниковый синтез с цитатами) — переносить его на research значит подгонять.
4. Интро-цена Sonnet 5 (−60 %) истекает 2026-08-31: решение, принятое ради неё, через месяц
   держится уже на −40 %.

**Оговорка честности:** это рекомендация «не менять при отсутствии данных», а не доказательство,
что Opus лучше. Если владелец хочет экономию — **вариант D** предпочтительнее чистого B: он
делает откат условием, а не намерением.

### 1.6 Что будет, если не решать

Вопрос третий раз переезжает планом дальше (TELEMETRY-OPT → TOKEN-ECON-P6 → ECO-OPT). Практическая
цена бездействия близка к нулю (пин работает), но **план не может закрыться `🟢`**: pending-вопрос
на закрытии даёт `🟠 Done with deviations` (plan-protocol §3), и item P3.3 остаётся незакрытым,
блокируя терминальность фазы P3.

## 2. `2026.07.15-TELEMETRY-OPT` OQ-5 — protection-surface: ось B (компаунд read-only) и ось C (сигнал permission-friction)

### 2.1 Постановка и что от неё осталось

Исходно спрашивалось: тюнить ли auto-approve на компаунд read-only Bash (**ось B**) и/или заводить
отдельный сигнал `permission_friction` в run-report (**ось C**), сверх дисциплины (**ось A**, уже
применена в `anti-drift` v0.4.0).

- `[ФАКТ]` **Ось B построена ДВАЖДЫ.** Движок Claude Code сам режет компаунд: «The recognized command
  separators are `&&`, `||`, `;`, `|`, `|&`, `&`, and newlines. **A rule must match each subcommand
  independently**» (first-party `/docs/en/permissions`, перечитано 2026-07-28 —
  `code.claude.com/docs/en/permissions`). Наш хук делает то же:
  `packages/harness/configs/claude-code/hooks/auto-approve/lib/analyze.sh` (`_segments`/`_segment_ok`).
  ⇒ «строить ли ось B» — **не вопрос**; вопрос сместился на «почему DENY всё же были».
- `[ФАКТ]` Ось C формулировалась как «завести свой сигнал». Свой изобретать не нужно: first-party
  OTel уже несёт `claude_code.tool_decision` с атрибутами `decision` (`accept`|`reject`) и **`source`**
  (`config` | `hook` | `user_permanent` | `user_temporary` | `user_abort` | `user_reject`).
  ⇒ ось C = выбор «adopt OTel-контур vs остаться на `tool_failures` в run-report».

### 2.2 Сверка форм с закрытым перечнем исключений — и что она вскрыла

**Метод.** Взяты run-report'ы флота (`<project>/.claude/runs/*.json`, schema 2) за живое окно и
классифицированы по ЧЕТЫРЁМ причинным классам. Числа воспроизводимы командой (§2.6).

`[ФАКТ]` **Окно 2026-07-07 … 2026-07-28, 247 run-report'ов, 13 проектов; 135 policy-shaped DENY:**

| Класс | Что это | Событий |
|:--|:--|--:|
| hook `deny_hard` | `rm`/деструктив, срез нашим хуком | **52** |
| Read-deny каталога (tool `Read`) | путь под `Read(...)`-запретом | **15** |
| Bash-DENY с текстом команды | разобраны ниже (66 уникальных форм) | **68** |

Разбор 68 Bash-DENY:

| Класс | Объяснение | Форм | Доля |
|:--|:--|--:|--:|
| **R1** | путь накрыт `Read(...)`-запретом **per-project** `.claude/settings.local.json` (`.env*`, `vendor/**`, `node_modules/**`, `storage/logs/**`, `storage/framework/**`, `**/*.lock`, `**/CHANGELOG.md`, `vendor/bin/**`) | **41** | 60 % |
| **R2** | команда **не парсится** — first-party класс «Commands the analysis can't parse» | **11** | 16 % |
| **R3** | мутация/деструктив (`rm`, `pkill`, `chmod -R`, `docker compose exec`, `composer show`) | **5** | 7 % |
| **R5** | политикой **не объясняется** — кандидат «отказ человека» | **11** | 16 % |

⇒ **113 из 135 (84 %) — работа политики по построению**, ещё 11 (8 %) — самонанесённый дефект
формы команды, и только **11 форм (8 %) остаются необъяснёнными**.

**Находка, меняющая ответ на вопрос «почему DENY были»** `[ФАКТ]`:

> Инвентаризация P4.1 классифицировала формы **против `settings.base.json` + `hooks/auto-approve/config.json`**
> (её собственный заголовок: «обоснование — Required Reads 3–4»). Но флотовые проекты несут
> **гораздо более широкий** `deny` в per-project `.claude/settings.local.json`: `agelto` — 34 правила,
> `dterema` — 35 (включая `Read(vendor/**)`), `vintera/cms` — 34, против **14** в `settings.base.json`.
> First-party прямо распространяет `Read`-запреты на Bash: «**Read and Edit deny rules apply … to file
> commands Claude Code recognizes in Bash, such as `cat`, `head`, `tail`, and `sed`**»
> (`code.claude.com/docs/en/permissions`, 2026-07-28). ⇒ бакет «c — needs-Owner ambiguous» (36/98, 37 %)
> в P4.1 в значительной части был **измерен против не той поверхности политики**, а не оставался
> необъяснимым по существу.

Прямое подтверждение на крупнейшей форме P4.1 (`grep -rn "…" …/Media.php`, 16×, 5 проектов, бакет c):
в свежем окне её прямой аналог — `grep -rn "function media(" …/vendor/spatie/laravel-medialibrary/src/InteractsWithMedia.php`
(проект `dterema`), и он попадает в **R1**: у `dterema` в `.claude/settings.local.json` стоит
`Read(vendor/**)`. То есть гипотеза P4.1 `[POSSIBLE-DEFECT]` «в части проектов не раскатан
auto-approve хук» **не требуется** для объяснения этой формы: политика запретила её штатно.
(Гипотеза не опровергнута полностью — она просто перестала быть ведущей.)

**Поформенная сверка «Топ-10 повторных форм» P4.1** (то, что предписано Scope Included item'а;
классы — из §2.2, `[ФАКТ]` для всех строк, кроме явно помеченной гипотезы):

| # | Форма (усечена как в архиве) | Бакет P4.1 | Объяснение сегодня |
|:--|:--|:--|:--|
| 1 | `grep -rn "guarded\|fillable\|…" …/Media.php` (16×, 5 проектов) | c | **R1** — vendor-путь под `Read(vendor/**)` per-project; прямой аналог подтверждён в свежем окне (`dterema`) |
| 2 | `cd …/vendor/filament && grep -rn "function datalist" forms/src` (4×) | a | **R1** — тот же `Read(vendor/**)`; компаунд-разбор здесь ни при чём |
| 3 | `head -20 grep -rn "virtualAs\|storedAs" --include=*.php …` (4×) | c | **R2** — команда не парсится (склейка `head` + `grep` без разделителя); класс живой: 11 форм в свежем окне |
| 4 | `ls vendor/laravel/framework/…/Schema/` (4×) | c | **R1** — vendor-путь |
| 5 | `grep -n "^DB_" .env.example ; grep -n "DB_HOST…" .env` (4×) | b | **R1** — сегмент `.env` под `Read(.env)` |
| 6 | `find . -path ./vendor -prune -o -name '<Test>.php' -print` (3×) | c | **не объяснено**; `[ГИПОТЕЗА, не проверена]` команда НАЗЫВАЕТ denied-каталог в аргументе `-path`, и проверка file-команд может матчить его. Проба — одна команда внутри проекта с `Read(vendor/**)`: `find . -path ./vendor -prune -o -name '*.md' -print` |
| 7 | `grep -n "DB_CONNECTION" .env ; grep -n "'default'" config/database.php` (3×) | b | **R1** — `.env` |
| 8 | `sed -n '1,200p' .env.example` (3×) | c | **объяснено repo-grounded:** `sed` СОЗНАТЕЛЬНО не в `allow` нашего хука (`$comment_security` конфига: тело в кавычках скрыто от анализатора) ⇒ команда уходит в обычный промпт; исход — решение человека, а не дефект |
| 9 | `rm -rf …/.claude/skills/plan-protocol` (3×) | b | **R3** — `deny_hard`, by design |
| 10 | `cat -n …/CHANGELOG.md` (2×) | b | **R1** — `Read(**/CHANGELOG.md)` |

**Итог по Топ-10:** 7 форм — штатная работа политики (6× Read-deny + 1× `deny_hard`), 1 — наш
сломанный синтаксис (R2), 1 — сознательное security-решение хука (`sed`), **1 остаётся
необъяснённой** с проверяемой гипотезой. Гипотеза P4.1 «хук не раскатан» не понадобилась ни разу.

**Сверка с закрытым first-party перечнем исключений read-only** (unquoted glob при write-capable
флагах · «analysis can't parse» · `cd`+`git` · `cd`+редирект):

| Исключение | Сработало в окне | Комментарий |
|:--|:--|:--|
| «analysis can't parse» | **да, 11 форм (R2)** | единственное исключение с реальным весом |
| unquoted glob при write-capable флагах | не обнаружено | в наблюдённых `find`/`sed` глобы **закавычены** |
| `cd` + `git` | не обнаружено | — |
| `cd` + редирект | не обнаружено | first-party отдельно оговаривает, что редирект **только** в `/dev/null` не спрашивает |

`[ФАКТ]` **R2 — это наш собственный дефект, а не политики.** Формы буквально такие:
`head -3; ls vendor/bin/pint 2>&1` · `head; grep -rn '…' .env` · `head -20; cat .env` ·
`grep -vE '^\s*#|^\s*$' echo "=== … ===";  grep -E …` · `cd …/app grep -n "…" .env cat .env`.
Это **склеенные/оборванные команды агента** (голый `head`/`grep` без файла, читающий stdin, плюс
вторая команда без разделителя). Движок такое не парсит и по документированному правилу спрашивает.
Тот же класс объясняет форму #3 топ-10 P4.1 (`head -20 grep -rn "…" --include=*.php …`, 4×,
3 проекта) — она не «загадочная», она **сломанная**, и класс живой (11 форм за три недели).

### 2.3 Чего эта сверка НЕ может дать — и это главный аргумент оси C

`[ФАКТ]` Run-report фиксирует текст `Permission to use Bash with command X has been denied` —
**одинаковый и для запрета политикой, и для отказа человека в интерактивном промпте**. Атрибуции
решения (`config` / `hook` / `user_reject`) в нашем сырье **нет по построению**. Поэтому 11 форм R5
(`grep -n "MINIO_ROOT_PASSWORD" .env.example`, `cat …/.env.example`, несколько
`find . -path ./node_modules -prune -o -name '…' -print`) классифицируются как «кандидат: отказ
человека» — но **доказать** это нечем.

Это ровно та разбивка, которую даёт first-party `claude_code.tool_decision.source`. Иными словами:
ось C — не «ещё один сигнал», а **единственный способ закрыть остаток вопроса машинно**.

### 2.4 Варианты по осям

**Ось B (тюнинг auto-approve под компаунд read-only):**

| # | Вариант | Цена | Риск |
|:--|:--|:--|:--|
| **B0** | **Ничего не трогать** | 0 | 0 — разбор построен дважды, а измеренный остаток к нему не относится |
| **B1** | Расширить allow-множество хука (напр. добавить `sed`/`awk`) | правка `config.json` | **повышение риска by design**: `$comment_security` конфига прямо объясняет, почему `awk`/`sed` не в allow (тело в кавычках скрыто от анализатора ⇒ авто-approve = одобрять произвольный код) |
| **B2** | Ослабить per-project `deny` (`vendor/**`, `node_modules/**`) | правка 10+ чужих конфигов | снимает 60 % DENY, но это **сознательная контекст-гигиена** (не читать vendor), а не дефект |

**Ось C (сигнал permission-friction):**

DENY_PATHS = re.compile(r"(^|[\s\"'/])(\.env(\.[A-Za-z0-9_.-]+)?)([\s\"';|&]|$)"
                        r"|(^|[\s\"'/])vendor/|node_modules/|storage/logs|storage/framework"

ENV_EXAMPLE = re.compile(r"\.env\.example")
UNPARSEABLE = re.compile(r"(^|[;&|]\s*)(head|tail|grep|cat)(\s+-\S+)*\s*;"
                         r"|(^|[;&|]\s*)(head|tail)(\s+-\S+)*\s+(echo|grep|find|ls|cat)\s"
                         r"|\"\s+(grep|find|ls|cat|echo)\s|'\s+(grep|find|ls|cat|echo)\s"
                         r"|\.env\s+cat\s|\S\s+cd\s+/")
MUTATION = re.compile(r"(^|[\s;&|])(rm|rmdir|pkill|kill|chmod|chown|mv|cp|tee|sudo)([\s]|$)"
                      r"|docker\s+compose\s+(exec|up|down|run)|(^|[\s;&|])composer\s+(show|require|update)")
FP_EXCEPTION = re.compile(r"find\s[^|;&]*\s(-exec|-delete)([\s]|$)|(^|[\s;&|])(watch|setsid|ionice|flock)\s")

def classify(cmd):
    if MUTATION.search(cmd): return "R3 мутация/деструктив (наша политика)"
    if UNPARSEABLE.search(cmd): return "R2 не парсится (first-party)"
    if ENV_EXAMPLE.search(cmd) and not re.search(r"(^|[\s\"'/])\.env([\s\"';|&]|$)", cmd):
        return "R5 не объяснено политикой"
    if DENY_PATHS.search(cmd): return "R1 Read-deny путь (наша политика)"
    if FP_EXCEPTION.search(cmd): return "R4 first-party исключение"
    return "R5 не объяснено политикой"

files = [f for d in DIRS for f in glob.glob(os.path.join(os.path.expanduser("~"), d, ".claude/runs/*.json"))]
rows, extra, dates = [], collections.Counter(), []
for f in files:

    for tf in doc.get("tool_failures") or []:
        s = (tf.get("snippet") or "").replace("\n", " ")
        m = re.search(r"Permission to use \w+ with command (.*) has been denied", s)
        if m: rows.append(m.group(1))
        elif "deny_hard" in s: extra["hook deny_hard"] += 1
        elif "denied by your permission settings" in s: extra["Read-deny каталога"] += 1
print(f"run-report'ов: {len(files)} | окно: {min(dates)} … {max(dates)}")
print(f"policy-shaped DENY всего: {len(rows) + sum(extra.values())}")
print(f"Bash-DENY с текстом команды: {len(rows)} (уникальных форм: {len(set(rows))})")
for k, v in extra.most_common(): print(f"  + {v}\t{k}")
b = collections.Counter(classify(c) for c in rows)
for k in sorted(b): print(f"{b[k]:>3}  {k}")
# PY
