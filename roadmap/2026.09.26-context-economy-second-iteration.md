## 1. Цель итерации

После `v0.23`–`v0.24` экосистема получила stub hub, digest-память, Codex context telemetry и fleet MCP hygiene. **Вторая итерация** закрывает разрыв:

> Один consumer-проект может включить три провайдера в `.swissknife.json`, но **каждая активная сессия** должна видеть только **свою** projection: скиллы, MCP, root instructions, agents — без «призраков» других IDE и без research-тяжёлых серверов на пустом чате.

Измеримый north star для пилота `project:chatom` + **Cursor only**:

| Метрика | Сейчас (поле, 2026-09-26) | Цель итерации 2 |
|:--|:--|:--|
| MCP процессы на одну Cursor-сессию | maind + perplexity (+ иногда дубли plugin) | **maind** только в profile `dev` |
| Perplexity в `.cursor/mcp.json` baseline | объявлен всегда | только profile `research` |
| Дубли MCP namespace (`maind` / `plugin-core-*`) | воспроизводится | doctor **FAIL** или авто-merge policy |
| Provider-visible skill `name` collisions | сотни путей / ~204 имени (аудит 09-25) | doctor: 0 collisions в **effective** set для Cursor |
| SessionStart digest | ~1270 ток (~25% SKM first-turn) | `minimal` default ≤400 ток |
| Hub sha в `CLAUDE.md` | drift vs registry HEAD | `maind sync` / generate-hub обновляет comment |

Платформенный слой Cursor (system tools, user rules, subagent catalog) **вне scope** SKM — не обещаем снижение % UI до нуля; обещаем **полный контроль managed слоя** и честный receipt.

## 2. Принцип: один активный провайдер — одна projection

### 2.1. SSOT остаётся общим

- `.swissknife.json` — семантический профиль скиллов (бакеты).
- `.ai/guidelines/agent-entrypoint.md` — текст root (генерация `CLAUDE.md` / `AGENTS.md`).
- `.mcp.json` (gitignored) + `.mcp.json.example` — каталог серверов.
- `config.json` ecosystem entry `projects[].mcp` — политика профилей (когда появится).

### 2.2. Проекции раздельны (не смешивать discovery)

| Артефакт | Claude Code | Codex | Cursor |
|:--|:--|:--|:--|
| Skills delivery | marketplace `connect` | `.agents/skills` publication | **не** читать весь Claude plugin cache как resident |
| MCP enablement | `enabledMcpjsonServers` | `.mcp.json` + Codex MCP config | `.cursor/mcp.json` + **profile** + UI toggle |
| Root MD | `CLAUDE.md` + rules | `AGENTS.md` | rules/hooks; **не** дублировать maind health block |
| Agents pack | `.claude/agents` | subagents via Codex | только роли с `adapters: [cursor]` или project pack |

**Новое требование (SK-CTX-8):** `skiller doctor --context --provider cursor` строит inventory **только** из корней Cursor contract (`.cursor/*`, project rules, effective MCP, **явно** подключённые SKM skills) и **не** считает Claude-only cache как обязательный resident, пока Cursor session не включила Claude bridge.

### 2.3. «Чисто под Cursor» (consumer playbook до кода)

Пока нет `harness mcp apply --profile`, владелец может:

1. **Baseline `.cursor/mcp.json`:** только `maind`; `perplexity` и `codegraph` убрать из файла или держать в локальном untracked overlay.
2. **Customize → MCP:** выключить Perplexity для workspace chatom; состояние per-project.
3. **Планирование:** перед `plan-design` / research — включить Perplexity в UI **или** скопировать research fragment из `.mcp.json.example` в локальный `.cursor/mcp.json` и перезапустить сессию.
4. **Гигиена fleet:** скрипт `bin/mcp-gc` (см. W9) — убить процессы `perplexity-web-mcp` / `maind mcp` без активного родителя Cursor/Claude.

Эти шаги должны стать **одной командой** `harness integrate --provider cursor --profile dev`.

### 3.1. Perplexity — отдельное решение

| Вопрос | Решение итерации 2 |
|:--|:--|
| Грузит ли систему? | Да: ~100–130 MB RSS Node на процесс; fleet умножает на число забытых сессий |
| Грузит ли контекст? | Да: tool schemas в каждом ходе, пока MCP подключён |
| Нужен ли на «привет»? | **Нет** |
| Когда включать? | `plan-design`, `task-research`, явный owner request |
| Skill-triggered auto-enable? | **W4**: Task pre-hook → `harness mcp apply --profile research`; не полагаться на LLM «догадался» |

Claude уже изолирован через `enabledMcpjsonServers`; **parity** — Cursor dev profile без perplexity по умолчанию.

### 3.2. Codex / Claude — не ломать

- Не удалять `.swissknife.json` `providers.selection` — только **не активировать** лишние writers в одной сессии.
- Codex `.agents/skills` symlinks остаются; reconcile удаляет **orphan** и **duplicate name**, не весь каталог.
- Claude `enabledMcpjsonServers` остаётся whitelist-механизмом; harness **не** добавляет perplexity в project settings при profile `dev`.

## 5. Дизайн: Cursor-pure skill surface

### 5.1. Проблема

Cursor агрегирует skills из:

- `~/.cursor/skills-cursor/*`
- `.agents/skills` (symlinks)
- `~/.claude/plugins/cache/swissknifeman/**` (если marketplace bridge активен)
- `.agents/skills` project-specific

`skiller budget` меряет **45** скиллов профиля; Cursor list — **сотни** entries.

### 5.2. Целевое поведение

1. **Marketplace connect для Cursor** не должен требовать полного Claude plugin cache в prompt (D8 ownership уже частично есть — довести до doctor gate).
2. **`skiller vendor` / publication** для Cursor: только `adapters` включающие `cursor` **или** явный list в `.swissknife.json` `cursor.skills` (optional).
3. **Doctor** печатает:
   - `CURSOR_SKILL_INDEX_COUNT`
   - `CURSOR_SKILL_DUPLICATE_NAME`
   - `CURSOR_SKILL_OUTSIDE_PROFILE`

### 5.3. Task bucket

Скиллы `task/*` остаются в репозитории, но:

- ⊕ always = 0 без marker `TASK_SESSION` / journal plan-run;
- slash-command / Task CLI injectает body при вызове.

## 7. Пилот и критерии закрытия итерации

**Пилот:** `project:chatom`, primary provider **Cursor**, профиль скиллов без изменений.

**Before (зафиксировано 2026-09-26):** см. evidence snapshot.

**After (GREEN итерации 2):**

1. `harness mcp apply --profile dev --provider cursor` → `.cursor/mcp.json` только maind; Perplexity процесс не стартует до `research`.
2. `skiller doctor --context --provider cursor` → 0 `PROVIDER_CROSS_LEAK`, 0 duplicate MCP namespaces.
3. `skiller budget --first-turn --provider cursor --json` → total ≤ prior receipt − perplexity tools − digest delta (minimal).
4. `maind health --cwd` → hub sha актуален; memory mode documented.
5. Fleet doc: `mcp-gc --dry-run` на машине владельца без false-positive на активной сессии.

**Не входит в GREEN:** снижение Cursor platform %, upstream default-off MCP, полное удаление plugin cache.
