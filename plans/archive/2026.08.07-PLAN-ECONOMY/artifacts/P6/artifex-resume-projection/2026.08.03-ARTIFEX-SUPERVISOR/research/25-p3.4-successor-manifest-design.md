## Selected ownership model

P2's manifest remains an immutable historical snapshot: its hashes describe the P2.6 candidate at
`6c2c2ef3`, not an eternal prohibition on successor edits to `cli.py`, tests or README. P3.4 owns
the next additive snapshot in `artifacts/P3/adapter-manifest-v1.json`; its validator proves both
layers without rewriting either predecessor artifact. RAG:— (repo-grounded: plan-protocol
provenance/derived-artifact rules, P2.6/P3.4 Files and the reproduced hash boundary).

The P3 manifest carries:

1. a `base_prototype` reference with the exact P2 manifest path, SHA-256 and item commit
   `6c2c2ef3`;
2. current hashes for every P3.4 implementation/test/evidence file needed to reproduce the bounded
   runner and readiness verdict;
3. exact admission-index, provider-parity and minimized smoke-row references already required by
   P3.4.

The P3 validator recomputes the P2 manifest hash, then recomputes every P2 file row from
`git show 6c2c2ef3:<path>`. It never compares those historical file hashes with the evolved worktree.
It separately recomputes every P3 file hash from the current committed tree, validates the two
admission/readiness rows, runs the evolved supervisor suite, and refuses a missing Git anchor,
changed P2 carrier, changed current P3 file, extra row or raw-content class.

## Rejected alternatives

- Regenerate `prototype-manifest-v1.json`: rewrites terminal P2 evidence and makes its original
  Completion Notes irreproducible.
- Remove `cli.py` from P3.4: contradicts the declared additive dispatch binding and D39/D74.
- Change `validate-prototype.py` to ignore successor files: mutates a terminal P2 deliverable and
  weakens the exact closure check for its original generation.
- Keep demanding the P2 validator on the current evolved root but call the known failure expected:
  leaves P3.4 acceptance red and turns a skipped check into false green.
- Copy P2 hashes into P3 without a Git anchor: duplicates declarations without proving the frozen
  bytes ever existed together.

## DoR consequence

D81 records the generation boundary. P3.4 returns to `Not started`, retains its existing
implementation scope, and adds exact successor-manifest acceptance. The P2 manifest/validator,
P2.6 terminal status and Completion Notes remain unchanged; no current-tree P2 validator claim is
made after P3-owned files evolve.
