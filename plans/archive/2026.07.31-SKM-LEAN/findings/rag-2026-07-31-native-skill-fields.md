## 1. Полный справочник frontmatter SKILL.md (Claude Code)

Источник: <https://code.claude.com/docs/en/skills> §«Frontmatter reference», прочитано
2026-07-31. Вердикт: **first-party, актуально**.

| Поле | Есть? | Семантика (по доку) |
|:--|:--|:--|
| `name` | да | Отображаемое имя в листинге; у plugin-скилла задаёт последний сегмент команды |
| `description` | рекоменд. | Что делает + когда применять. **`description` + `when_to_use` обрезаются на 1 536 симв в листинге** |
| `when_to_use` | **да** | Доп. контекст «когда вызывать» — триггер-фразы, примеры запросов. Дописывается к `description`, входит в тот же кап 1 536 |
| `argument-hint`, `arguments` | да | Автокомплит и `$name`-подстановки |
| `disable-model-invocation` | да | `true` → Claude не грузит скилл сам; **также запрещает preload в субагентов**; с 2.1.196 — и запуск по расписанию |
| `user-invocable` | да | `false` → скрыть из меню `/`. **Не** блокирует Skill tool |
| `allowed-tools` | да | Пре-апрув инструментов на ход вызова; грант снимается со следующим сообщением |
| `disallowed-tools` | да | Удаление инструментов из пула на время активности скилла |
| `model` | **да** | Модель на время активности скилла; действует **до конца текущего хода**, в настройки не пишется; значения — как у `/model`, либо `inherit` |
| `effort` | **да** | `low` / `medium` / `high` / `xhigh` / `max`; перекрывает effort сессии |
| `context` | **да** | `fork` → выполнение в форкнутом субагент-контексте |
| `agent` | да | Какой тип субагента при `context: fork` |
| `background` | да | Только при `context: fork`; `false` → дождаться результата в том же ходе. **Требует ≥ 2.1.218** |
| `hooks` | да | Хуки, привязанные к жизненному циклу скилла |
| `paths` | **да** | Glob-паттерны, **ограничивающие авто-активацию**. Формат — как у path-specific rules (`/docs/en/memory#path-specific-rules`) |
| `shell` | да | `bash` (дефолт) / `powershell` |

**Вердикт по брифу:** все четыре поля, названные владельцем (`paths`, `context: fork`,
`model`, `effort`), **существуют** и документированы first-party. Плюс обнаружено пятое,
прямо закрывающее задачу P3, — **`when_to_use`**.

## 2. Липкость тела скилла — подтверждена дословно

Источник: тот же док, §«Skill content lifecycle»:

> When you or Claude invoke a skill, the rendered `SKILL.md` content enters the conversation
> as a single message and **stays there for the rest of the session**. […] Claude Code does
> not re-read the skill file on later turns.

**Вердикт:** гипотеза владельца о «липкости тел» — **подтверждена first-party**, это не
догадка. `context: fork` — штатное средство против неё (тело уходит в форкнутый контекст).

## 3. `context: fork` — семантика и оговорки

Источник: тот же док, §«Run skills in a subagent»:

- тело скилла **становится промптом** субагента; истории разговора субагент **не видит**;
- таблица «что видит форкнутый скилл»: system prompt — от типа агента; промпт — контент
  SKILL.md; `CLAUDE.md` — виден, **кроме** агентов `Explore` и `Plan`;
- предупреждение дока: `context: fork` **имеет смысл только для скиллов с явной задачей**;
  скилл-«справочник» («используй такие-то конвенции») отдаёт субагенту гайдлайны без
  задачи и возвращается пустым.

**Вердикт для P3:** критерий отбора под `fork` — **процедурный скилл с задачей**, не
справочный. Это ограничение сужает кандидатов и обязано быть в спеке item'а.

## 5. Модель субагентов и AgentTool suppression (вход P4)

Запрос Perplexity 2026-07-31: «Claude Code 2.1.219 Opus 5 AgentTool suppression changelog».

- Публичный changelog 2.1.219 — **расширение** механики субагентов (вложенные субагенты,
  дефолтная глубина 1 → 3) и Opus 5 как дефолтная модель; **явного пункта про подавление
  AgentTool в changelog нет**.
- Ограничение приходит **инъецированной системной инструкцией** («не вызывай AgentTool,
  если пользователь не просил»), о чём есть внешние сообщения
  (<https://www.reddit.com/r/ClaudeCode/comments/1v6y5q2/>), а не запись в release notes.
- 2.1.220 — «bug fixes and reliability improvements», изменений политики не документировано.
- Источники: <https://code.claude.com/docs/en/changelog>, Reddit-тред выше.

**Наблюдение repo-grounded, усиливающее внешний факт:** системный промпт ЭТОЙ сессии
(Claude Code 2.1.220, Opus 5) содержит строку `Do not call the AgentTool unless the user
requested it` — то есть подавление наблюдаемо непосредственно, а не только по внешнему
сообщению.

**Вердикт для P4:** драйвер обязан запускать воркера **процессом** (`claude -p`), а не
через Agent tool: процессный путь под инъецированную политику не попадает, а сама
политика — не версия API и может меняться молча.

## 6. CooperBench (вход P4 — почему драйвер последовательный)

Запрос Perplexity 2026-07-31. Источник: <https://cooperbench.com/> (Stanford/SAP; статья
«Why Coding Agents Cannot be Your Teammates Yet»).

- Бенчмарк парных агентов на **общей кодовой базе**, задачи независимо реализуемы, но
  конфликтуемы без координации.
- Результат — «curse of coordination»: **средняя просадка ≈ 30 %** против одиночной
  работы; у сильнейших моделей кооперативный успех **≈ 25 %**.
- Классы отказов: expectation / commitment / communication failures.

**Вердикт для P4:** драйвер волны **последовательный** (один воркер за раз на один
репозиторий). Параллельный fan-out воркеров по одному дереву — прямо тот сценарий,
который бенчмарк меряет как деградацию. Параллелизм остаётся легитимным там, где
поверхности не пересекаются (`Workflow` по независимым файлам), — но это не режим
exec-волны плана.

## 7. Anthropic-канон авторства скиллов (вход P3/P2)

Источник: <https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices>,
прочитано 2026-07-31.

- Тело `SKILL.md` — **≤ 500 строк**; сверх лимита выносить в reference-файлы;
- **доменная разбивка** reference-файлов (`reference/finance.md` отдельно от `sales.md`),
  чтобы вопрос одного домена не тянул контекст другого;
- ссылки — **не глубже одного уровня** от SKILL.md: при вложенных ссылках модель читает
  файлы частично (`head -100`) и теряет содержимое;
- **утилитарные скрипты вместо генерации кода**: код скрипта в контекст не попадает,
  попадает только вывод;
- на старте предзагружаются **только `name` + `description`** всех скиллов; тело — по
  активации.

**Вердикт:** пункты 2 и 3 аудита `audits/skm.md` — прямое цитирование этого канона,
подтверждены first-party.
