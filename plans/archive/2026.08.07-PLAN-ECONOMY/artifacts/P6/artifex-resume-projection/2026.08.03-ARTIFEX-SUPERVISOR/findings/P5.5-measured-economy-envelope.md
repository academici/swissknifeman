# P5.5 — D123/D127 reopen: the measured provider economy envelope (2026-08-06)

**Session:** claude-sonnet-5/high, `/task:plan-run`. Scope: exactly the third and final
D123/D127 reopen on P5.5 — a measured `economy` object beside the existing booleans in both
provider folds, propagated verbatim into the run record, plus a third re-freeze of both G2B
manifests and one appended `g2b-generation-ledger-v1.json` entry. Zero provider processes.

## 1. Shape

Each successful business fold (`claude_code.fold_business_records`, `codex.fold_records` with
`include_economy=True`) now returns an `economy` key:

```text
economy.worker        — the 7 economy-evidence-v2 metric_fields, each a non-negative int or null
economy.coordinator    — the same 7 fields, always the measured integer 0
economy.unknown_reasons — {"worker/<field>": "<source-specific reason>"} for every null worker field
economy.inclusion_bases — {"worker/reasoning_tokens": {...}} only for claude-code, else {}
economy.zero_bases      — {"coordinator": {"component", "path", "statement"}}, always present
```

This is a per-attempt *fragment* of `economy-evidence-v2`'s own `lanes.<lane>.attempts[i]`
shape: `worker`/`coordinator` are the exact flat dicts the contract's `attempt` object expects,
and `unknown_reasons`/`inclusion_bases`/`zero_bases` use field-relative keys (`worker/<field>`,
`coordinator`) rather than full document pointers, so a later P5.4 assembly step only has to
prefix each key with `/lanes/<lane>/attempts/<n>/` to splice it into the full evidence document.
Both `tests/test_provider_claude_code.py::test_economy_envelope_conforms_to_economy_evidence_v2_and_bare_zero_is_refused`
and `tests/test_provider_codex.py::test_economy_envelope_conforms_to_economy_evidence_v2` prove
this by doing exactly that splice against the real, already-frozen
`artifacts/P1/validate-economy-evidence.py` (`validate_shape_v2`), reusing the P5.7 case bank's
`base_input` as the closed-shape carrier. The `zero_bases`/`inclusion_bases` `path`/`evidence_ref`
text is byte-identical to what that same P5.7 fixture (`artifacts/P1/economy-evidence-cases-v2.json`)
already encodes, so the producer and the frozen contract fixture agree by construction, not by
coincidence.

## 2. Extraction rules (D123/D127 rule 1 — extraction, never computation)

- `input_tokens`/`cached_input_tokens`/`output_tokens`: read by key from `usage`
  (`usage.input_tokens`/`usage.cache_read_input_tokens`/`usage.output_tokens` for claude-code;
  `usage.input_tokens`/`usage.cached_input_tokens`/`usage.output_tokens` for codex). Missing,
  non-dict `usage`, or a non-int/bool/negative value → `null` + a named `unknown_reasons` entry.
- `reasoning_tokens`:
  - claude-code — the sole sanctioned rule-1 instantiation: `0` with an `inclusion_bases` entry
    naming `output_tokens` as the containing field, **only when `output_tokens` itself extracted
    as a measured integer**; otherwise `null` (no basis without a valid containing field).
  - codex — plain extraction from `usage.reasoning_output_tokens`, never an inclusion basis.
- `cost_microunits`:
  - claude-code — `usd_to_cost_microunits(total_cost_usd)`: `Decimal(str(value)) * 1_000_000`
    quantized to zero places with `ROUND_HALF_UP`, cast to `int` — never binary float
    arithmetic. Proved on boundary values `0`, `0.0000005`, `1.9999995`, `1.23456789`.
  - codex — always `null`; the CLI reports no cost field on `turn.completed.usage` and a
    price-table conversion is banned by D25.
- `duration_ms`:
  - claude-code — `record.duration_ms` (provider-reported), extraction-only.
  - codex — the CLI reports no per-turn duration at all (no timestamp field exists anywhere in
    its allowed event shape). `fold_records` itself always returns `null` + a named reason;
    `activity.BusinessProviderActivityPort._fill_wrapper_duration` fills it, *after* `worker.run`
    returns, from the wrapper's own already-measured `result["duration_ms"]` (the whole-process
    wall time) and clears the placeholder reason. This is deliberately NOT threaded through
    `worker.run`'s `normalizer` callback: that callback is shared with the provider-free P2/P3
    smoke lane (`ProviderActivityPort`), and widening its call signature there risked smoke-lane
    regressions for a business-only need. The fill is entirely inside `activity.py`
    (`BusinessProviderActivityPort.run`), which is exactly the layer that already knows the
    measured wall time.
- `turns`: claude-code reads `num_turns` (extraction); codex counts the `turn.completed` events
  observed in the fold (event-derived — no `turns` field exists in codex's own JSON at all).

## 3. Coordinator (D123/D127 rule 2 — structural zero)

Both providers' `economy.coordinator` is the measured all-zero envelope with a `zero_bases`
entry pointing at `packages/artifex/lib/artifex/scheduler.py`
(`test_integration.test_p2_core_remains_provider_free_and_cli_only_exposes_selection` already
proves that file imports no provider, launches no subprocess and never references
`codex`/`claude`). `providers/common.zero_coordinator_envelope()` is the single shared
constructor both providers call, so the path/statement text cannot drift between them.

## 4. Boundary (smoke lane unaffected)

`codex.fold_records` gained a new `include_economy: bool = False` keyword — default `False`
preserves the P2/P3 smoke lane's exact prior return shape byte-for-byte
(`tests/test_provider_codex.py::test_smoke_path_default_never_carries_an_economy_key`). Only
`BusinessProviderActivityPort.run`'s codex branch passes `include_economy=True`. claude-code's
smoke (`fold_records`) and business (`fold_business_records`) folds were already separate
functions; only the latter changed. `security.observation`'s allowed-key set gained the
optional `economy` key with a closed five-key shape check; its absence (the smoke lane) is
unaffected.

## 6. What this item does not do

No admission validation, catalog resolution, refusal ordering, cap, permission, argv
construction or `dispatch-business` validate-only guarantee changed. No CLI surface was added —
`cli.py`'s `dispatch-business-intent` still surfaces only `kind`/`process_count`/`reason_code`;
exposing `economy` through that command (or assembling the full `economy-evidence-v2` document
from many per-attempt fragments) is P5.4's own scope, not this item's — this item's Deliverable
is that the run record a future pilot reads (`BusinessProviderActivityPort.run`'s direct return
value, after `security.observation`) already carries the measured envelope without re-parsing
provider output.
