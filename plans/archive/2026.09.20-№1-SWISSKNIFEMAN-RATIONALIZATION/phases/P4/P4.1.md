### P4.1 — Отобрать только измеримо полезные rationalization slices

**Intent:** Свести verified evidence P1–P3 в малый, трассируемый portfolio: отсеять неактуальные и недоказанные идеи, провести только дешёвые различающие эксперименты и передать P5 лишь vertical slices с verdict `go` и готовыми validation/rollback contracts.
**Why:** RAG:— Исходный аудит предлагает упрощения root instructions, Task, skills и provider surfaces, но не имел локального checkout; P1–P3 специально отделяют observed cost/value от activation и telemetry gaps. RAG:✅ 2026-09-20 Google SRE ограничивает canary по времени и охвату, сравнивает candidate с control и предупреждает о загрязнении сигнала параллельными canary; NIST RMF подтверждает accountable evidence/monitoring, но не задаёт portfolio reducer swissknifeman.
**Scope Included:** Evidence-to-candidate ledger для root/instruction, Task, skill, provider/parity/validation и P3 capability hypotheses; hard eligibility gates и dominance/merge pass; не более четырёх temporary-worktree experiments; максимум две valid matched A/B pairs на experiment; один portfolio с `go|keep|defer|reject`, applicability, dependencies, validation, rollback и post-change measurement для каждого outcome.
**Scope Excluded:** Weighted scoring/RICE/WSJF, новый portfolio framework или schema; больше четырёх experiments или двух valid pairs на candidate; full statistical programme; permanent source/config/provider/consumer writes; исправление Task/skills/validation defects; release, rollout, migration или P5 implementation; повтор P2 field audit либо P3 memory/codegraph pilot.

**Implementation Rules:** До triage потребовать GREEN P1–P3 outputs и запечатанный global-audit route; иначе `dependency-not-ready`. Из P1 hypothesis ledger, P2 evidence IDs и двух P3 verdicts построить полный intake без новых raw claims; каждому row назначить `eligible|keep|defer|reject|merged` с source IDs и reason. Experiment eligible только при доказанной текущей боли, одном изолируемом mechanism, существующем измерении, reversible temporary variant, bounded dependency set и реалистичном practical effect по P1; security/public/irreversible/owner-only change не экспериментировать в P4. Для каждого experiment до запуска заморозить hypothesis, exact baseline/candidate bytes или config, commit, prompt/tasks, primary metric, guardrails, P1 thresholds, invalid rule, stop и rollback. Выполнить ровно две valid matched pairs с одним изменяемым фактором и максимум одну replacement pair только для заранее определённой infrastructure-invalid причины; затем stop. `go` требует обеих valid pairs, practical threshold, GREEN guardrails/provider parity и P5-bounded rollback; mixed/incomplete/under-covered → `defer`, no material gain при acceptable baseline → `keep`, falsified/harmful/dominated → `reject`. Пустой GO-set не фабрикует readiness: запросить отдельное owner D# для empty producer set.
