# Идея: явное решение владельца «проверка не обязательна для done»

Статус: идея, не реализовано. Источник: сессия plan-run PLAN1 (azguard) P2.14, 2026-10-13.

## Проблема

`planner.plan.lifecycle.finish` (`packages/planner/lib/planner/plan/lifecycle.py`, ветки `done` и
`done_with_deviations`) требует, чтобы каждая проверка с `kind: acceptance` была записана с exit 0, иначе
`CHECKS_MISSING`. Обойти это без правки плана нельзя: единственный статус без этого требования — `blocked`, но он
означает «нужно решение или данные владельца», а не «владелец решил не запускать».

Случай из практики: пункт «P2 exit: полная квалификация» содержал пять проверок (`composer test`, `test:types`,
статика целиком, прогоны на трёх драйверах БД), которые план пометил `acceptance`. Владелец сказал «долгие прогоны не
запускай» и «пункт должен читаться выполненным». Исполнитель сначала предложил `blocked` (неверно по смыслу), потом
пришлось через `plan.py set` переписывать `kind` пяти проверок на `impact` вручную, весь массив `validation`.

Корень: вид проверки (`acceptance | impact | live`) выбирает автор плана на этапе дизайна, а решение «запускать ли
долгие прогоны сейчас» принимает владелец на этапе исполнения. Сейчас второе можно выразить только правкой первого.

## Предложение

1. `plan.py finish … --waive V3,V6 --waiver "<цитата владельца>"` — отдельный список проверок, снятых владельцем
   для этого завершения. Требования:
   - допускается только для `done_with_deviations` (статус `done` остаётся «всё доказано»);
   - `--waiver` обязателен, как `--escalation` для `blocked`; текст идёт в событие и в `result.waived`;
   - снять можно только проверку, объявленную в пункте; снять проверку, для которой записан красный exit, нельзя
     (`CHECKS_RED` остаётся);
   - снятая проверка в `result.checks` хранится как `waived`, а не как `0`; никакой код не должен читать её как
     зелёную.
2. Пункт, закрывающий фазу: фазовые acceptance-проверки снимаются тем же флагом, но только с отдельной пометкой
   в событии закрытия фазы (фаза с waived-проверкой не получает статус «полностью проверена»).
3. `plan.py show/stats` показывает waived-проверки отдельной строкой («не запускались по решению владельца»).
4. Гейт владельца: `waive` должен требовать `plan.py grant` с цитатой владельца, как другие owner-gates, чтобы агент
   не мог снять проверку по собственной инициативе.

## Что не менять

- Семантику `done`: все acceptance записаны с exit 0.
- Модель `kind`. `impact` остаётся «широкой защитой», не условием done; дизайн-правило «диагностика не в acceptance»
  остаётся в силе.

## Альтернативы

- Оставить как есть и описать в `plan-run.md`: «по явной просьбе владельца переводи проверки в `impact` через
  `plan.py set` и пиши deviation». Дёшево, но правит контракт плана, а не фиксирует решение владельца как событие, и
  теряется различие «план не требовал» и «владелец освободил».
- Флаг плана `settings.long_runs: ask|skip`. Грубее: освобождает не конкретные проверки, а класс.

## Открытые вопросы

- Нужна ли метка «долгая» на самой проверке (`cost: long`), чтобы владелец мог сказать «долгие не запускай» без
  перечисления идентификаторов, а исполнитель сам выбирал, что снять?
- Должен ли `reopen` напоминать о waived-проверках, чтобы их можно было догнать позже одной командой?
