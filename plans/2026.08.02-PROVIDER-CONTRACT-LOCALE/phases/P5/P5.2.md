### P5.2 — Preserve and explicitly register approved local overrides

**Intent:** Выполнить только approved `preserve`/`register-override` actions, закрепив exclusions до managed repair и оставив каждый ambiguous/unsupported case явным unresolved no-op. RAG:— (repo-grounded: P0.2 classification, D4/D28 and frozen P5.1 manifest)
**Why:** Same-name local trees are project-owned until доказано обратное; если repair запустить раньше preservation exclusions, provider adapter может принять override за drift или stale managed copy. RAG:— (repo-grounded: `findings/03-current-defects-2026-08-02.md`, P0.2 and predecessor ownership gates)
**Scope Included:** Rebind/verify only P5.1 rows assigned to P5.2; byte-preserving no-op for every `preserve`/`ambiguous` row; explicit project-config/lock registration only where the frozen P1 contract defines a local-override carrier and the Owner action names exact target/preimage; private backup before config mutation; P3 provider-scoped readback; redacted per-project result and rollback evidence; explicit unresolved reasons.
**Scope Excluded:** Copying override bytes into SKM; merging/adopting them as canonical; changing their content; inventing an override field when P1 has none; relink/refresh/cleanup; enabling a provider not selected by project intent; raw paths/content/secrets in committed evidence; touching rows outside the approved action set.
**Inputs:** Terminal P5.1 manifest/runner/Owner D# · terminal P0 classifications · frozen P1 override/config contract and P3 APIs · P4 terminal locale/provider artifacts.
**Files:** Approved live consumer targets referenced only by stable project/artifact IDs in `artifacts/P5/fleet-action-manifest.json` · private per-project backup area declared by the frozen recovery contract · append-only `plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/artifacts/P5/fleet-transaction-log.jsonl` · derived `plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/artifacts/P5/P5.2-results.json` · `plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/findings/P5-local-override-disposition.md` · plan index.
**Required Reads:** 1) P5.1 Completion Notes/item commit, frozen manifest/approval and complete transaction log 2) P0.2 classification and synthesis 3) frozen `provider-control-plane-v1.md`, `provider-recovery-gates-v1.md` and predecessor config/artifact contracts 4) terminal P3.2/P3.3 APIs/status codes 5) P4.6 repository acceptance bundle 6) P5 finding/research 7) each selected consumer's nearest `AGENTS.md` and exact target preimage after locator rebind.
**Implementation Rules:** `ambiguous` always remains `no-op-unresolved`; `local-override` content is never changed. Registration is legal only through the P1-owned explicit carrier and P3 plan/apply/readback boundary; a missing carrier, changed preimage, dirty overlapping target, unsupported provider or absent Owner action leaves the row unresolved without write. RAG:— (repo-grounded: D28, P0.2 and P3.2 boundaries) Private backups remain under the consumer's contract-defined state directory with restrictive permissions and are not committed; plan evidence stores value-free transaction/backup IDs and status only. One project is one rollback domain and one D47 transaction: `before` is durable before write, `accepted` is durable only after both-provider readback, and any partial provider/config failure reaches verified `rolled-back` before the cursor may continue.
**Code Guidance:** Use only `p5-consumer-reconcile.py apply|resume` with the frozen P5.2 action-set, approval, recovery contract and shared journal. Never call raw `skiller update --all`, generic `maind sync --all`, `--force`, global repair, `git add -A` or direct JSON mutation. Compare declared preimage immediately before write and read back through P3, not by trusting the writer result. On restart never replay an `accepted` transaction or skip a non-terminal one; run `resume` against the same carriers. If preservation requires semantic merge or a new schema field, stop that row and escalate; do not normalize, translate or relocate override bytes opportunistically.
