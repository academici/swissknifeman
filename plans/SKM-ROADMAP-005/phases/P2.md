# P2 — wf-status: консольный статус-репортер workflow-прогонов

## Phase Context

Фаза даёт детерминированную команду `swissknifeman wf status` вместо двух повторяющихся
трений (спека `roadmap/workflow-status-cli.md`): агенты советуют владельцу несуществующую в его
окружении команду `/workflows`, а на запрос «дай детальный статус» каждая сессия заново пишет
импровизированный парсер (жжёт токены, формат каждый раз разный).
Формат прогона стабилен и парсится без LLM: `~/.claude/projects/<proj>/<session>/subagents/
workflows/wf_*/` содержит `journal.jsonl` (события `started`/`result` с `agentId`),
`agent-<id>.meta.json` и скрипт с `export const meta` (декларация фаз).
Дом — корневой router `bin/swissknifeman` (D8), НЕ копия bash-артефакта по пакетам: копии дрейфуют.
Реализация — механическая (парсер + фиксированный шаблон + тесты на фикстуре реального прогона);
дизайна не требует, но парсер обязан быть защищённым: формат transcript-директорий внутренний
для Claude Code и меняется между версиями — неизвестные поля игнорировать, при несовпадении
формата печатать честное «формат не распознан», а не трейсбек.
Фаза закрыта, когда команда выдаёт стабильный отчёт и `--json`, а скиллы `task:*` перестали
советовать `/workflows`.
