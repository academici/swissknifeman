## 0. Контракт стенда (наследуют P3.2/P3.3/P3.4)

Контракт пинован прогонами `findings/P3.1-bench-harness-probe-2026-08-01.md` (D94);
здесь — как он применён в самом стенде.

- **Изоляция.** Рабочий workspace — временный каталог **вне** дерева репозитория
  (`tempfile.mkdtemp`), фикстуры копируются из `artifacts/p3-1-fixtures/**`. Флаг

  за собой (`shutil.rmtree`) сразу после прогона.
- **Наблюдаемая величина оси A.** `usage.input_tokens + usage.cache_creation_input_tokens
  + usage.cache_read_input_tokens` — верхнеуровневый `usage`, три компонента публикуются
  раздельно по каждому прогону (см. сырой лог — доступен по коммиту скрипта). Источник
  зафиксирован один на весь стенд, не меняется между прогонами.
- **Сильный сигнал** — уникальный маркер тела пробника (`ZZP31-<ПОЛЕ>-BODY`) в `result`
  при `exit 0`; для явного пути — `claude -p '/<имя-пробника>'`. **Слабый сигнал** —
  самоотчёт модели на просьбу перечислить скиллы; используется только как подтверждение,
  не как основание вердикта (везде помечен явно).
- **Шум.** Каждое плечо axis-A пары гоняется 3 раза, порядок чередуется (A,B,B,A,A,B),
  вердикт — по медиане суммы; |delta| ≤ max(spread_A, spread_B) ⇒ «неразличимо».
- **Граница.** Формула токенов и способ инъекции скилла раннера `quality/eval.py`
  (`--append-system-prompt`, `input_tokens + output_tokens`) в стенде НЕ используются
  (D94 §4–§5) — пробник кладётся на диск настоящим скиллом; из `eval.py` взят только
  резолв бинаря и форма процессного запуска.

## 4. Эскалация — расширенная фактура

`paths:` во frontmatter `zz-p31-paths` (валидный YAML-список, синтаксис сверен по
first-party доку — «Accepts a comma-separated string or a YAML list»,
<https://code.claude.com/docs/en/skills> §Frontmatter reference, WebFetch 2026-08-01):

```yaml
paths:
  - "*.zzp31paths"
```

Три независимых сигнала на живой 2.1.220, все воспроизведены:

1. **Ось A** — дельта резидентной суммы `usage` при подстановке `paths:` (−88) БАЙТ-В-БАЙТ
   равна дельте при `disable-model-invocation` (−88) на том же контроле. Запись
   `zz-p31-paths` стоит листингу ровно СТОЛЬКО ЖЕ, сколько запись, полностью снятая полем,
   которое по доку снимает её явно.
2. **Explicit-путь** — `claude -p '/zz-p31-paths' --output-format json --setting-sources
   project` → `result: "Unknown command: /zz-p31-paths"`, `exit 0` (не ошибка процесса —
   штатный ответ клиента «skill unknown»). Совпадает дословно с симптомом #49835
   («`/name` → Unknown skill»).
3. **Слабый сигнал (перечисление, только подтверждение)** — `zz-p31-paths` отсутствует в
   self-report листинге при сольном workspace, тогда как `zz-p31-ctrl` тем же промптом на
   аналогичном workspace присутствует первой строкой.

Дословная страница дока (`code.claude.com/docs/en/skills`, прочитана WebFetch 2026-08-01):
таблица «When loaded into context» (§«Control who invokes a skill») перечисляет ТОЛЬКО три
строки — `(default)`, `disable-model-invocation: true`, `user-invocable: false` — про
`paths:` эта таблица не говорит НИЧЕГО explicit. Соседняя строка референса поля `paths`
говорит только «limit when this skill is **activated**» — про листинг ни слова. Общее
утверждение дока (§«Skill listing budget») — «The listing always contains every skill
name» — не содержит оговорки про `paths:` и наблюдением этого стенда **не подтверждается**
для `paths`-варианта. D23 закрыл вопрос «не снимает» на основании (а) отсутствия
противоречащей строки в доке и (б) второго источника perplexity («still part of the
startup skill listing») — оба источника ДОКУМЕНТАЛЬНЫЕ, ни один не был прямым наблюдением
на живом клиенте. Этот стенд — первое прямое наблюдение поля `paths:` в этом плане, и оно
доку не соответствует.

**Что это НЕ доказывает:** авто-активация по совпадающему/несовпадающему файлу этим
заходом не измерена чисто (см. §3.1, фикстура загрязнена) — но при полностью снятой записи
листинга вопрос об авто-активации вторичен: скилла, которого нет в листинге и который не
находится по имени, для авто-активации эффективно не существует.

**Возможные причины (не выбираются этим item'ом, адрес — plan-design):** (а) #49835 живой
и в 2.1.220 не пофикшен, доки просто не обновлены под текущее поведение; (б) поведение
специфично для КОМБИНАЦИИ «project-скилл + `--setting-sources project`» и на других путях
загрузки (personal/plugin) отличается — не проверялось; (в) синтаксис `paths` требует
дополнительного условия, не покрытого доком (например, наличия хотя бы одного файла в
дереве на момент старта сессии, соответствующего паттерну — у нас файл `probe.zzp31paths`
БЫЛ, но только в конкретных прогонах авто-активации, не в прогонах оси A/explicit).

## 5. Сверка с моделью `budget.py`

```
$ packages/skiller/bin/skiller budget --first-turn --target <combined-ws> --json
```

На workspace со ВСЕМИ 8 фикстурами разом: модель `total=2559`, `verdict=OK`. Тем же
workspace, `claude -p 'List the names of every skill available to you...'` (наблюдение,
ось A) → сумма `usage` = **21430** (input=2, cache_creation=6155, cache_read=15273).

**Расхождение: 21430 − 2559 = 18871 ток** — числа НЕ сопоставимы 1:1, и это не дефект
замера: `resolve_active_set` (`packages/skiller/lib/skiller/budget.py:124`) строит набор
из `config`/`.swissknife.json` РЕЕСТРА, а не читает `.claude/skills/` каталог `--target`
напрямую (`budget.py:794,939`). У временного workspace стенда нет `.swissknife.json`, и
модель для него считает ДЕФОЛТНЫЙ `CORE_SKILLS`-набор (тот же `total=2559`, что видно у
нескольких проектов флота с пустым выбором — `findings/P1-fleet-baseline.md`, столбец
`skills`), а не 8 сырых фикстур, реально лежащих в `.claude/skills/` того же каталога.
Наблюдение стенда — реальный резидентный вес ЭТИХ ФАЙЛОВ на клиенте; модель считает
СОВЕРШЕННО ДРУГОЙ вход (реестровую конфигурацию). Строка для P3.2: модель `budget.py`
сегодня не видит «сырых» `.claude/skills/**`, не входящих в реестр/конфиг — если P3.2
планирует сверять модель со стендом на фикстурах, сверка обязана идти через
`.swissknife.json`/`config`, а не через голый `--target` каталога с самодельными
SKILL.md.

## 7. Известные ограничения стенда

- Авто-активация `paths:` по matching/non-matching файлу — фикстура `probe.zzp31paths`
  содержит имя скилла в тексте, что загрязняет самоотчёт модели в этих двух прогонах
  (§3.1). Не пересобиралось: вопрос закрыт по explicit-пути и оси A с более сильным
  сигналом, пересборка фикстуры под чистый повтор — вне необходимости для вердикта этого
  item'а.
- `background: false` против гипотетического `background: true` не различается
  однопроходным `claude -p` (см. §3.4) — вне заявленного скоупа item'а.
- Стенд гоняет ТОЛЬКО project-слой (`.claude/skills/` временного workspace); поведение
  personal-скиллов или скиллов, раздаваемых через `connect`/plugin-канал, не проверялось —
  вне скоупа item'а (реестр не трогается, D5).
