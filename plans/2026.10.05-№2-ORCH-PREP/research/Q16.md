# Q16

Запрос (perplexity-web-mcp stdio, default pool; search):

```text
October 2026, git 2.43+: running several coding agents in parallel on one repository, each in its own `git worktree` on its own branch, then integrating their branches into main one by one. Answer precisely with primary-source URLs (git-scm.com docs, GitHub docs):
1) Which state is per-worktree vs shared (index, HEAD, index.lock, refs, objects, config, hooks)? Is it safe for two worktrees to run `git commit` concurrently on different branches; what lock errors can appear (ref lock, packed-refs, gc/auto-gc) and how to avoid them?
2) Can the same branch be checked out in two worktrees; what does `git worktree add` refuse; `git worktree lock/prune/remove` semantics for cleanup after an agent dies.
3) Sequential integration with re-verification: `git rebase --exec <cmd>`, `git rebase --update-refs`, merge vs rebase for keeping a `merge=union` attribute file (append-only JSONL log) conflict-free; does union apply during rebase and cherry-pick (ort)?
4) How merge queues (GitHub merge queue, bors-ng) order and re-test PRs; what "affected checks after rebase" practice they use.
Answer in Russian, max 700 words.
```

Ответ (как вернул сервис, 2026-10-07):

"Состояние","Область"
"Рабочие файлы, index, index.lock, HEAD, reflog HEAD","Отдельные для каждого worktree"
"refs/heads, refs/remotes, refs/tags, refs/stash, reflogs веток","Общие"
"refs/bisect, refs/worktree, refs/rewritten","Отдельные"
"Objects, packs, packed-refs","Общие"
"Repository config","Общий; extensions.worktreeConfig=true включает дополнительный config.worktree, записываемый через git config --worktree"
"Hooks","По умолчанию общие; core.hooksPath можно переопределить конфигурацией worktree"
