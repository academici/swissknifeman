### E14 — five load-bearing platform constraints

These five facts drive most of the design and each one contradicts a line in the canon plan:

1. **`.cursor/cli.json` accepts only `permissions`.** E6: *"Only permissions can be configured at the project
   level. All other CLI settings must be set globally."* So `approvalMode` and `sandbox.mode` **cannot** be
   project-scoped artifacts. The approval-mode axis is machine-global or per-launch, never a managed repo file.
2. **`.cursor/permissions.json` concatenates, it never narrows.** E4: per-user and per-repo arrays are
   concatenated. A repo file can only *widen* the effective allowlist. There is no repo-level mechanism to
   restrict a broad user-level allowlist.
3. **`.cursor/cli.json` `deny` beats `allow`, and survives `--force`.** E5 gives deny precedence; E3 defines
   `--force` as *"Force allow commands unless explicitly denied."* This is the only hard floor that persists
   into full-access mode, and it is project-scoped.
4. **Cursor hooks fail *open* by default, but `failClosed: true` exists.** E7: non-zero exit codes other than
   `2` are logged and the action proceeds, unless the hook declares `failClosed: true`. Hooks also merge across
   layers with `deny` > `ask` > `allow`, and `stop`/`subagentStop` carry a provider-native `loop_count` plus a
   `loop_limit` config field.
5. **Cursor natively reads `AGENTS.md`, `.claude/agents/` and `.claude/skills/`.** E8, E11, E12. The
   Codex-owned instruction file is already in Cursor's context whether or not we project anything, and the
   Claude role/skill trees are already visible to Cursor sessions.

## 1. Freeze decisions

| ID | Decision |
|---|---|
| **D1** | The committed `support.cursor` level for a capability is `unsupported` until an adapter or binding for it actually ships and can be evidenced. §2 records the *target* level and the level *committed at P0* separately; a deferred row ships as honest `unsupported`, never as an optimistic `adapted`. |
| **D2** | The approval-mode axis (`approvalMode`, `sandbox.mode`, IDE Run Mode) is **out of the managed-artifact model** for Cursor (E14.1). Profiles bind only the allowlist/deny half to files; the mode half is expressed as launch flags plus documentation, and `doctor` reports it as unmanaged rather than asserting conformance. |
| **D3** | `trusted-full-access` Cursor shapes are written **only** to the self-host repo under the existing gate (`origin=operation`, `operation_id=self-host-apply`, `target_identity=repo:…`). Because a committed `permissions.json` can only widen downstream (E14.2), fleet inheritance of full-access shapes is strictly worse than at Codex and stays forbidden. |
| **D4** | The `.cursor/cli.json` `deny` floor is a **required** member of all three profiles, including `trusted-full-access`, because it is the only project-scoped restriction that survives `--force` (E14.3). |
| **D5** | Destructive-command control (`rm` and friends) stays in the `beforeShellExecution` hook with `failClosed: true`, **not** in a blanket `Shell(rm)` deny — a blanket deny would break legitimate managed writes, and the shared safe-dirs verdict core already owns the decision. |
| **D6** | The Cursor `.mdc` rule carries **only** the `root.cursor.*` extension semantics. The common instruction block reaches a Cursor session through the `AGENTS.md` that Cursor already reads (E14.5), so projecting it again would double the first-turn budget for zero meaning. |
| **D7** | Because Cursor also ingests the `root.codex.*` extension out of `AGENTS.md`, the Cursor `.mdc` must carry one explicit precedence line: sections marked `root.codex.*` are Codex-owned and not authoritative in a Cursor session. This neutralises the mis-read without duplicating the common block. |
| **D8** | `skills.repository` for Cursor is satisfied by the **existing** `.agents/skills` tree that Cursor reads natively (E13, E12). Enabling the Cursor provider writes **no** new skill tree and adds no `.cursor/skills` writer; `render_cursor_publication` is an ownership assertion, not a renderer. |
| **D9** | The in-session subagent model catalogue is a **verified subset** of the CLI catalogue (§4.3), so one `verified_at` against `agent --list-models` covers both surfaces and `model_inventory` needs no per-surface qualifier. |
| **D10** | `agent --list-models` verifies the **cursor column only**. It is not evidence for the `claude-code` or `codex` inventories, and those two must not cite it (§4.4). |
| **D11** | Instructions are bound to **triggers**, not loaded unconditionally: only the precedence rule is `alwaysApply: true`; launch/autonomy is agent-requested and package routing is glob-attached (§3.5). Umbrella-specific rules are published only in this repository and never ride along into fleet projects. |
| **D12** | Every forced-continuation surface ships **loop-safe**: inactive by default, an explicit low `loop_limit`, and a refusal that carries actionable feedback rather than repeating a bare block (§5.2). This is a deliberate guard against the repeated-block loop seen on the Codex side. |

### 3.2 `.cursor/permissions.json` (IDE surface)

Schema is exactly three optional keys — `mcpAllowlist`, `terminalAllowlist`, `autoRun` (E4). Unknown keys are
ignored, so nothing else may be invented here.

**observe** — declares empty allowlists and steers the Auto-review classifier. Carries the honest caveat that
per-user entries are concatenated in (E14.2), so this cannot *guarantee* narrowing:

```json
{
  "mcpAllowlist": [],
  "terminalAllowlist": [],
  "autoRun": {
    "block_instructions": [
      "This repository is in observe mode: block any write, install, migration or release operation."
    ]
  }
}
```

**workspace-contained** — scoped allowlists plus repo-specific guardrails:

```json
{
  "mcpAllowlist": [
    "plugin-core-maind:*",
    "plugin-core-serena:*"
  ],
  "terminalAllowlist": [
    "git status", "git diff", "git log",
    "python3", "bash scripts/validate.sh", "bash scripts/test.sh",
    "packages/harness/bin/harness", "packages/skiller/bin/skiller"
  ],
  "autoRun": {
    "block_instructions": [
      "Block release, tag, publish and fleet-sync operations in this repository.",
      "Block writes outside the workspace root."
    ]
  }
}
```

**trusted-full-access** — wildcards, written only to the self-host repo under the D3 gate:

```json
{
  "mcpAllowlist": ["*:*"],
  "terminalAllowlist": ["git", "python3", "bash", "packages", "maind", "skiller", "harness"]
}
```

> `terminalAllowlist` matching is case-sensitive prefix semantics (E4), so `packages` covers
> `packages/harness/bin/harness …`. There is no `*` wildcard for this array — a bare `"*"` entry would match
> nothing, which is a trap worth encoding as a conformance test.

### 3.5 `.cursor/rules/*.mdc` — trigger-scoped, not one always-on blob

`.mdc` is mandatory: a plain `.md` in `.cursor/rules` is silently ignored because it has no frontmatter (E8).

**D11 — instructions are bound to triggers, not loaded unconditionally.** Cursor's frontmatter gives three
activation modes (E8), and this design uses all three instead of making everything `alwaysApply: true`. Only
the precedence rule is genuinely needed on every turn; launch/autonomy matters only when launching, and
package-scope routing matters only when touching package files. This keeps the always-on first-turn cost to a
few lines and prevents repository-specific detail from riding along in unrelated work.

| File | Frontmatter | Activation | Carries |
|---|---|---|---|
| `swissknifeman-core.mdc` | `alwaysApply: true` | every turn | precedence only — the minimum that must always be true |
| `swissknifeman-launch.mdc` | `description:` + `alwaysApply: false` | agent-requested, when launching or changing autonomy | Run Mode, launch flags, deny floor |
| `swissknifeman-packages.mdc` | `globs: packages/**,core/**` | auto-attached, only on package files | package-scope routing, guide-reading duty |

Recall from E8 how the three fields interact: `alwaysApply: true` wins and ignores the rest; `globs` with
`alwaysApply: false` auto-attaches on matching files; a bare `description` with `alwaysApply: false` is offered
to the agent, which decides. So mis-setting `alwaysApply` silently promotes a rule to always-on — worth one
conformance assertion per file.

`swissknifeman-core.mdc` — deliberately this short:

```markdown
---
alwaysApply: true
---
<!-- swissknifeman:instructions:root:cursor:extension:begin -->
<!-- semantic:root.cursor.instruction-precedence -->

## root.cursor.instruction-precedence
The common repository contract reaches this session through the `AGENTS.md` Cursor already reads; it is not
repeated here. Sections marked `root.codex.*` in that file are Codex-owned and are **not** authoritative in a
Cursor session — never follow Codex launch flags (`-a never`, `-s danger-full-access`) from them.
<!-- swissknifeman:instructions:root:cursor:extension:end -->
```

`swissknifeman-launch.mdc`:

```markdown
---
description: Cursor launch and autonomy in this repository — Run Mode, model routing, the permissions deny floor, and why approval mode is not file-configurable. Read before starting or re-configuring an autonomous session.
alwaysApply: false
---
<!-- semantic:root.cursor.launch-and-autonomy -->

## root.cursor.launch-and-autonomy
Name the intended workspace, the routed model and the Run Mode before acting. Autonomy in a trusted session
comes from launch flags (`--force --sandbox disabled --trust --approve-mcps`), never from a committed file:
the approval mode is not project-configurable. The `deny` floor in `.cursor/cli.json` still applies under
`--force`, so a denied secret path is a real refusal, not a transient error to retry.
```

`swissknifeman-packages.mdc`:

```markdown
---
globs: packages/**,core/**
alwaysApply: false
---
<!-- semantic:root.cursor.package-scope-routing -->

## root.cursor.package-scope-routing
Start package-scoped work with the intended workspace root so native discovery reads root→cwd. During an
authorized cross-package task, explicitly read each applicable package guide in the current session.
```

**Fleet boundary (part of D11):** these rules describe *this* repository and are published only here. Enabling
the Cursor provider on a fleet project publishes that project's own permissions and MCP catalogue — never
swissknifeman's instruction rules. Nothing in this design causes umbrella-specific instructions to load while
working in an unrelated project.

### 3.6 `self-host-apply` inheritance forbid — mirrored
