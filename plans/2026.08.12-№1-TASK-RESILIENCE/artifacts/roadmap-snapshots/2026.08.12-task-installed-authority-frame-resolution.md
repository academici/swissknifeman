# Roadmap: package-relative authority-frame resolution in installed Task

**Статус:** ⬜ к внедрению. **Владелец:** `packages/task`.
**Критерий сработал:** Agelto, `2026.08.09-RELEASE-READINESS` P6.3, 2026-08-12.

## Обнаружение и граница инцидента

При первом preflight P6.3 executor ошибочно вызвал `plan-lint.py` из stale
`~/.codex/plugins/cache/swissknifeman/task/0.12.0`, хотя текущий native marketplace
`codex plugin marketplace list --json` указывает на source checkout
`/home/vostrikov/projects/packages/swissknifeman`. Cache-вызов завершился ошибкой

```text
decision-queue-v1: queue unreadable: request authority projection is invalid
```

Это не повреждение и не semantically invalid запись Agelto. Пункт P2.1 ранее сформировал
durable owner DecisionRequest `Q-P2.1-private-vendor-pin-v1` через Task decision-request
v1 и append-only записал request → claim → owner `apply` response в
`plans/2026.08.09-RELEASE-READINESS/decisions/queue.jsonl`. При P6.3 linter проверяет
terminal phase через `plan_gates._lint_terminal_phase_unresolved_decisions()` →
`plan_requests.unresolved_for_phase()` → `states()`; последний повторно валидирует этот
historical request. Это штатный путь, и resolved request должен дать пустой список
unresolved decisions. Повтор через canonical marketplace root подтвердил это: `plan-lint`
дал `0 errors`, а `plan_requests._request_errors(request)` вернул `[]`.

Значит, cache defect **не блокирует P6.3 в этой установке**; первоначальная остановка
была procedural misuse runtime root. Он остаётся реальным package portability defect:
installed Task package содержит все нужные файлы, но не может прочитать собственный config
без monorepo.

## Точная причина

Одинаковый исходный код `task 0.12.0` проходит в monorepo, но не в установленном Codex
plugin cache:

```text
PYTHONPATH=packages/task/lib
plan_requests._request_errors(request)  # []

PYTHONPATH=~/.codex/plugins/cache/swissknifeman/task/0.12.0/lib
AuthorityFrameError: authority-frame не найден:
~/.codex/plugins/cache/swissknifeman/packages/task/configs/authority-frame.json
```

`plan_authority.default_frame_path()` берёт `Path(__file__).parents[4]` и добавляет
`packages/task/configs/authority-frame.json`. Это верно только в checkout monorepo. В
установленном plugin package frame корректно поставляется по пути
`task/0.12.0/configs/authority-frame.json`; module-relative calculation уходит на
несуществующий `.../cache/swissknifeman/packages/task/...`. `_request_errors()` намеренно
fail-closed ловит `AuthorityFrameError` и выдаёт generic `request authority projection is
invalid`, после чего linter сворачивает его в `queue unreadable`.

Следовательно, причина — неверное разрешение package data в runtime projection, а не
содержимое `queue.jsonl`, не owner response и не Agelto plan. Исторический append-only
carrier нельзя переписывать для обхода этой ошибки.

## Версионная provenance

В Meta Agelto plan указан `Swissknifeman task 0.11.1`; owner request был создан 2026-08-10,
а cache, воспроизводящий package-path defect, содержит только `task/0.12.0`. Эта граница
действительно требует coverage, однако не меняет root cause: `authority-frame` resolver был
добавлен в commit `98a23ea0` 2026-08-09, а текущий source и installed `0.12.0` имеют
byte-identical `plan_requests.py` и `authority-frame.json`. Repro `0.12.0` падает раньше
semantic parsing historical request — на поиске собственного bundled файла.

Исправление поэтому обязано включать совместимый fixture: queue, созданный старым runtime,
читается опубликованным новым runtime. Это проверка upgrade compatibility, а не допущение,
что старый plan может быть проигнорирован или переписан.

## Требуемое исправление

1. Сделать bundled `configs/authority-frame.json` package-relative default для
   `plan_authority`, сохранив `TASK_AUTHORITY_FRAME` как явный override с прежним
   приоритетом. Нельзя зависеть от имени monorepo, cwd или домашнего каталога.
2. Сохранить fail-closed поведение: отсутствующий или malformed explicit override всё ещё
   обязан возвращать `AuthorityFrameError` с фактическим путём, а не literal fallback.
3. Добавить regression test в layout installed plugin: module из установленной/собранной
   package tree без `packages/task/` должен загрузить bundled frame и признать resolved
   request валидным. Отдельно проверить, что тот же fixture при missing frame остаётся
   красным.
4. Добавить consumer smoke test: `plan-lint` на v2 fixture с request → claim → response
   проходит decision-queue gate в published Codex projection. Генерация/publish package
   обязана сохранить `configs/` и запускать этот test до release.
5. Выпустить исправленный Task package и проверить его как installed cache; ручная правка
   `~/.codex/plugins/cache/**` не является remediation.

## Приемка

- `TASK_AUTHORITY_FRAME` имеет приоритет над bundled frame.
- Без override source checkout и installed Codex/Claude package находят один и тот же
  `authority-frame.json` из собственного package root.
- Historical resolved request `Q-P2.1-private-vendor-pin-v1` проходит re-validation;
  `unresolved_for_phase(..., 'P2')` не сообщает его как pending.
- Queue fixture, созданный Task `0.11.1`, проходит published Task `0.12+`; failure должен
  указывать на реальную schema/policy incompatibility, а не на package path.
- Missing/corrupt bundled frame даёт конкретный `AuthorityFrameError`; linter сохраняет
  fail-closed verdict.
- `bash packages/task/scripts/validate.sh` и generated provider projection checks зелёные;
  regression воспроизводит P6.3 incident без Agelto-specific special case.
