# Task plan-exec: control plane дороже самой разработки

**Дата:** 2026-09-22

**Статус:** 🔴 воспроизведённая полевая регрессия; remediation не реализована

**Field evidence:** CoreX `2026.09.19-№1-COREX-PLATFORM-HARDENING P5.13`

**Связанная, но отдельная проблема:**
[`2026.09.22-task-design-proof-overreach-diagnostic.md`](2026.09.22-task-design-proof-overreach-diagnostic.md)
описывает перегрузку проектирования. Этот carrier описывает другой дефект: дорогую церемонию
уже спроектированного, узкого и обратимого execution item.

## Короткий вывод

P5.13 был двухстрочным test-harness repair: вернуть file-level
`uses(PgTestCase::class)->group('pg');`. Реализация и три заявленных witness-команды занимают
минуты. Codex-сеанс занял около сорока минут, потому что `task:plan-exec` сделал исполнителя
оператором plan control plane: route proof, recovery, пятиносительный snapshot, admission,
contract/evidence graph, durable journal start, terminal evidence, projections, handoff,
reconciliation, lint и delivery receipt.

Каждый механизм по отдельности защищает реальный инвариант. Системный дефект в том, что их
стоимость почти не зависит от риска и размера item. Ограниченный обратимый repair платит ту же
когнитивную и transport-цену, что durable/public/DDL работа. Product change перестаёт быть
главной работой сессии.

## Что именно съело ресурсы

### Обязательная поверхность Task

Текущий Codex adapter `task:plan-exec` потребовал до первой product write:

1. прочитать adapter skill, intent routing, полный generated command и две protocol references;
2. захватить provider route evidence;
3. выполнить recovery prepare;
4. передать модели immutable five-carrier snapshot: весь `plan.md`, фазу, item, bundle и state;
5. скомпилировать evidence graph и Task contract;
6. выполнить batch admission и записать durable start.

После двухстрочной правки потребовались terminal decision, journal event, regenerated views,
successor bundle, handoff rewrite, reconciliation, plan lint и rendered delivery receipt.

Это execution control plane, но сегодня его порядок и recovery выполняет сама модель через
много мелких tool calls. Детерминированная механика потребляет reasoning budget и создаёт новые
точки отказа вместо того, чтобы быть одной операцией harness.

### Усилители стоимости в самом контракте P5.13

- `Files` включал CHANGELOG и отдельный plan receipt для двухстрочной тестовой правки.
- `Validation` требовал полный root `composer test`, хотя достаточный regression witness — root
  SQLite selection/exclusion для конкретного PG-файла.
- полный `plan.md` размером около 77 KB и вся фаза передавались модели, хотя решение полностью
  содержалось в item spec и двух точечных source files.
- plan-wide lint после closure поднял исторический долг десятков старых terminal states, не
  пересекающийся с product acceptance P5.13.

### Provider/route defect

План пинил P5.13 на Codex `gpt-5.6-terra/medium`. Фактическая сессия была
`gpt-5.6-sol/medium`. Task contract запрещает undershoot, но разрешает overshoot, поэтому дорогая
модель законно исполнила mechanical item. Exact native pin оказался документом, а не
экономическим gate.

### Ошибки исполнителя

Framework не объясняет всю потерю времени. Codex также:

- сначала открыл skill по неверному пути;
- запустил большой snapshot с недостаточным transport budget и потерял вывод;
- повторил snapshot через удерживаемую PTY-сессию и вручную прочитал большие chunks;
- сделал неудачную попытку patch-операции над `handoff.md`;
- после явного owner-сигнала «максимально экономно» продолжил церемонию без ранней оценки
  `control-plane cost > product risk`;
- не остановился до journal mutation с рекомендацией перезапустить item на pinned Terra/Composer.

Следовательно, Swiss Knife Man создал сильный стимул и высокую цену ошибки, но исполнитель
усугубил её локальными решениями. Исправление должно покрыть оба слоя.

## Причинная цепочка

```text
узкий готовый item
  → явный plan-exec включает полный lifecycle
  → adapter передаёт orchestration модели, а не harness
  → fail-closed носители читаются и обслуживаются по одному
  → transport/reconciliation failures порождают repair calls
  → exact model pin не блокирует дорогой overshoot
  → проверки control plane превосходят product change
  → быстрый implementation item занимает десятки минут
```

## Желаемая модель: native-first execution capsule

Цель — сохранить authority, durability и честное evidence, но убрать их из основного reasoning
loop модели. Агент должен получить максимум готового контекста задачи и использовать нативные
возможности разработки: прочитать несколько source files, изменить код, запустить сфокусированные
проверки и вернуть результат.

### P0 — один preflight вместо ручного control plane

Ввести одну детерминированную операцию harness, которая атомарно:

- проверяет route, authority, dependencies и batch membership;
- выполняет recovery/prepare и durable start;
- валидирует snapshot и bundle внутри harness;
- возвращает модели компактную execution capsule: Intent, Included/Excluded, Files, точные
  Required Read excerpts, Validation и известный foreign baseline.

Полные `plan.md`, phase carrier, protocol canon и raw bundle не должны попадать в model context
по умолчанию. Их hashes и validation остаются в harness receipt. Полный carrier открывается
только при конкретной ambiguity или repair code.

### P0 — один finalizer после product acceptance

Вторая детерминированная операция должна принять фактические command receipts и атомарно:

- проверить terminal policy и product anchor;
- дописать terminal journal event;
- обновить state/status/decision views и successor bundle;
- построить handoff и delivery receipt;
- выполнить только closure-delta lint.

Stale handoff или историческая plan-wide диагностика ремонтируются внутри finalizer либо
возвращаются одним typed result. Модель не должна вручную угадывать порядок десяти writers.

### P0 — экономический route gate

Перед mutation exact native pin должен быть двусторонним:

- undershoot остаётся запрещён;
- overshoot bounded/mechanical item на более дорогой model class возвращает
  `ECONOMY_ROUTE_OVERSHOOT` и готовую native launch recommendation;
- owner может явно разрешить overshoot, но молчаливое повышение больше не считается нормой.

Это особенно важно для Composer/Terra items. Sol/Astra должны использоваться для
durable/DDL/security/public-contract и независимой qualification, а не для механических листьев.

### P1 — risk-proportional execution contracts

Design discipline должна различать product acceptance и отчётность:

- CHANGELOG/plan receipt не включаются автоматически в каждый bounded repair;
- root full suite требуется только при доказанном integration radius;
- regression selection/exclusion witness предпочтительнее полного suite, если он прямо доказывает
  изменённое поведение;
- global historical lint не блокирует closure item, который не создал соответствующую диагностику;
- Required Reads содержит semantic inputs, а не весь ancestry плана.

Не вводить новые профили и schema vocabulary до P0-пилота. Сначала сократить orchestration и
измерить эффект.

### P1 — исполнительский stop rule

Adapter обязан дать модели короткое правило:

> Если до первой product write control plane потребовал больше трёх tool calls либо очевидно
> дороже самой правки, остановить pre-mutation, назвать mismatch и предложить pinned дешёвый
> route. После owner-сигнала об экономии не открывать новые общие carriers без конкретной
> блокирующей причины.

Это advisory stop до mutation, а не разрешение бросить открытый durable run.

## Измеримый пилот

Первый кандидат — следующий bounded mechanical item уровня Composer/Terra, например CoreX
`2026.09.19-№1-COREX-PLATFORM-HARDENING P5.17`. Сравнить current и capsule paths.

P0 успешен, если одновременно:

- до первой product write не больше трёх tool calls и не больше двух минут wall-clock;
- модель не читает полный master plan, phase carrier или protocol canon;
- implementation + focused validation остаются основной частью wall-clock;
- terminal finalization выполняется одной операцией и максимум одним typed repair;
- фактическая model/effort совпадает с exact pin либо есть явный owner override;
- нет owner interruption из-за ceremony или непрозрачного прогресса;
- authority, terminal evidence, recovery и delivery tests остаются GREEN.

Дополнительно записывать без выдуманных оценок: число tool calls до/после product write,
переданные model-context bytes, wall-clock preflight/product/finalize и число repair cycles.

## Предполагаемые владельцы изменения

- `packages/task/commands/plan-exec.md` — compact agent contract и economy stop;
- `packages/task/lib/task/` — агрегированные preflight/finalize seams поверх существующих owners;
- `packages/task/scripts/` — provider-neutral CLI для двух атомарных операций;
- `packages/task/adapters/` и provider projections — компактная capsule вместо ручной церемонии;
- plan design guidance — risk-proportional Files/Validation/Required Reads;
- tests — bounded-item latency/call-budget scenario, overshoot refusal и сохранение high-risk gates.

## Решение на сегодня

Не переписывать Task немедленно и не добавлять новый execution mode. Field regression уже
доказан одним чистым bounded incident. Следующий шаг — owner-решение на P0 capsule/finalizer и
экономический route gate, затем один пилот P5.17. P1 меняет contract discipline только после
измеренного результата пилота.
