## Root cause

D118 correctly redirected the nested `codex plugin` commands, but the P7.2 executor remained
an already-active interactive Codex process backed by `/home/vostrikov/.codex`. That parent
continued its normal JSONL and SQLite/WAL writes while measuring the host snapshot. Therefore
the row could not satisfy strict host-state zero delta even though the plugin payload itself
was contained. RAG:— (repo-grounded:
`findings/P7-self-host-probes-2026-07-19.md`)

The missing boundary is executor/session isolation, not another plugin flag. Current
first-party docs provide the necessary supported primitives: `CODEX_HOME`,
`CODEX_SQLITE_HOME`, non-interactive `codex exec --ephemeral`, `--ignore-user-config`, and
single-run environment authentication. RAG:✅ 2026-07-23
(`findings/P7-codex-session-isolation-docs-2026-07-23.md`)

## Decision

Supersede D118 only in its execution carrier and zero-delta proof:

1. The current host-backed interactive session ends after committing this design.
2. The next P7.2 attempt is launched from a neutral owner shell, not from a Codex tool call,
   hook, nested session or `resume`.
3. The launcher creates fresh existing task-specific directories for `HOME`, `CODEX_HOME`
   and `CODEX_SQLITE_HOME`.
4. Exactly one non-persisted automation credential is present for the `codex exec` process:
   `CODEX_ACCESS_TOKEN` or `CODEX_API_KEY`. Neither credential is printed, copied into a
   plan artifact, written to `auth.json`, or forwarded to model-launched subprocesses.
5. The executor is `codex exec --ephemeral --ignore-user-config` with the routed
   model/effort, `approval=never`, `danger-full-access`, and
   `shell_environment_policy.exclude` for both credential variables.
6. Its first P7.2 action snapshots the explicit absolute host path
   `/home/vostrikov/.codex`; the native plugin row then reuses the same task-specific
   state roots. The final isolated comparison requires host and repository delta zero.

This clean-room run resumes P7.2 at the D118 RED native row. Earlier non-native evidence stays
historical and usable, but the aggregate remains non-GREEN until the clean-room native row is
GREEN and the isolated rollback evidence is reconciled.

## Rejected alternatives

- **Repeat inside the current interactive session:** cannot provide a quiescent host-state
  baseline because the measurer itself writes the measured store.
- **Exclude active JSONL/SQLite/WAL paths:** weakens the strict acceptance rule and makes
  hidden host coupling invisible.
- **Use only `CODEX_HOME`/`HOME` for nested plugin commands:** already failed; it does not
  relocate the parent executor's state.
- **Copy or reuse host `auth.json`:** preserves a host-state dependency forbidden by D118.
- **Invent another `-c`/environment key:** unsupported; current docs already expose the
  complete public state-root pair.

## Execution and authority boundary

The clean-room isolated run may only:

- rerun the native marketplace/plugin row;
- reconcile the already-started isolated matrix and rollback evidence;
- if and only if all isolated rows are GREEN, derive the exact live path/action inventory
  and request the existing Approval Owner D#.

It must stop without live mutation when:

- neither or both automation credential variables are set;
- the routed model/auth is unavailable;
- any required state directory cannot be created;
- the host or repository snapshot changes;
- a credential reaches a spawned repository command;
- the native row or any prior isolated acceptance remains RED.

Because an ephemeral non-interactive run cannot pause and later resume the same persisted
thread, D119 supersedes D96 only for the P7.2 owner-gate carrier: the clean-room isolated run
ends at the exact approval request, and any approved live action starts in a separate
self-contained new-session command carrying that D#. P7.3 remains closed until P7.2 is
terminal GREEN.
