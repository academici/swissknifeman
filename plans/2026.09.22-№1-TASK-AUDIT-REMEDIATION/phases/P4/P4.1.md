**Implementation Rules:** Use one explicit lock domain around authoritative read/check/append and exception sidecar checks; after lock acquisition reread current bytes. Any nonempty malformed row blocks authoritative mutation with typed `JOURNAL_CORRUPT`; diagnostic/bounded readers may report corruption but cannot convert it to absence. Open append target without following symlinks, write complete encoded row with append semantics, fsync file and directory where P1 contract requires, and return success only after the declared durable boundary. Resolve exception decision through `plan_decisions.load_decisions()` and require accepted, unsuperseded, unique, correct plan/item/target digest/field scope and explicit grant marker. Validate strict timezone-aware UTC timestamp, finite nonnegative cost/duration, integer nonnegative turns and terminal ordering. Parse calendar dates with a real date parser; chronology rule changes only if P1 proves it is part of append-only semantics. Projection temp-write/replace sequence fsyncs required objects, serializes concurrent generators and rejects symlinks in write/check mode.
**Code Guidance:** Reuse the minimal durable lock/write primitive from P3 if its contract matches; otherwise extract one package-private primitive rather than duplicating open/fsync/lock logic. Concurrency tests use multiprocessing barriers/pipes, not probabilistic sleeps. Fault injection marks exact boundaries (before write, after write/before fsync, after file fsync/before directory fsync) and asserts only outcomes promised by the platform contract. Test conflicting terminal results separately from duplicate same-result idempotency. Legacy invalid data, if admitted by P1 compatibility, is read-only and cannot authorize new writes until migrated by the existing migration protocol.
**Validation:** 1) Focused tests cover one synchronized duplicate-terminal race, one malformed journal row, one unrelated decision exception, invalid/valid date and metric boundaries, and symlink/durable projection behavior; 2) one end-to-end start→terminal→reconcile smoke recovers the expected state; 3) `python3 -m unittest discover -s packages/task/tests -v` and `bash packages/task/scripts/validate.sh`; 4) record repaired behavior and explicit filesystem limitations in `findings/P4-history-durability-results.md`; 5) plan bundle/lint and `git diff --check` GREEN. No repeated stress rounds or exhaustive crash cut-point campaign is required unless the smoke exposes instability.
**Deliverables:** Transactional journal mutation and strict readers; typed exception authority; valid time/metrics/dates; crash-consistent symlink-safe projections; deterministic concurrency/fault tests; per-finding evidence map and compatibility notes.
