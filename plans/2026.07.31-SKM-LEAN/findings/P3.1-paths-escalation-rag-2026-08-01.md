# RAG-выжимка захода разбора эскалации P3.1 — `paths:` (2026-08-01)

Слой 1 (сырьё). Заход: `plan-design 2026.07.31-SKM-LEAN P3.1`, разбор эскалации
`findings/P3-native-fields-smoke.md` §4. Собрано ПОСЛЕ прогонов стенда — предмет проверки:
не «работает ли поле» (это уже наблюдение стенда), а **какой механизм** объясняет
наблюдение и что об этом говорят первичные источники сегодня.

Лестница (`root.decision-verification`): first-party док (WebFetch) → GitHub issue (WebFetch)
→ `perplexity-web`. `context7` не звался: предмет — не API библиотеки, а поведение живого
клиента и статус его баг-трекера.

## 1. First-party док — дословные строки о `paths` (WebFetch 2026-08-01)

Источник: <https://code.claude.com/docs/en/skills>, страница снята целиком 2026-08-01.

§Frontmatter reference, строка `paths` — **дословно**:

> `paths` | No | Glob patterns that limit when this skill is activated. Accepts a
> comma-separated string or a YAML list. **When set, Claude loads the skill automatically only
> when working with files matching the patterns.** Uses the same format as
> [path-specific rules](/docs/en/memory#path-specific-rules).

§«Skill listing budget» — **дословно**:

> Claude Code loads a listing of skill names and descriptions into context so Claude knows
> what's available. **The listing always contains every skill name**, but if you have many
> skills, Claude Code shortens descriptions to fit the listing's character budget…

Ни в одной строке страницы `paths` не назван среди механизмов, влияющих на СОСТАВ листинга:
таблица «When loaded into context» (§«Control who invokes a skill») перечисляет только
`(default)`, `disable-model-invocation: true`, `user-invocable: false` — сверено этим заходом
повторно, состав строк тот же, что зафиксирован в `findings/P3-native-fields-smoke.md` §4.

**Новое по сравнению с заходом P3.1** (в §4 вердикта этой детали нет): строка `paths` отсылает
к **path-specific rules** как к своему формату — `/docs/en/memory#path-specific-rules`. У
path-specific правил носитель загружается, когда сессия РАБОТАЕТ с совпавшим файлом, а не
резидентно. Это первичное указание на то, что `paths` у скиллов может быть реализован тем же
загрузчиком — и тогда отсутствие записи в листинге при отсутствии совпавшего файла есть
поведение механизма, а не поломка. Док этого прямо не говорит (и его же строка про листинг
такому чтению противоречит), поэтому вывод остаётся ГИПОТЕЗОЙ, а не фактом.

## 2. Апстрим-issue #49835 — состояние на 2026-08-01 (WebFetch)

Источник: <https://github.com/anthropics/claude-code/issues/49835>.

- Статус — **open**. Заголовок: «[BUG] Skill with paths frontmatter is completely
  undiscoverable». Метки: `area:skills`, `bug`, `has-repro`, `platform:macos`.
- Симптом дословно: «Adding a `paths` field to a skill's `SKILL.md` frontmatter causes the
  skill to be entirely excluded from discovery. It does not appear in the `/` autocomplete
  menu, is not listed as an available skill, and invoking it directly returns "Unknown
  skill: "».
- Репро автора issue — **скилл PERSONAL-слоя** (`~/.claude/skills/test-skill/SKILL.md`),
  версия клиента **2.1.92**, `paths: "*.rs,Cargo.toml,Cargo.lock"`; снятие строки `paths:`
  возвращает `/test-skill` в работу.
- Ожидание автора дословно: «The `paths` field should limit when the skill auto-activates
  based on file patterns, not prevent the skill from being discovered. The skill should remain
  invokable via `/name` regardless of `paths`.»
- **Ответов мейнтейнеров нет**, фикс-версия не названа, комментариев в треде нет.
- Соседние issues, названные в треде: **#45587** (`paths` с несколькими паттернами матчит
  только первый — для правил, не скиллов), **#39105** (`paths` отсутствует в документации
  скиллов).
- В issue **ничего не сказано** о том, лежал ли в дереве файл, совпадающий с паттерном.

**Что это даёт разбору эскалации.** Репро апстрима снято на PERSONAL-слое, наш стенд — на
PROJECT-слое (`.claude/skills/` временного workspace, `--setting-sources project`). То есть
гипотеза «(б) поведение специфично для комбинации project-скилл + `--setting-sources project`»
(`findings/P3-native-fields-smoke.md` §4) первичным источником **ослаблена**: тот же симптом
воспроизводится и на другом слое загрузки, у другого автора, на другой ОС. Отдельного прогона
personal-слоя эта гипотеза больше не требует — тем более что `CLAUDE_CONFIG_DIR` запрещён
D94 (уносит OAuth на среде владельца), а писать в реальный `~/.claude/skills/` владельца стенд
не имеет права.

Одновременно issue **не закрывает** третью гипотезу: у автора issue, как и у нашего стенда, в
дереве не было файла, совпадающего с паттерном (`*.rs`/`Cargo.toml` в пустом каталоге
скилла — репро состоит из одного `SKILL.md`). Оба наблюдения — из состояния «совпавшего файла
нет».

## 3. `perplexity-web` (второй источник, 2026-08-01)

Запрос: «Claude Code 2.1.x skill frontmatter `paths:` — skill disappears from listing and
`/name` returns Unknown command; known bug (#49835) or intended conditional loading requiring a
matching file? Reports 2.1.100–2.1.220».

Вердикт источника: «This looks like a real bug, not intended conditional loading» — со ссылкой
на тот же док (`paths` scopes auto-activation, `/name` должен работать) и на #49835. Отдельно
названо: «A later July 2026 update note also mentions a fix for CLAUDE.md or SKILL.md `paths`
frontmatter values with **many brace groups**» — то есть область в 2.1.x действительно
патчилась, но по другому симптому (брейс-группы; наш паттерн `*.zzp31paths` брейсов не
содержит). Практический совет источника совпадает с нашим: убрать `paths` либо проверить
конкретную версию своим прогоном.

**Класс этого источника — подтверждающий, не решающий.** Он читает тот же док и ту же issue,
что и мы; прямого наблюдения «с совпавшим файлом в дереве» в нём нет. Прибора «версия, в
которой поле почините» ни один источник не даёт.

## 4. Что осталось непроверенным ни одним источником

1. Поведение `paths`-скилла, когда файл, совпадающий с glob, **лежит в дереве** на момент
   старта сессии. Ни док, ни issue, ни второй источник этого случая не описывают; стенд P3.1
   мерил ось A и explicit-путь БЕЗ совпавшего файла (`findings/P3-native-fields-smoke.md`
   §3.1, §4 — файл `probe.zzp31paths` клался только в два прогона авто-активации).
2. Поведение, когда совпавший файл **прочитан внутри сессии** (формулировка дока — «when
   working with files matching the patterns», а не «when such a file exists»).
3. Поведение на канале раздачи `connect` (плагин-скилл) — ни один источник его не отделяет от
   personal/project.

Пункты 1–2 закрываются узким дозамером на уже построенном стенде (адрес — item **P3.6**).
Пункт 3 остаётся названной границей: отдельного прибора у нас нет, и он нужен только при
положительном вердикте по 1–2.
