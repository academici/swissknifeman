# Roadmap: skill-rules.json сайдкар (роутинг скиллов)

**Статус:** отложено (низкий приоритет). **Критерий внедрения:** замеренные **мис-активации**
скиллов — нужный скилл не подхватывается по `description` на реальном потоке.

## Идея

Паттерн из `itgoyo/awesome-agent-skills` (ChrisWiles): генерируемый `skill-rules.json` с
keyword/pathPattern-скорингом, который хук подсовывает Claude как подсказку, какой скилл
рассмотреть.

## Почему отложено

- **Скиллы УЖЕ автозагружаются** по `description` в актуальном Claude Code — сайдкар во многом
  дублирует нативное поведение (тот же вывод, что и про skm2 `auto-skill.js`).
- **Двойное сужение**: skiller к тому же ставит per-type **набор бакетов** (профиль), т.е. в
  проект попадают только релевантные скиллы — пространство для мисматча и так узкое.
- Дополнительная генерёжка + ещё один хук в горячем пути — стоимость без доказанной выгоды.

## Дизайн (если дойдём)

- **Сайдкар, НЕ поле SKILL.md** (никаких выдуманных `triggers`): `skiller registry`
  авто-эмитит `skill-rules.json` из существующего frontmatter — `tags`/`description` →
  keywords, `outputs`/`produces_for` → pathPatterns.
- Потребитель — тот же `UserPromptSubmit`-роутер, что для агентов/команд (см.
  [`agent-command-router-hook.md`](agent-command-router-hook.md)); скиллы добавляются лишь как
  ещё один источник подсказок, и только если измерены мисматчи.

## Зависимости

- `skiller registry` (генерёжка артефактов) — точка, куда добавить эмиссию сайдкара.
- Общий router-хук — переиспользуется (не плодить второй).
