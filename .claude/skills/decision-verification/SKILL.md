# Дисциплина верификации решений (работа НАД пакетом)

Внутренний скилл (не экспортируется). Это **governance моей работы над swissknifeman**: чтобы
вердикты и решения здесь не строились на устаревшем знании. **Полный канон** (лестница движков,
confidence, формат вывода) — реестровый скилл `general/verify-claims`
([packages/skiller/skills/general/verify-claims/SKILL.md](../../../packages/skiller/skills/general/verify-claims/SKILL.md));
здесь — только активация для репо-работы, **без дублирования** лестницы.

## Когда активировать

- **Разбор чужого аудита/плана** (как Perplexity-аудиты в `research/`): любой вердикт/**отказ** на
  внешнем факте — даже если аудит выглядел полным.
- **Большое планирование/дизайн** изменения: выбор подхода, библиотеки, формата, интеграции.
- **Выбор или обновление зависимости/инструмента/MCP-сервера** (имя пакета, команда, поддерживается ли).
- **Утверждение** «это current best practice / стандарт / так больше не делают».

## Правило (классификация заявления)

- **Repo/code-grounded** (есть в коде/конфиге ЭТОГО репо, «реализовано в файле Y») → подтверждаю
  **чтением кода**, он авторитетен. RAG не нужен.
- **Стабильное общее знание** (синтаксис, устоявшиеся паттерны, математика) → без проверки.
- **Внешнее + staleness-чувствительное** (версии/API, «ещё актуально», рынок, чужой сервис/MCP, цены) →
  **верифицировать через RAG** по лестнице канона: `context7` (доки библиотек) → Perplexity (native MCP
  при `PERPLEXITY_API_KEY`, иначе keyless `perplexity-web`) → `WebSearch/WebFetch` → `research/research`
  для глубокого. Указать источник + дату + confidence; `low` — пометить «требует подтверждения».

Широта: всё, что **не** чистая реализация уже-спланированного-и-проверённого ТЗ, подкрепляй данными.

## Спец-клауза: ревью аудита

Для КАЖДОГО пункта реши — вердикт repo-grounded или внешний? repo-grounded → подтверди кодом; внешний
(«библиотека/сервер/рынок уже это умеет», «устарело») → **до-проверь по лестнице ДО финализации**, даже
если аудит «полный». Лучше подстраховаться, чем отклонить по устаревшему знанию.

## Связанные

- `general/verify-claims` (реестр) — **канон-источник** лестницы и confidence (читай его, не копируй сюда).
- `general/mcp-advisor` (реестр) — *что подключить* (движки context7/perplexity/web); этот — *когда верифицировать*.
- `release-discipline` (root) — после верификации: завершение изменения (validate → registry → PR).
