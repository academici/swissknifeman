# P3.4 required-read defect — 2026-08-04

## Observation

P3.4 must connect the terminal P2 compiler and scheduler activity boundary to the frozen
`worker-envelope-v1` request/result contract. Its current Required Reads include the aggregate P1
and P2 manifests plus provider parity carriers, but they do not include either frozen contract
body. The aggregate manifests expose identities and hashes, not the slice fields, worker request,
event/result taxonomy, refusal order, or executable mutation semantics.

The read set also names `compiler.py` only indirectly through the P2 manifest and omits its
conformance test plus the current scheduler/CLI tests that define the live P2 adapter seam. The
executor therefore cannot distinguish the immutable compiled slice payload from the scheduler's
injected activity input without inspecting undeclared repository files or inventing a bridge.

## Consequence

Implementing `worker.py`, provider-aware `start`/`resume`, or normalized observations from the
listed inputs would silently create a second slice/result contract. That would violate the frozen
P1 ownership boundary and D39's requirement that P3 remain an additive adapter over the existing
P2 state machine.

## Required remediation

`task:plan-design 2026.08.03-ARTIFEX-SUPERVISOR P3.4` must add, in normative order:

1. the slice-manifest contract, independent cases and validator, followed by the terminal P2
   compiler and its test;
2. the authority contract/cases/validator and terminal P2 authority/scheduler sources/tests that
   own the dispatch input and durable activity seam;
3. the worker-envelope contract, independent cases and validator before provider implementations;
4. the existing CLI and CLI tests before the additive provider binding.

The remediation must not alter frozen P0/P1 bytes, terminal P2/P3.1–P3.3 code, P3.4 scope,
validation, deliverables, or provider evidence.
