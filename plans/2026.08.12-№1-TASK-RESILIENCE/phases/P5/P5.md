# P5 — Durable terminal delivery and provider parity

## Phase Context

P5 связывает terminal final с durable plan state и убирает штатный audit loop.
Receipt строится только по terminal journal/state и переносит exact persisted
`handoff.Next`. Fresh independent phase audit становится owning audit-fixer:
он группирует находки по root seam, сам чинит всё безопасное в границах
фазы, повторяет acceptance, пересобирает candidate и только затем выдаёт
финальный verdict. Canonical смысл после product seam проецируется owning
generators в Claude/Codex, registry и docs. RAG:— (repo-grounded:
`research/08-P5-audit-fixer-design.md`, D24).

**Scope Included:** terminal/handoff receipt; phase candidate fingerprint/close lifecycle; same-root audit repair; exact item/state/candidate rebinding; provider generation; registry/docs parity.

**Scope Excluded:** transport-level interception; unbounded repo-wide cleanup; repair вне union фазового Scope/Files без bounded-incidental evidence; public/frozen/authority/safety changes без DecisionRequest; release tag; project rollout; manual generated edits.

> **Контракт фазы (contract-first).** Потребляет: P1–P4 product semantics · Производит: byte-bound delivery + one-invocation audit-fixer + byte-current provider surface · Границы: no final before durable terminal; no routine audit→repair→audit chain.
