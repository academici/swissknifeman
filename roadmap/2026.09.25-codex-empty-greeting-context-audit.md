### 3.1. Desired state не совпадает с effective state

CoreX `.swissknife.json` объявляет семь plugins:

```text
core, laravel-testing, oss-dev, php, php-packages, quality, task
```

Однако `codex plugin list --json` показывает **12 включённых SKM plugins**:

```text
architect, axioma, core, dart, devops, laravel-auth, laravel-data-layer,
laravel-testing, php, quality, system, task
```

Это не просто наличие старых cache directories: skills из 11 этих plugin roots реально
попали в prompt. Например, `architect` дал 15 записей, `devops` — 11, `system` — 7.
Следовательно, глобальное effective plugin state Codex шире project desired state и создаёт
resident-налог на каждом ходе.

Одновременно `oss-dev` и `php-packages` из project desired state не представлены как
enabled marketplace plugins; часть нужной поверхности приходит отдельными project links.
Текущая схема смешивает два канала вместо одного проверяемого effective set.

### 3.2. Task bucket в этом замере

Plugin `task` включён, но `task:*` / `task-plan-*` skills в стартовом каталоге отсутствуют.
В prompt есть только маленький project skill `general:plan-protocol`, который явно требует
owner invocation. Поэтому Cursor-вывод о resident Task bucket нельзя автоматически переносить
на Codex: command-only admission в этой Codex-сессии выглядит рабочим.

## 4. Почему `skiller budget` дал ложное спокойствие

Команда:

```text
skiller budget --first-turn --provider codex --json
```

вернула **4 433 токена / OK**:

| Источник receipt | Оценка |
|:--|--:|
| 55 skills | 2 118 токенов |
| 11 agents | 964 токена |
| `CLAUDE.md` + rule | 767 токенов |
| SessionStart hooks | 0 |
| 3 deferred MCP servers | 584 токена |

Фактический первый запрос был **23 108 токенов**, то есть в **5,21 раза** больше receipt.
Не весь разрыв принадлежит SKM: system/developer instructions и tool schemas контролирует
платформа. Но provider receipt содержит собственные измеримые ошибки:

1. `--provider codex` в first-turn path всё равно считает `CLAUDE.md`, хотя Codex реально
   инжектировал `AGENTS.md`.
2. Он считает 11 файлов `.claude/agents`, хотя их описания не представлены как такой каталог
   в сохранённом Codex prompt.
3. Provider listing ожидает **57** skills и **7 379 символов**, а фактический prompt содержит
   **100** skills и **21 683 символа** — в 2,94 раза больше текста листинга.
4. Receipt не объединяет native/project links, effective `codex plugin list` и OpenAI/global
   roots, поэтому не видит коллизии и лишние enabled plugins.
5. Verdict `OK` применяется к неполному измерению и сейчас не отвечает на вопрос «сколько
   реально занял первый ход Codex».

Нулевой SessionStart hook подтверждён и является хорошим результатом: в отличие от Cursor
field case, mAInd digest в эту Codex-сессию не инжектировался. `.mcp.json` объявляет `maind`,
`codegraph` и `perplexity`; receipt учитывает только deferred lower bound. Их полные schemas
не видны в сохранённом стартовом tool surface, поэтому приписывать им неизвестную часть
23 108 токенов нельзя.

## 5. Вердикт по оптимальности

Текущая загрузка **неоптимальна**, причём причины разделяются по владельцам.

| Наблюдение | Вердикт | Владелец |
|:--|:--|:--|
| 23 108 токенов на `Привет!` | Высокий cold-turn overhead | Codex + extensions |
| `model_switch` 17 885 символов | Искажает этот baseline вверх; нужен контрольный запуск | Codex platform |
| 100 resident skill descriptors | Слишком широкий discovery set | Codex + SKM delivery |
| 12 enabled SKM plugins при 7 desired | Подтверждённый reconcile gap | SKM |
| Две duplicate-name пары | Подтверждённый multi-channel gap | SKM |
| Codex receipt считает Claude surfaces | Подтверждённый measurement bug | SKM/skiller |
| CoreX `AGENTS.md` — 911 байт в файле | Компактный и уместный project context | CoreX |
| mAInd SessionStart digest отсутствует | Для пустого Codex-чата оптимально | mAInd/harness |
| Task skills не resident | Для этого Codex route оптимально | Task/skiller |

Главный практический вывод: уменьшение `AGENTS.md` почти ничего не даст. Сначала нужно
свести effective plugins к project policy и сделать provider receipt честным. Platform blocks
и schemas останутся заметным нижним пределом даже после ремонта SKM.

## 6. Предлагаемый ремонт и проверка

### C1 — Codex effective-set diagnostics (P0, skiller)

**Source status 2026-09-25: выполнено.** `skiller doctor --context --provider codex`
читает `codex plugin list --json` и `codex debug prompt-input`, сопоставляет native inventory
с `.swissknife.json` и возвращает три реализованных кода:
`CODEX_PLUGIN_ENABLED_OUTSIDE_PROJECT_POLICY`, `CODEX_DESIRED_PLUGIN_NOT_EFFECTIVE` и
`SKILL_DUPLICATE_NAME`. `SKILL_MULTI_CHANNEL` остаётся расширением Cursor/general carrier.

`skiller doctor --context --provider codex` должен объединять:

- `.swissknife.json` desired plugins;
- `codex plugin list --json` с `enabled`;
- project `.agents/skills`;
- global `.agents/skills` и `~/.codex/skills`;
- enabled OpenAI/SKM plugin caches.

Минимальные typed diagnostics:

- `CODEX_PLUGIN_ENABLED_OUTSIDE_PROJECT_POLICY`;
- `CODEX_DESIRED_PLUGIN_NOT_EFFECTIVE`;
- `SKILL_DUPLICATE_NAME`;
- `SKILL_MULTI_CHANNEL`.

### C2 — Безопасный reconcile Codex plugins (P0, skiller)

Нужен детерминированный effective set для текущего cwd. Поскольку native plugin state может
быть глобальным и нужен другим проектам, reconcile не должен слепо отключать plugin для всей
машины. Сначала следует определить provider-supported project override; если его нет — launch
profile или явный warning с точной командой и последствиями.

### C3 — Настоящий Codex first-turn receipt (P0, skiller)

**Source status 2026-09-25: выполнено.** Receipt использует native observed inventory и
`AGENTS.md`, исключает `.claude/agents` и Claude SessionStart hooks, отделяет managed estimate,
помечает platform overhead как excluded и завершается `INCOMPLETE`, если native discovery
недоступен. Live CoreX check нашёл 99 entries / 97 unique names, 7 plugins вне policy,
2 desired plugins вне effective state и две duplicate-name пары.

`--first-turn --provider codex` должен:

- считать `AGENTS.md`, а не `CLAUDE.md`;
- не считать `.claude/agents` как будто они resident в Codex;
- использовать effective native plugin inventory;
- показывать отдельно `managed_estimate` и `provider_observed`, если доступен JSONL;
- не выдавать общий `OK`, когда provider-visible inventory не измерен.

### C4 — Удаление двух project/plugin коллизий (P1, skiller delivery)

После выбора одного канала `db-test-preflight` и `node-pnpm-preflight` должны встречаться
ровно один раз. Cleanup требует ownership readback, чтобы не удалить пользовательские skills.

### C5 — Чистый повторный эксперимент (P1, field acceptance)

Создать новую Codex-сессию сразу на целевой модели и отправить только `Привет!`. Зафиксировать:

- input/cached tokens, context window, TTFT;
- count и char size skill descriptors;
- отсутствие `model_switch`;
- `skiller budget --first-turn --provider codex` рядом с observed JSONL.

### C6 — Отдельный upstream сигнал (P2, Codex)

Передать в provider audit дублированную пару multi-agent instructions: полный collaboration
block загружается даже когда следующий block запрещает proactive delegation. Это нельзя
исправить в SKM, но можно измерять отдельно от managed footprint.

## 9. Критерий закрытия

1. Effective SKM plugin set для CoreX объясним project policy; лишние enabled plugins дают
   typed warning либо безопасно reconciled.
2. Provider-visible каталог не содержит duplicate names и не смешивает project links с тем
   же marketplace content.
3. `skiller budget --first-turn --provider codex` считает Codex surfaces и явно отделяет
   managed estimate от недоступного platform overhead.
4. Чистая сессия без `model_switch` создаёт второй receipt; observed/managed разрыв объяснён
   по слоям, а не скрыт verdict `OK`.
5. Общий multi-provider carrier сохраняет различия: Codex не получает mAInd digest и не
   показывает resident Task skills в зафиксированном field case.

Пункты 1 и 3 имеют source implementation; carrier закрывается только после C2/C4,
release/fleet delivery и чистого C5 receipt без `model_switch`.
