### P5.1 — Skill description quality contract

**Intent:** Extend `skiller bucket-audit` with a versioned, additive `description-trigger-priority/v1` view that joins the existing trigger-debt ratchet to budget and observed-usage evidence without converting missing telemetry into a rewrite verdict. RAG:— (repo-grounded: `packages/skiller/scripts/desc-trigger-burndown.txt`; `packages/skiller/lib/skiller/quality/audit.py`; `packages/skiller/docs/guide/skill-taxonomy.md`).
**Why:** The validator already prevents new trigger debt and the authoring guide defines priority as observed usage multiplied by listing share, but the audit JSON does not expose ratchet membership, listing share, evidence class or a filtered queue. Authors must currently join 61 keys by hand, and the live probe saw only two scanned projects plus zero direct calls, so an alphabetical or bulk pass would manufacture confidence. RAG:— (repo-grounded: `artifacts/source-roadmap/skill-description-quality.md`; `findings/06-p5-design-baseline.md`).
**Scope Included:** Additive audit schema/version marker; load and exact-key validation of `scripts/desc-trigger-burndown.txt`; combined listing-cost share derived from existing `tier0`; `trigger_debt`; nonnegative priority score equivalent to `loaded_count × listing share`; evidence enum distinguishing observed skill-call from resident-only and unobserved; stable score/evidence/key ordering; top-level debt counts and signal coverage; `--description-debt` human/JSON filter; stale/missing/duplicate ratchet diagnostics; docs and regression fixtures.
**Scope Excluded:** Rewriting any canonical `skills/**/SKILL.md`; adding debt rows; changing the trigger regex or 300/450 character gates; treating resident visibility as a direct activation; treating zero calls or two scanned projects as evidence that a skill is unused; changing overlap/dead/thin verdicts; reading raw transcripts through a new path; CI-enabling a new warning flood; P6 instruction ablations.
**Inputs:** `artifacts/source-roadmap/skill-description-quality.md` · `findings/06-p5-design-baseline.md` · `research/06-p5-field-gaps.md` · D2 · D10 · current ratchet, budget and bucket-audit output.
**Files:** `packages/skiller/lib/skiller/quality/audit.py` · `packages/skiller/tests/test_audit.py` · `packages/skiller/docs/guide/skill-taxonomy.md` · `packages/skiller/README.md` · `CHANGELOG.md`.
**Required Reads:** 1) `artifacts/source-roadmap/skill-description-quality.md` 2) `findings/06-p5-design-baseline.md` 3) `research/06-p5-field-gaps.md` 4) `decisions/D10-evidence-first-field-promotion.md` 5) `packages/skiller/AGENTS.md` 6) `packages/skiller/skills/repository-bootstrap/skill-authoring/SKILL.md` 7) `packages/skiller/scripts/desc-trigger-burndown.txt` 8) `packages/skiller/scripts/validate.sh` 9) `packages/skiller/lib/skiller/quality/audit.py` 10) `packages/skiller/lib/skiller/budget.py` 11) `packages/skiller/tests/test_audit.py` 12) `packages/skiller/docs/guide/skill-taxonomy.md`.
**Implementation Rules:** `desc-trigger-burndown.txt` remains the debt-membership owner and `budget.py` remains the token/listing-cost owner; audit joins their outputs and must not duplicate the trigger regex or token formula. JSON additions are backward-compatible and carry `contract_version=description-trigger-priority/v1`. Priority uses positive direct `loaded_count` as evidence and reports the denominator/coverage; resident-only or zero-call rows remain explicitly insufficient for a routing-failure verdict. Stable ordering is score descending, then evidence strength, then key; ties never depend on filesystem order. Missing/malformed/duplicate ratchet keys produce named diagnostics and cannot silently disappear. `--description-debt` filters presentation only and never writes skills or the ratchet. RAG:— (repo-grounded: D10; current validator/audit ownership).
**Code Guidance:** Reuse `iter_registry_skills()`, `skill_budget()` and `collect_usage()`; add small pure join/score/sort functions with synthetic rows before touching CLI rendering. Keep score math integer or explicitly normalized so platform float formatting cannot reorder ties. Do not infer auto-activation from prose, scan new transcript sources, or special-case the current 61 keys. Test one positive-call row, resident-only zero, unobserved zero, equal-score tie, stale key, duplicate key, empty debt and additive JSON compatibility. No description is edited merely to make this item look productive.
**Validation:** `PYTHONPATH=packages/skiller/lib:packages/skiller/tests python3 -m unittest test_audit` is green; `packages/skiller/bin/skiller bucket-audit --description-debt --json` emits `description-trigger-priority/v1`, exactly matches current ratchet membership, reports signal coverage and orders deterministically across two repeated runs; the command performs zero writes to `skills/` and `scripts/desc-trigger-burndown.txt`; `bash packages/skiller/scripts/test.sh` and `bash packages/skiller/scripts/validate.sh` are green; `packages/skiller/bin/skiller registry --check` is green; `npm --prefix packages/skiller run docs:standalone:build` and `npm --prefix packages/skiller run docs:build` are green; `CHANGELOG.md` has an `[Unreleased]` entry.
**Deliverables:** Additive description-trigger priority contract and filtered CLI view; explicit evidence/coverage semantics; focused tests for ranking and fail-closed ratchet joins; updated authoring/CLI documentation; no bulk skill-content mutation.
