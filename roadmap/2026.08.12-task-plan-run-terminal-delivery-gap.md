# `task:plan-run`: terminal delivery не fail-closed в installed Task 0.12.0

## Инцидент

Agelto `2026.08.09-RELEASE-READINESS` P6.3 был закрыт journal-событием
`closed-green` и state `🟢 Done`, но финальный ответ не содержал ни обязательного
`Delivery receipt: <JSON>`, ни `Рекомендация следующего шага:`, ни native launch-block
реального преемника P6.4. Пользователь обнаружил пропуск после закрытия.

Это **не** использование Task 0.11. Фактически был установлен
`~/.codex/plugins/cache/swissknifeman/task/0.12.0` (manifest version `0.12.0`). В его
`runtime/plan-protocol/SKILL.md` §§6/terminal delivery и в inherited
`commands/plan-exec.md` уже есть точное правило: до final построить
`terminal-delivery-receipt/v1`, а в final вывести exact recommendation.

## Воспроизводимый контур

1. Вызвать native `$ task:plan-run 2026.08.09-RELEASE-READINESS P6.3`.
2. Installed `task-plan-run/command.md` требует «прочти
   `packages/task/commands/plan-exec.md` целиком», но это monorepo-relative locator.
   В published cache такого пути нет; действительный путь —
   `<installed-task-root>/commands/plan-exec.md`. Первые fresh launches завершились на
   ошибочном cache path до product mutation.
3. После user-authorized direct continuation был вручную записан terminal journal/state,
   но не выполнены inherited steps 7–8: rewrite handoff, `plan-delivery.py`, exact final.
4. Запустить:

   ```bash
   python3 packages/task/scripts/plan-delivery.py \
     --plan-dir plans/2026.08.09-RELEASE-READINESS --subject P6.3 --kind terminal
   ```

   На фактически закрытом P6.3 команда возвращает exit 0, но receipt содержит stale handoff
   `# HANDOFF … after P6.2`, `Next: … P6.3` и предлагает снова выполнить уже terminal P6.3.
   Следовательно, этот вызов не является fail-closed guard against the observed omission.

## Причинная цепочка

1. **Adapter inheritance gap.** `plan-run` не materializes its mandatory terminal tail and
   ссылается на source-tree path, который не существует в installed projection. Это делает
   исполнение зависимым от ручного обнаружения второго command file.
2. **Publication identity gap.** У cache и marketplace source одинаковый version `0.12.0`,
   но SHA-256 различаются для `commands/plan-exec.md`, Codex `task-plan-exec/command.md` и
   `lib/task/plan_delivery.py`. SemVer не доказывает, что agent прочитал ту же policy, которую
   предполагает source; publication lock не даёт terminal-time content attestation.
3. **Receipt correlation gap.** `task.plan_delivery._handoff()` проверяет лишь наличие
   непустого `**Next:**`; `build_terminal_receipt()` не сверяет заголовок handoff `after <subject>`
   с terminal journal subject/run-id и не проверяет, что recommendation advances to a legal
   successor. Поэтому stale P6.2 handoff прошёл как P6.3 receipt.
4. **Provider enforcement gap.** Даже при существующей prose, Codex adapter не имеет
   структурного terminal-output gate: agent может вызвать journal/state или дать `final` без
   receipt labels, а runtime это не остановит.

## Граница ответственности

Исполнитель P6.3 нарушил уже доступное правило: закрытие было сделано вручную после обхода
runtime blocker и без полного inherited `plan-exec` steps 7–8. Это нельзя списать только на
cache. Но runtime обязан был сделать такой обход наблюдаемым и запретить финал; два следующих
слоя не сделали этого, поэтому инцидент воспроизводим для любого исполнителя.

## Предлагаемое решение

1. В generated `task-plan-run` materialize/inline shared terminal contract либо resolve parent
   command только через discovered installed package root; запретить source-tree literal
   `packages/task/commands/...` в published adapter.
2. Publication lock должен attest exact digests inherited command/runtime files и отвергать
   cache/source divergence под одним version; новая policy требует immutable release identity
   или content digest in manifest.
3. Сделать `plan-delivery` subject-aware: для item receipt handoff title обязан быть
   `after Pn.m`, journal pointer/run-id должен быть current, Next не может указывать terminal
   subject; invalid correlation → `FINAL_BEFORE_TERMINAL_FORBIDDEN`.
4. Codex/Claude adapter перед terminal final строит receipt сам и emits only structured terminal
   block containing `Delivery receipt:` and `Рекомендация следующего шага:`. Отсутствие exact
   labels или receipt verification — nonzero terminal gate, не advisory prose.

## Приёмка

- Installed-package fixture без source monorepo: `$ task:plan-run` получает полный inherited
  terminal contract и может закрыть item без ручного поиска файла.
- Source/cache same version with different inherited digest → publication/activation reject.
- Fixture с terminal `P6.3` journal/state, но handoff `after P6.2`/Next `P6.3`:
  `plan-delivery.py --kind terminal` returns nonzero `FINAL_BEFORE_TERMINAL_FORBIDDEN`.
- Happy fixture produces exact successor P6.4 recommendation and native launch-block.
- Provider transcript contract test rejects terminal final without both required labels.
