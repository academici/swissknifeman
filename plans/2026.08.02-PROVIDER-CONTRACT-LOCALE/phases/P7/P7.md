# P7 — Validate provider strengths, release, and operationalize

## Phase Context

P7 is the release boundary for the provider-control-plane and locale programme. It starts only
after P0–P6 are terminal and their frozen contracts, repository acceptance, migration results and
two-run fleet-health bundle exist at the exact identities named by those phases. It distinguishes
shared semantic parity from provider-native strengths: Claude Code and Codex are evaluated against
the same desired capability IDs, while provider-exclusive or unsupported surfaces keep their own
declared expectations. A complete but non-green P6.3 fleet report remains release-blocking unless a
later Owner D# names the exact exception and its consequences. P7 may assemble a release candidate
and operational documentation, but it may not tag, push, publish, mutate consumers or repair Brain.

P7.2/P7.3 follow the D39 per-cwd carrier in `roadmap.md`: a root coordinator owns the
regression/release manifest and close, while each affected package mutation is performed from
its own fresh cwd and yields a scoped evidence record. Deterministic blocker predicates are
machine stop conditions in P7.1/P7.3 Validation, not Owner decisions.

**Scope Included:** exact-set provider acceptance; negative and regression suites for shared semantics, native strengths, drift, locale independence and state isolation; operational/migration/rollback documentation; generated-doc and package validation; release-candidate manifest; independent adversarial audit and explicit Owner release decision.

**Scope Excluded:** new provider or locale semantics; weakening frozen P1/P2/P6 contracts; accepting missing/unsupported required rows as green; live consumer/Brain repair; quarantine deletion; tag, push, package publish or release announcement; claiming provider equivalence beyond measured semantic capability IDs.

> **Контракт фазы (contract-first).** Потребляет: terminal P0–P6 commits; frozen `provider-control-plane-v1`, `locale-resolution-v1`, `provider-recovery-gates-v1` and `provider-health-v1`; P4 repository acceptance; P5 convergence/unresolved sets; P6 two-run exact-set fleet evidence · Производит: minimized provider acceptance bundle, permanent regression gates, operator/migration/rollback docs, release-candidate manifest and independent Owner-facing audit · Границы: no new semantics, no fleet/Brain mutation, no destructive cleanup and no tag/push/publish.
