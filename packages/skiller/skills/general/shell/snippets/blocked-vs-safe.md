# Заблокировано vs безопасно (cookbook, дополняется)

Растущая таблица конкретных `rm`/`rmdir`-конструкций, столкнувшихся с
`safe-dirs`-хуком. Найден новый паттерн — допиши строку, не переписывай
тело `SKILL.md`.

| Паттерн | Вердикт | Почему | Замена |
|:--|:--|:--|:--|
| `for f in a b c; do rm -rf "$f"; done` | ❌ deny_hard | `rm` не первый токен сегмента (`do rm ...`) | `rm -rf a b c` (один вызов) |
| `sudo rm -rf x` | ❌ deny_hard | `rm` не первый токен (`sudo rm`) | выполнить вручную (`!`-префикс) |
| `find . -name '*.tmp' -exec rm {} \;` | ❌ deny_hard | `rm` внутри `-exec`, не голова сегмента | `find . -name '*.tmp' -delete` (не rm) либо ручное подтверждение |
| `xargs rm -rf` | ❌ deny_hard | `rm` не первый токен (`xargs rm`) | раздельные вызовы `rm -rf <path>` |
| `rmdir -p a/b/c` | ❌ deny_hard | `-p`/`--parents` не в белом списке (лезет к родителям) | `rmdir a/b/c` без `-p`, либо `rm -rf a` |
| `rm -rf a b c` (все под доверенным корнем) | ✅ safe | `rm` — голова сегмента, флаги/пути валидны | — |
| `rm -rf path/*` (не трогает `.git`) | ✅ safe | глоб — дети корня, не сам корень, не `.git` | — |
| `rm -rf .git/hooks/*` | ❌ deny_hard | `protect_git`: компонент `.git` в пути | ручное подтверждение |
| 5 раздельных Bash-вызовов `rm -rf <path>` | ✅ safe | каждый — свой безопасный сегмент | — |
| for-цикл с динамическим списком путей, semantically не переписывается в multi-arg | ❌ deny_hard (по форме, не по сути) | цикл всегда триггерит `rm`/`rmdir` не-в-голове | `harness safe-dirs delete <path> [<path> …]` (не проходит через shell rm вообще) |
