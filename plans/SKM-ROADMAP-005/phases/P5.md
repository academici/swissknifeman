# P5 — changelog-discipline: enforcement заполнения CHANGELOG

## Phase Context

Фаза превращает CHANGELOG из «дисциплины, которая держится на памяти сессии» в enforced-правило
(спека `roadmap/changelog-discipline.md`). Наблюдение владельца 2026-07-10: корневой `CHANGELOG.md`
заполняется нерегулярно; скилл `oss-dev/release-engineering` существует, но активируется только
на релизных задачах, а в повседневных коммитах запись в `[Unreleased]` пропускается.
Два контура. Пакеты (SemVer-строгие): классификация из conventional commits (`fix:` → patch,
`feat:` → minor), **major — всегда ручное решение владельца** (breaking не выводится автоматикой);
каждый содержательный коммит оставляет строку в `[Unreleased]` нужной группы Keep a Changelog.
Проекты (без SemVer): компактные записи со ссылкой на коммит, систематизация — в релиз.
Enforcement — commit-гейт в `harness` (прецедент git-гейта SKM-AUDIT-004 P7.4): содержательный дифф
без правки CHANGELOG → **warning в контекст модели, не блок**; осознанные исключения (docs-only,
chore) снимаются skip-маркером. Опциональная механизация — `skm release`.
Фаза закрыта, когда гейт ловит пропуск записи, а `release-engineering` описывает повседневную
дисциплину, не только релиз.

> СКЕЛЕТ — не детализирован, разворачивается /task:plan-design SKM-ROADMAP-005 P5

## DoR (Definition of Ready)

Прогоняется `/task:plan-design` перед выдачей «фаза готова»; `plan-audit` сверяет пост-фактум.

- [ ] Все `[NEEDS CLARIFICATION]` сняты (0 маркеров в фазе).
- [ ] Scope Included / Scope Excluded фазы заполнены (эквивалент Goals/Non-Goals).
- [ ] Alternatives для несущих решений зафиксированы в D-логе.
- [ ] Open Questions разнесены по статусам `open-questions.md`.
- [ ] Несущие факты несут RAG-маркеры (`RAG:✅ …` / `[UNVERIFIED]`).
