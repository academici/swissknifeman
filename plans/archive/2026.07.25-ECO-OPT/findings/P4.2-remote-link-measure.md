# P4.2 — замер бюджета ожидания cross-machine памяти (2026-07-28)

Требование item'а (`research/06-P4-target-design.md` §4): измерить фактическое время/объём
дайджеста ПО КАНАЛУ до принятия дефолтов таймаута/ретраев, а не брать их «из ощущений».

## Метод

Единственная машина, доступная в этой сессии исполнения P4.2, — сама будущая host-машина
(ADR-0001 п.1: хост = ТЕКУЩАЯ машина); второй физической машины для настоящего LAN-замера
ещё нет (её ставит P4.3 — rollout). Поэтому замер честно ограничен **тем, что технически
доступно сейчас**: HTTP-сервер (`http.server`), эмулирующий контракт `/agentmemory/health` и
`/agentmemory/memories`, поднят на loopback И на выбранном LAN-интерфейсе этой машины
(`192.168.31.93`, реальный физический NIC `enp3s0`, а не petli), клиент — тот же
`core.http.http_get_json`/`ping`, которые реально используют `memory.py`.

**Честная граница метода (анти-самообман):** соединение loopback→loopback и
LAN-IP→тот-же-LAN-IP на ОДНОЙ машине оба идут через локальный сетевой стек ядра и НЕ
проходят через физический коммутатор/Wi-Fi другой машины — значит это НЕ настоящий
cross-machine замер, а верхняя граница «накладных расходов нашего кода + стека сокетов»,
без реальной сетевой задержки (свитч/Wi-Fi/маршрутизация) и без нагрузки Node-движка
(здесь — синтетический `http.server`, не настоящий `agentmemory`). Расхождение с
ожиданием (findings §6 практики — «1-2с лёгкие, 5-10с тяжёлые» для LAN/VPN) — ожидаемо и
не сглаживается: **выбранные дефолты держат запас НАД измеренным числом** именно потому,
что настоящая LAN-задержка (P4.3, вторая машина) этим замером не поймана.

Payload дайджеста синтезирован по реальному размеру корпуса памяти (`state_store.db` —
6,4 МБ, `findings/P4-cross-machine-facts.md` §4): JSON-массив фактов, суммарно ~6,43 МБ.

Воспроизводимая команда (heredoc, тот же код что в `core/http.py`/`memory.py`):

```bash
python3 - <<'PY'
import json, statistics, sys, time, threading
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
sys.path.insert(0, "/home/vostrikov/projects/packages/swissknifeman")
from core.http import http_get_json, ping

LAN_IP = "192.168.31.93"
FACT = {"content": "x" * 400, "type": "fact", "timestamp": "2026-07-28T00:00:00Z"}
N = 6_400_000 // len(json.dumps(FACT))
PAYLOAD = json.dumps({"memories": [FACT] * N}).encode("utf-8")

class Handler(BaseHTTPRequestHandler):
    def log_message(self, *a): pass
    def do_GET(self):
        body = b'{"status":"ok"}' if self.path.startswith("/agentmemory/health") else PAYLOAD
        self.send_response(200); self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body))); self.end_headers()
        self.wfile.write(body)

def bench(host, label):
    httpd = ThreadingHTTPServer((host, 0), Handler)
    port = httpd.server_address[1]
    threading.Thread(target=httpd.serve_forever, daemon=True).start()
    url = f"http://{host}:{port}"
    ping(f"{url}/agentmemory/health")  # warmup
    light = [( _t := time.perf_counter(), ping(f"{url}/agentmemory/health", timeout=3),
              (time.perf_counter()-_t)*1000)[-1] for _ in range(20)]
    heavy = [( _t := time.perf_counter(), http_get_json(f"{url}/agentmemory/memories?namespace=", timeout=10),
              (time.perf_counter()-_t)*1000)[-1] for _ in range(10)]
    print(f"[{label}] light median={statistics.median(light):.2f}ms heavy median={statistics.median(heavy):.2f}ms")
    httpd.shutdown()

bench("127.0.0.1", "loopback")
bench(LAN_IP, "LAN-interface")
PY
```

## Результат (2026-07-28, на дереве этого item'а)

| Операция | Объём | Время — loopback (127.0.0.1) | Время — LAN-интерфейс (192.168.31.93) |
|:--|:--|:--|:--|
| health ping (лёгкая) | ~15 байт | median 0.44мс (min 0.31 · max 0.61, n=20) | median 0.43мс (min 0.31 · max 0.60, n=20) |
| memories-дамп (тяжёлая, ~6,4 МБ) | 6 427 264 байт | median 12.57мс (min 9.69 · max 14.35, n=10) | median 12.03мс (min 9.47 · max 16.19, n=10) |

Дельта loopback↔LAN-интерфейс на этой машине — **в пределах шума** (оба пути — локальный
сетевой стек ядра, без реального сетевого прыжка). Это ОЖИДАЕМЫЙ результат метода, а не
довод «канал дешёвый» — см. границу метода выше.

## Выбранные дефолты (`packages/maind/lib/maind/constants.py`)

| Константа | Значение | Обоснование |
|:--|:--|:--|
| `MEMORY_LIGHT_TIMEOUT_S` | 3с | health/auth-проверка; практика LAN/VPN (findings §6: 1-2с) + запас, т.к. настоящая LAN-задержка этим замером не поймана |
| `MEMORY_HEAVY_TIMEOUT_S` | 10с | export/digest (весь пул, до ~6,4 МБ и будет расти); верхняя граница практики (findings §6: 5-10с) — запас на реальный Node-движок (не синтетический http.server) + реальный сетевой прыжок |
| `MEMORY_RETRIES` | 2 | практика findings §6 (2-3 ретрая) |
| `MEMORY_RETRY_BACKOFF_S` | 0.5с (экспоненциальный: 0.5/1.0) | практика findings §6 (backoff) |

Ретраи применяются ТОЛЬКО к read-операции `export()` (used by digest/count) — не к
`store`/`forget`: контракт `store` не несёт operation-id, повтор мутации рискует дублем
(ADR-0001 п.5, `research/06` §5). `HTTPUnauthorizedError` не ретраится — тот же токен даст
тот же 401.
