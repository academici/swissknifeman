# Task package validation discovers support directories as plans

## Observation

After B1 closure, `bash packages/task/scripts/validate.sh` compiled Python, checked Bash and
required command files, and completed its Python suite successfully (`Ran 562 tests`, `OK`). Its
final repository-wide `plan-lint plans/` step exited non-zero.

The blocking diagnostics treat `plans/.claude/` and `plans/__pycache__/` as plan roots and require a
`plan.md` and `handoff.md` inside each. The first directory is tool state with nested ignore rules;
the second is ignored Python bytecode (`git check-ignore -v` attributes it to root `.gitignore`).
Neither matches a canonical plan id or appears in `git status --short`.

The scoped command remains green:

```text
python3 packages/task/scripts/plan-lint.py plans/2026.08.07-PLAN-ECONOMY --baseline HEAD
plan-lint: OK (1 план(ов), 0 ошибок, 0 предупреждений; новых от рабочего дерева: 0)
```

## Impact

Repository-wide package validation cannot be treated as green in this workspace even though the
selected plan and all P1.1–P1.4 acceptance commands pass. The false discovery also obscures genuine
legacy warnings behind support-directory errors.

## Proposed remediation

Owning source: plan-root discovery in `packages/task/scripts/plan-lint.py` (and its tests). Discovery
should admit only canonical plan-id directories and explicitly exclude hidden/tool-state and Python
cache directories before requiring plan files. The behavior needs fixtures for `.claude` and
`__pycache__`, then a green `bash packages/task/scripts/validate.sh`.

Plan command:

```text
/task:plan-design 2026.08.07-PLAN-ECONOMY P3.6
```

The design pass should attach this finding to P3.6 or create an earlier owning fix item without
changing B1's frozen contract semantics.
