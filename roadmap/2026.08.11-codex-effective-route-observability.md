# Roadmap: authoritative effective-route evidence for Codex Task execution

**Статус:** ⬜ к внедрению. Критерий сработал: Agelto, `2026.08.09-RELEASE-READINESS` P2.7, 2026-08-11 (LEAN P1.1 и P1.2).
**Владельцы:** `packages/task` и Codex provider adapter. **Не владелец:** скилл или model prompt.

## Симптом

`$ task:plan-run` должен сравнивать Route item'а с **effective** model/effort текущего
Codex thread. Вместо этого adapter требует, чтобы агент сам передал эти поля в
`route_evidence.capture_actual(..., source="self-attested")`.

Воспроизводимый замер в Codex CLI 0.147.0:

```bash
env | cut -d= -f1 | rg -i '(^|_)(codex|model|reasoning|effort)(_|$)'
# CODEX_THREAD_ID
# CODEX_CI

codex doctor --json
# checks.config.load.details.model: config default only
# no active-thread effective model; no reasoning effort
```

`codex doctor --json` в этом запуске сообщил config default `gpt-5.6-sol`, а не
attested effective route текущего thread. `codex resume --help` позволяет задать `-m` и
`-c model_reasoning_effort=...`, но не предоставляет read-only query effective route
уже работающей сессии. Поэтому config, launch-block и память агента не являются evidence
текущего запуска.

Дополнительный минимальный repro Task runtime:

```python
capture_actual('implementation', 'medium', source='self-attested', model='gpt-5.6-terra')
capture_actual('implementation', 'high', source='self-attested', model='gpt-5.6-terra')
```

Оба значения принимаются. Функция валидирует только принадлежность строк frozen ladder;
она не связывает их с `CODEX_THREAD_ID`. Агент может ошибиться, как произошло здесь, и
создать ложный `ROUTING-BLOCKED`.

## Incident record — 2026-08-11, LEAN P1.2

В текущем Codex thread оператор подтвердил effective route `gpt-5.6-terra/high`, но
исполнитель без provider-bound evidence сам подставил `gpt-5.6-terra/medium`. Это создало
ложный `routing-blocked` event для `2026.08.10-TASK-LEAN-AUTONOMY P1.2` до start event и без
смены item state. Повторный Task Contract с теми же входами и только заменой caller-supplied
route на `implementation/high` вернул `pre_mutation=allow` и `pre_final=allow`.

Это не доказывает route через runtime: operator correction — evidence инцидента, а не
замена immutable provider evidence. Append-only журнал нельзя тихо переписать; поэтому
будущая реализация должна предотвращать сам ложный event, а не пытаться объявить его
продуктовым сигналом задним числом.

## Incident record — 2026-08-11, LEAN P1.1

Тот же сбой повторился при bounded audit repair P1.1: исполнитель self-attested
`implementation/medium`, хотя владелец подтвердил effective route
`gpt-5.6-terra/high`. Это добавило ложный `routing-blocked` event в append-only журнал,
хотя byte-fresh item state остался `🟡 In progress`, а повторная проверка Task Contract
с `implementation/high` вернула `pre_mutation=allow`.

Эта запись — evidence инцидента, а не попытка переписать журнал или доказать route
через пользовательскую коррекцию. P1.1 не получает новый scope: его Deliverables не
включают provider-bound effective-route telemetry. Исправление остаётся roadmap work
владельцев `packages/task` и Codex adapter по решению ниже.

## Incident record — 2026-08-11, LEAN P2.4

При bounded audit repair `2026.08.10-TASK-LEAN-AUTONOMY P2.4` Codex thread фактически
работает как `gpt-5.6-terra/high`: текущий runtime config содержит
`model = "gpt-5.6-terra"` и `model_reasoning_effort = "high"`, а оператор подтвердил
effective route. `codex doctor --json` при этом отдал только model и не отдал effort;
Task command, следуя текущему fail-closed literal, записал бы `unknown/unknown` и
`block:ROUTE_UNDERSHOOT` до journal start.

Это coverage defect provider adapter, а не недобор текущего исполнения и не основание
переписать P2.4 spec, journal или generated state. Canary report обязан отделить
operator-confirmed effective route от отсутствующей thread-bound provider evidence;
исправление остаётся задачей владельцев roadmap entry.

## Почему это отдельный defect

[`2026.08.10-plan-run-routing-blocked-terminal-loop.md`](2026.08.10-plan-run-routing-blocked-terminal-loop.md)
устраняет последствия ложного routing reject: он не должен терминализировать item. Но он
не делает self-attestation доказательством. Текущий `2026.08.10-TASK-LEAN-AUTONOMY` P1.1
также прямо исключает `proof of model behavior`; эту проблему нельзя молча включить в его
scope.

## Решение

1. Codex host/provider adapter передаёт immutable, thread-bound route evidence до первого
   plan gate: concrete model, provider-neutral model class, reasoning effort, `thread_id`,
   capture timestamp и source/version. Предпочтительный контракт — structured tool/runtime
   metadata; environment variable допустима только если платформа гарантирует её integrity.
2. Task получает actual route только через этот adapter (`source=provider-doctor` или новый
   canonical source), а `self-attested` запрещён для allow/block решения в `plan-run` и
   `plan-close`.
3. Пока Codex не предоставляет такую telemetry, adapter возвращает `unknown`; command
   выдаёт nonterminal `ROUTE-UNVERIFIABLE` с launch-block, не создавая journal `blocked`,
   state transition или ложное model/effort assertion.
4. `codex doctor --json` либо получает явно документированный active-thread mode, либо
   adapter перестаёт трактовать config default как actual route. Не подменять это чтением
   `~/.codex/config.toml`: CLI flags, profiles и orchestration могут его переопределять.

## Приемка

- fixture с effective `gpt-5.6-terra/high` проходит routing `implementation/high` без
  self-attestation;
- fixture с lower effort получает nonterminal routing rejection, а provenance содержит
  provider source и thread binding;
- отсутствие provider evidence даёт `ROUTE-UNVERIFIABLE`, не `ROUTING-BLOCKED` и не
  `blocked` journal result;
- изменение config default при неизменном fixture не меняет route verdict;
- тест доказывает, что agent-supplied `medium`/`high` не может изменить verdict;
- regression fixture воспроизводит этот incident: один и тот же thread получает
  caller-supplied `medium` при effective `high`; adapter обязан отвергнуть подстановку до
  `journal.append`, а P1.2-подобный item остаётся `Not started` без `blocked` event;
- Codex и Claude adapters соблюдают один provider-neutral schema contract, а generated
  projections проходят package validation.

## Доказательства

- Agelto P2.7: ложная self-attestation создала `routing-blocked` до product work.
- `packages/task/lib/task/route_evidence.py:100` — caller-supplied `capture_actual`.
- `packages/task/adapters/codex/skills/task-plan-run/command.md:70-72` — command требует
  агенту подставить «фактический» route без runtime probe.
- OpenAI: [GPT-5.6 model guidance](https://developers.openai.com/api/docs/guides/latest-model)
  документирует selectable reasoning effort, но не гарантирует его exposure агенту в
  already-running Codex thread.
