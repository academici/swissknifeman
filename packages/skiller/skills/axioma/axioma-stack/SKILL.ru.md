## Контекст

`ecosystem-reuse-gate` — универсальный механизм без данных: путь к реестру
он получает параметром. Этот скилл — Axioma-конкретная привязка: указывает,
ГДЕ живой канон, объясняет его структуру и запускает механизм против него.
Читать сразу после `axioma-doctrine` (принцип «reuse by default») и перед
`new-project`/`tech-stack-selection` — доктрина объясняет ПОЧЕМУ, этот скилл
даёт КОНКРЕТНЫЙ вердикт по проектируемой единице.

Единственный источник данных — живой файл
`02-Knowledge/00-Strategy/Ecosystem_Tech_Radar.md` в vault Brain. Этот скилл
НЕ хранит копию его содержимого — вшитая копия дрейфует от канона при первой
же правке радара. Здесь только путь, структура и алгоритм чтения.

## Входные данные

- Проектируемая функциональная единица (что делает фича/пакет).
- Языковой кластер потребителя (PHP/Laravel на `CoreX`, Dart/Flutter на
  `AxiomaErpSdk`, Node/Scraping, Frontend/Design System — секция §1 радара).
- Путь к канону: `02-Knowledge/00-Strategy/Ecosystem_Tech_Radar.md` **относительно корня vault Brain** (не CWD текущего проекта). Проектируешь ВНЕ Brain — сперва определи корень vault Brain (maind-хаб экосистемы / известный путь), открой радар там; CWD-относительный путь молча схлопнет гейт в no-op.

## Структура канона (4 секции)

1. **§1 Языковые кластеры** — таблицы «задача → рекомендовано / запрещено»
   по каждому кластеру (PHP/Laravel, Dart/Flutter, Node/Scraping, Frontend).
   Читать секцию своего кластера первой.
2. **§2 Карта: функциональная единица → пакет/вендор** — плоский список всех
   учтённых единиц с состоянием (`пакет` / `вендор` / `use-vendor` /
   `build-new` / `keep-per-project`). Быстрый поиск точного совпадения.
3. **§3 Gap-roadmap** — единицы с подтверждённым дублированием, ещё не
   закрытые пакетом/вендором, приоритизированные по числу потребителей.
   Проектируемая единица здесь = дублирование уже опознано экосистемой.
4. **§4 Прецеденты решений** — 7 обобщённых if-then правил в форме,
   которую напрямую прогоняет `ecosystem-reuse-gate` (правила идентичны,
   секция радара — источник, не копия).

## Алгоритм

1. Прочитать `axioma-doctrine`, если ещё не прочитан в этой сессии
   проектирования (задаёт принцип, этот скилл — его исполнение).
2. Открыть `02-Knowledge/00-Strategy/Ecosystem_Tech_Radar.md`.
3. Вызвать `ecosystem-reuse-gate` с параметром пути = этот файл и
   проектируемой единицей — механизм гейта не переписывается здесь, только
   вызывается (см. `requires`).
4. Внутри вызова: найти единицу сначала в §2 (точное/близкое совпадение),
   при необходимости уточнить по таблице своего кластера в §1; если единица
   уже фигурирует в §3 — это дополнительный сигнал «дублирование подтверждено
   экосистемой», не отдельная ветка алгоритма.
5. Получить от гейта вердикт (`use-vendor` / `use-package` / `build-new` /
   `keep-per-project`) с указанием сработавшего правила из §4.
6. Оформить reuse-отчёт (см. «Выходные данные») с прямой цитатой строки
   радара, обосновывающей вердикт — не пересказ, а цитата.
7. Несколько единиц в одной задаче проектирования → повторить шаги 3–6 для
   каждой, отчёт — по одной строке на единицу.

## Выходные данные

Reuse-отчёт в чате, одна строка на единицу:

`<единица> → <вердикт> (правило N) — «<цитата строки радара>»`

Не отдельный файл — решение встраивается в диалог проектирования
(`new-project` / `tech-stack-selection`), как и у `ecosystem-reuse-gate`.
