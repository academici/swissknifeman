## 6. Вердикт: раскатывать

Перенос путём path-scoped `.claude/rules` на этом классе проектов (Nuxt/Vue-приложение с
большим авторским `CLAUDE.md`, без Boost/`.ai`-генератора CLAUDE.md) даёт измеримую,
воспроизводимую экономию резидентного счёта (−2 374 ток / −17 % строки `CLAUDE.md + rules`
именно у этого пилота) без потери знания — контент не удалён, а перенесён целиком и
подтверждённо подгружается по требованию (§5). Отрицательного или нулевого исхода не
получено — раскатка **раскатывать**, со следующей оговоркой для входа P2.6.

**Оговорка для P2.6 (обязательна к переносу процедурой ниже):** проекты флота с
Boost/`.ai`-generated `CLAUDE.md` (в текущем реестре — минимум `vintera/cms`,
`sibintek-insiders`, `diabox`; возможно, `agelto`/`flexcrm` частично, где `.ai/guidelines/**`
уже подключён к какому-то генератору) **этой процедурой напрямую не раскатываются** — перенос
там требует правки `.ai/guidelines/**` источников + регенерации штатным инструментом пилота
(`php artisan boost:update` или его аналог), что шире периметра `CLAUDE.md` +
`.claude/rules/**`, объявленного этим item'ом, и является отдельным design-решением (какой
инструмент считается «правильным путём правки» для каждого генератора, как это соотносится
с `git add -A`-запретом и с чужими незакоммиченными правками в `.ai/**`) — не механическим
повтором этой процедуры.

## 7. Процедура переноса (вход P2.6)

Применимо к проекту флота, у которого `CLAUDE.md` — прямой авторский файл (не Boost/`.ai`-
generated целиком; см. проверку в шаге 0):

0. **Проверка предусловия.** `head -3 <проект>/CLAUDE.md` и поиск фраз «не редактировать»/
   «generated by»/«edited only in `.ai/guidelines`» в первых ~10 строках файла. Найдено → проект
   **не** подходит под эту процедуру, адрес — §6 (оговорка), решение по нему отдельное. Не
   найдено → продолжать.
1. Разметить хаб-блок (`<!-- swissknifeman:hub:start -->` … `:end`, если есть) и любые другие
   managed-маркеры (`<!-- maind:healthcheck … -->`) — они не участвуют в инвентаризации и не
   трогаются (P2.5/`root.generated-artifacts`).
2. Инвентаризировать ОСТАЛЬНЫЕ секции поимённо: секция описывает поведение/конвенцию,
   применимую к КОНКРЕТНОМУ поддереву/расширению файлов → «path-специфична», иначе →
   «общеприменима». Секция без честного узкого glob'а (карта каталогов, роутинг скиллов,
   процессные гейты вроде Definition of Done) остаётся резидентной — это НЕ пробел, а вердикт.
3. Секции одного «носителя» (например, все правила про тему/CSS, все правила про Nitro/API)
   группируются в ОДИН файл `.claude/rules/<носитель>.md`, а не разбрасываются поштучно —
   меньше файлов, тот же эффект, проще ревью.
4. `paths:` — ровно то поддерево, где знание применимо; `paths: ["**"]` и любой эквивалент
   запрещены (Implementation Rule 4 item'а). Секции «Запрещено»/сводные списки чаще всего
   ДУБЛИРУЮТ уже перенесённые секции построчно короче — при переносе носителя переносить и
   соответствующие строки сводного списка, оставляя в `CLAUDE.md` только по-настоящему общие
   пункты (см. §2, `## Запрещено`).
5. Перенос — не пересказ: текст копируется дословно в новый файл с YAML `paths:` (форма —
   `packages/harness/configs/claude-code/agent-packs/backend-laravel/rules/tests.md`), затем
   снимается из `CLAUDE.md` целиком; осиротевший заголовок верхнего уровня (все подсекции
   вынесены) снимается вместе с содержимым.
6. Проверка отсутствия дубля: `grep -n` по заголовкам перенесённых секций против нового
   `CLAUDE.md` — пусто.
7. Замер «до/после»: `skiller budget --first-turn --target <проект>` на git worktree HEAD (до)
   и на рабочем дереве после коммита (после) — строка `CLAUDE.md + rules` в отчёт.
8. Коммит ТОЛЬКО `CLAUDE.md` + `.claude/rules/**`, поимённо (`git add -A` запрещён), по
   commit-конвенции проекта, в его текущей ветке — SHA в отчёт.
9. При желании — поведенческая проба по образцу §5 (не обязательна per-проектно при массовой
   раскатке P2.6, если процедура уже подтверждена этим пилотом; но обязательна, если поведение
   клиента у конкретного проекта чем-то отличается, напр. другой провайдер/адаптер).
