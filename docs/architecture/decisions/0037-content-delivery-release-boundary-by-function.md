# ADR 0037: Content, delivery and release: the aicore boundary is drawn by function

## Status

Accepted

## Context

[ADR 0004](0004-aicore-foundation-and-generalisation-boundary.md) assumed that the files of the skill library move into
`aicore` whole. Reading the code showed otherwise: most files mix general mechanics with the policy of the library
(buckets, the core set, profiles, presets, `.swissknife.json`, the host configuration, the project registry, the hub).
Moving a file whole would have put that policy into the foundation, and every other module would then depend on it.

## Decision

- **By function, not by file.** A function moves into `aicore` when it works on explicit parameters and knows no
  bucket and no host. It moves verbatim: only imports change, and where a library constant was read, an explicit
  parameter takes its place. Policy and the command line stay in the owning module until its own stage.
- **Three subpackages.**
  - `aicore.content`: `skill` (frontmatter, content hash, descriptor, `requires`), `budget` (token estimate and context
    budgets), `publication` (manifest bytes, whole-file artifacts, Codex plugin manifest, publication lock),
    `commands` (the shared part of command projection), `eval` (grading, benchmarks, runner, context).
  - `aicore.delivery`: `codex`, `claude`, `distribution`, `materialize` (managed skill copies, manifest, lock, sync).
  - `aicore.release`: `attestation`, `version`, `changelog`.
- **Layering.** `content` imports `util`, `provider`, `artifacts` and `config`; `release` imports `util` and `content`;
  `delivery` imports everything below it; the older subpackages import none of the three. A test in
  `packages/aicore/tests/test_architecture.py` keeps this.
- **No library knowledge in the foundation.** What the library used to read from its own place is a parameter of the
  call: the package that owns the publication-version map (`package_root` of `aicore.release.attestation.build` and
  `check`), the identities that appear in generated provenance (`DistributionIdentity`), the host-owned MCP servers
  (`measure_mcp(target, *, host_servers=None)`), the code prefix of a command error. Generated bytes, hashes and report
  texts stay the same.
- **The old names stay.** `skiller` re-exports the moved names or wraps them thinly, so its callers and tests keep
  working; a re-export is removed with the stage that moves its last user.
- **What stays, and where it is decided.** In `skiller`: selection and composition, the publication catalog and the
  rendering of unit kinds, `registry.py` and `skills.json`, connect, vendor, update, status and `skillset` planning.
  Fleet delivery, the host configuration and the root bootstrap belong to the hub; `topology`, `listing` and `state`
  to `maind`; `brain_sync` to `brain`; the command catalog and wrapper texts of command projection to `task`. The
  ownership map (`configs/ecosystem-units.json`) keeps these as entries with their stage.
- **One token formula.** `aicore.content.budget.estimate_tokens` is the only implementation; `harness` imports it
  instead of keeping a copy, and its test checks that it is the same function.

## Alternatives considered

- Move the files whole: rejected, it moves library policy into the foundation.
- Leave everything in `skiller` and let others import it: rejected, it breaks the rule that modules reach each other
  only through the foundation, bridges and events.
- Copy the functions into each consumer: rejected, the token formula already drifted once between two copies.

## Consequences

- `aicore` grows by three subpackages and two contracts ([ADR 0038](0038-skill-descriptor-agent-skills-standard.md),
  [ADR 0039](0039-eval-result-context.md)); `skiller` shrinks to policy and commands.
- The text of the skiller instructions points at `aicore.content.budget` as the source of token math.
- Each later stage moves what remains with its module; none of them needs to change `aicore` signatures.

## Supersedes

None. It refines [ADR 0004](0004-aicore-foundation-and-generalisation-boundary.md): the assumption that whole files
move is dropped, the generalisation boundary itself stands.
