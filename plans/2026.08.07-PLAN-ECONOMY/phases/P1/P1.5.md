### P1.5 — Свести контракт, оценить выполнимость и заморозить владельческим гейтом

**Intent:** Свести четыре контракта фазы в один согласованный набор, измерить перестроенный путь исполнителя на РЕАЛЬНОМ плане против замороженного порога P0.5, вынести результат владельцу и после его явного решения заморозить контракт читателей v1 D-записью и строками `## 7. Contracts`.
**Why:** Вывод «расхождений нет» делается только тогда, когда видны все четыре формы сразу: реестр, слепок, история и путь ссылаются друг на друга, и рассогласование между ними обнаружится либо здесь, либо в P2 ценой переделки. Главное же — контракт, который не проходит собственный порог, будет либо отключён целиком, либо порог поднимут задним числом; обе развязки убивают план, поэтому оценка выполнимости обязана предшествовать заморозке (митигация pre-mortem #1, D28). Заморозка публичного контракта протокола — владельческий гейт, а не решение исполнителя — RAG:— (repo-grounded: `plan.md` `## 2. Execution Rules`); тот же порядок уже применён к порогу в P0.5.
**Scope Included:** Сквозная сверка четырёх контрактов; до freeze — дополнение reader/read-path формы двумя ПРОФИЛЯМИ существующего `auditor` (`scoped-review` и `full-audit`) без пятого reader и с явным `return-to-root`; реконструкция пути исполнителя для реального плана из существующих файлов; замер реконструкции инструментом оценки P0 против порога `read-budget` v1; отчёт с явной пометкой «оценка, не доказательство»; вынесение владельцу; после решения — D-запись о заморозке, строки в `## 7. Contracts`, строка в `## 6. Update Log`, version bump плана.
**Scope Excluded:** Любая реализация (P2/P3/P4/P6); новый/пятый reader; форма model-judgement capsule и вызов reviewer'а (P4.5/P6.3); правка порога (P0.5 — порог здесь не пересматривается, а проверяется); миграция существующих планов (D3); изменение форм задним числом без D-записи; сборка `roadmap.md` (режим `finish` всего плана).

**Implementation Rules:** - **Читателей остаётся РОВНО четыре:** `scoped-review` и `full-audit` — профили существующего `auditor`, не новые роли. Машинная спецификация несёт `review_profiles` с `reader: auditor`; `scoped-review.control = return-to-root`, а `full-audit` ссылается на полный auditor path. Свежесть контекста не означает handoff владения root run — RAG:✅ 2026-08-08 (`findings/19-…` R23; D125).
- **Профиль не подменяет capsule:** P1 фиксирует только право/границу чтения. Точный минимальный состав diff/validation/fingerprint evidence и запреты transcript/chain-of-thought/self-evaluation принадлежат P4.5/P6.3. Здесь запрещено незаметно расширять executor path или класть history на него.
- **Сквозная сверка — по объявлениям, а не по прозе.** Проверяется: каждый `carrier_id` пути существует в реестре; каждый носитель реестра либо стоит в чьём-то пути, либо помечен `superseded_by`; класс `history` отсутствует на пути исполнителя; поля слепка не пересекаются с полями, объявленными исторической проекцией; ни один контракт не требует поля журнала вне запечатанной схемы. Расхождение → правка контракта + D-запись (`supersedes D#`, если отменяется раннее решение), а не подгонка отчёта.
- **Реконструкция строится из СУЩЕСТВУЮЩИХ файлов**, а не сочиняется: ядро — `## 1. Context` + `## 2. Execution Rules` + `## 3. Routing` реального плана; контекст фазы — Phase Context реальной фазы; ТЗ — один реальный item целиком; входы — его `Required Reads`; состояние — синтетический слепок по схеме P1.2, заполненный реальными значениями. Каждый фрагмент сохраняется файлом в `artifacts/p1-path-reconstruction/`, чтобы число было воспроизводимо.
- **Мерится ПОЛНЫЙ путь целиком**, включая per-file overhead калибровки P0.1: путь стал из четырёх слотов пятью, и экономия обязана считаться с учётом этого, а не по «телу без обвязки» (митигация pre-mortem #8).
- **Замер идёт минимум по ДВУМ реальным планам** разного веса — один крупный (пол >150 КБ по `findings/00-…` §2) и один здоровый (<40 КБ), — и по МИНИМУМ трём пунктам в каждом, включая самый тяжёлый по `Required Reads`. Один пункт одного плана не является распределением.
- **Отчёт называет себя оценкой.** Носители ещё не перестроены (это P2), поэтому измеряется реконструкция, а не факт; раздел «что этот замер НЕ доказывает» обязателен, как в P0.4.
- **Артефакт `p1-feasibility.json` — генерируемый** (root.generated-artifacts): руками не правится, пересобирается прогоном; несёт на каждый замеренный пункт вес по слотам, сумму, порог, единицу (id калибровки + `model_id`) и вердикт.
- **Не проходит порог → правится КОНТРАКТ, а не порог.** Способы правки перечисляются в отчёте (дробление пункта, вынос содержимого в bundle, перенос секции в другой носитель); подъём порога — только через владельца и новую D-запись, отменяющую D17.
- **Владельческий гейт обязателен.** Исполнитель предлагает и обосновывает; D-запись о заморозке и строки `## 7. Contracts` пишутся ТОЛЬКО после явного решения владельца. Строки `## 7. Contracts` для четырёх контрактов переводятся из ⬜ в 🟢 в этот момент и не раньше.
- После решения: D-запись в `## 5. Decision Log`, строка в `## 6. Update Log` с датой и ролью владельца, version bump, заполнение Phase Handoff.
**Code Guidance:** Кода в item'е почти нет — есть необратимое решение и число, на которое оно опирается, поэтому главный риск: выдать реконструкцию за факт или предпочтение дизайнера за вывод из измерения. ЗАПРЕЩЕНО помечать item 🟢 и при непройденной сквозной сверке: несведённое расхождение между контрактами — это дефект, который в P2 стоит переделки, а не «мелочь оформления».
