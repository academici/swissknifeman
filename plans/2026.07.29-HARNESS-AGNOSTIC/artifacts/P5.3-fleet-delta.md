## 5. НЕ раскатано на потребителей (D45)

Merge переключил у флота ровно две вещи — код пяти CLI и код MCP-серверов хаба (оба через
зашитые пути в основное дерево). **Всё остальное у потребителей живёт копиями и кэшем и без
явной команды на их стороне не доезжает вовсе.** Ни одна из перечисленных ниже команд в этом
плане не выполнялась и выполнена не будет — это отдельная работа с собственным гейтом:

| Что НЕ доехало | Носитель у потребителя | Команда раскатки | Статус |
|:--|:--|:--|:--|
| Скиллы connect-канала | кэш плагинов Claude Code; у локального marketplace **auto-update выключен по умолчанию** | `/plugin marketplace update swissknifeman` + `/reload-plugins` в проекте | отдельная работа, вне плана |
| Скиллы vendor-канала | физические копии в репо проекта + `skills-lock.json` | `skiller sync` (при дрейфе — `skiller sync --repair`) | отдельная работа, вне плана |
| Agent-packs | установленные копии в `.claude/` + `agent-pack.lock.json` | `agent-packs upgrade` | отдельная работа, вне плана |
| Корневые инструкции провайдеров | `CLAUDE.md` / `AGENTS.md` целей | `harness instructions` на цели | отдельная работа, вне плана |
| Провизионеры maind на целях | `.mcp.json`, `.claude/**`, `.codex/**` целей | `maind sync --project <id> --mode update` \| `--mode repair` | отдельная работа, вне плана |

Источник утверждения про кэш и auto-update — first-party дока Claude Code
(`findings/06` Ф23, прямой WebFetch `code.claude.com/docs/en/discover-plugins`: «Third-party
and local development marketplaces have auto-update disabled by default», «plugins are copied
to a cache»), подтверждено вторичным RAG (Ф24).

Наблюдаемое следствие уже видно в §4: три из четырёх целей дают `failed` на провизионерах
`mcp`/`skills-catalog`/`instructions` — это ровно «новые правила у потребителя ещё не
раскатаны», ожидаемое состояние, а не дефект.

## 7. Приложения и воспроизводимость

Сырые файлы снимка «ПОСЛЕ» в дерево не коммитятся сознательно: приёмка — дельта, а не второй
базлайн, и коммит «снимка ПОСЛЕ» рядом с «ДО» провоцировал бы будущее сравнение не с тем
файлом. Воспроизведение — три команды из `P5.1-fleet-baseline/README.md`, дословно, тем же
контуром (без префикса PATH), плюс сверка:

```
diff -u plans/2026.07.29-HARNESS-AGNOSTIC/artifacts/P5.1-fleet-baseline/doctor-before.txt <(swissknifeman doctor)
```

Для двух JSON — рекурсивная сверка по ключам (`projects status`) и сверка множествами по
`evidence`/`rows`/`surface_map` (`provider-audit`); списки в `provider-audit` не упорядочены
стабильно между прогонами, поэтому позиционный `diff` по ним даёт ложные расхождения — сверять
только множествами или по ключу `(surface_id, provider)`.
