# Cross-project optimizer

Goal: across several similar projects (shared core packages), find duplicated code/schemas and
extract the shared part into core. Signal comes from **three sources** (no single merged code
graph, none needed): topology (where to look) → duplicates (what repeats) → shared memory (what
changed recently). Point-fixes go through Serena in the target project.

## Workflow

### 1. Fleet map — where to look
```bash
maind fleet manifest                 # JSON: projects (paths/scopes/code) + groups by SHARED package
```
`shared_packages` — projects sharing a package (e.g. azguard-core across flexcrm+azguard+corex).
These are ready-made optimization groups: improving the shared package affects every consumer.

### 2. Memory — what changed recently
```bash
maind fleet features --namespace axioma     # "did feature X" facts from shared group memory
```
Correlate similar features across projects: if two projects did something close, it's a candidate
for a shared helper. (Log a fact: `maind fleet log "<what you did>" --project <id>`.) This is a
cross-project task by definition — raise group context explicitly, same path as the general
guideline ([ecosystem-mcp] → "Cross-project task"): `maind memory recall --scope ns:<name>`
(SessionStart digest does NOT carry it by default, D10 — [docs/guide/memory.md]).

[ecosystem-mcp]: ../ecosystem-mcp/SKILL.md
[docs/guide/memory.md]: ../../../packages/maind/docs/guide/memory.md

### 3. Duplicates — what exactly repeats
```bash
maind fleet duplicates --group azguard-core --min-tokens 60 --json   # by package consumers
maind fleet duplicates --projects flexcrm,azguard --json            # by explicit list
```
Cross-project clones (`cross_project: true`) first. jscpd (via npx) scans sources
(vendor/node_modules/packages ignored). Tune `--min-tokens` (lower → more noise).

### 4. Point analysis — Serena in the project
Open the specific duplicate in each project through the code graph (Serena):
`get_symbols_overview`, `find_symbol`, `find_referencing_symbols` → exact location and all callers.

### 5. Extract into core
Shared code → shared package (corex/azguard/vaulter — themselves projects; changes flow back via
symlinks). Fix call sites in consumers. Log the result:
`maind fleet log "extracted <X> into <core-package>" --project <core>`.

## Principles

- **Group by shared packages** (`shared_packages`), not by every project — optimization only
  makes sense where code actually overlaps.
- **Duplicates are candidates, not a verdict**: similar code can be justified (different domains).
  Extraction decision is by meaning, via Serena, not jscpd alone.
- **Write to shared memory** what you extracted — so the next pass sees history and doesn't
  duplicate work.
- You already have access to all repositories (hub workspace trust). More —
  [code graph](../../../packages/maind/docs/guide/code-graph.md), [fleet](../../../packages/maind/docs/guide/fleet.md).
