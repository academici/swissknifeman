# To Spec

Read the agreed decisions and inspect the affected interfaces and behavior.
Preserve the user's terminology and link to the sources that settle material
decisions. Resolve scope-changing gaps with the user before committing to a
requirement.

Describe the problem, intended outcome, scope boundaries, and relevant
constraints. Specify observable behavior, failure cases, and compatibility or
migration requirements that apply. Write acceptance criteria that a reviewer can
verify, and link each criterion to the relevant requirement.

Record assumptions and unresolved questions separately. Deliver the spec in
the requested format and location. Use the repository's established spec format
when it has one.
