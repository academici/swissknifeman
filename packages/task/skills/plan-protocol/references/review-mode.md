# Review mode

Applies to `task:plan-audit` and to a review item added by `--review`.

1. Runs only on explicit owner request: one reviewer, one pass over the whole target, no subagents
   unless the owner asked.
2. Read-only over product code and execution state. Inputs: `plan.py show`, `plan.py check`, the item
   context packs, the product diff, recorded check results.
3. Judge against the item contracts: scope, acceptance checks, deliverables, decisions.
4. Each finding: severity by demonstrated impact, evidence (`path:line` or command output), owning
   item. Uncertainty is a question, not a defect.
5. Output: a knowledge JSON verdict document (`GREEN`, `ATTENTION` or `RED`) using `add-document`
   and one `plan.py log <plan> <Pn> --type note` event naming it. Human Markdown is generated by the API.
6. Fixes are execution work of the owning item (`plan.py reopen` by the owner when it is closed);
   the reviewer does not fix and does not start a second pass without a new question.

Optional `--reviewer provider/model[/context][/effort]` requests a fresh read-only reviewer on that
exact native route; without an explicit review request no review runs. `plan-run` accepts
`--review-effort`; review/audit accept `--effort`. See the Task package's
`references/reviewer-selection.md` for route parsing, native session independence and the bounded
two-completed-round/one-owning-correction policy. JSON and `plan.py` remain the state API;
reviewer flags do not restore `plan-work`, launch agents from Python or execute check commands.
