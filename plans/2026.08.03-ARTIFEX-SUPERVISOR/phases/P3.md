# P3 — Add provider adapters and fresh worker lifecycle

## Phase Context

P3 binds the terminal P2 candidate to the installed Codex and Claude Code CLIs without moving
provider semantics into the deterministic scheduler. Pure additive adapters map one frozen
`worker-envelope-v1` request into literal argv and untrusted provider records back into the same
closed result taxonomy. One shared bounded process runner owns timeout, byte/event caps, process
groups, redaction and fresh-attempt behavior. RAG:— (repo-grounded:
`research/09-p3-provider-adapter-design.md`).

**Scope Included:** plan-local Codex/Claude adapter modules, parity cases/validator, provider
registry, bounded activity-port/CLI binding, fake-binary tests and minimized live smoke evidence.

**Scope Excluded:** package/root CLI or fleet rollout, provider fallback, session reuse, raw
streams/prompts/transcripts/secrets, unbounded/nested workers, P2 state-machine changes, P4 fault
certification, hook repair, production business slices and any acceptance based on docs alone.

> **Контракт фазы (contract-first).** Потребляет: terminal P2 candidate/manifest, terminal P0 provider matrix and P1 worker/authority/economy contracts · Производит: pure Codex/Claude adapters, explicit parity bank, one bounded fresh-worker activity binding and minimized smoke/aggregate evidence · Границы: plan-local prototype only; no package/fleet rollout, session reuse, provider fallback or child-agent execution.
