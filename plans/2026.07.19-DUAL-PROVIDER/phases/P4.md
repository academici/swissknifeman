# P4 — Task-command parity и provider-neutral model routing

## Phase Context

P4 отделяет semantic workflow task-команд и plan-протокола от provider-specific
frontmatter, invocation syntax и model selector'ов. Единственный semantic inventory
остаётся в `packages/task/commands/`, а provider metadata/routing фиксируются versioned
contract'ом и детерминированными projections. Claude сохраняет текущие slash commands,
frontmatter pins и plan literals через compatibility gate; Codex получает thin generated
skill adapters и observed owner invocation `$ task:…`. Routing использует стабильные
model classes и независимую effort axis, а provider mapping fail-closed при отсутствии
capability или при undershoot. Завершение фазы — frozen contract, два adapter set,
neutralized plan gates и exhaustive parity/no-write evidence без исполнения FOREMAN/fleet.

**Scope Included:** owner-approved provider-command/routing contract; stable command IDs;
semantic command catalog; model-class/effort/capability vocabulary; Claude и Codex
projections; invocation rendering; plan status/item/Next/orchestration semantics; routing
undershoot/overshoot diagnostics; independent inventory parity; operator/reference docs.

**Scope Excluded:** изменение P0/P1 provider precedence; skill marketplace/install ownership
из P3; harness permissions/hooks/MCP/agents (P5); mAInd runner/deployment/analytics (P6);
unattended multi-provider FOREMAN runner; self-host release verdict (P7); реальные
user-global installs; редактирование bootstrap `.agents/skills` как канона; fleet rollout;
provider SDK/runtime dependency; переименование существующих task IDs.

> **Контракт фазы (contract-first).** Потребляет: terminal P3.5, frozen v1.0.0 capability/config/artifact/migration/skill-publication contracts, P2 artifact engine, P3 publication adapters и owner refinement D19 · Производит: frozen provider-command-routing contract, neutral command catalog, byte-compatible Claude commands, generated Codex skill adapters, neutral plan routing/invocation gates и exhaustive parity evidence для P5–P7/FOREMAN reconcile · Границы: не меняет permissions/deployment/analytics, bootstrap root adapters, FOREMAN или fleet targets.

**Entry gate:** P4.1 не начинается, пока P0.3/P0.4, P1.1–P1.4, P2.1–P2.4 и
P3.1–P3.5 не терминальны; пять входных contracts не frozen v1.0.0; P3 conformance не
доказывает publication path для task adapters. Draft placeholders, текущий handoff syntax
и untracked root `.agents/skills` не являются API/release evidence. RAG:— (repo-grounded:
`research/08-p4-task-command-routing-design.md`, D11/D12/D19–D23)
