## Synthesis

P5.1 remains one bounded additive audit feature. The failed bundle is repaired by replacing its
prose placeholder with exact repository paths; no runtime output or host transcript becomes a
portable input. The live scan changed in size but not in decision value: the debt subset still has
no positive direct-call evidence, so the item must deliver an honest queue rather than content
rewrites.

The implementation boundary is deliberately asymmetric. Bucket-audit parses the ratchet as data
and fail-closes its filtered projection on missing files, malformed/duplicate rows or keys absent
from the current registry. It does not decide whether a description now satisfies the trigger
formula: `validate.sh` already owns that regex and its stale-by-trigger diagnostic, and package
validation remains the integration gate. This avoids a second trigger policy while keeping the
queue deterministic.

The existing per-skill `tier0`, `loaded_count` and `channel` fields remain compatible. The new
contract derives evidence class and priority from those fields, reports denominator and coverage,
and uses stable score/evidence/key ordering. Human and JSON `--description-debt` outputs are
read-only projections of the same joined rows. Current bucket-audit help, the skill taxonomy and
the root changelog are the sufficient documentation surfaces. The large
`bucket-audit-2026-07.md` file remains a historical evidence snapshot and is not pulled into this
narrow item's execution context.
