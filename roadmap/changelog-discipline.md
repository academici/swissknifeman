# Roadmap: changelog-discipline — CHANGELOG заполняется всегда, а не иногда

**Статус:** ⬜ к внедрению (идея Owner 2026-07-10).
**Дом:** скилл `oss-dev/release-engineering` (канон уже есть) + commit-гейт `harness`
(прецедент git-гейта SKM-AUDIT-004 P7.4) + возможная команда `skm release`.

## Проблема (наблюдение Owner)

Корневой `CHANGELOG.md` заполняется нерегулярно — дисциплина держится на памяти сессии.
Скилл `release-engineering` (SemVer, CHANGELOG, release notes) существует, но активируется
только на релизных задачах; в повседневных коммитах запись в `[Unreleased]` пропускается.

## Правила (проект решения)

**Для пакетов (SemVer-строгие):**
1. Классификация изменений — из conventional commits: `fix:` → patch, `feat:` → minor;
   **major — всегда решение владельца вручную** (breaking не выводится автоматикой).
2. Каждый содержательный коммит обязан оставить строку в `[Unreleased]` соответствующей
   группы (Added/Changed/Fixed/…) — enforcement, не пожелание: PostToolUse/PreToolUse
   commit-гейт (прецедент P7.4) предупреждает, если дифф содержательный, а CHANGELOG
   не тронут; `|| skip`-маркер для осознанных исключений (docs-only, chore).
3. Релиз = систематизация `[Unreleased]` → версия с датой + сводное описание + тег
   (конвейер уже описан в release-engineering; добавить механизацию `skm release`,
   прецедент паспорта релиза findings/P5-release.md SKM-AUDIT-004).

**Для проектов (без SemVer):**
4. Компактные записи + **ссылка на коммит** в каждой строке (GitHub-стиль:
   `- краткое описание ([abc1234](…/commit/abc1234))`) — потом систематизируются в
   общее описание и релизятся батчем.
5. Формат единый — Keep a Changelog структура, RU-язык записей (writing-style).

## Реализация

- Правка `release-engineering` (секция «повседневная дисциплина», не только релиз).
- Хук-гейт в `harness` (содержательный дифф без правки CHANGELOG → warning в контекст
  модели, не блок).
- Опционально `skm release` — сборка версии из `[Unreleased]` + conventional commits.

## Критерий внедрения

Вместе с пакетом SKM-плана оркестрации/дисциплины (settings-doctor, workflow-craft,
wf-status, ephemeral-дисциплина, plan-homes) — трогает те же слои (скиллы + harness-хуки).

## Источник

Наблюдение Owner 2026-07-10: «CHANGELOG в корне не всегда заполняется; пакетам — чёткая
patch/minor/major стратегия (major вручную), проектам — компактные записи со ссылками на
