## §1. P8.1 — `closure/Pn.json`: отчёт закрытия фазы с классом свидетельства

Образец — `evals/m5a/results/synthetic-20260711T105905Z.json` (финдинг §5.2): гейты с
классом (`PASS_SYNTHETIC` vs `PENDING_USER_PILOT`), метрики с `label`, `limitations[]`,
`external_side_effects: []`, хеши входов. Наш аналог — один файл на фазу.

**Дом:** `plans/<PLAN-ID>/closure/<Pn>.json` (новый опциональный каталог раскладки 2.0,
рядом с `findings/`/`research/`; судьба при архивации — остаётся в архиве, как `findings/`).

**Схема v1** (ключи фиксированы; отсутствие ключа = ошибка схемы, а не «нет данных» —
«нет данных» выражается значением):

```json
{
  "schema_version": 1,
  "plan": "2026.07.25-ECO-OPT",
  "phase": "P8",
  "closed_at": "2026-07-30",
  "closed_by": {"command": "plan-close", "actor": "sonnet/low"},
  "phase_status": "🟢 Done",
  "git": {"head_sha": "<40 hex>", "branch": "<ветка>", "dirty": false},
  "inputs_sha256": {"plan.md": "<64 hex>", "phases/P8.md": "<64 hex>"},
  "items": [
    {"id": "P8.7", "status": "🟢 Done", "evidence_class": "real",
     "evidence": "PYTHONPATH=. python3 -m unittest core.tests.test_io -v — 9 passed (на <sha>)"}
  ],
  "gates": [
    {"id": "validate.sh:task", "status": "PASS", "evidence_class": "real",
     "evidence": "bash packages/task/scripts/validate.sh — exit 0 (на <sha>)"},
    {"id": "fleet-adoption", "status": "PENDING", "evidence_class": "baseline_pending",
     "evidence": "ни один живой план кроме ECO-OPT не включил Closure Protocol v1"}
  ],
  "metrics": [
    {"name": "lint_new_from_closure", "value": "0", "label": "real"},
    {"name": "docs_impact_blocked_changes", "value": "0", "label": "baseline_pending"}
  ],
  "limitations": ["<честное ограничение сдачи>"],
  "external_side_effects": []
}
```

**Класс свидетельства — enum РОВНО из трёх** (дословно из контракт-блока):
`real` (прогон на закоммиченном дереве, evidence несёт команду и число) ·
`synthetic` (фикстура/один кейс — evidence обязан это называть) ·
`baseline_pending` (числа нет; **вместо пропуска строки** — явная запись с причиной).
Запрет, ради которого приём и берётся: отсутствующее число НЕ выражается отсутствием ключа.

**Активация (аддитивность).** Всё поведение включается одним opt-in полем в `## 0. Meta`
плана: `Closure Protocol | v1` (замер 6 — лишние Meta-поля легальны). Плана без поля гейты
не касаются; **закрытые записи не переписываются никогда**. Этот план (`ECO-OPT`) получает
поле в рамках P8.1 — dogfood; включение у `2026.07.24-AGENT-RELIABILITY` и
`2026.07.18-FOREMAN` — решение владельца, не побочный эффект item'а.

**Потребители (условие DoR — §6.1 `research/09`; иначе «provenance theatre», §9.6 финдинга):**

| Потребитель | Что читает | Что делает |
|:--|:--|:--|
| `plan_lint.py` (машинный, детерминированный) | `closure/<Pn>.json` + `## Phase Status` + Status Board | схема; `items[]` ↔ таблица фазы (id/статус) без расхождений; `phase_status` ↔ строка Status Board; `evidence_class: real` при пустом `evidence` = ERROR с именем item'а/гейта; фаза терминальна при `Closure Protocol: v1`, а файла нет = ERROR с именем ожидаемого пути |
| `plan-audit <ID> Pn` (семантический) | тот же файл — **первым входом** ступени 1 | перепрогоняет команды из `evidence` на `git.head_sha`; расхождение с заявленным классом = находка Major; `inputs_sha256["phases/Pn.md"]` ≠ текущему хешу ⇒ ТЗ фазы правился после закрытия — проверить, не съехал ли scope |
| `plan-close <ID> Pn` (писатель) | — | собирает файл механически из полей items (шаг 4a), НЕ прозой |

Хеши имеют названного потребителя (строка выше) — иначе по рамке переноса их писать нельзя.

**Границы:** `preflight_record`/`operation_key` (приём B2) в P8 НЕ входит — отложен D41;
closure-отчёт берёт от него только идею «редактированная запись с хешами входов», без
хеширования дерева (полевая цена O(N²), §8.3).

## §2. P8.2 — `Consequences` в D-записи

**Носитель — инлайн-подполе внутри ячейки `Решение`**, литерал `**Consequences:**`.
Пятая колонка отклонена замером 7: шапка `D# | Дата | Решение | Почему` — байт-в-байт
литерал реестра `CANON_LITERALS` с i18n-директивой и тестом; её правка = переписывание
шапки во всех планах флота, то есть прямое нарушение аддитивности. Форма уже обкатана
вручную — D40/D41 этого плана несут `**Consequences:**` внутри ячейки.

**Гейт (при `Closure Protocol: v1`):** ERROR, если ячейка `Решение` D-записи содержит
маркер отмены/замены решения (`supersedes D`, `отменён`, `отменяет D`) и НЕ содержит
`**Consequences:**`. Литерал уходит в `CANON_LITERALS` + `<!-- i18n-keep: **Consequences:** -->`
в `SKILL.ru.md` (иначе красный `tests/test_canon_literals.py`).

**Честная граница гейта, которую item обязан назвать вслух:** канон требует `Consequences`
у КАЖДОЙ несущей D-записи, а машина ловит только машинно-детектируемый подкласс
(отмена/замена). Выдавать гейт за полное покрытие запрещено — это ровно тот «формализм
галочки», который §9.4 финдинга называет деградацией docs-гейтов.

**Словарь зрелости возможности** (второй половина приёма C2 — «статусы плана описывают
item, а не зрелость возможности»). Enum РОВНО из пяти, латиницей, байт-в-байт:

| Значение | Что означает | Что НЕ означает |
|:--|:--|:--|
| `available` | есть команда/поверхность И есть свидетельство работы (тест/прогон) | — |
| `experimental` | работает на нашем стенде, контракт может измениться | «готово» |
| `behind-gate` | код есть, включается флагом/решением владельца | «включено» |
| `disabled` | в дереве есть, в поставке выключено, причина названа | «сломано» |
| `superseded` | заменено другим механизмом, живёт для обратной совместимости | «удалено» |

SSOT словаря — скилл `plan-protocol` §6 (рядом с шестью статусами, отдельным абзацем
«зрелость возможности ≠ статус item'а»). Потребитель — матрица P8.5 и её проверялка
(`scripts/status-check.py` держит зеркало enum'а с комментарием синхрона — осознанный дубль
по образцу `validate.sh` ↔ `core.project.PROJECT_TYPES`).

## §3. P8.3 — `CHECKPOINTED`: отказ несёт точную команду возобновления

Приём B3: поверхность без права записи возвращает не «сделано» и не «пропущено», а
состояние + **точную локальную команду** продолжения (финдинг §2.1: `next_command`).

**Носитель — строка `Возобновление: <точная команда>` в поле `Pending Work` item'а.**
Отклонено (замер 8): (а) седьмой статус — шесть статусов байт-в-байт читают
`plan_lint.STATUSES`, `TERMINAL_STATUSES` и cross-plan-гейт `plans/cross-plan-files.py:33`,
это контракт трёх живых планов; (б) семнадцатое поле item'а — `REQUIRED_ITEM_FIELDS`
проверяется у каждого item'а каждого плана флота, новое поле мгновенно делает их невалидными.

**Гейт (при `Closure Protocol: v1`):**

| Статус item'а | Требование к `Pending Work` | Диагностика при нарушении |
|:--|:--|:--|
| `🔴 Blocked` | строка `Возобновление: <команда>` — непустая команда | ERROR: «<Pn.m> 🔴 Blocked без строки `Возобновление:` — отказ обязан нести точную команду продолжения, а не «пропущено»» |
| `⛔ Skipped by decision` | `Возобновление: —` И ссылка `D<номер>` в том же поле | ERROR с именем item'а и напоминанием, что решение о пропуске обязано быть предъявлено D-записью |
| остальные | требований нет | — |

Литерал `Возобновление:` → `CANON_LITERALS` + i18n-директива (кириллица — обязательно).

**Разграничение с существующей формой `waiting:`/`ОЖИДАНИЕ:`** (handoff §8): та про
**шаг плана**, который реален, но неисполним сейчас (тайм-гейт); `Возобновление:` — про
**item**, который исполнитель не смог закрыть. Два механизма для одного случая не заводятся:
у `waiting:` носитель — `handoff.Next`, у `Возобновление:` — `Pending Work` item'а.

Писатели, которых надо научить: `plan-exec.md` (ставит статус 🔴), `plan-close.md`
(реконсиляция item'а, шаг 4 — «Нет подтверждения … оставь/верни 🟡/🔴»).

## §4. P8.4 — docs-impact гейт (пакет-скоуп + escape hatch с причиной)

Приём D1 с **сужением** (§9.4: «любой .md засчитан» деградирует; наш зачёт — по пакету).

**Поверхности (изменение требует правки доков):**

| Класс | Пути | Зачёт даёт правка |
|:--|:--|:--|
| пакет | `packages/<pkg>/{bin,lib,commands,configs}/**` | `packages/<pkg>/docs/**` |
| общий | `core/**.py` | `docs/core/**` |
| зонтик | `bin/**`, `install.sh`, `scripts/*.{sh,py}` | `docs/*.md` (`develop.md`/`deploy.md`/`index.md`/`control-surface.md`/`routing.md`) |

Зачёт считается **по своему классу**: правка доков harness не закрывает изменение в maind.
`docs/{skiller,harness,maind,analyst}/**` в зачёт НЕ входит — это gitignored сборочные копии
(замер 10); источник истины — `packages/<pkg>/docs/**`.

**НЕ поверхности (осознанные исключения, каждое с причиной):** `**/tests/**` и
`scripts/test-*.py` (тесты доков не требуют) · `plans/**` (плановая бухгалтерия) ·
`.github/**` · `**/*.md` (доки сами) · `CHANGELOG.md` · `packages/skiller/skills/**`
(канон скилла — сам скилл; его карта генерируется `skiller registry`, отдельного докописания
не требует) · генерируемые артефакты (`skills.json`, `skills/_index.md`,
`.claude-plugin/marketplace.json`, `docs/guide/{graph,budget}.md`).

**Escape hatch с причиной** (как в исходнике, финдинг §7.1): переменная
`DOCS_NOT_NEEDED="<причина>"` либо файл `.docs-not-needed` с непустым текстом; причина
**печатается** в отчёт гейта. Пустая причина обходом не считается.

**Дом обязательности — CI, не pre-commit** (`research/09` §5 + §9.3: соло-режим ⇒ рост
трения и обход `--no-verify`). Интерфейс: `python3 scripts/docs-impact.py --base <ref>`
(в CI — `--base` от базы PR), локально `--staged`. Выход: 0 — ок; 1 — список затронутых
поверхностей + какие доки ждались (каждая строка называет объект и причину; сплошного
обхода дерева нет — читается только `git diff --name-only`).

## §5. P8.5 — матрица возможностей с Evidence/boundary

Приём D3 (`docs/STATUS.md` исходника, финдинг §7): столбец «Evidence / boundary» + раздел
«Known limitations» с прямой фразой «видимая CLI-группа не доказывает, что её рантайм включён».

**Файл — `docs/status.md`** (зонтичный, отслеживаемый; попадает в nav
`docs/.vitepress/config.mts` — иначе страница-сирота).

**Форма таблицы:** `| Пакет | Возможность | Зрелость | Evidence / boundary |`, где
`Зрелость` — значение словаря §2 байт-в-байт, а `Evidence / boundary` — либо
воспроизводимое доказательство (команда/тест/артефакт), либо честно названная граница
(«есть команда, рантайм требует внешнего процесса X»). Пустой Evidence запрещён.

**Проверялка `scripts/status-check.py`** (детерминированная, stdlib): значение `Зрелость`
в enum · `Evidence / boundary` непуст · `Пакет` существует на диске (`packages/<pkg>` либо
`core`) · нет дублей `(Пакет, Возможность)` · нет строк-заглушек (`TODO`, `—` в Evidence).

**Граница item'а:** сверка матрицы с ЖИВЫМИ контрактами (все ли CLI-группы перечислены —
приём D2, `coverage_check.py`) в P8 НЕ входит (D41, M на грани L). Это значит: матрица
ловит нечестную зрелость, но не ловит **пропущенную** возможность. Сказать это в самой
странице — иначе получится «полная карта», которой она не является.

## §6. P8.6 — CI-гигиена: запрещённые пути/суффиксы + тег = версия

Приёмы D4 + F4, оба — дешёвая мелочь, у обоих сегодня в репо есть **правило прозой и нет
гейта**.

**`scripts/public-hygiene.py`** — fail-closed по отслеживаемому дереву (`git ls-files`,
не обход ФС):
запрещённые суффиксы `.sqlite`, `.sqlite3`, `.db`, `.log`, `.pem`, `.key`, `.p12`, `.zip`,

Отчёт называет КАЖДЫЙ путь и правило, по которому он запрещён (полевой контрпример

самодостаточен.

**`scripts/verify-tag.py <tag>`** — тег `vX.Y.Z` обязан иметь в root `CHANGELOG.md`

выпущенных (`[Unreleased]` не считается). Носитель версии зонтика — CHANGELOG, а не
`package.json`: корневого `package.json` нет, версии в `packages/*/package.json` —
пакетные (замер 9).

**CI:** новый workflow `.github/workflows/hygiene.yml`. Job `hygiene` (push/PR) —
docs-impact (P8.4), status-check (P8.5), public-hygiene (P8.6); job `release-tag`
(`on: push: tags: ['v*']`) — verify-tag. Файл создаёт **P8.4** (первый по порядку),
P8.5 и P8.6 дописывают свои шаги — конфликт разрешается порядком, не мержем (§11).

## §7. P8.7 — `core/io.py`: проверка цели перед атомарной заменой

Приём F5 (финдинг §2.6: `derived.py` — 37 строк, «не symlink, регулярный файл,
`st_nlink == 1`»).

**Контракт:** `assert_safe_replace_target(path)` — при существующей цели: `path.is_symlink()`
⇒ отказ; не регулярный файл (каталог/FIFO/устройство) ⇒ отказ; `st_nlink != 1` ⇒ отказ.
Несуществующая цель — норма (обычный первый write). Отказ — исключение с текстом, называющим
**объект и причину** («`<path>` — символьная ссылка: атомарная замена подменила бы ссылку,
а не файл»).

**Точка вызова:** `atomic_write_text` перед `os.replace` (`core/io.py:117`) ⇒ `atomic_write_json`
получает проверку транзитивно. Параметр отключения `check_target=True` — по умолчанию
включён; отключение легально только с комментарием на месте вызова (нам сегодня не нужно:
отслеживаемых симлинков в дереве нет, замер 5).

**Дедуп, а не новая идея:** тот же инвариант руками написан в
`packages/maind/lib/maind/provider_deploy.py:176,220,346`. Перевод этих мест на хелпер в P8.7
НЕ входит (чужая поверхность, отдельная Validation) — кандидат roadmap; сам факт дубля
фиксируется в докстринге хелпера, чтобы связь не потерялась.

## §8. P8.8 — `validate.sh`: секции тела, анти-дублирование проекции, полнота pressure

Приёмы A1 + E3 дельтой. Все три проверки — в существующий heredoc
`packages/skiller/scripts/validate.sh` (stdlib-python внутри bash, без новых файлов кода).

**(1) Обязательные секции тела — только CORE-девятка, с рэтчетом.** Сплошной гейт неисполним
(замер 1: максимум 83/160). Правило: для скиллов из `configs/core-policy.json::skills`
(9 шт., резидентны в каждом проекте) тело обязано нести
(а) **активационную** секцию — заголовок `##`, матчащий `(?i)^\s*\d*\.?\s*(when\b|activate\b)`;
(б) **секцию ссылок** — заголовок из `{Links, References, Related skills, Related}`.
(б) включается сразу ERROR — долга нет (9/9 проходят). (а) — ERROR с рэтчетом
`packages/skiller/scripts/skill-sections-burndown.txt` (стартовые три строки:
`general/context-economy`, `general/compact-responses`, `research/query-craft`), механика
дословно как у `desc-burndown.txt` (`validate.sh:94-110,296-306`), включая гейт **протухшей
записи**: скилл уже несёт секцию ⇒ строку убрать.

**(2) Тонкая проекция не дублирует канон.** Гейт стоит на артефакте
`2026.07.24-AGENT-RELIABILITY` P1.2/P1.5 (замер 12: сегодня проекции — полные копии
55–321 строк). Пары «проекция ↔ канон» берутся из объявленного источника
(`packages/skiller/adapters/repository-bootstrap/publication-lock.json`, при его отсутствии —
`configs/repository-bootstrap-skills.json`), не угадываются. Проверки на каждую проекцию
`.claude/skills/<n>/SKILL.md` и `.agents/skills/<n>/SKILL.md`:
(а) тело ≤ `PROJECTION_MAX_BODY_LINES = 15` непустых строк;
(б) есть ссылка на путь канона;
(в) ни один заголовок `##` канона не воспроизведён в проекции (это и есть «дублирование»).
**Fail-closed без ложных срабатываний:** проекции есть, а объявленного источника пар нет ⇒
ERROR с именем ожидаемого файла (состояние противоречиво); ни проекций, ни источника ⇒
проверка молча пропускается (standalone-раскладка пакета).

## §11. Pre-mortem: «через 6–12 месяцев P8 провалилась — почему»

Фаза меняет формат закрытия для всех живых планов ⇒ high-stakes по критерию «ядро
экосистемы». Независимые причины провала и митигации:

1. **Closure-отчёт стал ритуалом.** Его пишут, но никто не перепрогоняет evidence ⇒
   «provenance theatre» (§9.6). *Митигация:* потребитель назван и исполняется машиной
   (`plan_lint`), а не только человеком; `evidence_class: real` без `evidence` = ERROR.
2. **Гейты подняли трение, и их обходят.** *Митигация:* обязательность только в CI
   (не pre-commit); escape hatch docs-гейта с печатаемой причиной; гейт секций — рэтчетом,
   а не «покрасить сотню скиллов».
3. **Аддитивность нарушена на практике:** кто-то включил `Closure Protocol: v1` у
   AGENT-RELIABILITY в середине exec'а, и его закрытые фазы стали красными. *Митигация:*
   гейт «файла нет» срабатывает только на фазы, закрываемые ПОСЛЕ включения (сравнение
   `closed_at` фазы отсутствует — поэтому правило проще и жёстче: включать поле только на
   плане, у которого нет терминальных фаз, ИЛИ одновременно дописать closure-файлы уже
   закрытым фазам; выбор — за владельцем, item фиксирует оба пути в докстринге канона).
4. **Три items правят те же файлы, что чужой план, и ловят конфликт мержем.** *Митигация:*
   cross-plan-гейт + порядок §10 + `plans/cross-plan-files.py --strict` перед каждым item'ом.
5. **Гейт проекций написан против формата, который чужой план потом изменил.** *Митигация:*
   пары берутся из объявленного лока, а не из угадывания путей; отсутствие лока = ERROR,
   а не тихий зелёный.
6. **Словарь зрелости разъехался между скиллом и проверялкой.** *Митигация:* зеркало с
   комментарием синхрона + `status-check.py` падает на неизвестном значении (расхождение
   проявляется первым же красным CI, а не тихо).
