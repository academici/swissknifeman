# P0.6 cold-start blocked by uncommitted predecessor handoff

## Verdict

`2026.08.02-PROVIDER-CONTRACT-LOCALE P0.6` cannot execute from the current tree. The
repository `HEAD` is `39fe0ea68124af3784ae0b772240d5b1dcb0ffbe` (`P0.5` item commit),
while the terminal `P0.5` state/bookkeeping and the `P0.6` executable specification are
not tracked by that commit.

This violates the repository cold-start invariant that the next executable item starts
from its predecessor's committed handoff. It also makes the generated `P0.6` bundle a
digest over uncommitted inputs rather than committed, tree-anchored evidence.

The mandatory pre-mutation Task Contract call returned `pre_mutation=allow` before
`bundles/P0.6.json` existed. The owning bundle `--check` independently failed with
`view missing or unreadable`. This is a false-positive compiler/gate boundary and must be
repaired at the Task Contract or bundle-admission owner rather than treated as evidence that
the cold start was complete.

## Evidence

The following read-only checks were run from the repository root:

```text
git rev-parse HEAD
git show -s --format='%H %s' HEAD
git ls-files --error-unmatch plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/phases/P0/P0.5.state.md
git ls-files --error-unmatch plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/phases/P0/P0.6.md
git ls-files --error-unmatch plans/2026.08.02-PROVIDER-CONTRACT-LOCALE/bundles/P0.6.json
git status --short -- plans/2026.08.02-PROVIDER-CONTRACT-LOCALE
```

All three `git ls-files --error-unmatch` checks failed. The status output shows the
predecessor bookkeeping/specification carriers as untracked or modified. No product or
contract bytes were changed during the blocked `P0.6` attempt.

The additional gate checks were:

```text
task.task_contract.build(..., actual_route=frontier/high) -> pre_mutation=allow
plan-views.py bundle --item P0.6 --check -> view missing or unreadable
```

## Remediation

Reconcile and commit `P0.5` bookkeeping first:

```text
$ task:plan-close 2026.08.02-PROVIDER-CONTRACT-LOCALE P0.5
```

After that close produces a committed handoff and the generated `P0.6` bundle passes
`--check` against the committed tree, resume `P0.6` with `task:plan-run` under
`frontier/high`.
