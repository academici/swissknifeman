# P4 — Канон планов: репо-дом, имена, дом workflow-скриптов

## Phase Context

Фаза правит SSOT плановой системы — скилл `general/plan-protocol` и валидатор
`packages/task/lib/task/plan_lint.py` — ОДНИМ заходом, чтобы не перекатывать канон дважды (D2).
Сливаются две спеки: `roadmap/plan-homes.md` (репо-дом планов по умолчанию вместо vault; ось
видимости `visibility:` для публичных OSS-репо; канон имён с полем `supersedes:` и архивом
предшественника; доставка схемы компактной скилл-картой ≤50 строк + секции CLAUDE.md обоих
контекстов) и `roadmap/workflow-craft.md` ч.1.6 (единственный дом workflow-скриптов —
`plans/<ID>/workflows/`, имя `wf-<кодовое-имя-lower>-<назначение>.js`, наличие скрипта — часть DoR
фазы исполнения плана с ЗАЯВЛЕННОЙ оркестрацией).
Оба изменения — публичный контракт протокола для всей экосистемы, потому дизайн-items идут на
opus/high (см. `## 3. Routing`), а `plan_lint` и скилл правятся СИНХРОННО: расхождение валидатора
и SSOT — известный класс дефекта (CLAUDE.md пакета task). Скилл — двуязычный: источник
`SKILL.ru.md`, `SKILL.md` регенерируется (ручная правка EN = дефект). Все новые lint-проверки —
warning-only (канон 2.0 `plan_lint.py`): существующие планы (`SKM-ROADMAP-005`, `SKM-AUDIT-004`)
НЕ ломаются, `validate.sh` остаётся зелёным (он падает только на ERROR, не на WARNING).
**Формат имени плана — `<ГГГГ>.<ММ>.<ДД>-<КОДОВОЕ-ИМЯ>`** (напр. `2026.07.10-SETTINGS-DOCTOR`,
D16): датовый префикс даёт хронологическую сортировку `plans/` и ориентацию «когда» без чтения
Meta. Старый паттерн `[A-Z][A-Z0-9-]+` остаётся валидным (back-compat, D24), существующие планы НЕ
переименовываются. Миграция только вперёд: терминальные уходят в архив по мере закрытия.
Фаза закрыта, когда канон описан в скилле, линтер его проверяет (warning-уровень), скилл-карта
`ecosystem-map` заведена и секции CLAUDE.md раскатаны в обоих контекстах.

**Scope Included (фаза):** репо-дом плана по умолчанию + поля Meta `visibility`/`supersedes` +
датовый канон ID (D16/D24) в `plan-protocol` (§2/§4/§12 + snippet `plan-template.md`) · раздел
`plans/<ID>/workflows/` и канон имён скриптов в `plan-protocol` (§2) · lint-правила `plan_lint.py`
(регулярка ID с back-compat · warning неканоничного места/имени workflow-скрипта · warning
`supersedes`-преемственности по совпадению кодового имени с архивным) · компактная скилл-карта
`ecosystem-map` (бакет `axioma`, ≤50 строк, указатели вместо копий) · секции «документация и
планы» в CLAUDE.md обоих контекстов (vault + монорепо) · DoR-клауза «готовый workflow для фаз с
заявленной оркестрацией» в §7 скилла + парная warning-проверка `plan_lint` · статусные строки
`roadmap/README.md` + корневой `CHANGELOG.md`.

**Scope Excluded (фаза):** переименование существующих планов (D16 — миграция только вперёд) ·
построение maind-провижионера `plans-doc` для авто-раскатки блока CLAUDE.md во ФЛОТ (D30 —
отдельная maind-инфра, не измеренная в этом плане; блок доставляется существующим каналом
managed-block по мере его провижининга) · часть 2 `workflow-craft.md` (fleet-синтез скриптов —
D1) · копирование канона `plan-protocol` внутрь скилл-карты (карта — указатель, не энциклопедия) ·
исполнение массивного мультиагентного workflow как обязательного для ЛЮБОГО 2+-фазного плана (D29 —
ручное item-by-item исполнение workflow не требует; условие применяется только к фазам с заявленной
оркестрацией) · правка самого Workflow-тула Claude Code (вне репо) · ERROR-уровень для любой новой
проверки (все — warning, back-compat).
