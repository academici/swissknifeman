# analyst — continuous learning ecosystems academici

Deterministic (stdlib-only, **on-demand — without daemon**) layer that accumulates
«hard-won lessons» from task threads Claude Code for all ecosystem projects at once and -
**with a man at the gate** — turns them into reusable knowledge (memory mAInd → skills).
Not a separate analyzer in each project, but ONE layer on top of many packages and projects.

> Implemented circuit: **P1 (MVP)** — `digest` + lessons-store + human `review`/`promote`;
> **P2** — cross-project aggregator `scan`; **P3** — confidence-arithmetic (Beta/decay) +
> numeric state-machine `recompute` + mem0-taxonomy; **P4** — `suggest` → DRAFT skill
> (`SKILL.ru.md` in staging, promoter - person). Further on roadmap: `analyst-capture` + `observe.sh` (P5).
>
> 📖 Documentation: [`docs/`](docs/) (VitePress — standalone + umbrella unit).

## Why is this so (anti-collapse)

Naive «self-learning» calls *model collapse*. Proven antidote - **self-verification**
+ **never throw away ground-truth** (human-verified anchors). Therefore human-gate +
provenance + validate-before-promote — is not caution, but a sufficient condition against degradation.

## Data flow (MVP)

```
<project>/.claude/runs/<sid>.json          (run-report — writes SessionEnd-hook harness)
   │  analyst digest → deterministic candidate extraction (high-precision signals)
   ▼
<project>/.claude/analyst/lessons/{ephemeral,candidate,curated,deprecated}/<id>.json  (LOCAL)
<project>/.claude/analyst/audit.ndjson     (append-only provenance)
   │  analyst review  → list + diff against active (Jaccard, stdlib)
   │  analyst promote <id>  → MAN confirms → state++ → audit
   ▼  (curated) → maind memory → pops up on SessionStart (memory-digest-hook)
```

**Privacy invariant:** raw materials (raw-transcript) — LOCAL-only; goes out only
abstract lesson (trigger+action+evidence). Secrets are by reference only, never by value.

## Commands

```bash
analyst digest    [--cwd | --session UUID]      # run-report → candidates for ephemeral/
analyst review    [--state ephemeral|candidate|curated] [--json]
analyst promote   <id> [--to candidate|curated] [--yes]   # human-gate; curated → memory mAInd
analyst deprecate <id>                          # soft-demo (not deleted - audit)
analyst doctor                                  # environment diagnostics
analyst workflow-scan --output DIR --now ISO    # read-only workflow fleet evidence
```

## Configuration

Nine thresholds are settings (the model parameters of `confidence.py` stay in the code). They are read through
`aicore.config`; the schema is `configs/config.schema.json` and every key is listed, commented out, in
`config.example.toml` (generated by `aicore config example packages/analyst --write`; do not edit by hand).

| Key | Default | Meaning |
|:--|:--|:--|
| `recompute.candidate_min_n` | 15 | observations to promote ephemeral → candidate (adaptive for low-activity projects) |
| `recompute.candidate_min_conf` | 0.6 | confidence for that promotion |
| `recompute.curated_min_n` | 50 | observations after which a candidate is flagged ready for curated |
| `recompute.curated_min_conf` | 0.8 | confidence for that flag |
| `recompute.curated_min_passrate` | 0.95 | share of passing tests for that flag |
| `recompute.deprecate_conf` | 0.6 | confidence below which a candidate is deprecated / a curated lesson is flagged |
| `recompute.candidate_min_n_floor` | 3 | lowest adaptive candidate threshold |
| `digest.pathology_window` | 5 | latest runs inspected for a recurring pathology |
| `digest.pathology_min_hits` | 2 | runs of the window that must show the code |

Layers, lowest to highest: the schema defaults, the machine file (`~/.config/swissknifeman/config.toml`), the
project file (`<project>/.swissknifeman/config.toml`, under `[analyst]`), the environment
(`SKM_ANALYST_RECOMPUTE__CANDIDATE_MIN_N=7`), and `--config FILE`. Without any file the behaviour is unchanged.

```bash
swissknifeman config set analyst.recompute.candidate_min_n 20 --project
swissknifeman config explain analyst recompute.candidate_min_n   # value, layer, file:line, what it overrides
```

An invalid value stops the command with the file and line. The cross-project state (`scan`, `suggest`, proposals)
lives in the `analyst` folder of the machine state directory (`~/.local/state/swissknifeman/analyst`, or under
`SKM_HOME`); a folder left at `~/.swissknifeman/analyst` is still read, with one warning, until it is moved.
Documentation that says `<state>` means that directory.

## Skills

The plugin ships the skill `session-observer` (analysis of a finished session). It lives in
`packages/analyst/skills/` and is released with the module.
A project gets them through the `system` bucket of `skiller`: `skiller connect` enables the plugin `analyst` and
`skiller sync` copies the skills into the project; the plugin can also be installed on its own.
