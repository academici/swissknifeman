### P1.3 — Session continuity controller

**Intent:** Make one provider-neutral controller choose and persist `continue-root`, `isolated-child-return` or `cold-start-root` for every runnable continuation, with a reason/evidence gate for the non-default outcomes. RAG:— (repo-grounded: artifacts/source-roadmap/2026.08.15-owner-decision-same-session-continuity.md:68-120).
**Why:** The decision queue already returns `resume-root`, but `PlanNextCarrier` and the Codex launcher can still erase that meaning and manufacture a fresh process, losing loaded evidence without adding capability or independence. RAG:— (repo-grounded: artifacts/source-roadmap/2026.08.15-owner-decision-same-session-continuity.md:29-40; packages/task/lib/task/command_render.py:106-169).
**Scope Included:** `session-work-estimate/v1` and `session-continuity-decision/v1` schemas/reducer; lifecycle, route/capability, context-health, remaining P1.2 batch, loaded-input reuse and cold-start-cost inputs; default `continue-root`; exact canonical cold-start reasons; isolated-review path; DecisionRequest `resume-root` preservation; renderer, handoff/lint and delivery receipt consumption; deterministic fixtures for compatible, insufficient, owner-wait and independent-boundary cases.
**Scope Excluded:** Building a provider UI card/modal; claiming control over an external conversational final write-site; weakening durable DecisionRequest authorization; self-attested route/context sufficiency; heuristic cold start because an item/turn ended; changing P4 terminal transcript scope.

**Implementation Rules:** The reducer accepts only provider-attested route/context inputs and the digest-bound remaining batch from P1.2. `continue-root` is the default for active compatible work and unavailable context telemetry; `cold-start-root` requires exactly one canonical hard-boundary reason and a durable checkpoint; `isolated-child-return` requires a bounded reviewer task that returns evidence to the authoritative root. Renderers and delivery verify the decision rather than choosing again. Preserve `waiting-owner`/`resume-root` identity and do not emit a runnable successor for an unresolved request. RAG:— (repo-grounded: artifacts/source-roadmap/2026.08.15-owner-decision-same-session-continuity.md:102-120,140-159; packages/task/lib/task/plan_requests.py:553-563).
**Code Guidance:** Model the controller as a small pure reducer plus schema validation; keep transport adapters additive. Test order-sensitive cases: compatible route + telemetry unavailable stays in root; insufficient attested context permits a cold start only after checkpoint; missing reason/evidence rejects; waiting owner yields no launch; design/audit terminal boundaries keep their mandated cold start; isolated review cannot become the new root. Never use command name alone, status prose, cost preference or a failed validation as a cold-start reason. Do not implement the provider UI/final bridge here; expose a typed integration result for P4.
