# P7.2 live-preflight remediation design

**Scope:** design only for `P7.2`; no package source, live target, FOREMAN, fleet, tag or
push changes are authorized by this record.

## Observed facts

1. The live `.codex/hooks.json` is tracked and contains the P6 memory SessionStart command,
   but there is no `.swissknifeman/provider-artifacts.lock.json` record for it.
2. P5's `harness.codex.lifecycle.hooks` renders the same path as a whole-file artifact;
   P2 classifies the existing bytes as `ownership-conflict` and both normal and explicit
   repair correctly refuse before write.
3. The corresponding `harness.codex.lifecycle.handler` is missing. It cannot be created
   independently while its registration has refused.
4. P6's live `maind sync --project swissknifeman --dry-run` reaches the same P2 deployment
   gate and returns `MAIND_PROVIDER_DEPLOY_REFUSED` for MCP. The temporary P6 conformance
   is not a valid ownership record for the live root.

## Non-options

- Do not delete, overwrite or retroactively lock `.codex/hooks.json` from P7.2.
- Do not use `--repair` to turn an `ownership-conflict` into a managed artifact.
- Do not put P6 memory semantics in a P5-only renderer or copy a Claude hook into Codex.
- Do not relax P2's fail-closed conflict result, add a global bypass, or treat an Owner D#
  as implicit adoption.

## Required owner decision

The frozen P2/P5/P6 contract needs an explicit, additive migration design before any repair
can execute. The preferred route is a P2 **bootstrap-transfer** operation with all of these
properties:

| Property | Requirement |
|:--|:--|
| Target | Only the exact root `.codex/hooks.json` and missing `.codex/hooks/lifecycle.py`; no user/global/fleet target. |
| Admission | Exact pre-image SHA-256, exact target paths, a named owner D#, and a recoverable backup are mandatory. Any other bytes remain `ownership-conflict`. |
| Composition | A P6-owned caller composes the existing memory hook and P5 lifecycle observer into one native JSON projection; neither provider is translated from Claude bytes. |
| Provenance | One P2 lock transaction records both artifacts, ordered source hashes, source/render hashes and the transfer decision; ordinary update/repair semantics remain unchanged. |
| Validation | First transfer, second no-op, managed-drift refusal + explicit repair, rollback, outside-entry preservation, and P6 MCP live dry-run GREEN. |

This is a contract-minor/public managed-ownership change. Owner approval D103 accepts
this design only; a later D104 must freeze the exact additive contract/API candidate before
package source implementation. The alternative—permanently declaring
Codex lifecycle/MCP unavailable for the self-host root—fails P7.2's required-provider
acceptance and is rejected.

## Approved Owner Decision D103 — bootstrap-transfer design

**Approved design:** Add one narrowly admitted P2 bootstrap-transfer operation. It is
not ordinary `--repair`, does not weaken `ownership-conflict`, and is unavailable without
the exact preimage, target inventory and owner decision below.

| Class | Exact path | Exact action | Constraint |
|:--|:--|:--|:--|
| Live root | `.codex/hooks.json` | Read only during design; after a separately implemented transfer, make one P6-owned native composition of the existing memory `SessionStart` hook and P5 lifecycle observer. | Admission preimage SHA-256 is exactly `7d7538d021228e8e61d124f4b60b6db04434f8121de30b8672f05e4bf038c3db`; capture a recoverable backup before mutation; any different bytes refuse. |
| Live root | `.codex/hooks/lifecycle.py` | Create only as the companion P5 lifecycle handler in the same transaction. | Must be absent before transfer; no independent apply while its registration is refused. |
| Live root | `.swissknifeman/provider-artifacts.lock.json` | Create/update the P2 transaction record for exactly the two artifacts above. | Record D103, preimage/backup, ordered source hashes and render hashes; preserve unrelated records. |
| Owning source (future bounded remediation) | `core/provider_lock.py` | Add the explicit, fail-closed transfer admission and reversible provenance record. | No global adoption/bypass; ordinary create/update/repair behavior unchanged. |
| Owning source (future bounded remediation) | `packages/harness/lib/harness/hooks.py` | Supply P5 lifecycle fragment/handler input to the native composition seam. | It remains a provider-native Codex renderer; no Claude-byte translation. |
| Owning source (future bounded remediation) | `packages/maind/lib/maind/{provider_deploy.py,provision/deploy.py}` | Invoke the P6-owned composition/transfer request and retain refusal on all non-admitted targets. | `MAIND_PROVIDER_DEPLOY_REFUSED` remains the outcome outside the exact D103 admission. |

**Anti-scope:** No other `.codex/**`, `.claude/**`, home/global target, package source
outside the named owners, FOREMAN, fleet, P7.3+, tag or push is authorized. P7.2 itself
does not perform this transfer and remains blocked until the owning remediation is green.

## Approved Owner Decision D104 — implementation freeze

D104 is deliberately separate from D103. Owner approval authorizes source implementation only
for this exact additive candidate; it still does not authorize a live apply, repair or
P7.3+.

| Surface | Candidate frozen semantics |
|:--|:--|
| Artifact contract | Bump `provider-artifact-contract.md` from `1.1.0` to backward-compatible `1.2.0`; add the closed `bootstrap-transfer` admission, never an observation/action replacement. Existing `1.0.0`/`1.1.0` locks and normal plan/apply/repair semantics are byte-compatible. |
| Core API | Add only `BootstrapTransferAdmission` and `plan_bootstrap_transfer(root, expected, *, lock_bytes, admission) -> ArtifactPlan` in `core.provider_lock`; descriptor fields are `decision_id`, `existing_target_path`, `existing_preimage_sha256`, `created_target_path`, `existing_artifact_id`, `created_artifact_id`, and `require_absent_lock=True`. It validates these exact fields before every write. |
| Exact admission | `decision_id == "D104"`; `existing_target_path == ".codex/hooks.json"`; `existing_preimage_sha256 == "sha256:7d7538d021228e8e61d124f4b60b6db04434f8121de30b8672f05e4bf038c3db"`; `created_target_path == ".codex/hooks/lifecycle.py"`; artifact IDs are `harness.codex.lifecycle.hooks` and `harness.codex.lifecycle.handler`; no lock exists before transfer. Any difference refuses without backup, target or lock write. |
| Transaction | The first target is backed up at `.codex/hooks.json.provider-artifact.bootstrap-transfer.bak`; the second target is created; then one canonical P2 lock containing exactly the two records is written. Rollback restores the first target from that backup, removes the transaction-created handler and removes the transaction-created lock only after exact transaction-record verification. |
| Composition | `maind` owns structured native Codex JSON composition: preserve the preimage memory `SessionStart` command exactly and add exactly the P5 observer `SessionStart` command generated by `harness`; duplicate/missing/non-`SessionStart` entries refuse. No string substitution and no Claude byte is an input. |
| No-write/result | `plan`, `doctor`, `dry-run` and every failed admission write nothing. Ordinary `--repair` does not select bootstrap-transfer. `MAIND_PROVIDER_DEPLOY_REFUSED` remains stable for all non-admitted paths/preimages. |

The source file inventory and execution order are exact: P2.6 changes the P2 contract/core
only; P5.8 changes harness lifecycle rendering only after P2.6; P6.7 changes mAInd caller
integration only after P5.8; P6.8 is evidence-only. This is a sequential chain, not parallel
work and not a P7 substitute.

## Proposed execution sequence after approval

1. Reopen the owning P2/P5/P6 remediation scope; freeze the transfer API and exact semantic
   composition in an Owner D#.
2. Implement it with focused `core`, `harness` and `maind` tests and package validations.
3. Independently audit the transfer/rollback contract and commit the repair.
4. Start a fresh `gpt-5.6-terra/high` P7.2 session; repeat its Docker-isolated matrix,
   rollback and live no-write preflight.
5. Only then prepare P7.2's normal exact live path/action inventory and live Owner D#.
