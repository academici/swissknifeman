# P3.1 — fail-closed and projection recovery

## Before

`plan-run` принимал `provider-config` как declared actual-route source. Это делало static
`CODEX_HOME/config.toml` заменой settings активного thread: новая сессия могла запускаться с
другим route, но пройти gate по сохранённому default. При отсутствии API команда также выдавала
native launch-block как будто новый launch сам добавит evidence; это создавало operator loop.

Baseline reproduction по исходному commit: `route_evidence.SOURCES` содержал
`provider-config`; в `bundles/P2.3.json` один D22 required-read ordinal был эмитирован дважды.

## Fix

- `route_evidence.capture_actual()` отклоняет `provider-config` как undeclared source.
- Canonical `plan-run` допускает только provider-bound обе оси active thread. При их отсутствии
  outcome — `waiting`, без предписания открыть новую сессию.
- Bundle builder оставляет первое occurrence одинакового `(field, ordinal, path, selector)`;
  одинаковые path- и D-resolver source в одном declaration больше не дублируются.
- Provider projections, Claude golden и package/root docs пересобраны owning generators.
