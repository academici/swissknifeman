# P7.2 — Owner Approval: provider selection и `.mcp.json` ownership

**Scope:** design-only boundary after D107. Этот документ не разрешает package/source
изменения, provider-config write, P2 transfer, live apply/repair/rollback, P7.2 execution,
P7.3+, FOREMAN, fleet, tag или push.

## Evidence baseline

- D107 принял P6 как `🟠 Done with deviations`; D106/P6.10 оставили live operation
  non-green и доказали zero-write. P6 не переоткрывается.
- В live root отсутствует `.swissknife.json`, а `config.json` не содержит provider layer
  ни для `swissknifeman`, ни в defaults. По frozen provider-config contract результат —
  legacy `claude-code=true`, `codex=false`.
- Live `.mcp.json` существует как gitignored machine-owned carrier, имеет SHA-256
  `cf4537196c3fefd6fd3980221bd3677f74e7867392ad49364e1e891e1f7c8283` и server IDs
  `maind`, `perplexity-web`, `serena`; matching P2 lock отсутствует. Поэтому ordinary P2
  whole-file plan обязан вернуть `ownership-conflict`, а `repair` не вправе усыновить файл.
- D104 transfer ограничен `.codex/hooks.json`/`.codex/hooks/lifecycle.py`; он не даёт
  authority на `.mcp.json` или включение Codex.

## Две оси Owner Approval

### S — effective provider selection этого проекта

- **S1 (рекомендация):** создать/дополнить project-owned
  `.swissknife.json#/providers` так, чтобы только `swissknifeman` явно выбирал
  `claude-code=true` и `codex=true`. Fleet/default/global carriers не менять.
- **S0:** сохранить legacy Claude-only selection. Тогда dual-provider acceptance P7.2
  недостижим; P7 и release track прекращаются либо отдельно переопределяются владельцем.

### O — ownership существующего live `.mcp.json`

- **O1 (рекомендация):** разрешить один exact, closed P2 transfer candidate только для
  live-root `.mcp.json` с указанным preimage SHA-256. Transfer обязан сохранить текущие
  три server ID/definition на первой транзакции, сделать recoverable backup, добавить
  ровно один matching artifact record к canonical P2 lock после D104 transaction и
  отказывать на любом другом path/preimage. Ordinary update/repair и implicit adoption
  не меняются; новая general-purpose adoption API запрещена.
- **O0:** оставить `.mcp.json` unmanaged. Тогда ordinary required-provider plan остаётся
  non-green и P7.2 не запускается.

Смешанные комбинации `S1+O0` и `S0+O1` не открывают P7.2: первая всё ещё блокируется
ownership, вторая не доказывает dual-provider self-host. Единственная исполнимая комбинация
для текущего плана — **S1+O1**.

## Рекомендация и точный literal

Рекомендация — **S1+O1**: это минимальная authority expansion, ограниченная одним проектом,
одним provider-selection carrier и одним exact machine-owned preimage. Механика version/API,
item decomposition, isolated worktree и validation остаётся делегированной D66/D79 и не
выносится владельцу как отдельный выбор.

Точный ответ владельца:

```text
APPROVE P7.2 AUTHORITY S1+O1: ENABLE PROJECT-LOCAL claude-code+codex FOR swissknifeman ONLY; AUTHORIZE ONE EXACT P2 .mcp.json TRANSFER CANDIDATE FOR SHA256:cf4537196c3fefd6fd3980221bd3677f74e7867392ad49364e1e891e1f7c8283; DESIGN/NO-WRITE ONLY; NO LIVE APPLY/REPAIR/ROLLBACK YET
```

Отказ/остановка:

```text
REJECT P7.2 AUTHORITY S0+O0: KEEP LEGACY CLAUDE-ONLY AND .mcp.json UNMANAGED; STOP P7 AND THE PLAN
```

## Continuation after approval

После exact `S1+O1` root agent фиксирует D108 и выполняет только bounded plan-design:
материализует exact contract-preserving P2/P6 remediation items, project-carrier merge rules,
temporary-root/no-write/rollback validation и fresh P7.2 rerun route. До отдельного normal
P7.2 live path/action gate никакой live mutation не разрешена. При `S0+O0` P7.2 не
переоткрывается и successor отсутствует.
