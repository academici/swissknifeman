# P3 — Provider-rooted owner attestation и durable authority

## Phase Context

P3 устраняет confirmed N-03, N-06, N-10, N-11 и N-14 как один trust chain:
неподделываемая/fail-closed provider attestation, атомарная grant activation, durable
commitment/replay state и policy только по observed/verified facts.

**Scope Included:** Codex/Claude provider adapters, owner materialization, authority request/response stores, observed-action analyzers, threat model.
**Scope Excluded:** pretending local transcript/env is a security root; journal append transaction; privacy/portability; consumer rollout.

> **Контракт фазы.** Потребляет: GREEN P1/P2 evidence · Производит: honest, replay-resistant owner/authority decision chain · Граница: no unproven provider security claim.

> **Phase Assurance | v1.**
> Impact: security-external
> Integration Seams: `provider-attestation` · `owner-materialization` · `authority-observation` · `durable-replay-store`
> Live or Irreversible: no
> Audit Intent: direct-close-eligible
> Rationale: trust-boundary change receives an independent security review named in Routing; phase audit still requires explicit owner-bound admission.

## DoR (Definition of Ready)

- [ ] P1/P2 terminal GREEN and P1 has an explicit provider capability/fallback decision.
- [ ] STRIDE assets/actors/entry points и provider support matrix заморожены.
- [ ] Any security-vs-workflow-guard downgrade is explicit and not hidden behind a digest.

## Phase Acceptance

- Agent-controlled env/transcript cannot mint security authority; unsupported providers fail closed or are explicitly workflow-only.
- Grant activation, replay consumption and commitment aggregation are atomic/durable under concurrency and process restart.
- Policy consumes observed/verified facts; unverifiable action requires approval.
- Independent review finds no open spoofing/tampering/replay/elevation path in the sealed candidate.
