## 1. Что показал замер (три вывода, меняющие постановку фазы)

**Вывод 1. Цель «`CLAUDE.md` ≤ 200 строк» на umbrella уже достигнута** — 88 строк / 2 381 ток
(`findings/P2…probe` §3). За 200 строк выходят проекты флота (779 / 598 / 527 / 503 / 461 /
402). Значит предмет — не «сократить umbrella», а (а) не дать ему уползти (машинный инвариант)
и (б) снять с флота то, что раздувает ЕГО файл.

**Вывод 2. Главный резидентный носитель флота генерирует сам swissknifeman.** Хаб-блок
`<!-- swissknifeman:hub:start … end -->` — 72 % `CLAUDE.md` agelto (10 319 из 14 203 ток),
66 % flexcrm, 51 % dterema-app. Внутри блока 200 строк из 237 — **перечисление установленных
скиллов с описаниями**, то есть второй платный экземпляр того, что Claude Code показывает сам:
нативный листинг несёт имя+описание каждого доступного скилла резидентно (RAG:✅ §9 findings).
Проектная часть `CLAUDE.md` agelto без managed-блоков — **153 строки**, то есть в норме.

**Вывод 3. Строка «MCP tool-defs» измерителя моделирует поведение, которого нет по умолчанию.**
Tool search в Claude Code включён по умолчанию: резидентны имена инструментов и инструкции
сервера, схемы отложены (RAG:✅ три first-party страницы + perplexity, §5.1 findings). Оценка
`150 ток × схема` честна лишь как верхняя граница ПРИ ВЫКЛЮЧЕННОМ tool search. На umbrella эта
строка — 49 % всей суммы (5 250 из 10 757), у agelto — 34 % (10 950 из 32 611).

Сложив выводы 2 и 3: **больше половины «красного» бюджета — либо наша собственная дубль-эмиссия,
либо фантом модели**. Это и объясняет, почему гейт красен у 5/5 и потому ничего не значит
(`plan.md` §1) — причина не только в жире, но и в приборе.

## 4. Почему пилот, а не сплошная раскатка

Правка `CLAUDE.md` 19 чужих репозиториев — необратимая работа по чужой поверхности, и её
эффект до замера неизвестен. Репозиторий уже держит правило «реализуем против измеренной
проблемы, а не в её ожидании» (`root.speculative-work`), и план уже использует эту фигуру в
P3 (пилот `paths:` → вердикт → раскатка). P2 повторяет её дважды: перенос знания в
path-scoped rules (P2.2 → P2.6) и сокращение хаб-блока (P2.5 → P2.6). Вердикт пилота — число
«до/после» на одном проекте, а не впечатление.

## 5. Риски конструкции

1. **Сокращая хаб-блок, можно потерять обнаружение скилла у провайдера без нативного
   листинга** (Cursor `.ai/skills`, `AGENTS.md`/`GEMINI.md`). Митигация — форма блока
   определяется каналом-целью, а не проектом (D20), плюс машинная сверка «каждый скилл блока
   присутствует в нативном активном наборе» перед вырезанием.
2. **Пере-издание модели MCP меняет все итоговые числа.** Baseline P1.2 снимается по старой
   модели → «до/после» законно только после пере-замера обеими моделями (D19,
   `Consequences`). Отдельный риск — заморозить порог (P1.3/OQ-1) поверх фантомной половины
   бюджета: вынесен в **OQ-4**.
3. **Диета канона может молча снять обязательство.** Митигация — `catalog.json` несёт
   `obligations`/`compatibility_assertions`, а `python3 -m harness.instructions --check` уже
   стоит в `validate.sh:105`: удаление, ломающее утверждение, красит гейт.
4. **`.mcp.json.example` default-on пишет в чужие репозитории** (файл + строка `.gitignore`)
   на ближайшем `maind sync`. Митигация — dry-run по флоту с публикацией «что изменится» до
   раскатки (P2.4 → P2.6).
