## Reconciliation

The bridge has three owners and must not mint a fourth contract. The P1.2 triplet defines what a
compiled slice means; the terminal P2 compiler produces that exact pending manifest. The P1.3/P2
authority and scheduler carriers define when `dispatch_worker` is legal and ensure durable intent
precedes the injected activity. The P1.4 triplet defines the only legal provider-neutral request,
events, terminal result and refusal order; terminal P3.1–P3.3 already implement the provider-native
mapping beneath it.

P3.4 may therefore add only a pure manifest-to-activity adapter and the shared bounded process
runner. It must pass the terminal compiler result through the existing scheduler/authority seam,
derive no alternate status/acceptance decision, and return one minimized observation. The existing
CLI may add explicit provider selection and `--max-slices 1` only on the prescribed `start`/`resume`
paths; omitted provider must retain the terminal P2 no-provider refusal. Contract/body changes,
synthetic defaults for missing fields, and direct runner-to-store writes remain forbidden.

The normative read order is synthesis/defect → slice contract/cases/validator → terminal compiler
and test → authority contract/cases/validator → terminal authority/scheduler and tests → worker
contract/cases/validator → terminal provider adapters/tests/parity → terminal CLI/test/README →
aggregate manifests and empirical P0 inputs. This moves the neutral owners ahead of implementation
convenience shapes while retaining the aggregates as final identity/hash gates.

Add those finite carriers to P3.4 Required Reads, remove the no-write escalation, and reset P3.4 to
`⬜ Not started`. Preserve P0/P1 bytes, terminal P2/P3.1–P3.3 artifacts, D34/D36–D40, P3.4

does not acquire an orchestration workflow. RAG:— (repo-grounded: sources above).
