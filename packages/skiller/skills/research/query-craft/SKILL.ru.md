# Query-craft — как сформулировать запрос к поисковому движку

Это про **КАК спросить**, а не про «когда» и не про «что подключать».
- **Когда** вообще искать/верифицировать факт → скилл `general/verify-claims` (классификация
  claim'а, лестница движков, цитирование).
- **Что** подключить проекту (context7/perplexity/web как серверы) → `general/mcp-advisor`.
- **Этот** скилл — единственный момент: запрос уже решено отправить; **сформулируй его так, чтобы
  получить точный ответ с первой попытки**, а не общую воду.

Проблема, которую он закрывает: запросы уходят размытыми — «Laravel, как сделать так-то?»,
«Filament, у нас должна быть минимальная версия 4». Движок не знает ни версии, ни стека, ни
контекста — и отвечает по медиане (часто по устаревшей мажорной версии). Цена размытости —
неверный ответ, на который потом опираются.

## Железное правило: НИКОГДА не отправляй голый запрос по библиотеке без версии и контекста

Перед отправкой запроса по фреймворку/библиотеке/инструменту (Laravel, Filament, Vue, Nuxt,
Livewire, Tailwind, …) **запрос обязан нести**: точное имя + **версию** (или диапазон «минимум X»),
**стек/окружение**, **конкретную задачу**, **временные рамки** при свежести.

| ❌ Анти-паттерн (так НЕ спрашивать) | ✅ Детализированный запрос |
|:--|:--|
| `Laravel как сделать очередь?` | `Laravel 11: настройка очередей на Redis с горизонтальным масштабированием через Horizon — актуальный синтаксис конфигурации на 2025` |
| `Filament — минимальная версия 4` | `Filament v4 (минимум 4.x, не 3.x): как объявить кастомное поле формы — изменения API относительно v3` |
| `Vue composition api лучшие практики` | `Vue 3.5 <script setup>: паттерны организации composables для крупного SPA, актуальные рекомендации` |
| `как тестировать` | `Laravel 11 + Pest 3: тест-изоляция БД через RefreshDatabase vs транзакции — что рекомендуют сейчас` |

> Если версия неизвестна — **возьми максимально свежую стабильную** и **скажи это явно** в запросе
> («актуальная стабильная версия на 2025», «последний мажор»), либо сперва уточни версию из
> `composer.json`/`package.json` проекта (repo-grounded — читается, не угадывается). Брать «по
> максимуму свежую» — дефолт, если из проекта версия не извлекается.

## Анатомия хорошего запроса (5 слотов)

Собирай запрос из слотов — пропуск слота = потеря точности. (Источник правил — официальный
prompt-guide Perplexity, см. провенанс внизу; те же принципы работают для WebSearch.)

1. **Инструкция-глагол** — что сделать: `сравни` / `объясни` / `перечисли` / `покажи синтаксис` /
   `найди изменения API`. Глагол задаёт форму ответа.
2. **Субъект + версия** — точное имя и **версия/диапазон**: `Filament v4`, `Laravel 11`,
   `Vue 3.5`, `минимум Filament 4 (не 3.x)`.
3. **Контекст/окружение** — стек, цель, аудитория, ограничения: `в проекте Laravel+Inertia+Vue`,
   `для production`, `для крупного SPA`, `совместимо с PHP 8.3`.
4. **Конкретика** — ключевые слова, имена методов/пакетов/стандартов, даты: `через Horizon`,
   `RefreshDatabase`, `Spatie Permission`, `на 2025`.
5. **Формат и лимит** — как подать ответ и сколько: `таблицей`, `списком top-5`, `с примерами кода`,
   `только официальная документация`. **Список без лимита → всегда задавай число** (`top-5`).

Минимальный шаблон:
```
<глагол> <субъект vX.Y> для <контекст/стек>, <конкретика/ключевые слова>, <временные рамки>.
Ответ: <формат>, <лимит>.
```

## Выбор движка (что куда)

Сначала движок — формулировка подстраивается под него. (Лестница «когда» — у `verify-claims`;
здесь — как сформулировать под уже выбранный движок.)

| Нужен факт о… | Движок | Как формулировать |
|:--|:--|:--|
| API/метод/опция конкретной библиотеки | **context7** (`resolve-library-id` → `query-docs`) | сначала резолвни id библиотеки **с версией**, запрос — узкий: имя символа/опции, а не общий вопрос |
| best practice / «ещё актуально» / сравнение / свежее изменение / рынок | **Perplexity** (`search` / `search_advanced` / `search_deep`) | полный 5-слотовый запрос (см. выше); версия+контекст ОБЯЗАТЕЛЬНЫ |
| одна известная страница/URL, тривиальная проверка | **WebSearch / WebFetch** | точные ключевые слова; для WebFetch — конкретный вопрос к странице |

> **context7 — про версию в id.** Узкое место context7 не формулировка прозой, а **правильный
> id+версия** при `resolve-library-id`. Резолвишь библиотеку → проверь, что взята нужная мажорная
> версия, потом задавай предметный `query-docs` (имя метода/опции), а не общий вопрос.

## Режимы Perplexity Web MCP (три инструмента)

Инструменты сервера `perplexity-web` (keyless-мост). Выбор режима = баланс глубина/скорость:

| Инструмент | Когда | Стоимость | Как формулировать |
|:--|:--|:--|:--|
| `mcp__perplexity-web__search` | дефолт: один проверяемый факт, быстрый ответ с цитатами | быстро | один сфокусированный 5-слотовый запрос |
| `mcp__perplexity-web__search_advanced` (`sources: web\|academic\|social`) | когда важен **контроль источника**: научка (`academic`) для пейперов/исследований, форумы (`social`=Reddit/форумы) для живого опыта/edge-cases, или их комбо | как search | тот же запрос + **явный выбор `sources`** под тип факта |
| `mcp__perplexity-web__search_deep` | глубокое: рынок, конкурентный ландшафт, обзор темы по 20+ источникам | **медленно, до ~5 мин** | широкий запрос с явными целями и желаемой структурой ответа; НЕ для одного факта |

**Выбор `sources` в `search_advanced`:**
- `web` — общий дефолт (документация, блоги, новости).
- `academic` — научные статьи, пейперы, цитируемость, формальные методы.
- `social` — Reddit и форумы: живой опыт, подводные камни, «у кого ещё так ломалось».
- комбинируй (`web+academic`), когда нужны и официальные доки, и формальное подтверждение.

> **Не пали `search_deep` зря.** До ~5 минут на запрос. Для одного факта/версии/сравнения хватает
> `search` или `search_advanced`. `deep` — только когда нужен синтез по многим источникам (см.
> «Стоимость» у `verify-claims`/`context-economy`).

## Надёжность keyless-моста `perplexity-web` (lock / таймаут на тяжёлых запросах)

`perplexity-web` — **keyless-мост через браузерный профиль** (один общий профиль). Отсюда два
наблюдаемых отказа, особенно на сложных/долгих запросах:

- **`Profile is locked by another … instance`** — профиль занят другой/зависшей сессией. Параллельно
  два запроса к `perplexity-web` слать нельзя.
- **Браузер закрывается на «thinking» → таймаут**, хотя ответ реально генерился. Тяжёлый запрос
  (особенно `search_deep`, до ~5 мин) перерастает таймаут моста — результат теряется.

**Что делать (порядок):**
1. **Не парралель** к `perplexity-web` — один запрос за раз; не ставь его в один батч с другим
   `perplexity-web`-вызовом. (Другие движки — context7/WebSearch — параллелить можно.)
2. **Тяжёлый запрос → дроби или меняй движок.** Вместо одного `search_deep` — несколько узких
   `search` (см. «один запрос = один факт»); либо для глубокого синтеза эскалируй в
   `research/research` поверх WebSearch/WebFetch.
3. **Lock не отступает / повторный таймаут → переключись на движок:** `WebSearch`+`WebFetch`
   (Claude-native, без браузерного профиля) для того же факта; для доков библиотеки — `context7`.
   Не упирайся в залоченный мост.
4. **Системно (для тяжёлых/частых запросов): перейди на API-key вариант** — нативный
   `@perplexity-ai/mcp-server` с `PERPLEXITY_API_KEY` (точнее/быстрее, без браузерного профиля и его
   таймаутов; каталог — `harness configs/claude-code/mcp/perplexity.json`). keyless-мост — для
   лёгких запросов без ключа; «сложные запросы по таймауту» — сигнал, что пора на ключ.

> Это **операционный обход**, не фикс сервера (мост — внешний, не в этом репо). Повторяющийся отказ
> моста маршрутизируй через [field-feedback-loop] (кандидат: дефолт на API-key вариант в каталоге
> harness для проектов с тяжёлым ресёрчем).

## Антипаттерны формулировки (правь до отправки)

- **Голый субъект без версии** — `Filament как...` → добавь `v4`/диапазон.
- **Несколько вопросов в одном запросе** — движок отвечает фрагментарно; **разбей** на отдельные
  запросы (один запрос — один факт/тема).
- **Список без лимита** — `дай список пакетов` → `top-5 пакетов ...`.
- **Расплывчатый глагол** — `расскажи про X` → `сравни X и Y по ...` / `покажи синтаксис ...`.
- **Без временных рамок на свежем факте** — для версий/релизов/«ещё актуально» добавляй
  `на 2025` / `актуальное` / `последний мажор`.
- **Описание самого инструмента в запросе** — не объясняй движку «поищи в вебе»; он сам.
- **Объяснение «почему мне это надо» вместо предмета** — контекст (слот 3) — это стек/цель, а не
  биография задачи.

## Итерация (если ответ мимо)

Формулировка — итеративна. Промах → **уточняющий follow-up**, а не переписывание с нуля:
`Только про европейские политики`, `Сфокусируйся на v4, игнорируй v3`, `Дай таблицей`,
`Используй только первичные источники, если слабые — перечисли ограничения`.

Анти-галлюцинация (high-stakes): добавь грунд-правило в запрос —
`Каждое утверждение — со ссылкой; если данных нет — скажи «не знаю», не угадывай`.

## Чеклист качества (перед отправкой запроса)

- [ ] Субъект несёт **версию/диапазон** (или явно «актуальная стабильная»); по библиотеке —
      сверена с `composer.json`/`package.json`, если доступно.
- [ ] Есть **контекст/стек** и **конкретика** (ключевые слова/имена), не общий вопрос.
- [ ] Один запрос = один факт/тема (не склеены несколько вопросов).
- [ ] Список — **с лимитом** (top-N); задан **формат** ответа.
- [ ] Выбран **движок** под тип факта (context7 для API · Perplexity для практик/свежести · Web для
      известного URL) и **режим** (`search`/`advanced`/`deep`) по глубине; `deep` не пущен ради
      одного факта.
- [ ] В `search_advanced` `sources` выбраны под тип факта (academic/social/web).
- [ ] На свежем факте есть **временные рамки**.
- [ ] При lock/таймауте `perplexity-web` — не параллелил; тяжёлый запрос раздроблён или переключён на
      WebSearch/context7; постоянная тяжёлая нагрузка → API-key вариант.

## Смежные скиллы

- `general/verify-claims` — **когда** искать/верифицировать (классификация claim'а, лестница
  движков, цитирование+confidence). Этот скилл подключается ПОСЛЕ её решения «надо проверить» —
  и отвечает «как сформулировать». `produces_for: verify-claims`.
- `general/mcp-advisor` — **что подключить** проекту (perplexity/context7/web как серверы). Здесь —
  как пользоваться уже подключённым.
- `research/research` — глубокий ресёрч-плейбук (source-tiers, синтез, knowledge graph); сюда
  эскалируешь, когда запрос перерастает в многошаговое исследование.
- `general/context-economy` — каждый движок стоит контекста/прав; не держи неиспользуемые. `deep`
  дорог по времени — лишний раз не пускай.
