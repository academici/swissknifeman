# P4.4 round-2 recovery design

## Inputs and classification

This synthesis consumes `findings/25-p4.4-round2-recovery-preflight-2026-08-15.md`, the rejected
`p4.4-task-plan-1` checkpoint and reviews, D40/D45, and the frozen
`english-authoring-overlay-v1` / `locale-authoring-review-v1` contracts. No external fact class is
load-bearing. RAG:— (repo-grounded: those committed carriers).

The second `FIX_REQUIRED` proves that the original checkpoint fingerprint exhausted its bounded
review budget. It does not prove that P4.4 scope or the frozen contracts are wrong. The remaining
work is local and reversible: preserve the committed candidate as evidence, create a materially
different replacement checkpoint, and prove the three known gaps before admission.

## Alternatives

| Alternative | Verdict | Reason |
|:--|:--|:--|
| Resume `p4.4-task-plan-1` with round 3 | Rejected | Directly violates D40/D45 and would erase the bounded-exit property. |
| Restore every P4.4 product path to `980ee79d` and discard all candidate work | Safe but not selected | Preserves rollback but wastes the restored routing semantics and the useful negative evidence already committed. |
| Retire the old fingerprint and create `p4.4-task-plan-2` from committed HEAD | Selected | Keeps append-only evidence, reuses verified work, and gives the materially changed candidate one bounded review budget. |

## Selected recovery

`p4.4-task-plan-1` remains rejected and immutable. A retirement carrier binds its base/candidate,
round-1/round-2 records and `accepted=false`; it is never rewritten into a success.
`p4.4-task-plan-2` starts from committed `e3555fd6` and changes the material fingerprint before any
new checkpoint review:

1. replace candidate-selected token allowlists with a preimage-derived, per-command ordered
   inventory bound to `git:980ee79d` and the candidate source digest; cover every frontmatter
   machine value, inline-code token, fenced code fragment, URL, path, command, ID, key,
   placeholder, parser literal and diagnostic/action code, including newly introduced candidate
   literals;
2. make tests independently compare the inventory with the source and fail on an omitted,
   reordered, multiplicity-changed or newly unclassified machine literal;
3. remove the two byte-identical English entries from the RU overlay. For these whole-command
   units the v1 sparse-overlay result is deliberately English fallback:
   `resolved_locale=en`, `fallback=true`, `overlay_sha256=null`. This is a contract-defined result,
   not a claim that English bytes are Russian;
4. run fresh distinct English semantic and RU/fallback reviews against the replacement candidate,
   then the zero-mutation checkpoint reviewer. Only explicit pass/`APPROVE` evidence admits the
   rows.

The first replacement candidate gets round 1. One `FIX_REQUIRED` permits one grouped fix commit,
fresh content-review evidence and round 2. A second `FIX_REQUIRED` creates an owner DecisionRequest
between exact rollback/defer and an explicit contract revision; it does not create another
replacement checkpoint automatically. This is the bounded escape required by the repository Task
development philosophy.

## Evidence reuse and downstream boundary

The replacement reuses the committed route-start fix, restored routing branches, old negative
reviews, and P4.3/P4.6 deferred-derived set. It does not rerun unrelated package suites before the
Task replacement checkpoint is accepted. Later P4.4 package checkpoints retain their existing
one-cwd/ten-row limit, and P4.6 remains the sole owner of generated command references.

The design changes no semantic command ID, route, helper API, frozen locale contract, consumer
project, provider target, fleet state, trust or credential. It adds plan/evidence carriers and a
bounded forward product-repair path only.
