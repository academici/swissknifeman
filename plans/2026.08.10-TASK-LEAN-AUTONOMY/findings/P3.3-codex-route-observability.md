# P3.3 — Codex route observability and native launch provenance

**Date:** 2026-08-11

## Evidence

- The official Codex CLI documentation says `/status` shows the current session configuration and
  `/model` chooses model and reasoning effort. RAG:✅
  (`https://learn.chatgpt.com/docs/codex/cli`)
- The official configuration reference documents `model_reasoning_effort`; explicit model/config
  overrides apply to newly created threads. RAG:✅
  (`https://learn.chatgpt.com/docs/config-file/config-reference`)
- The official app-server documentation documents `thread/read`. A local probe of Codex CLI
  `0.147.0` for the active `CODEX_THREAD_ID` returned only `modelProvider` and `status`, not model
  or reasoning effort. RAG:✅ for API existence; RAG:— for the local observed reply.
  (`https://learn.chatgpt.com/docs/app-server`)

## Decision

No documented programmatic current-thread API observed in the installed version supplies both
required route axes. `plan-run` therefore consumes **fresh native launch provenance** (`-m` plus
`model_reasoning_effort`) as `source="cli-flag"`, clearly distinct from runtime telemetry. It does
not read private session rollouts, static configuration, actor strings, or agent self-attestation.
The stricter provider-attested policy remains with `plan-exec`.

## Verification

The regression test asserts that canonical and rendered Codex `plan-run` surfaces use `cli-flag`
and contain neither `provider-doctor` nor `self-attested`. A fresh `codex exec` smoke launch with
the exact model and reasoning flags verifies that the native command accepts the route contract.
