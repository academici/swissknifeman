## 1. What actually collided

P5.2's escalation reads as two problems; they are one structural problem plus one non-problem.

**Structural.** The G2B generation manifest is defined as *"the hash set of whatever
`packages/artifex/**` currently contains"* (F1). P5.5 froze that set **before** the package could
execute a business admission — G2B could *admit* work and *not run* it. D118 then (correctly,
under owner delegation) put the missing execution seam in the package. But a package-owned
execution seam is, by the manifest's own construction rule, **part of the successor generation** —
not evidence about it. The collision is therefore not "P5.2 accidentally touched P5.5's files";
it is **"the successor generation was frozen one capability short of being a successor"**.

That reframing decides the ownership question: the seam is producer output, and `phases/P5.md`
names exactly one producer — P5.5 ("only P5.5 may mutate exact successor package/contract/
assurance paths"; "P5.2–P5.4 own evidence only and never refresh package generations"). D109's
Consequences already generalize the response class: *any* drift in the successor surface
**reopens P5.5 instead of being patched in a pilot** (F5).

**Non-problem.** The Claude Code "version drift" is a PATH accident, not a capability gap: the
pinned `2.1.222` build is still on disk and prints the exact frozen literal, and the package
already resolves `SKM_CLAUDE_BIN` before PATH (F3/F4). The frozen pin can be **honored** rather
than bumped, so no owner grant, contract bump or package edit is required for it.

## 2. Options considered

### Option A — grant P5.2 authority to re-freeze P5.5's manifests

P5.2 keeps the seam in its own scope and, as part of its own gate, rewrites
`business-successor-generation-v1.json` / `business-successor-assurance-v1.json`.

- Requires a **new** owner grant: it supersedes the phase contract `Границы` and D109.
- Makes the measuring item define the measured boundary — the G2B digest that P5.3/P5.4/P6 pin
  would be authored by the pilot that measures it. That is measurement self-certification, the
  exact failure class D107/D109 were written to prevent.
- P5.5's assurance would then describe bytes its own producer item never independently assured.
- **Rejected.**

### Option B (recommended) — reopen P5.5 as the sole producer, adopt the seam, re-freeze

P5.5 goes `🟠 Done with deviations` → `🟡 In progress` with a D# reason; it adopts the four
already-committed seam files (all inside D108's own scope list, F1), proves the seam's conformance
in its own validator/test set, re-freezes both manifests (no provider process, F2), and closes
again. P5.2 reverts to a pure consumer: plan-local harness, evidence, validator, finding.

- **No new owner authority needed.** D108 is `revoked=false`, `consumer=P5.5 only`, and every
  touched path is already inside its exact scope; its acceptance predicate is re-runnable; its
  finite probe budget is untouched (F2).
- Matches the plan's own prescribed response to successor drift (D109, F5).
- D113's terminal-evidence acceptance rule is unaffected: the same two minimized R2 observation
  rows carry over verbatim and are mechanically revalidated by the writer itself (F2).
- Downstream stays coherent: P5.3/P5.4/P6 keep pinning "the exact G2B digest", which now denotes a
  package that can actually execute a business admission.
- Price, named: one extra producer cycle; P5.5's terminality is re-earned rather than assumed;
  the G2B digest moves `7c1187f0…` → the value recomputed at re-freeze time (F1 shows
  `f13c30f2…` for the current tree, valid only while no further package byte changes).

### Option C — revert the package seam, put the bridge in `run-pilot.py`

- Contradicts D118 (owner-delegated architecture decision, package-owned) and P5.2's own Scope
  Excluded ("design or implement a second/plan-local successor inside the pilot harness").
- Was already tried and voided as D116 under D117.
- **Rejected.**

### Version pin: option V1 (recommended) vs V2

- **V1 — execute against the pinned build.** Set `SKM_CLAUDE_BIN=~/.local/share/claude/versions/
  2.1.222` for the pilot; the live probe then returns the exact frozen literal (F3/F4). No grant,
  no contract change, no package change. Limit: the build's continued presence must be re-probed
  immediately before dispatch, never assumed (F3).
- **V2 — bump the pin to `2.1.223`.** Requires a new owner grant (it edits the frozen
  `business-dispatch-admission-v1@1.0.0` contract text, `provider-business-projection-v1.json`
  and `BUSINESS_VERSION`), reopens P5.5 for a second reason, and re-dates every provider claim
  against a CLI surface nobody has re-verified at that version. **Rejected while V1 works**; if
  the 2.1.222 build ever disappears, V2 becomes the only path and needs an owner carrier then.

## 3. Resulting item topology

| Item | Owns | Change from current spec |
|:--|:--|:--|
| P5.5 (reopened) | the whole G2B surface: contract, runtime, provider mapping, **execution seam**, generation + assurance manifests | Scope Included gains the D118 seam adoption + re-freeze; status `🟡`; Files unchanged (seam paths already listed) |

Coupling surface touched by this reconcile (for later phases): `business-successor-generation-v1.
json` / `business-successor-assurance-v1.json` (P5.5 producer; P5.2/P5.3/P5.4/P6 consumers) and
`packages/artifex/lib/artifex/{activity,cli}.py` (P5.5 producer only, from now on).
