## Known Deviations (process)

- **Smoke definition self-corrected mid-run.** The first real rollback pass used
  `bash packages/task/scripts/validate.sh` as originally written and returned
  `smoke_passed: false` (a genuine `ERROR`/`FAILED` in that historical commit's own
  journal-fixture/`test_provider_command_parity` tests — pre-existing debt of that
  old tree, unrelated to this item's diff). Investigated (`git worktree add` a
  throwaway debug worktree at `PRE_PLAN_SHA`, ran the same command with full
  untruncated output) and reclassified as a smoke-definition mismatch rather than a
  real rollback defect (see previous section for the corrected definition).
  `run_canary.py::rollback_rehearsal`/`_smoke_steps` was rewritten in place and the
  rollback phase alone was re-run against the SAME already-committed worktree
  (the six case commits were not re-dispatched a second time — no repeat real-provider
  cost). A first draft of the fix computed `.py` file paths from this script's own
  (main-repo) location rather than from the worktree actually checked out at call
  time — caught before being treated as the fix (a fake-dispatch dry run alone would
  not have caught this; it needed the tree-relative file-count cross-check above) and
  corrected before the real re-run reported here.
- **Worktree-root `mktemp` directory not `rmdir`'d.** `git worktree remove
  "$CANARY_WT"` succeeded and the worktree entry is gone from `git worktree list`;
  the now-empty parent `$CANARY_ROOT` (created by `mktemp -d -p /tmp`) could not be
  removed — the local harness auto-approve hook (`~/.claude/hooks/auto-approve/`)
  hard-denies any `rm`/`rmdir`-shaped command on a path outside
  `safe-dirs.json`'s registered directories, and `/tmp` is not registered there.
  This is an environment-level constraint outside this item's tool permissions, not
  a defect in the rollback/cleanup logic itself; `git worktree list` and `git status
  --short` on the main repo are both clean, which is what this item's Validation
  actually checks. The same class of leftover empty `/tmp` directories is already
  visible for several *other*, unrelated worktrees in this repository's own
  `git worktree list` output (pre-existing pattern across this plan's earlier
  phases, not introduced here).
