# Синтез rollout-дизайна

Цель — не делать Codex глобальным неявным состоянием и не обходить protection
managed files. Вместо этого P0 сначала определяет и реализует проектную Codex
проекцию для connect-канала либо явно ограничивает канал с точной диагностикой.
Затем один существующий проект служит пилотом; только зелёная повторяемая
проекция и health допускают следующий проект. Некорректные реестровые временные
пути исключаются из выбора, но не удаляются автоматически.

Трассировка: «те же выборы» → P0.1 контракт выбора + P1.1 пилот;
«дорабатывать и повторять» → P0.2 + P1.2; «все проекты последовательно» → P2.1.
